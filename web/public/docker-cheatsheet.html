Image · Layer · Container

Each RUN/COPY/ADD = a cached, content-addressed layer, shared across images. A container adds one writable copy-on-write layer (ephemeral → use volumes for data).

CLI Reference

docker run -d --name web -p 8080:80 app:1.2
docker ps [-a]                   # running / all
docker exec -it web sh           # shell in a container
docker logs -f --tail=100 web

docker stats     docker top web  # live resources
docker images    docker history app:1.2
docker system df                 # disk usage
docker system prune [-a]         # reclaim space !

Exit codes: 137=OOM/SIGKILL · 143=SIGTERM · 139=segfault · 125/126/127=docker/exec errors.

Layer Caching Rules

  • Cache invalidates from the first changed instruction to the end → order least→most frequently changing.
  • Copy deps first, install, THEN copy source — so a code change doesn't bust the deps layer:
COPY package.json package-lock.json ./
RUN npm ci               # cached unless deps change
COPY . .                 # only this busts on code edit
RUN npm run build
  • .dockerignore shrinks context & stops .git/node_modules busting cache !
  • Clean up in the same RUN (a later delete doesn't shrink the image) !
  • Pin base by tag/digest; don't apt upgrade in builds.

Multi-Stage & Base Images

# build stage
FROM golang:1.22 AS build
WORKDIR /src
COPY . .
RUN CGO_ENABLED=0 go build -o /app ./cmd
# tiny final stage
FROM gcr.io/distroless/static
COPY --from=build /app /app
USER nonroot
ENTRYPOINT ["/app"]
BaseUse
scratchstatic binary (Go/Rust)
distrolessapp+runtime, no shell → small & secure
alpine (~5MB)tiny, musl libc gotchas !
debian-slimglibc, safe default

CMD vs ENTRYPOINT

  • ENTRYPOINT = the executable; CMD = default args (overridable by docker run img args).
  • Exec form ["nginx","-g","daemon off;"] → your process is PID 1, gets SIGTERM → graceful stop.
  • Shell form nginx -g ... → wrapped in /bin/sh -c, swallows signals → no graceful shutdown, 10s then SIGKILL !
  • PID 1 must reap zombies & handle signals — add --init/tini if your app can't.
  • Entrypoint script: do setup then exec "$@" (hand off PID 1) !

BuildKit & buildx

# build secret — NOT baked into any layer
RUN --mount=type=secret,id=npmrc \
    npm ci
docker build --secret id=npmrc,src=$HOME/.npmrc .

# package-manager cache across builds
RUN --mount=type=cache,target=/root/.cache go build ./...

# multi-arch + shared CI cache
docker buildx build --platform linux/amd64,linux/arm64 \
  --cache-to type=registry,ref=acme/app:cache \
  --cache-from type=registry,ref=acme/app:cache -t app .
  • Secrets via ARG/COPY persist in image history forever — use BuildKit --secret !
  • CI cache never hits? runners are ephemeral → registry cache (--cache-to/from).

Registries & Tags

docker tag app:1.2 ghcr.io/acme/app:1.2
docker push ghcr.io/acme/app:1.2
docker pull ghcr.io/acme/app@sha256:...   # by digest
  • Ref = registry/namespace/repo:tag (defaults docker.io/library, :latest).
  • Tags are mutable pointers; digests (@sha256) are immutable — deploy by digest for reproducibility !
  • :latest is a trap (surprise upgrades, unclear what's running) !
  • Build once → promote the same digest across envs; don't rebuild per env.
  • Docker Hub anon pull limits break CI → auth / pull-through mirror.

  • Volumes aren't removed with the container (dangling volumes eat disk) — run --rm -v / volume prune.

Compose

services:
  web:
    build: .
    ports: ["8080:80"]
    depends_on:
      db: { condition: service_healthy }   # wait for READY !
    environment: { DB_HOST: db }
  db:
    image: postgres:16
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD","pg_isready","-U","postgres"]
      interval: 5s
      retries: 5
volumes: { pgdata: {} }
docker compose up -d --build   |   down [-v]
docker compose logs -f web     |   exec web sh
docker compose config          # render merged config
  • Compose makes a user-defined net → services reach each other by service name.
  • Plain depends_on waits for START, not READY — add condition: service_healthy !
  • Override files (-f base.yml -f prod.yml) & .env for per-env config.

Resources & Runtime

docker run --memory=512m --cpus=1.5 \
  --restart=on-failure:3 --init \
  --log-opt max-size=10m --log-opt max-file=3 app
  • Over memory limit → OOMKilled (137); over CPU → throttled, not killed.
  • Old JVM/Node saw HOST memory, not the cgroup → OOM; modern runtimes respect cgroups !
  • Default json-file logs grow unbounded → set max-size/max-file !
  • --ulimit nofile fixes "too many open files"; --shm-size for Chrome/Postgres.

Security

  • Shared kernel → weaker isolation than a VM; defense in depth.
  • Run non-root (USER); --cap-drop ALL then add only what's needed; --read-only + tmpfs.
  • --security-opt no-new-privileges; keep the default seccomp/AppArmor profile.
  • Never --privileged, --net/--pid=host, or mount /var/run/docker.sock (= root on host) !
  • No secrets in image/ENV/ARG (leak in history/inspect) — BuildKit --secret at build, mounted files/secret manager at runtime !
  • The docker group = root-equivalent.

Image Supply Chain

  • Scan images for CVEs (Trivy / Grype / Docker Scout) in CI & at the registry; fail on criticals.
  • Patch = rebuild regularly (a pinned base rots) — digests for reproducibility + a rebuild pipeline for security.
  • Minimal base = fewer packages = fewer CVEs.
  • Sign images (cosign/sigstore) & verify in admission; SBOM (syft) to know contents; provenance/SLSA attestations.
  • Only run signed+scanned images (Kyverno/OPA/Binary Authorization).

☐ Dockerfile Review Checklist

  • ☐ Multi-stage: no build tools/SDK in the final image.
  • ☐ Minimal pinned base (distroless/slim + tag or digest, not :latest).
  • ☐ Non-root USER; no secrets in ARG/ENV/layers.
  • ☐ .dockerignore present; deps copied & installed before source (cache).
  • ☐ Cleanup in the same RUN; versions pinned.
  • ☐ Exec-form ENTRYPOINT/CMD (PID 1 signals); --init if needed.
  • ☐ HEALTHCHECK defined; ports published, not just EXPOSEd.
  • ☐ Image scanned; runs read-only + cap-dropped.

★ Troubleshooting Playbook

Exits immediately (code 0/1)

  • ☐ logs + exit code; main process ended / wrong CMD → run with a shell / override entrypoint.

OOMKilled (137)

  • ☐ inspect .State.OOMKilled; raise --memory or fix leak; check runtime is cgroup-aware.

Image is huge

  • ☐ history/dive; multi-stage, smaller base, clean in-layer, .dockerignore.

Cache never hits in CI

  • ☐ ephemeral runners → buildx --cache-to/from registry; fix instruction order & context.

Containers can't connect

  • ☐ user-defined network + service name (not localhost); check network inspect, ports.

Disk full

  • ☐ system df → system prune (mind -a); rotate logs; prune volumes/build cache.
