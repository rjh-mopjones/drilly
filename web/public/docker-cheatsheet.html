Image · Layer · Container

flowchart TD D["Dockerfile"] -->|build| IMG["Image = read-only layers + config JSON"] IMG --> L1["layer: base rootfs"] IMG --> L2["layer: deps"] IMG --> L3["layer: app"] IMG -->|run| C["Container
= image + thin R/W layer"]

Each RUN/COPY/ADD = one cached, content-addressed (sha256) layer, shared across images via overlay2. A container adds a single copy-on-write writable layer — ephemeral, so persist real data in volumes. An image is layers + a config blob (CMD, ENV, ports); a manifest ties them together.

Container = a Process (vs VM)

Not a lightweight VM — a normal Linux process on the host kernel, isolated by 3 kernel features:

FeatureControls
namespaceswhat it sees: pid (own PID 1), net, mnt, uts (hostname), ipc, user
cgroupswhat it uses: CPU, memory, block IO, PID count
union FSits root: overlay2 stacks R/O layers + a R/W layer
ContainerVM
Kernelshared (host)own guest kernel
Bootmsseconds+
Isolationweakerhardware-enforced
  • ps aux on the host shows the container's PIDs as ordinary processes — its PID namespace just hides the rest !
  • Shared kernel ⇒ a kernel exploit escapes a container, not a VM. For hard multi-tenancy use gVisor/Kata or a VM boundary !
  • No kernel inside ⇒ Linux images can't run on the Mac/Win kernel — Docker Desktop hides a Linux VM.

Architecture: CLI → runc

docker CLI --HTTP over /var/run/docker.sock--> dockerd
dockerd --gRPC--> containerd --> shim --> runc --> your PID 1
  • dockerd — API server: images, build, networks (bridges + embedded DNS + iptables), volumes. Orchestrates; does not run your process.
  • containerd — lifecycle + image pull; drivable directly (K8s does — dropped dockershim).
  • runc — the OCI runtime that actually sets up namespaces/cgroups, sets the root FS, then execs the entrypoint and exits; the shim keeps stdio + exit status.

OCI (image / runtime / distribution specs) decouples "container" from "Docker" — Podman (daemonless, rootless), nerdctl, CRI-O run the same images.

! The socket /var/run/docker.sock = root on the host. The docker group is root-equivalent — treat both as crown jewels.

CLI Reference

docker build -t app:1.2 .          # build from Dockerfile
docker run -d --name web -p 8080:80 app:1.2
docker ps [-a]                     # running / all
docker exec -it web sh             # shell into a running ctr
docker run --rm -it app sh         # throwaway shell
docker logs -f --tail=100 web
docker inspect web                 # full JSON (.State, .NetworkSettings)
docker stats      docker top web   # live resources / procs
docker images     docker history app:1.2   # layers + sizes
docker cp web:/etc/app.conf .      # copy out of a ctr
docker system df                   # disk usage
docker system prune [-a] [--volumes]  # reclaim space !

Exit codes: 0=clean · 1=app error · 137=SIGKILL/OOM (128+9) · 143=SIGTERM (128+15) · 139=segfault · 125=docker run failed · 126=cmd not executable · 127=cmd not found.

! prune -a deletes all unused images (not just dangling); --volumes can nuke data.

Layer Caching Rules

  • Cache invalidates from the first changed instruction to the end → order steps least → most frequently changing.
  • Copy deps first, install, THEN copy source — a code edit must not bust the deps layer:
COPY package.json package-lock.json ./
RUN npm ci                 # cached unless deps change
COPY . .                   # only this busts on a code edit
RUN npm run build
  • Cache key = instruction text + checksum of copied files + parent layer. Same inputs ⇒ hit.
  • .dockerignore shrinks context & stops .git/node_modules/*.log from busting COPY cache + leaking secrets !
  • Chain + clean in the same RUN — a later rm in a new layer doesn't shrink the image !:
RUN apt-get update && apt-get install -y --no-install-recommends \
      curl ca-certificates \
 && rm -rf /var/lib/apt/lists/*
  • Pin base by tag/digest; don't apt upgrade in a build (non-reproducible).

Multi-Stage & Base Images

# --- build stage (has the toolchain) ---
FROM golang:1.22 AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -o /app ./cmd
# --- tiny final stage (no compiler) ---
FROM gcr.io/distroless/static
COPY --from=build /app /app
USER nonroot
ENTRYPOINT ["/app"]
BaseUse / trap
scratchfully static binary (Go/Rust); no shell, no certs
distrolessruntime only, no shell → small & low-CVE
alpine (~5MB)tiny; musl libc + DNS quirks !

  • Multi-stage = build tools stay behind; only artifacts land in the shipped image. tip --target build to stop at a stage; COPY --from=nginx:alpine to steal files from any image.
  • No shell (scratch/distroless) ⇒ exec/HEALTHCHECK CMD-SHELL won't work — debug via an -debug tag or ephemeral docker debug !

CMD vs ENTRYPOINT & PID 1

  • ENTRYPOINT = the executable; CMD = default args, overridable by docker run img ARGS. Together: ENTRYPOINT ["nginx"] + CMD ["-g","daemon off;"].
  • Exec form ["nginx","-g","daemon off;"] → your process is PID 1, receives SIGTERM → graceful stop.
  • Shell form nginx -g ... → wrapped in /bin/sh -c; the shell is PID 1 and swallows signals → no graceful shutdown, 10s grace then SIGKILL (137) !
# entrypoint.sh: do setup, then HAND OFF PID 1
#!/bin/sh
set -e
migrate_db
exec "$@"          # exec = replace shell, keep signals !
  • PID 1 is special: it must reap zombies and handle signals. If your app can't, add --init (tini) or ENTRYPOINT ["tini","--"] !
  • docker stop = SIGTERM → wait --time (10s) → SIGKILL. Trap SIGTERM to drain connections.

BuildKit & buildx

# build secret — NOT baked into any layer
RUN --mount=type=secret,id=npmrc npm ci
docker build --secret id=npmrc,src=$HOME/.npmrc .

# package-manager cache reused across builds
RUN --mount=type=cache,target=/root/.cache/go-build \
    go build ./...

# multi-arch + shared CI cache
docker buildx build --platform linux/amd64,linux/arm64 \
  --cache-to   type=registry,ref=acme/app:cache,mode=max \
  --cache-from type=registry,ref=acme/app:cache \
  -t acme/app:1.2 --push .
  • BuildKit (default since 23.0) = parallel stage builds, better cache, --mount secrets/cache/ssh.
  • Secrets via ARG/ENV/COPY persist in image history forever — use --secret; they never hit a layer !
  • CI cache "never hits"? Runners are ephemeral → local cache is gone. Use registry cache (--cache-to/from) or gha cache !

Registries & Tags

docker tag app:1.2 ghcr.io/acme/app:1.2
docker push ghcr.io/acme/app:1.2
docker pull ghcr.io/acme/app@sha256:ab12...   # by digest
  • Ref = registry/namespace/repo:tag (defaults docker.io/library, :latest).
  • Tags are mutable pointers; digests (@sha256:) are immutable — deploy by digest for reproducibility !
  • :latest is a trap: surprise upgrades, unclear what's actually running, breaks rollbacks !
  • Build once → promote the same digest dev→stage→prod; never rebuild per environment.
  • A manifest list maps one tag to per-arch images (amd64/arm64) — the daemon pulls the match.
  • Docker Hub anon pull limits break CI → authenticate or run a pull-through mirror.

Networking — under the hood

A container is a process in its own net namespace. Docker wires it up with a veth pair (virtual cable): one end is eth0 inside, the other attaches to a host bridge (docker0 / br-<id>, an L2 switch).

RuleChainDoes
MASQUERADEPOSTROUTINGsrc-NAT ctr IP → host IP (egress)
DNATPREROUTINGhost:8080 → ctr:80 (published port)
  • Same bridge = can talk; different user-defined networks are isolated even by IP — Docker's iptables drops cross-net traffic unless a ctr is attached to both !
  • Embedded DNS at 127.0.0.11 (user-defined nets only) resolves container names + --network-alias. This is why Compose service names "just work".
  • overlay adds ~50B VXLAN headers → smaller effective MTU → "large requests hang" bugs over VPNs !
  • Put custom firewall rules in the DOCKER-USER chain — Docker won't clobber it.

Volumes & Storage

docker run -v pgdata:/var/lib/postgresql/data pg   # named
docker run --mount type=bind,src=$PWD,dst=/app app # bind (explicit)
docker run --tmpfs /run:size=64m app
docker volume ls | prune
  • The writable layer is ephemeral — dies with the container. Persist via a volume !
  • Volumes are not removed with the container (dangling volumes eat disk) — run --rm drops anon vols; volume prune reclaims.
  • Root container → files land root-owned on the host (UID mismatch pain on bind mounts) ! Run as a matching UID or chown.
  • Bind mount over a populated image dir hides the image's files (e.g. mounting empty node_modules) !
  • Back up a named volume: run a throwaway ctr that mounts it + a host dir, then tar it out:
docker run --rm -v pgdata:/v -v $PWD:/b alpine \
  tar czf /b/pgdata.tgz -C /v .

Compose — basics

services:
  web:
    build: .
    ports: ["8080:80"]
    depends_on:
      db: { condition: service_healthy }   # wait for READY !
    environment: { DB_HOST: db }
  db:
    image: postgres:16
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD","pg_isready","-U","postgres"]
      interval: 5s
      timeout: 3s
      retries: 5
volumes: { pgdata: {} }
docker compose up -d --build   |   down [-v]
docker compose logs -f web     |   exec web sh
docker compose ps              |   config   # render merged
  • Compose auto-creates a user-defined network → services reach each other by service name.
  • Plain depends_on waits for START, not READY — add condition: service_healthy ! The app still needs its own connection retry.

Compose — in depth

  • Overrides: -f base.yml -f prod.yml deep-merge (later wins); compose.override.yml auto-loads in dev.
  • Profiles: profiles: [debug] → only start with --profile debug (optional services).
  • Env interpolation: ${DB_PASS:?err} (required), ${PORT:-8080} (default). Values from shell + .env in the project dir.
  • Scale: docker compose up --scale worker=3 (drop the fixed container_name first).

Resources & Runtime

docker run --memory=512m --memory-swap=512m \
  --cpus=1.5 --pids-limit=200 \
  --restart=on-failure:3 --init \
  --read-only --tmpfs /tmp \
  --log-opt max-size=10m --log-opt max-file=3 app
  • Over memory limit → OOMKilled (137); over CPU → throttled, not killed.
  • --cpus=1.5 = cgroup CPU quota; --cpuset-cpus pins to specific cores.
  • Old JVM/Node saw host memory, not the cgroup → OOM. Modern runtimes are cgroup-aware; still set -XX:MaxRAMPercentage / verify !
  • Default json-file logs grow unbounded → set max-size/max-file or a driver !
  • --ulimit nofile=… fixes "too many open files"; --shm-size for Chrome/Postgres crashes.

Security

  • Shared kernel → weaker than a VM; do defense in depth.
  • Run non-root (USER in the Dockerfile); --cap-drop ALL then add only what's needed (--cap-add NET_BIND_SERVICE).
  • --read-only rootfs + --tmpfs for writable paths; --security-opt no-new-privileges; keep the default seccomp/AppArmor profile.
  • Never --privileged, --net=host/--pid=host, or mount /var/run/docker.sock — each ≈ root on the host !
  • No secrets in image / ENV / ARG (leak via history/inspect) — BuildKit --secret at build; mounted files / secret manager / --env-file at runtime !
  • Prefer rootless Docker (user namespaces) to shrink blast radius. The docker group = root-equivalent.
  • Hard multi-tenancy (untrusted code): a shared kernel isn't enough — reach for gVisor (userspace kernel) or Kata (lightweight VM per container) !
  • Python slimming: python:3.12-slim + --no-cache-dir; prefer glibc wheels — alpine forces source builds of many C-extension packages (slow, needs a toolchain) !

Image Supply Chain

  • Scan for CVEs (Trivy / Grype / Docker Scout) in CI & at the registry; fail the build on criticals.
  • Patch = rebuild regularly — a pinned base rots as new CVEs land. Digests for reproducibility plus a scheduled rebuild pipeline for security (not a contradiction).
  • Minimal base = fewer packages = smaller CVE surface (distroless/slim/scratch).
  • Sign images (cosign/sigstore) & verify at admission; ship an SBOM (syft) so you know contents; attach provenance (SLSA) attestations.
  • Enforce "only signed + scanned images run" via Kyverno / OPA Gatekeeper / Binary Authorization.

Container Lifecycle & States

docker create nginx   # created: fs+config ready, NOT running
docker start <id>      # running: process executing
docker pause <id>      # paused: frozen via cgroup freezer
docker unpause <id>    # → running
docker stop <id>       # SIGTERM → grace(10s) → SIGKILL → exited
docker kill <id>       # SIGKILL now → exited
docker rm <id>         # removed: writable layer destroyed
docker run nginx      # = create + start
StateMeaning
createdfs + config prepared, no process yet
runningPID 1 executing
pausedall procs frozen (cgroup freezer), RAM held
exitedstopped; logs + fs still inspectable, can start again
removedwritable layer gone — unsaved data lost !
  • An exited container still exists — docker ps -a lists it; rm is what frees the R/W layer.
  • stop vs kill: stop is polite (SIGTERM first, drain window); kill is immediate SIGKILL — use only when wedged !
  • --restart policy re-runs the same container on exit; it does not recreate a fresh one.

overlay2 · CoW · Whiteouts

The storage driver implements image layering + the container's copy-on-write root. Default on Linux = overlay2 (kernel overlayfs): lowerdir (R/O image layers) + upperdir (R/W) → a merged view.

docker info | grep "Storage Driver"   # overlay2
ls /var/lib/docker/overlay2/          # layer data on disk
  • Copy-on-write: first write to a file from a lower layer copies the whole file up before the write — even to change one byte.
  • Write-heavy (DBs, big logs) ⇒ latency spikes + write amplification + no sharing → put hot data in a volume to skip the union FS entirely !
  • Page-cache is shared: N containers on one R/O layer share cached pages in RAM.
  • Whiteout = marker in an upper layer (char device 0/0) that hides a lower-layer file. It hides but does not remove — the bytes still ship. That's why an rm'd secret is still in the image !

Layer Count vs Content (myth)

"Fewer layers = faster containers" is wrong. At runtime overlayfs merges all R/O layers into one view once at start; 5 or 25 layers read the same. Startup is dominated by pulling missing layers + starting the process, not layer count.

  • Optimize layer content, not count: small base, no toolchain in the final image, clean up in-RUN, multi-stage. That shrinks pulls — the actually-slow thing.
  • More well-ordered layers can improve cache reuse — chasing a low count can hurt it !
  • Squashing collapses to one layer: kills cross-image layer sharing + cache reuse. Rarely worth it — reach for multi-stage instead.

Accounting for every byte

docker history app:1.2   # size + instruction per layer
docker inspect app:1.2   # .RootFS.Layers digest list
dive app:1.2             # interactive per-layer file browser

Signing, Mirrors & Promotion

Signing = who published it + untampered

cosign sign   ghcr.io/acme/app@sha256:9f3a...
cosign verify ghcr.io/acme/app@sha256:9f3a... \
  --certificate-identity ...
  • cosign/sigstore = modern (keyless OIDC, signs images + SBOM/attestations). DCT/Notary (DOCKER_CONTENT_TRUST=1) = older TUF-based. You sign the digest → trust bound to immutable content.
  • Admission controller refuses unsigned/untrusted images ⇒ "only run what we built & approved."

Pull-through mirror

Proxy that caches Docker Hub layers on the LAN: first pull fetches upstream, rest served locally. Dodges anon rate limits, cuts bandwidth, survives brief upstream outages. Point registry-mirrors in daemon.json. Distinct from a private registry (stores your images) !

Build once → promote the digest

crane copy ghcr.io/acme/app@sha256:9f3a... \
           ghcr.io/acme/app:prod

Never rebuild per environment — bytes would differ, so "what passed staging" isn't what's in prod. Build one image, test that digest, re-point tags forward. Config comes from env/secrets at runtime, not a rebuild !

Design / Debug — the 5 Axes

Any "write a Dockerfile" or "why is this broken" question reduces to five checks. When you write, satisfy all five; when you debug, find which is violated.

DinD: three ways to build in CI

  • docker.sock mount — simplest, but = root on the host !
  • Docker-in-Docker (--privileged) — isolated but privileged.
  • Kaniko / Buildah — daemonless, rootless, no privileged socket. Safest for shared runners.

Networking — debug playbook

Two containers "can't talk" — walk it top-down:

  • ☐ Same network? docker network inspect <net> — both listed? Default bridge has no DNS; you need a user-defined net !
  • ☐ Right target? Use the service/container name, not localhost (that's the caller itself).
  • ☐ DNS resolves? exec … getent hosts db / nslookup db → 127.0.0.11 answers on user-defined nets.
  • ☐ Port right? Talk to the container port, not the published host port; is the server bound to 0.0.0.0 not 127.0.0.1? !
  • ☐ Cross-net isolation: two different user-defined nets are firewalled apart even by IP — attach one ctr to both, or merge nets !

HEALTHCHECK & Graceful Shutdown

HEALTHCHECK --interval=30s --timeout=3s \
  --start-period=10s --retries=3 \
  CMD curl -fsS localhost/health || exit 1
  • Sets container health = starting → healthy / unhealthy; drives Compose depends_on: service_healthy and orchestrator restarts.
  • --start-period = grace for slow boots (failures don't count yet). Keep the probe cheap — it runs forever !
  • Distroless/scratch has no shell/curl ⇒ ship a tiny static health binary or use the orchestrator's probe instead !

Graceful shutdown

  • docker stop → SIGTERM → app should stop accepting work, drain in-flight, close conns → exit before the 10s --time deadline, else SIGKILL (137).
  • Trap it: trap 'graceful' TERM (shell) or a signal handler in the app; wrapper scripts must exec "$@" so the app is PID 1 !
  • STOPSIGNAL changes which signal stop sends (e.g. nginx wants SIGQUIT for graceful).

☐ Dockerfile Review Checklist

  • ☐ Multi-stage: no compiler/SDK/build tools in the final image.
  • ☐ Minimal pinned base (distroless/slim + tag or digest, not :latest).
  • ☐ Non-root USER; no secrets in ARG/ENV/layers (BuildKit --secret).
  • ☐ .dockerignore present; deps copied & installed before source (cache).
  • ☐ Install + cleanup in the same RUN; package versions pinned; no apt upgrade.
  • ☐ Exec-form ENTRYPOINT/CMD (PID 1 gets signals); --init/tini if the app can't reap.
  • ☐ WORKDIR not RUN cd; COPY not ADD (unless extracting).
  • ☐ HEALTHCHECK defined; ports published (-p), not just EXPOSEd.
  • ☐ Image scanned in CI; runs --read-only + --cap-drop ALL + no-new-privileges.
  • ☐ Log rotation + memory/CPU limits set on run/compose.

Exits immediately (0/1)

  • ☐ logs + exit code; main process ended / wrong CMD → override entrypoint with a shell to poke around.

OOMKilled (137)

  • ☐ inspect .State.OOMKilled; raise --memory or fix the leak; confirm the runtime reads the cgroup.

Image is huge

  • ☐ history/dive; go multi-stage, smaller base, clean in-layer, add .dockerignore.

Cache never hits in CI

  • ☐ ephemeral runners → buildx --cache-to/from registry; fix instruction order & context size.

Containers can't connect

  • ☐ user-defined network + service name (not localhost); check network inspect, published ports, DNS.

Disk full

  • ☐ system df → system prune (mind -a/--volumes); rotate logs; prune build cache.
