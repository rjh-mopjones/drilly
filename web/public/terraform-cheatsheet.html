Workflow

flowchart LR W["write HCL"] --> I["init
providers+backend"] I --> P["plan
refresh+diff → proposal"] P --> A["apply
converge"] A --> D["destroy"]

plan = refresh real state → build DAG → diff desired vs actual → propose create/update/replace/destroy. apply executes it (NOT transactional — can fail mid-way, leaving partial state).

Providers

terraform {
  required_version = "~> 1.7"
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 5.0" }
  }
}
provider "aws" { region = "us-east-1" }
provider "aws" { alias = "west", region = "us-west-2" }  # multi-region
  • ~> 5.0 = >=5.0,<6.0 (pessimistic). Pin providers.
  • Commit .terraform.lock.hcl (pins versions + checksums) ! init -upgrade to bump.
  • Pass aliased providers into modules explicitly; never hardcode creds — use env/OIDC/assume-role.

State — what & why

  • State = map from config addresses → real resource IDs + cached attrs. Terraform diffs config vs state vs reality.
  • State holds secrets in PLAINTEXT — encrypt & lock down the backend; who reads state reads secrets !
  • Never hand-edit terraform.tfstate — use state subcommands !
  • Lose state → Terraform forgets it owns the infra → tries to recreate it !
terraform state list
terraform state show aws_instance.web

Remote Backend & Locking

terraform {
  backend "s3" {
    bucket         = "acme-tfstate"
    key            = "prod/app/terraform.tfstate"
    region         = "us-east-1"
    dynamodb_table = "tf-locks"   # state locking !
    encrypt        = true
  }
}
  • Remote state = team collaboration + locking (no concurrent applies corrupting state).
  • Partial config: leave secrets/env values out of the block → pass via -backend-config.
  • Version the state bucket for recovery. force-unlock only when certain no apply is running !
  • Isolate state per component/env → smaller blast radius.

State Operations

terraform import aws_instance.web i-0abc123   # or import{} block
terraform state mv  A  B      # rename/move, no recreate
terraform state rm  ADDR      # forget (does NOT destroy real infra)
terraform apply -replace=ADDR # force recreate (was: taint)
terraform state pull > s.json # dump (last resort)

Prefer declarative refactors

moved  { from = aws_instance.a  to = aws_instance.b }
import { to = aws_instance.web   id = "i-0abc123" }
removed{ from = aws_instance.old }

moved/import blocks are version-controlled & survive across the team — better than one-off state mv ! Always plan to verify after.

Modules

module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "~> 5.0"          # PIN registry/git modules !
  cidr    = "10.0.0.0/16"
}
# git source: source = "git::https://.../mod.git?ref=v1.2.0"
# local:      source = "./modules/network"
resource "x" "y" { subnet_id = module.vpc.public_subnets[0] }
  • Root module = your config; child modules = reusable groups. Public API = variables (in) + outputs (out).
  • Design: single purpose, sensible defaults, minimal required inputs, composition over one god-module !
  • Don't wrap a single resource for no reason; don't hardcode providers inside reusable modules.
  • Unpinned modules = surprise breakage !

Drift

  • Drift = real infra diverges from state (console edits, other tools, autoscalers).
  • terraform plan refreshes and shows drift as changes even with no config change.
  • Reconcile: apply to revert to config · update config to match reality · import if unmanaged · plan -refresh-only to accept into state.
  • lifecycle { ignore_changes = [tags, desired_count] } to tolerate expected drift — but it can hide real problems !
  • Continuous drift detection: scheduled plan -detailed-exitcode in CI, TFC drift detection, driftctl.
  • Prevent it: least-privilege so humans can't ClickOps.

lifecycle & Dependencies

lifecycle {
  create_before_destroy = true   # no-downtime replace
  prevent_destroy       = true   # guard prod DB !
  ignore_changes        = [tags]
  replace_triggered_by  = [aws_x.y.id]
}
  • Implicit deps (a references b's attribute) are preferred; depends_on only when there's no reference link (reduces parallelism).
  • Terraform builds a DAG → applies independent resources in parallel (-parallelism=10); destroys in reverse order.
  • "Cycle:" error → break with indirection/splitting. terraform graph to visualize.
  • Provisioners (local/remote-exec) are a last resort — prefer user_data/images !

Testing & Policy

  • Cheap→expensive: fmt -check → validate → tflint → terraform test (1.6+, .tftest.hcl) → Terratest (real infra).
  • Security static scan: tfsec / checkov / Trivy (public buckets, open SGs, unencrypted).
  • Policy-as-code: Sentinel (TFC) / OPA-Conftest (Rego on plan JSON).
  • Cost: Infracost in PR. Assertions: pre/postconditions & check blocks. Wire it all in pre-commit + CI.

CI/CD & Secrets

  • plan-in-PR (post plan as a comment) → review → apply-on-merge; apply the saved -out plan so what's reviewed is applied.
  • Atlantis (PR-comment plan/apply + locking) · Terraform Cloud/Enterprise (remote runs, Sentinel, private registry) · GitHub Actions with OIDC (no static keys).
  • No undo — roll forward or revert the commit & apply.
  • Secrets: never in code/tfvars/git; source via env/Vault/OIDC — but they still land in state (encrypt it) !
  • sensitive=true redacts CLI output, NOT state !

  • Stable layers (network) separate from fast-changing ones (app).

☐ Plan Review Checklist

  • ☐ Any destroy / replace (-/+) — is downtime/data-loss intended? Prod DB guarded by prevent_destroy? !
  • ☐ Unexpected drift in the diff (someone changed it out-of-band)?
  • ☐ Secrets in the diff / plan output leaking to CI logs?
  • ☐ A count index shift recreating unrelated resources?
  • ☐ Change scoped to the right state / workspace / env?
  • ☐ Providers & modules pinned; lock file committed.
  • ☐ No hardcoded creds; backend encrypted + locked.
  • ☐ Reviewed the saved plan (-out), applying that exact artifact.
