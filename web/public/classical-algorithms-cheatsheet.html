Linear Regression

yhat = w·x + b     minimise MSE = ||Xw - y||^2
normal eq:  w = (XᵀX)⁻¹ Xᵀ y      (convex, global min)
gradient descent:  w -= η·Xᵀ(Xw - y)/n
CostUse when
Normal eqO(p³ + np²)p small (< ~10⁴), exact
GD / SGDO(np) per stepbig n, sparse, streaming

Gauss-Markov assumptions

  • Linearity, independent errors, homoscedasticity (constant variance), no perfect multicollinearity → OLS is BLUE.
  • ! Multicollinearity: XᵀX near-singular → coefficients huge/unstable, signs flip. Fix with Ridge or drop/​combine features.
  • ! Sensitive to outliers (squared loss); can predict outside sane range. Standardise for GD (not needed for normal eq).

High-bias / low-variance. Interpret coef = Δy per unit x, others held fixed. R² = fraction of variance explained but rises with any added feature → use adjusted R².

Ridge / Lasso / Elastic Net

Ridge (L2):  min ||Xw-y||² + λ·Σwⱼ²   → w=(XᵀX+λI)⁻¹Xᵀy
Lasso (L1):  min ||Xw-y||² + λ·Σ|wⱼ|   (no closed form)
Elastic:     α·L1 + (1-α)·L2
PenaltyEffect
RidgeΣw²shrink all, keep all; handles collinearity
LassoΣ|w|sparse → feature selection
Elasticbothsparse + groups correlated features
  • Why L1 is sparse: its diamond constraint has corners on the axes → optimum lands at wⱼ=0; L2's sphere has none. Soft-thresholding zeroes small coefs.
  • Ridge closed form always invertible (λI regularises the singular XᵀX — that's the fix for OLS's failure mode).
  • Bayesian view: Ridge = Gaussian prior on w, Lasso = Laplace prior. Both are the MAP estimate under that prior.
  • ! Lasso arbitrarily picks one of a correlated group and zeroes the rest → Elastic Net keeps the group together and is more stable.
  • ! Standardise first — penalty is scale-dependent. ! Don't penalise the intercept. Pick λ by CV; larger λ = more bias, less variance.

Logistic Regression

p = σ(w·x+b) = 1/(1+e^-(w·x+b))
logit: log(p/(1-p)) = w·x+b   (linear boundary)
loss = -Σ[y·log p + (1-y)·log(1-p)]   (convex)
grad = Xᵀ(p - y)   ← same shape as linear reg!
  • Discriminative classifier; models P(y|x) directly. Fit by GD or Newton/IRLS (2nd-order, few iters).
  • ! Not MSE — with the sigmoid, MSE is non-convex; log-loss (cross-entropy) is convex and is the MLE.
  • Multiclass: softmax (multinomial) or one-vs-rest. Coef → odds ratio e^wⱼ.
  • Naturally calibrated (outputs are probabilities). Regularise with L2/L1 exactly as linear.
  • ! Perfect separation → weights diverge to ±∞; regularisation prevents it. The honest linear baseline for any classification task.
  • Log-loss is convex (single global min) → GD/Newton always find the optimum. Fast to train and serve (O(p) per prediction), naturally streaming with SGD.

Naive Bayes

argmax_y  P(y)·∏ᵢ P(xᵢ|y)          (Bayes rule, ∝)
work in LOG space:  log P(y) + Σ log P(xᵢ|y)
VariantFeature type
Gaussiancontinuous (per-class μ,σ)
Multinomialcounts — text, TF
Bernoullibinary presence/absence
  • "Naive" = features conditionally independent given y (usually false, still works — decision boundary robust even when probabilities are miscalibrated).
  • ! Laplace smoothing (+1): an unseen feature-class pair gives P=0 → whole product 0. Mandatory for text.
  • ! Log-space or 100s of tiny probs underflow to 0.
  • Generative; O(np) train, one pass, streaming-friendly. Strong high-bias baseline for spam/text; no scaling needed.
  • Often beats logistic on tiny n (its generative assumptions substitute for data) but logistic overtakes it as n grows — the classic generative/discriminative pair.

k-Nearest Neighbors

predict: find k nearest by distance
  classify → majority vote   regress → mean
NO training — "lazy": just stores the data
  • k = bias/variance knob: k=1 → zero train error, high variance (noisy boundary); large k → smoother, higher bias. Odd k breaks ties; tune by CV.
  • ! Must scale features — distance is dominated by large-range features otherwise.
  • ! Curse of dimensionality: in high-d all points are ~equidistant → "nearest" is meaningless. Reduce dims first.
  • Predict cost O(nd) per query (brute force); KD-/ball-trees help in low-d, use approximate NN (HNSW) at scale.
  • Metric matters: Euclidean default, Manhattan for high-d, cosine for text/embeddings. Odd k for binary; distance-weighting (1/d) softens the k choice.
  • Non-parametric, zero training cost but heavy serving — the opposite profile to eager models. kNN ≠ k-means (supervised lookup vs unsupervised clustering).

Decision Trees (CART)

greedy recursive split; pick (feature,threshold)
that maximises impurity DROP (information gain)
Gini = 1 - Σpₖ²      entropy = -Σpₖ log pₖ
regression → minimise variance / MSE of leaves
  • Gini vs entropy: nearly identical splits; Gini is cheaper (no log). Leaf predicts majority class / mean.
  • No scaling, handles mixed types & non-linear interactions, interpretable (white box).
  • ! High variance / overfits — a deep tree memorises. Control with max_depth, min_samples_leaf, min_samples_split (pre-pruning) or cost-complexity pruning (α·|leaves|, post).
  • ! Unstable: small data change → different tree. Motivates ensembles. Can't extrapolate beyond training range.
  • Split search sorts each feature → O(n·p·log n) build; prediction is O(depth), a handful of comparisons. Handles missing values via surrogate splits.
  • Build cost O(n·p·log n). Rarely used alone → RF / boosting.

Bagging & Ensembles

TrainsFightsExample
BaggingparallelvarianceRandom Forest
BoostingsequentialbiasGBM/XGB
Stackingmeta-modelbothblend diverse
Votingparallel—hard/soft
  • Error = bias² + variance + noise. Bagging averages many low-bias/high-variance models on bootstrap samples → variance falls, bias unchanged.
  • Bootstrap: sample n with replacement → each bag covers ~63.2% of rows (1-1/e); the rest are out-of-bag.
  • Diversity is the whole game — if base models make the same errors, averaging does nothing.
  • ! Stacking leaks unless the meta-model trains on out-of-fold predictions. Soft voting (avg probs) > hard when models are calibrated.

Random Forest

bagged trees + random FEATURE subset per split
classify → majority vote   regress → average
predict variance ≈ ρσ² + (1-ρ)/B · σ²  → ↓ρ helps
  • Two randomness sources: bootstrap rows + random features (max_features ≈ √p classif, p/3 regress). Feature subsetting decorrelates trees (drops ρ) — that's the extra variance cut over plain bagging.
  • OOB error = free validation from the ~37% of rows each tree didn't see; no separate CV needed.
  • Knobs: n_estimators (more = better, never overfits — plateaus), max_features, max_depth. Parallel, robust, low-tuning.
  • ! Can't extrapolate (predictions bounded by training leaves). ! Impurity importance is biased toward high-cardinality features → prefer permutation importance or SHAP.
  • Variance-of-average floor: Var ≈ ρσ² as B→∞, so once trees are decorrelated, more trees only shave the (1−ρ)/B term — it plateaus, never overfits. Contrast boosting, where more trees eventually overfit.

Gradient Boosting (GBM)

Fₘ(x) = Fₘ₋₁(x) + η·hₘ(x)
hₘ fits the NEGATIVE GRADIENT of the loss
  (= residuals y-F for squared error)
start F₀ = mean / log-odds
  • Sequential — each shallow tree (depth 3–8 = interaction order) corrects the current ensemble's errors → drives down bias.
  • Gradient descent in function space: any differentiable loss (MSE, log-loss, quantile) via its gradient.
  • η (learning rate / shrinkage) trades off vs n_estimators — small η + more trees generalises better. Standard: η≈0.01–0.1.
  • ! Overfits if over-trained (opposite of RF). Regularise: early stopping on a val set, subsample (<1, "stochastic GB"), column subsample, tree depth/leaf caps.
  • Why it beats RF on accuracy: it drives bias down (RF only cuts variance) — but it's sequential (can't parallelise across trees) and far more tuning-sensitive.
  • Supports quantile loss for prediction intervals and Huber for robustness — any differentiable loss via its gradient.

XGBoost

obj = Σ loss + Σ Ω(fₜ),  Ω = γT + ½λ||w||²
2nd-order Taylor: uses gradient gᵢ AND hessian hᵢ
leaf weight w*ⱼ = -Σgᵢ / (Σhᵢ + λ)
  • Regularised GBM: explicit L2 (λ) on leaf weights + γ penalty per leaf (min split gain). This built-in regularisation is why it beat vanilla GBM.
  • Second-order (Newton) split gain uses Hessian → better steps. Sparsity-aware default direction for missing values.
  • Engineering: pre-sorted/​histogram splits, column blocks, cache-aware, parallel within a tree.
  • Key knobs: eta, max_depth, min_child_weight, subsample, colsample_bytree, lambda/gamma, n_estimators+early stop.
  • Split gain = ½[G_L²/(H_L+λ) + G_R²/(H_R+λ) − G²/(H+λ)] − γ; a split is only taken if the gain clears γ (pre-pruning built into the objective).
  • ! Tune with early stopping or you'll over-boost. hist tree method (histogram binning, à la LightGBM) is now the fast default. The tabular workhorse.

LightGBM vs CatBoost

Signature trick
XGBoostlevel-wise, 2nd-order, sparsity-aware
LightGBMhistogram, leaf-wise growth, GOSS + EFB
CatBoostordered boosting, native categoricals
  • LightGBM: histogram binning + leaf-wise (grows the highest-loss leaf) → fastest on big data. GOSS keeps large-gradient rows; EFB bundles sparse features.
  • ! Leaf-wise overfits small data → cap num_leaves and set min_data_in_leaf. num_leaves ≤ 2^max_depth.
  • CatBoost: ordered target statistics avoid target-leakage on categoricals; strong defaults, best when many category columns.
  • All three > deep nets on typical tabular data. Pick LightGBM for speed, CatBoost for categoricals, XGBoost for maturity.

Support Vector Machines

hard margin:  min ½||w||²  s.t. yᵢ(w·xᵢ+b) ≥ 1
soft margin:  min ½||w||² + C·Σξᵢ  (slack ξᵢ≥0)
margin width = 2/||w||;  SVs are points on/inside
  • Maximises the margin → good generalisation. Only support vectors (points on/violating the margin) define the boundary; rest irrelevant.
  • C = regularisation: large C → hard fit, narrow margin, low bias/high variance; small C → wide margin, more slack, higher bias.
  • Hinge loss; solved via the dual QP → exposes the kernel. Decision = sign(w·x+b). The hinge is convex → a single global optimum.
  • ! Scale features. ! Training is O(n²)–O(n³) → poor past ~10⁵ rows (use LinearSVC/SGD for linear + big n). No native probabilities (Platt scaling adds them).

Kernels & the Kernel Trick

K(x,x') = φ(x)·φ(x')   — inner product in a
lifted space, computed WITHOUT building φ
decision uses only dot products → swap in K
KernelK(x,x')
Linearx·x'
Polynomial(x·x' + c)^d
RBF/Gaussianexp(-γ·||x-x'||²)
  • Trick: non-linear boundaries at linear cost — never materialise the (possibly ∞-dim) feature map. Needs a PSD (Mercer) kernel.
  • RBF γ = reach of one point: large γ → tight, wiggly, overfits; small γ → smooth. Tune (C, γ) jointly by grid CV.
  • ! Default to RBF; try linear first when p ≫ n (text) — often already separable and far cheaper.

k-Means Clustering

minimise inertia = Σ ||x - μ_c(x)||²  (WCSS)
Lloyd: assign nearest centroid → recompute means
       → repeat to convergence
init: k-means++  (spread-out seeds)
  • Unsupervised, hard assignment. Converges to a local min → run multiple restarts (n_init), keep best inertia.
  • Choose k by elbow (inertia vs k) or silhouette score; there's no "true" k.
  • ! Assumes spherical, equal-size, equal-density clusters (Euclidean) — fails on elongated/​nested shapes.
  • ! Scale features; sensitive to outliers (means shift) → k-medoids is robust. Complexity O(n·k·d·iters).
  • Converges because each step (assign, then re-mean) never increases inertia and assignments are finite — but only to a local optimum of a non-convex objective. MiniBatchKMeans for large n.

Hierarchical / DBSCAN

  • Hierarchical (agglomerative): merge closest clusters bottom-up → dendrogram; cut at a height for k. Linkage: single (chaining), complete, average, Ward (min variance, default). O(n²log n), no k upfront.
  • DBSCAN: density-based via (eps, min_samples). Finds arbitrary shapes, labels noise/outliers, needs no k.
  • Core point = ≥ min_samples within eps; clusters grow through core points; unreachable points = noise.
  • No k to choose and it flags outliers natively — the go-to when clusters are arbitrary shapes with noise, where k-means fails.
  • ! DBSCAN struggles with varying density and is eps-sensitive (use a k-distance plot). HDBSCAN handles variable density.

GMM & EM

p(x) = Σₖ πₖ · N(x | μₖ, Σₖ)   (soft clusters)
EM:  E-step → responsibilities γᵢₖ = P(k|xᵢ)
     M-step → update πₖ,μₖ,Σₖ from weighted pts
maximise log-likelihood; monotone ↑, local optimum
  • Soft assignment + elliptical clusters (full covariance) — strictly more flexible than k-means.
  • k-means = GMM special case: spherical equal Σ, hard assignment (γ → 0/1).
  • Pick k by BIC/AIC. Restart (local optima). Covariance types: full / diag / tied / spherical trade flexibility vs params.
  • ! A component can collapse onto one point (Σ→0, likelihood→∞) — regularise covariance / floor variance.

PCA

center X → directions of max variance =
top eigenvectors of covariance C=(1/n)XᵀX
compute via SVD: X = UΣVᵀ  (V = components)
project: Z = X·V_k   (keep k components)
  • Unsupervised linear reduction: new orthogonal axes ranked by explained variance (eigenvalues). Equivalent to minimising reconstruction error.
  • Pick k by cumulative explained variance (e.g. 95%) or scree elbow.
  • ! Standardise first — else the largest-scale feature dominates the top PC.
  • ! Components are not interpretable features, and PCA is unsupervised — the max-variance axis needn't be the most predictive (see PLS/LDA for supervised).
  • Use SVD, not covariance eigendecomposition — forming XᵀX squares the condition number; truncated SVD gives the top-k cheaply for large/sparse data. ! Fit PCA inside the CV fold — it learns axes from data and leaks otherwise.

t-SNE / UMAP / LDA

UseNote
t-SNE2-D vizlocal structure, non-linear
UMAPviz + preprocfaster, more global
LDAsupervisedmax class separation
  • ! t-SNE is for pictures only — cluster sizes & between-cluster distances are meaningless; don't run downstream models on its output. perplexity is the key knob; non-deterministic.
  • UMAP: preserves more global structure, faster, embeds new points.
  • LDA (Fisher): supervised — maximises between-class / within-class scatter; yields ≤ C-1 dims. It's also a classifier.

AdaBoost

init weights wᵢ = 1/n
for m in 1..M:
  fit weak learner hₘ on weighted data
  err = Σ wᵢ·1[hₘ(xᵢ)≠yᵢ] / Σ wᵢ
  αₘ = ½·ln((1-err)/err)         (learner vote)
  wᵢ *= exp(αₘ·1[miss])          (upweight misses)
final: sign( Σ αₘ·hₘ(x) )
  • The original boosting: reweight the data so each stump focuses on what the ensemble still gets wrong; confident-and-correct learners get a bigger vote αₘ.
  • Base learner is usually a decision stump (depth-1 tree). Equivalent to forward stagewise additive modelling with exponential loss — that's the link to GBM (which generalises to any differentiable loss).
  • ! Exponential loss is sensitive to label noise / outliers — persistent mislabels get exponentially upweighted. GBM with log-loss/Huber is more robust; prefer gradient boosting in practice.
  • Still low-tuning and interpretable-ish; largely superseded by XGBoost/LightGBM but a classic derivation to know.

Tuning Strategy

  • Baseline first — defaults + a simple model; know the floor before you tune.
  • Few knobs, coarse-to-fine: wide log-spaced grid to find the region, then narrow around the best point.
  • CV every candidate — optimise out-of-sample score, not train fit. Favour the simpler model within 1 standard error of the best.
  • Random > grid for large spaces (covers each dim better); Bayesian (Optuna/Hyperopt) is most sample-efficient.
  • Early stopping for boosting instead of gridding n_estimators: set it high, let a val metric pick the count.
  • ! Coupled knobs aren't separable — tune eta↔n_estimators and C↔γ jointly; one-at-a-time misses the optimum.
  • Tune inside a Pipeline; keep a final untouched test set (nested CV for an honest estimate).

Leakage & Pipelines

Pipeline([("scale", StandardScaler()),
          ("pca",   PCA(n_components=0.95)),
          ("knn",   KNeighborsClassifier())])
cross_val_score(pipe, X, y, cv=5)  # refit per fold
  • Any statistic learned from data — a scaler's mean, an imputer's fill, PCA axes, a target encoding — must be fit on the training fold only, then applied to validation. A Pipeline enforces that mechanically.
  • ! Fit-then-split leaks: scaling/imputing/PCA on the full dataset lets validation statistics bleed into training → inflated CV, collapse in prod.
  • ! Target-encoding leak: mean-encoding a category on the same rows you train on injects the row's own label. Fix: out-of-fold encoding, leave-one-out, or smoothing (n·catμ + m·globalμ)/(n+m); CatBoost's ordered stats do it structurally.
  • Pipelines also kill train/serve skew — the identical transforms run at predict time. Ship the whole Pipeline, not just the model.

Class Imbalance

  • Reweight the loss first — sklearn class_weight="balanced", XGBoost scale_pos_weight = n_neg/n_pos. Cheap, no data duplication, usually enough.
  • Resample — oversample minority / SMOTE (synthetic interpolation) / undersample majority. ! Do it inside the CV fold (imblearn Pipeline) — oversampling before the split duplicates rows across train and val → leak.
  • Tune the threshold — don't accept 0.5; pick it off the precision-recall curve to match business cost.
  • ! Accuracy is the null model at 99:1 — report PR-AUC, F1, recall@precision, or balanced accuracy instead.
  • Senior line: imbalance is a loss-weighting + threshold problem, not automatically a "must oversample" problem.

Generative vs Discriminative

ModelsLearns
DiscriminativeLogistic, SVM, trees, kNNP(y|x) / boundary
GenerativeNaive Bayes, GMM, LDAP(x,y) = P(x|y)P(y)
  • Discriminative models the decision boundary directly — usually higher accuracy when you only need to classify, and it makes no distributional assumptions about x.
  • Generative models how each class generates data, so it can sample, handle missing features, and often learns faster with little data (Naive Bayes shines on small text sets) — at the cost of stronger assumptions.
  • Classic pairing: Naive Bayes (gen) ↔ Logistic Regression (disc) — same linear form, NB wins on tiny n, logistic wins as n grows (it converges to the lower asymptotic error).
  • LDA is generative (Gaussian per class, shared Σ) and yields a linear boundary; QDA drops the shared-Σ assumption for a quadratic one.

Convexity & Loss Functions

Logisticlog-loss (CE)yes → global
SVMhingeyes → global
AdaBoostexponentialyes (stagewise)

  • Convex = one global minimum, so gradient descent (or a closed form) is guaranteed to find the best fit — the reason linear/logistic/SVM "just work".
  • ! Logistic with MSE is non-convex — the sigmoid makes squared loss bumpy. Log-loss is the MLE and convex; always use it.
  • Non-convex objectives (trees, k-means, GMM, nets) rely on greedy heuristics or restarts and only reach a local optimum → init and n_init matter.

Whiteboard Answer Skeleton

Every "explain algorithm X" answer follows a 4-beat structure — say all four and you sound like you've implemented it, not memorised it.

  • 1. Objective — what does it optimise? Name the loss first (MSE, log-loss, hinge, inertia, likelihood).
  • 2. Mechanism — how does it optimise it? The update rule, the greedy split, the E/M step, the QP.
  • 3. Knobs + complexity — what controls capacity and what does it cost to train/serve.
  • 4. Decisive tradeoff — the one-line reason you'd pick it or not (interpretable but linear; SOTA but a black box; flexible but O(N²)).

For comparisons, name the distinguishing axis (bagging cuts variance / boosting cuts bias; L1 sparse / L2 shrinks; PCA linear-global / t-SNE non-linear-local) rather than listing disconnected facts. For derivations: start from the loss, take the gradient, simplify to the clean form.

SVM Dual & Support Vectors

dual:  max Σαᵢ − ½ΣΣ αᵢαⱼ yᵢyⱼ K(xᵢ,xⱼ)
       s.t. 0 ≤ αᵢ ≤ C,   Σαᵢyᵢ = 0
w = Σ αᵢ yᵢ xᵢ     f(x)=sign(Σ αᵢyᵢ K(xᵢ,x)+b)
  • The dual depends on data only through dot products → this is where the kernel plugs in (swap xᵢ·xⱼ for K).
  • αᵢ = 0 for non-support-vectors → prediction cost scales with the number of support vectors, not n. Points with 0 < αᵢ < C sit exactly on the margin; αᵢ = C are inside/violating it.
  • C is the upper bound on each αᵢ — the soft-margin/regularisation cap. SVR extends the idea with an ε-insensitive tube for regression.
  • ! Kernel SVM stores the training kernel → O(N²) memory; another reason it stalls on large n.

  • ☐ Normal equation: ∂/∂w ||Xw-y||² = 2Xᵀ(Xw-y)=0 → w=(XᵀX)⁻¹Xᵀy.
  • ☐ Ridge: add λ||w||² → w=(XᵀX+λI)⁻¹Xᵀy (always invertible).
  • ☐ Logistic gradient: ∇ = Xᵀ(σ(Xw)-y) — same form as linear.
  • ☐ Why L1 sparse: diamond corners lie on axes; L2 sphere doesn't.
  • ☐ Gini = 1-Σpₖ²; split maximises weighted impurity drop.
  • ☐ RF variance: ρσ² + (1-ρ)σ²/B — decorrelation (↓ρ) cuts it.
  • ☐ Boosting: hₘ fits −gradient of loss (residuals for MSE).
  • ☐ SVM margin = 2/||w|| → minimise ½||w||².
  • ☐ Kernel trick: replace x·x' with K(x,x'); no explicit φ.
  • ☐ k-means / EM: alternate assign ↔ update; monotone ↓ inertia / ↑ likelihood.
  • ☐ PCA: eigenvectors of covariance = SVD of centered X.
  • ☐ PCA is max-variance: maximise wᵀCw s.t. ||w||=1 → Lagrangian → Cw=λw; variance along w equals its eigenvalue λ.
  • ☐ SVM dual: only dot products appear → kernelise; αᵢ>0 only for support vectors.
  • ☐ AdaBoost: αₘ=½ln((1−err)/err); upweight misses by e^αₘ; = stagewise exponential-loss fit.
  • ☐ XGBoost gain: ½[G_L²/(H_L+λ)+G_R²/(H_R+λ)−G²/(H+λ)]−γ; leaf w*=−G/(H+λ).
  • ☐ Bagging vs boosting: average low-bias/high-var → cut variance; add high-bias/low-var → cut bias.
  • ☐ State every model as objective · fit · knob · complexity · tradeoff.
