Logical Query Execution Order

flowchart TD A["FROM / JOIN"] --> B["WHERE (row filter)"] B --> C["GROUP BY"] C --> D["HAVING (group filter)"] D --> E["SELECT (cols, window fns)"] E --> F["DISTINCT"] F --> G["ORDER BY"] G --> H["LIMIT / OFFSET"]

SELECT aliases are created at step 5 — invisible to WHERE/GROUP BY/HAVING, usable in ORDER BY.

Table Design & DDL

CREATE TABLE IF NOT EXISTS trades (
  id     bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  ref    text NOT NULL UNIQUE,
  ccy    char(3) NOT NULL DEFAULT 'USD',
  qty    numeric(18,4) NOT NULL CHECK (qty > 0),
  px     numeric(18,6) NOT NULL,
  notnl  numeric(18,4) GENERATED ALWAYS AS (qty*px) STORED,
  ts     timestamptz NOT NULL DEFAULT now()
);
  • TEMP = session-scoped, dropped on disconnect
  • UNLOGGED = no WAL, fast, lost on crash !

       (2,'MSFT', 50,DEFAULT);   -- DEFAULT = column default
-- bulk from query

RETURNING PG

  • Works on INSERT / UPDATE / DELETE / MERGE
  • Returns affected rows w/o re-query — grab generated keys
INSERT INTO trades(sym,qty) VALUES('IBM',10)
RETURNING id, ts;          -- get serial/default
UPDATE trades SET qty=qty+5 WHERE id=1 RETURNING *;

Join-UPDATE / DELETE PG

UPDATE settlements s
SET status='confirmed'
FROM trades t                      -- extra rel in FROM
WHERE s.trade_id=t.id AND t.sym='AAPL';

DELETE FROM trades t
USING counterparties c             -- extra rel in USING
WHERE t.cp_id=c.id AND c.blocked;
! No JOIN keyword — list rels in FROM/USING, link in WHERE. Beware unjoined preds = cartesian.

UPSERT — ON CONFLICT PG

INSERT INTO instruments(isin,name,px)
VALUES('US0378331005','Apple',191)
ON CONFLICT (isin) DO UPDATE
  SET px = EXCLUDED.px,            -- proposed row
      name = EXCLUDED.name
WHERE instruments.px <> EXCLUDED.px;   -- optional guard
-- ignore dupes:
INSERT INTO instruments(isin) VALUES('..')
ON CONFLICT DO NOTHING;
  • EXCLUDED.* = the row that failed to insert
  • Conflict target = unique/PK index cols (or ON CONSTRAINT name)

MERGE ANSI (PG15+)

MERGE INTO positions p
USING eod_trades t ON p.sym=t.sym
WHEN MATCHED AND t.qty=0 THEN DELETE
WHEN MATCHED THEN UPDATE SET qty=p.qty+t.qty
WHEN NOT MATCHED THEN INSERT(sym,qty) VALUES(t.sym,t.qty);
vs ON CONFLICT
Multi-action (UPDATE+DELETE+INSERT)
Joins arbitrary source rel, no unique index needed
! No RETURNING pre-PG17; PG17+ supports it

SELECT & Query Mechanics

Logical execution order

  • FROM/JOIN → build row set
  • WHERE → filter rows
  • GROUP BY → aggregate
  • HAVING → filter groups
  • SELECT → compute cols/aliases
  • DISTINCT → dedupe
  • ORDER BY → sort
  • LIMIT/OFFSET → slice
! SELECT aliases run after WHERE, so WHERE alias=... fails. ORDER BY/GROUP BY can see them PG.

Pagination

-- offset: simple, slow deep pages
SELECT * FROM trades
ORDER BY ts DESC, id DESC
LIMIT 50 OFFSET 5000;
-- keyset: O(1) deep, needs unique tiebreak
SELECT * FROM trades
WHERE (ts, id) < (:ts, :id)
ORDER BY ts DESC, id DESC
LIMIT 50;
! OFFSET still scans+discards skipped rows; keyset seeks via index. Tuple compare order must match ORDER BY.

DISTINCT vs DISTINCT ON PG

-- dedupe whole row
SELECT DISTINCT ccy FROM trades;
-- 1 row per ccy: latest trade
SELECT DISTINCT ON (ccy) ccy, ts, px
FROM trades
ORDER BY ccy, ts DESC;
! DISTINCT ON leading ORDER BY cols must match the ON list; the rest picks the kept row.

LATERAL — per-row subquery / top-N per group

SELECT i.symbol, t.*
FROM instruments i
CROSS JOIN LATERAL (
  SELECT * FROM trades t
  WHERE t.instrument_id = i.id
  ORDER BY t.ts DESC LIMIT 3
) t;
  • LEFT JOIN LATERAL ... ON true keeps left rows with no match.
  • Subquery may reference earlier FROM items.

Semi / Anti join

-- semi: counterparties WITH trades
SELECT * FROM counterparties c
WHERE EXISTS (SELECT 1 FROM trades t
              WHERE t.cp_id = c.id);
-- anti: WITHOUT trades
SELECT * FROM counterparties c
WHERE NOT EXISTS (SELECT 1 FROM trades t
                  WHERE t.cp_id = c.id);
  • Anti alt: LEFT JOIN ... WHERE t.id IS NULL.
  • ! NOT IN (subquery) returns no rows if any value is NULL — use NOT EXISTS.

GROUP BY / HAVING

  • WHERE filters rows (pre-group); HAVING filters groups (post-agg).
  • HAVING can use aggregates; WHERE cannot.
  • Every non-aggregated SELECT col must be in GROUP BY.
SELECT counterparty_id, sum(notional) AS vol
FROM trades
WHERE status = 'SETTLED'
GROUP BY counterparty_id
HAVING sum(notional) > 1e6;

FILTER & conditional pivot

PG per-aggregate FILTER (WHERE ...) beats CASE: 
SELECT
  count(*) FILTER (WHERE side='BUY')  AS buys,
  count(*) FILTER (WHERE side='SELL') AS sells,
  sum(notional) FILTER (WHERE ccy='USD') AS usd
FROM trades GROUP BY instrument_id;
ANSI fallback: sum(CASE WHEN side='BUY' THEN 1 ELSE 0 END).

DISTINCT / ORDER BY inside agg

string_agg(DISTINCT ccy, ',' ORDER BY ccy)
array_agg(price ORDER BY ts DESC)
! ORDER BY inside agg sorts its input only.

Running total / rolling avg

  ORDER BY trade_ts) AS run_tot,

  ROWS 6 PRECEDING) AS ma7

Can't filter window inline !

WITH r AS (
  SELECT *, ROW_NUMBER() OVER (
    PARTITION BY cpty
    ORDER BY trade_ts DESC) rn
  FROM trades)
SELECT * FROM r WHERE rn = 1;
  • Window fns illegal in WHERE/HAVING/GROUP BY — wrap in CTE/subquery. PG QUALIFY not supported.

CTEs & Recursion

Basic & chaining

WITH big AS (
  SELECT counterparty_id, SUM(notional) AS tot
  FROM trades GROUP BY counterparty_id
), ranked AS (
  SELECT *, rank() OVER (ORDER BY tot DESC) AS r
  FROM big
)
SELECT * FROM ranked WHERE r <= 10;
  • Comma-chain many CTEs; each sees earlier ones.
  • Scope = the single statement.

Inlining

ClauseEffect
NOT MATERIALIZEDinline into outer query (folds, pushes predicates)
MATERIALIZEDforce one-time eval, reuse result ! blocks predicate pushdown
default (PG12+)inline if used once & side-effect-free
WITH t AS NOT MATERIALIZED (
  SELECT * FROM trades WHERE book='FX'
) SELECT * FROM t WHERE notional > 1e6;

Pre-PG12 always materialized (optimisation fence).

Data-modifying CTE PG

WITH moved AS (
  DELETE FROM settlements
  WHERE status='stale'
  RETURNING *
)
INSERT INTO settlements_archive
SELECT * FROM moved;
  • INSERT/UPDATE/DELETE ... RETURNING feeds rows downstream.
  • All sub-statements see the same snapshot ! a modifying CTE can't see another's changes; order of execution not guaranteed.
  • Outer must reference the CTE or it still runs once.

WITH RECURSIVE

WITH RECURSIVE nums(n) AS (
  SELECT 1                 -- base
  UNION ALL
  SELECT n+1 FROM nums     -- recursive
  WHERE n < 100
)
SELECT n FROM nums;
WITH RECURSIVE tree AS (
  SELECT id, parent_id, 1 AS lvl
  FROM instruments WHERE parent_id IS NULL
  UNION ALL
  SELECT c.id, c.parent_id, t.lvl+1
  FROM instruments c JOIN tree t
    ON c.parent_id = t.id
)
SELECT * FROM tree;
  • UNION dedups; UNION ALL faster, needs own guard.
  • Recursive term refs CTE name exactly once.

SEARCH / CYCLE PG14+ ANSI

WITH RECURSIVE tree AS ( ... )
  SEARCH DEPTH FIRST BY id SET ord
  CYCLE id SET is_cyc USING path
SELECT * FROM tree ORDER BY ord;
ClauseAdds col
SEARCH DEPTH/BREADTH FIRST BY col SET ordordering col
CYCLE col SET flag USING pathbool flag + path array; stops at repeat
  • CYCLE guards infinite loops on cyclic graphs !

EXPLAIN — Catch & Fix Slow Queries

1. Catch slow queries

ToolUse
pg_stat_statementsTop offenders by total_exec_time, mean_exec_time, calls
auto_explainLogs plans of slow stmts (auto_explain.log_min_duration)
log_min_duration_statementLog any stmt > N ms
SELECT query, calls, mean_exec_time, total_exec_time
FROM pg_stat_statements
ORDER BY total_exec_time DESC LIMIT 20;

2. Read the plan

EXPLAIN (ANALYZE, BUFFERS)
SELECT * FROM trades WHERE counterparty_id = 42;
  • Read inner → outer, bottom-up; child nodes feed parents.
  • Compare estimated rows vs actual rows (=rows × loops).
  • Hunt the node with the biggest actual time / shared-buffer reads.
  • BUFFERS shows heap/index pages hit vs read from disk.

3. Scan nodes

4. Join nodes

Nested LoopInner side tiny / indexed; few outer rows

5. Red flags

  • ! est. vs actual rows off by 10×+ → stale stats, run ANALYZE
  • ! Seq Scan on big table w/ selective filter → missing index
  • ! Nested Loop with huge loops count → N+1-style blowup
  • ! Sort/Hash Disk: ...kB → raise work_mem
  • ! high Rows Removed by Filter → predicate not using index

Transactions, Locking & Isolation

BEGIN;
  UPDATE accounts SET bal = bal-100 WHERE id=1;
  SAVEPOINT sp1;
  UPDATE accounts SET bal = bal+100 WHERE id=2;
  ROLLBACK TO sp1;   -- undo to savepoint, txn alive
COMMIT;              -- or ROLLBACK
  • Locks/snapshots are txn-scoped; released at COMMIT/ROLLBACK.
  • Statement error aborts whole txn → only ROLLBACK/ROLLBACK TO allowed until cleared.

Queue / worker pattern

SELECT id FROM jobs
WHERE status='ready'
ORDER BY id
FOR UPDATE SKIP LOCKED   -- skip rows others hold
LIMIT 10;                -- or NOWAIT → error if locked
  • SKIP LOCKED: each worker grabs disjoint rows, no contention. PG

Deadlocks !

  • Cause: txn A locks r1→r2, txn B locks r2→r1.
  • PG auto-detects after deadlock_timeout (1s) & aborts one (40P01); survivor proceeds.
  • Avoid: lock rows in a consistent order; keep txns short; take SELECT … FOR UPDATE up front; use SKIP LOCKED for queues.

Deadlock — wait-for cycle

flowchart LR T1["Txn 1
holds row A
wants row B"] -->|"waits for B"| T2["Txn 2
holds row B
wants row A"] T2 -->|"waits for A"| T1

Cycle = deadlock. PG's detector (after deadlock_timeout, default 1s) aborts one txn with SQLSTATE 40P01. Avoid: lock rows in a consistent order; keep txns short; SELECT … FOR UPDATE up front; SKIP LOCKED for queues.

MVCC — tuple version chain

flowchart LR V1["v1
xmin=100 xmax=150"] -->|"UPDATE @150"| V2["v2
xmin=150 xmax=0"]

A row UPDATE writes a NEW tuple; the old one stays until VACUUM. A snapshot sees the version whose xmin committed before it and whose xmax did not — readers never block writers.

Keys & uniqueness

CREATE TABLE trades (
  id    uuid PRIMARY KEY DEFAULT gen_random_uuid(), -- PG
  ref   text NOT NULL,
  book  text NOT NULL,
  UNIQUE NULLS NOT DISTINCT (ref, book)  -- PG15+
);
  • PG NULLS NOT DISTINCT treats NULLs as equal (PG15+); default ANSI is NULLS DISTINCT !
  • PG gen_random_uuid() built-in (PG13+)

Deferrable (check at COMMIT)

ALTER TABLE trades ADD CONSTRAINT fk_book
  FOREIGN KEY (book) REFERENCES books(id)
  DEFERRABLE INITIALLY DEFERRED;
-- per-tx override:
SET CONSTRAINTS fk_book IMMEDIATE;
  • Defers FK/UNIQUE check to txn end → allows transient violations (e.g. cyclic inserts) ! only constraints declared DEFERRABLE

EXCLUDE (no overlaps)

CREATE EXTENSION btree_gist;  -- for = on scalars
ALTER TABLE bookings ADD CONSTRAINT no_overlap
  EXCLUDE USING gist (
    room WITH =, during WITH &&);
  • No two rows where room= AND time ranges overlap (&&)
  • Generalizes UNIQUE (which is WITH = on all cols)

DOMAIN (reusable typed constraint)

CREATE DOMAIN ccy AS char(3)
  CHECK (VALUE ~ '^[A-Z]{3}$');     -- PG ~ regex
CREATE DOMAIN pos_amt AS numeric
  NOT NULL CHECK (VALUE > 0);
-- use like a type:
amount pos_amt, currency ccy
  • Centralizes CHECK/NOT NULL/DEFAULT across tables ! domain NOT NULL is weak vs col NULLs from outer joins

Procedure PG (PG11+)

CREATE PROCEDURE settle(d date)
LANGUAGE plpgsql AS $$
BEGIN
  UPDATE settlements SET done=true WHERE dt=d;
  COMMIT;            -- legal in proc, NOT in fn
END $$;
CALL settle('2026-06-10');
  • Invoke with CALL, not SELECT. Can COMMIT/ROLLBACK; no return value (use INOUT).

Triggers

CREATE FUNCTION audit_trade()
RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  INSERT INTO trade_log(tid,act,at)
  VALUES (NEW.id, TG_OP, now());
  RETURN NEW;        -- BEFORE: NEW shapes write
END $$;

CREATE TRIGGER trg_audit
AFTER INSERT OR UPDATE ON trades
FOR EACH ROW EXECUTE FUNCTION audit_trade();

Views, Admin, Roles & psql

Views

CREATE VIEW open_trades AS
  SELECT * FROM trades WHERE status='OPEN'
  WITH CHECK OPTION;
  • Auto-updatable if 1 table, no DISTINCT/GROUP/agg/window/UNION.
  • WITH CHECK OPTION: blocks INSERT/UPDATE that violate WHERE. LOCAL = this view only; CASCADED = +underlying views.

Materialized views

CREATE MATERIALIZED VIEW mv_pnl AS
  SELECT cpty_id, sum(pnl) FROM settlements
  GROUP BY cpty_id;
REFRESH MATERIALIZED VIEW mv_pnl;
-- non-blocking; needs UNIQUE index:
CREATE UNIQUE INDEX ON mv_pnl(cpty_id);
REFRESH MATERIALIZED VIEW CONCURRENTLY mv_pnl;
  • Stores data on disk; stale until REFRESH. ! plain REFRESH takes ACCESS EXCLUSIVE lock.
  • WITH NO DATA = unscannable until first refresh.

Data Cleaning & De-duping

Pipeline: profile → normalise identifiers → coerce types/sentinels → dedupe (deterministic tiebreak) → assign key (flag unkeyable rows) → validate. ! order matters — capture info before you collapse it.

Sentinels → NULL (do BEFORE joins/aggregates)

NULLIF(col,'N/A')
CASE WHEN lower(trim(c)) IN ('','-','n/a','null')
     THEN NULL ELSE c END
! sentinels skew COUNT/SUM/joins if left as text.

Normalise text

lower(trim(regexp_replace(c,'\s+',' ','g')))
-- ' AAPL '  ->  'aapl'
PG collapses runs of whitespace; trims edges; case-folds. ! Case-sensitive unit trap: capture markers like GBp (pence) vs GBP (pounds) from the raw value before lower() — case-folding first destroys the ×100 you need to normalise the price.

Safe casts: strip then guard

SELECT regexp_replace(amt,'[^0-9.\-]','','g')::numeric
WHERE pg_input_is_valid(
        regexp_replace(amt,'[^0-9.\-]','','g'),'numeric');
FnUse
pg_input_is_validPG16+ test cast w/o error
::numeric PG= CAST(.. AS numeric) ANSI

Safe date parse (mixed/corrupt formats)

CASE
  WHEN pg_input_is_valid(d,'date') THEN d::date  -- PG16+
  WHEN d ~ '^\d{2}/\d{2}/\d{4}$'  THEN to_date(d,'DD/MM/YYYY')
  ELSE NULL                       -- unparseable / impossible (mon 13)
END
! Return NULL for bad values — never let one corrupt row abort the whole batch.

Dedup: keep one row per key

-- newest per key
SELECT DISTINCT ON (k) *           -- PG only
FROM t ORDER BY k, ts DESC;

-- portable / for DELETE; deterministic tiebreak
SELECT * FROM (
  SELECT *, row_number() OVER (PARTITION BY k
    ORDER BY quality_col DESC NULLS LAST, ts DESC) rn
  FROM t) s WHERE rn=1;
PG DISTINCT ON is non-ANSI; ORDER BY must lead with key. Tiebreak on a quality column so the winner is deterministic; flag rows with no usable key rather than dropping them.

Delete dupes via ctid

DELETE FROM t a USING t b
WHERE a.k=b.k AND a.ctid < b.ctid;  -- keep 1
PG ctid = physical row id (not stable across VACUUM).

Deterministic key (reproducible)

md5(lower(trim(sym))||'|'||trade_dt||'|'||cpty)
! use business cols, NOT gen_random_uuid() — UUID changes every run.

Orphans / broken FKs

SELECT t.* FROM trades t
LEFT JOIN instruments i ON i.id=t.instr_id
WHERE i.id IS NULL;   -- drop/quarantine/backfill
! never silently drop — quarantine to a side table.

Gotchas & Footguns

NULL & 3-valued logic

  • NULL = NULL → UNKNOWN (not true). Use IS NULL / IS NOT NULL.
  • a IS NOT DISTINCT FROM b = NULL-safe equality ANSI.
  • WHERE keeps rows only when predicate is TRUE; UNKNOWN is dropped.

NOT IN trap !

-- if subquery yields any NULL,
-- NOT IN returns ZERO rows
SELECT * FROM trades t
WHERE t.cpty_id NOT IN
  (SELECT cpty_id FROM blocked);  -- broken if NULL

-- safe:
WHERE NOT EXISTS (
  SELECT 1 FROM blocked b
  WHERE b.cpty_id = t.cpty_id);

count & aggregates

ExprCounts

Integer division !

5 / 2          -- = 2 (int floor)
5::numeric / 2 -- = 2.5  PG cast ::
5 * 1.0 / 2    -- = 2.5  (ANSI)

Timestamps

  • timestamp = wall clock, NO tz conversion → silent off-by-hours. Prefer timestamptz.
  • timestamptz stores UTC; converts on display per SET timezone.
  • Cast: ts AT TIME ZONE 'UTC'.

GROUP BY

  • Every non-aggregated SELECT col must appear in GROUP BY (else column must appear in GROUP BY).
  • Exception: cols functionally dependent on grouped PK PG.

  • DISTINCT & UNION sort+dedup (slow). Use UNION ALL if dupes OK.
