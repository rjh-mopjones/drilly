Resource Hierarchy & Projects

Organization        (domain root, org policies)
 └─ Folders          (dept / env grouping)
     └─ Projects      (isolation + billing + quota unit)
         └─ Resources (VMs, buckets, ...)
  • IAM policy inherits downward: a role at org/folder applies to everything beneath — union, never subtractive !
  • Project = fundamental unit. Has ID (global, immutable), number, display name; APIs enabled per project; quotas per project.
  • Billing account is a separate resource from IAM — split billing admin from resource admin.
  • Regions contain zones (independent failure domains). Design across ≥2 zones (regional) for HA.
  • Resource scope: VPC is global, subnets/PDs/instances are regional/zonal; Cloud Storage buckets are regional/dual/multi.
  • Org policies (constraints) cap what's allowed org-wide (e.g. block public IPs, restrict regions) — guardrails, not IAM grants.

IAM — Roles & Service Accounts

# binding = member + role on a resource
gcloud projects add-iam-policy-binding acme-prod \
  --member="serviceAccount:app@acme-prod.iam\
.gserviceaccount.com" \
  --role="roles/storage.objectViewer"
  • Role types: basic (Owner/Editor/Viewer — too broad, avoid !), predefined (service-scoped, preferred), custom (least-privilege bespoke).
  • member = user / group / serviceAccount / domain / allUsers / allAuthenticatedUsers. Grant to groups, not individuals.
  • Permissions are granted only via roles, never directly. Policy = list of bindings.
  • Service account = identity and resource. Attach to VM/Cloud Run/GKE; never download SA keys if avoidable !
  • Workload Identity Federation = keyless auth for CI/external (GitHub Actions) via short-lived tokens; GKE Workload Identity = KSA → GSA. Prefer over keys.
  • IAM Conditions add context (time, resource, IP); Policy Analyzer / Recommender flags over-broad grants.

Serverless — Run / Functions / App Engine

gcloud run deploy api --image=REGION-docker.pkg\
.dev/acme-prod/repo/api:v2 \
  --region=us-central1 --concurrency=80 \
  --min-instances=1 --no-allow-unauthenticated
  • Cloud Run: run any container, request-driven, scales to zero; key trait = concurrency >1 per instance (unlike Lambda's 1) → cheaper for I/O-bound.
  • --min-instances cuts cold starts; CPU always-on vs request-only — always-on idles cost money !
  • Revisions + traffic splitting for canary/blue-green; Cloud Run Jobs for run-to-completion batch.
  • Cloud Functions gen2 runs on Cloud Run; triggers HTTP / Pub/Sub / Storage / Eventarc.
  • App Engine: standard (sandbox, scale-to-zero) vs flexible (containers on VMs); legacy — new work → Cloud Run.
  • Reach a VPC via Serverless VPC Access connector / Direct VPC egress. Guard invocation with IAM — don't leave public unless intended !

  • Regional cluster = HA control plane + nodes across zones (vs zonal single point).

Cloud Storage — Classes & Rules

ClassMin store · use
Standard—; hot / frequent
Nearline30d; <1×/month
Coldline90d; <1×/quarter
Archive365d; rarely / compliance
  • Strongly consistent globally (read-after-write, list). 11 nines durability. Objects immutable — overwrite = new version.
  • Location: region / dual-region / multi-region (availability & latency vs cost).
  • Uniform bucket-level access (IAM) > legacy ACLs; turn on Public Access Prevention !
  • Lifecycle rules tier/expire; Autoclass auto-tiers; versioning; retention policy + bucket lock (WORM).
  • Signed URLs for temp scoped access; CMEK via Cloud KMS; requester-pays shifts egress cost.
  • Early-deletion fees on cold classes; egress + retrieval cost bites !

Block & File Storage

ProductShape
PD balancedSSD default boot/general
PD ssd / extremelatency / provisioned IOPS DB
HyperdiskIOPS·throughput·capacity decoupled
Local SSDephemeral NVMe, 375GB/dev !
Filestoremanaged NFS, ReadWriteMany
  • PD/Hyperdisk are network-attached — survive a stopped VM, re-attachable. Local SSD is ephemeral — lost on stop/terminate/live-migrate. Never put a DB on it !
  • Regional PD = synchronous 2-zone replication for HA (force-attach on zone loss) — not a backup (replicates corruption) !
  • Hyperdisk decouples capacity/IOPS/throughput → stop over-buying capacity just for IOPS; tune live.
  • Snapshots = incremental, compressed, global → restore any region (backup + migration). Custom image = OS template; machine image = whole VM.
  • Grow-only (snapshot+restore to shrink); automate via snapshot schedule (resource policy). Filestore for POSIX ReadWriteMany, not object.

VPC — global net, firewall, NAT

flowchart LR LB["Global App LB
anycast VIP"] --> A["subnet region-A
(private VMs / GKE)"] LB --> B["subnet region-B"] A --> NAT["Cloud NAT"] --> INT["internet egress"] A --> PGA["Private Google Access
→ Google APIs"]
  • VPC is global; subnets are regional (primary + secondary/alias ranges). AWS VPC is regional — key difference !
  • Firewall rules are stateful, on the VPC, priority-ordered, target by tag/SA; default-deny ingress. Hierarchical FW policies at org/folder.
  • Cloud NAT = managed egress for private VMs (no NAT instances). Private Google Access reaches Google APIs without an external IP.
  • Shared VPC (host/service projects) is the org pattern; peering is non-transitive ! Hybrid via Cloud VPN / Interconnect.
  • Allow health-check ranges: 35.191.0.0/16, 130.211.0.0/22 ! Premium vs Standard network tier (global anycast needs Premium).

DNS, CDN & Edge

  • Cloud DNS: managed authoritative, anycast, 100% SLA. Public zone (internet) vs private zone (per-VPC internal names). Same name in both = split-horizon.
  • DNS routing policies turn DNS into traffic mgmt:
    PolicyUse
    Weightedcanary / A-B split
    Geolocationnearest / data-residency
    Failoverhealth-checked DR
    TTL caching makes it coarse — LB does fast per-request routing !
  • DNSSEC signs records (anti-spoof); publish DS at registrar. Hybrid: inbound/outbound forwarding + DNS peering.
  • Cloud CDN is a feature of the external App LB backend (--enable-cdn), not standalone; global POPs. Tune cache key + TTL for hit ratio; prefer versioned URLs over invalidation (rate-limited) !
  • Media CDN for video/large media; Certificate Manager for Google-managed/self TLS; backend bucket serves static assets.

Relational DB — SQL / AlloyDB / Spanner

NeedService
managed MySQL/PG/SQLServerCloud SQL
PG, high perf + HTAP analyticsAlloyDB
global, horizontal, strong SQLCloud Spanner
  • Cloud SQL HA = synchronous standby in another zone + auto-failover (not read scaling); add read replicas for read scale & cross-region.
  • AlloyDB: PG-compatible, columnar cache for analytics, faster than vanilla PG; good OLTP+light-analytics.
  • Spanner: TrueTime, external consistency, horizontal scale, 99.999% multi-region — but pricey; avoid monotonic/hotspot keys !
  • Serverless apps → Cloud SQL Auth Proxy / connectors / private IP — avoid public IP !
  • Scale reads with replicas + a cache (Memorystore); don't scale a single primary by resizing forever.

NoSQL — Firestore & Bigtable

NeedService
document, real-time, mobile/offlineFirestore
wide-column, PB-scale, µs latencyBigtable
  • Firestore: document DB, strong consistency, real-time listeners, offline SDKs, ACID transactions. Every query needs an index; no joins ! Security Rules gate direct client access.
  • Bigtable: wide-column, PB-scale, µs single-key + range scans, HBase API. No cross-row txns, no secondary indexes.
  • Row-key design is everything — sequential/timestamp-prefixed keys create hotspots ! Use field-promotion / salting / reversed keys.
  • Bigtable fit: time-series, IoT, AdTech, analytics serving. SSD vs HDD; add nodes to scale throughput linearly.

Pub/Sub & Eventing

  • Pub/Sub = global, serverless topics/subscriptions (≈ SNS+SQS combined). Push or pull; at-least-once → make consumers idempotent !
  • Ack deadline; redelivery on nack/timeout; always set a dead-letter topic + retry backoff !
  • Ordering keys (per-key order) & optional exactly-once; retention + seek/replay & snapshots.
  • Fan-out = many subscriptions per topic; schemas (Avro/Protobuf); message filtering cuts downstream cost.
  • Pub/Sub Lite = cheaper, throughput-provisioned, zonal (less durable / more ops).
  • Eventarc routes events (Audit Logs / Storage / Pub/Sub) → Cloud Run/Functions/GKE (CloudEvents).

BigQuery — essentials & cost

-- partitioned + clustered scan stays cheap
SELECT user_id, SUM(amount)
FROM `acme-prod.sales.orders`
WHERE _PARTITIONDATE = '2024-01-01'   -- prune
GROUP BY user_id;
  • Serverless columnar warehouse; storage & compute separate. Pricing: on-demand (per-TB scanned) vs slots (editions, autoscaling reservations).
  • Cut cost: partition + cluster tables; avoid SELECT * !; dry-run to estimate bytes; custom quotas; BI Engine for dashboards.
  • Streaming (Storage Write API) vs batch loads; external/federated tables (BigLake); materialized views; scheduled queries; BQML in-SQL ML.
  • Nested/repeated fields (arrays/structs); authorized views + column/row-level security for governance.
  • Wrong tool for OLTP / low-latency point lookups ! Pattern: Pub/Sub → Dataflow → BigQuery.

Memorystore & Caching

  • Memorystore: managed Redis / Redis Cluster / Memcached. Redis = data-structure server (persistence, HA, pub/sub); Memcached = simple multi-threaded sharded KV.
  • Tiers: Basic = single node, no failover (not prod !); Standard = replica + auto-failover. Redis Cluster shards for horizontal scale.
  • Wins: sub-ms latency, DB offload (fewer queries/connections), cheaper than upsizing the DB.
  • Patterns: cache-aside (default), write-through, write-behind. TTL bounds staleness; invalidate on write for correctness.
  • Failure modes: cache stampede (hot key expiry → DB flood → jittered TTL / lock / early recompute); hot key (one shard); low hit ratio = pure overhead !
  • Cache is not a source of truth — must be correct when empty. Reach from Cloud Run via private IP + Serverless VPC Access.

Security Services

  • Cloud KMS: key rings/keys/versions, rotation, CMEK, Cloud HSM/EKM; envelope encryption; default encryption at rest everywhere.
  • Secret Manager for secrets (versions, rotation, IAM) — never env vars/plaintext/repo !
  • Cloud Armor = WAF + DDoS on the external App LB (preconfigured OWASP rules, rate limiting, adaptive, geo/IP).
  • IAP = zero-trust / BeyondCorp access to apps/VMs without a VPN. VPC Service Controls = perimeters against data exfiltration.
  • Security Command Center (CSPM, threat detection, misconfig); Binary Authorization (only attested images run); org policies as guardrails.
  • Defense in depth: least-privilege IAM + perimeter + edge WAF + encryption + audit.

Observability — Cloud Operations

  • Cloud Monitoring: metrics, dashboards, uptime checks, alert policies, PromQL/MQL; SLO + error-budget burn alerts.
  • Cloud Logging: sinks to BigQuery/GCS/Pub-Sub, log-based metrics, log router. VM memory/disk needs the Ops Agent — not collected by default !
  • Cloud Trace (latency/spans), Error Reporting (grouped exceptions), Profiler (CPU/heap).
  • Cloud Audit Logs = who-did-what (≈ CloudTrail): Admin Activity (free, always on) vs Data Access (opt-in, high volume → cost) !
  • Golden signals: latency, traffic, errors, saturation. Alert on symptoms + SLOs, not every metric.

IaC & CI/CD

  • Terraform (google provider) is the standard; Deployment Manager is deprecated ! State in a GCS backend with locking — local state corrupts for teams !
  • Modules for reuse; separate env by project/workspace + separate state; plan → review → apply; import existing resources.
  • K8s-native: Config Connector (GCP resources as CRDs); Config Sync = GitOps reconcile-to-Git (corrects drift).
  • Cloud Build = CI (build/test → image); Artifact Registry (Container Registry deprecated !) w/ vuln scan; Cloud Deploy = CD (promote one immutable artifact dev→stg→prod, approvals, canary, rollback).
  • Promote the same artifact — never rebuild per env ! Keyless CI via Workload Identity Federation; secrets from Secret Manager; Binary Authorization gate.

Cost Optimization & Billing

  • Compute: committed-use for baseline, Spot for fault-tolerant, auto sustained-use, right-size via Recommender, scale to zero (Cloud Run).
  • Storage: GCS Autoclass/lifecycle tiering (mind early-deletion fees), Hyperdisk over legacy PD, prune snapshots/idle disks.
  • Network egress is the silent bill ! internet egress, inter-region, cross-zone chatter; Premium vs Standard tier.
  • BigQuery: on-demand bytes-scanned vs slot reservations; partition/cluster; custom quotas; no SELECT *.
  • Visibility: Budgets + alerts, billing export to BigQuery, labels for allocation, Active Assist / Recommender.
  • Anti-patterns: idle external IPs/disks, always-on Cloud Run CPU, un-tiered logs, oversized non-prod, forgotten dev projects.

Architecture Framework & DR

Pillars: operational excellence · security/privacy/compliance · reliability · cost · performance · sustainability.

PatternRTO/RPO
Backup & restorehours; cheapest
Cold / pilot-light10s of min
Warm standbyminutes

  • Zone = failure domain; regional survives a zone loss; multi-region for DR/global reach.
  • Cross-region data: Spanner multi-region, GCS dual/multi-region, Cloud SQL cross-region replicas, global snapshots.
  • Stateless + externalized state; retries w/ backoff+jitter; idempotency; quotas are a reliability risk ! Practice DiRT / game days.

★ Architecture Review Checklist

Security

  • ☐ No basic/Owner roles handed out broadly; predefined/custom + least privilege; grant to groups.
  • ☐ No service-account keys in code/repo — Workload Identity (Federation) instead.
  • ☐ Public Access Prevention on buckets; CMEK where required; secrets in Secret Manager.
  • ☐ Edge protected (Cloud Armor); IAP/VPC-SC where exfiltration/zero-trust matters; DNSSEC on public zones.

Reliability

  • ☐ Regional (multi-zone) for every stateful tier; no single-zone prod DB; Local SSD never holds state.
  • ☐ Decoupled via Pub/Sub; dead-letter topics; retries w/ backoff+jitter; idempotent consumers.
  • ☐ Defined RTO/RPO + tested DR; global LB + health-check failover; snapshot schedules.

Performance & Cost

  • ☐ Right service for the access pattern (Bigtable/Firestore key design; BigQuery not for OLTP).
  • ☐ BigQuery partitioned/clustered, no SELECT *; Cloud Run concurrency & CPU tuned; cache hit ratio watched.
  • ☐ Private Google Access / Cloud NAT to avoid external IPs; minimize cross-region egress.
  • ☐ Budgets/alerts; labels for cost allocation; no idle IPs/disks; committed-use for steady load.

Operations

  • ☐ IaC (Terraform + GCS backend w/ locking), not click-ops; project/env separation; promote one artifact.
  • ☐ Monitoring + Logging + Trace + alerts; Audit Logs on; SLOs + error budgets; runbooks.
