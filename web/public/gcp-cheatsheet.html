Resource Hierarchy & Projects

Organization
 └─ Folders (dept / env)
     └─ Projects  (isolation + billing + quota unit)
         └─ Resources (VMs, buckets, ...)
  • IAM policy inherits downward: a role at org/folder applies to everything beneath !
  • Project = the fundamental unit — has ID (global, immutable), number, name; APIs enabled per project; quotas per project.
  • Billing account is separate from IAM — split billing admin from resource admin.
  • Regions contain zones (failure domains). Design across ≥2 zones (regional) for HA.
  • Global vs regional vs zonal resources — VPC is global, subnets regional, VMs zonal.

IAM — Roles & Service Accounts

# binding = member + role on a resource
gcloud projects add-iam-policy-binding acme-prod \
  --member="serviceAccount:app@acme-prod.iam.gserviceaccount.com" \
  --role="roles/storage.objectViewer"
  • Role types: basic (Owner/Editor/Viewer — too broad, avoid !), predefined (service-scoped, preferred), custom.
  • Permissions are granted only via roles, never directly.
  • Service account = identity and resource. Attach to VM/Cloud Run/GKE; never download SA keys if avoidable !
  • Workload Identity Federation = keyless auth for CI/external; GKE Workload Identity = pods → SA. Prefer over keys.
  • Org policies (constraints) cap what's allowed; IAM Conditions for context.

Serverless — Cloud Run / Functions

  • Cloud Run: run any container, request-driven, scales to zero; key trait = concurrency >1 per instance (unlike Lambda's 1) → cheaper for I/O-bound.
  • min-instances to cut cold starts; CPU always-on vs request-only — always-on idles cost money !
  • Revisions + traffic splitting for canary/blue-green. Jobs for run-to-completion.
  • Cloud Functions gen2 runs on Cloud Run; triggers HTTP / Pub/Sub / Storage / Eventarc.
  • Reach a VPC via Serverless VPC Access connector / Direct VPC egress.
  • Guard invocation with IAM (authenticated) — don't leave public unless intended !

  • Strongly consistent globally (read-after-write, list). 11 nines durability.
  • Location: region / dual-region / multi-region (availability vs cost/latency).
  • Uniform bucket-level access (IAM) > legacy ACLs; turn on Public Access Prevention !
  • Lifecycle rules to tier/expire; versioning; retention policy + bucket lock (WORM).
  • Signed URLs for temp access; CMEK via Cloud KMS.
  • Early-deletion fees on cold classes; watch egress/retrieval cost !

VPC — global net, firewall, NAT

flowchart LR LB["Global HTTPS LB
anycast VIP"] --> A["subnet region-A
(private VMs / GKE)"] LB --> B["subnet region-B"] A --> NAT["Cloud NAT"] --> INT["internet egress"] A --> PGA["Private Google Access → Google APIs"]
  • VPC is global; subnets are regional (primary + secondary/alias ranges). (AWS VPC is regional — key difference !)
  • Firewall rules are stateful, on the VPC, priority-ordered, target by tag/SA.
  • Cloud NAT = managed egress for private VMs (no NAT instances). Private Google Access to reach Google APIs without external IP.
  • Shared VPC (host/service projects) is the org pattern; peering is non-transitive.
  • Health-check ranges must be allowed: 35.191.0.0/16, 130.211.0.0/22 !

  • Cloud SQL HA = synchronous standby + auto-failover (not read scaling); add read replicas for reads.
  • Spanner: TrueTime, external consistency, scales horizontally — but pricey; avoid hotspot keys !
  • Serverless apps → Cloud SQL Auth Proxy / connectors (avoid public IP) !

Firestore & Bigtable

  • Firestore: document DB, strong consistency, real-time listeners, offline SDKs. Every query needs an index; no joins ! Native vs Datastore mode.
  • Security Rules gate direct client access; transactions supported.
  • Bigtable: wide-column, PB-scale, µs single-key + range scans, HBase API. No cross-row transactions, no secondary indexes.
  • Row-key design is everything — sequential/timestamp-prefixed keys create hotspots ! Use field-promotion/salting/reversed keys.
  • Fit: time-series, IoT, AdTech, analytics serving. SSD vs HDD; nodes scale throughput.

Pub/Sub & Eventing

  • Pub/Sub = global, serverless topics/subscriptions (≈ SNS+SQS combined). Push or pull; at-least-once → be idempotent !
  • Ack deadline; redelivery; dead-letter topic + retry backoff (always set a DLT) !
  • Ordering keys (per-key order) & optional exactly-once; retention + seek/replay & snapshots.
  • Fan-out = many subscriptions per topic; schemas (Avro/Protobuf); filtering.
  • Pub/Sub Lite = cheaper, throughput-provisioned, zonal (less durable/ops).
  • Eventarc routes events (Audit Logs / Storage / Pub/Sub) → Cloud Run/Functions/GKE (CloudEvents).

BigQuery — essentials & cost

  • Serverless columnar warehouse; storage & compute separate. Pricing: on-demand (per-TB scanned) vs slots (editions, autoscaling reservations).
  • Cut cost: partition + cluster tables; avoid SELECT * !; dry-run; custom quotas; BI Engine.
  • Streaming (Storage Write API) vs batch loads; external/federated tables (BigLake).
  • Nested/repeated fields (arrays/structs); materialized views; scheduled queries; BQML.
  • Authorized views + column/row-level security for governance.
  • Wrong tool for OLTP / low-latency point lookups ! Pattern: Pub/Sub → Dataflow → BigQuery.

Security & Observability

Secure

  • Cloud KMS (key rings/keys/versions, rotation, CMEK, Cloud HSM/EKM); envelope encryption; default encryption at rest.
  • Secret Manager for secrets (versions, rotation, IAM) — not env/plaintext !
  • Cloud Armor = WAF + DDoS on the external App LB (OWASP rules, rate limiting, adaptive).
  • IAP = zero-trust/BeyondCorp access to apps/VMs without a VPN. VPC Service Controls = perimeters vs data exfiltration.
  • Security Command Center (CSPM/threats); Binary Authorization (trusted images).

Observe

  • Cloud Monitoring (metrics/alerts/uptime/PromQL) + Cloud Logging (sinks to BigQuery/GCS/Pub-Sub, log-based metrics; Ops Agent for VM mem/disk !).
  • Cloud Trace, Error Reporting, Profiler. Cloud Audit Logs = who-did-what (≈ CloudTrail); Data Access logs cost !

Architecture Framework & DR

Pillars: operational excellence · security/privacy/compliance · reliability · cost · performance · sustainability.

DR (RTO/RPO ↓, cost ↑)

PatternRTO/RPO
Backup & restorehours; cheapest
Cold / pilot-light10s of min
Warm standbyminutes
Hot / multi-region~0; priciest
  • Zone = failure domain; regional survives a zone loss; multi-region for DR/global.
  • Cross-region data: Spanner multi-region, GCS dual/multi-region, Cloud SQL cross-region replicas.
  • Stateless + externalized state; retries w/ backoff+jitter; idempotency; quotas are a reliability risk ! Practice DiRT.

Cost Optimization

  • Compute: committed-use for baseline, Spot for fault-tolerant, auto sustained-use, right-size via Recommender, scale to zero (Cloud Run).
  • Storage: GCS Autoclass/tiering (mind early-deletion fees), Hyperdisk over old PD, prune snapshots.
  • Network egress is the silent bill ! internet egress, inter-region, cross-zone; Premium vs Standard tier.
  • BigQuery: on-demand bytes-scanned vs slots; partition/cluster; custom quotas; no SELECT *.
  • Visibility: Budgets + alerts, billing export to BigQuery, labels for allocation, Active Assist/Recommender.
  • Anti-patterns: idle external IPs/disks, always-on Cloud Run CPU, un-tiered logs, cross-region chatter.

★ Architecture Review Checklist

Security

  • ☐ No basic/Owner roles handed out broadly; predefined/custom + least privilege.
  • ☐ No service-account keys in code/repo — Workload Identity (Federation) instead.
  • ☐ Public Access Prevention on buckets; CMEK where required; secrets in Secret Manager.
  • ☐ Edge protected (Cloud Armor); IAP/VPC-SC where exfiltration/zero-trust matters.

Reliability

  • ☐ Regional (multi-zone) for every stateful tier; no single-zone prod DB.
  • ☐ Decoupled via Pub/Sub; dead-letter topics; retries w/ backoff+jitter; idempotent consumers.
  • ☐ Defined RTO/RPO + tested DR; global LB + health-check failover.

Performance & Cost

  • ☐ Right service for the access pattern (Bigtable/Firestore key design; BigQuery not for OLTP).
  • ☐ BigQuery partitioned/clustered, no SELECT *; Cloud Run concurrency & CPU tuned.
  • ☐ Private Google Access / Cloud NAT to avoid external IPs; minimize cross-region egress.
  • ☐ Budgets/alerts; labels for cost allocation; no idle IPs/disks.

Operations

  • ☐ IaC (Terraform + GCS backend), not click-ops; project/env separation.
  • ☐ Monitoring + Logging + Trace + alerts; Audit Logs on; runbooks/SLOs.
