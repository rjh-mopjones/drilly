Memory Model & Lock-Free

JMM & happens-before

  • No HB edge → writes may be invisible/reordered across threads. Single-thread order preserved; cross-thread is not, absent sync.
  • HB sources: monitor unlock→lock, volatile write→read, Thread.start, join, final field freeze (ctor end).

volatile

  • Guarantees visibility + no reorder across the access. ! NOT atomic for compound ops: i++ is read-mod-write → lost updates.
  • Use for flags / publish-once refs; use atomics for counters.

Safe publication

MechanismNote
final fieldvisible after ctor; no leak of this
volatile / AtomicRefwrite publishes object + its writes
static initializerJVM guarantees once + visible
concurrent collectionput-then-get is safe

Atomics + CAS

AtomicInteger n = new AtomicInteger();
int v;
do { v = n.get(); }       // CAS loop
while (!n.compareAndSet(v, v+1));
n.updateAndGet(x -> x+1);  // built-in
  • AtomicInteger/Long/Reference; lock-free, spins under contention.
  • ! ABA: value A→B→A passes CAS — use AtomicStampedReference.
  • LongAdder/LongAccumulator: striped cells, beats Atomic for hot counters; sum() not atomic snapshot.

VarHandle (9+)

  • Replaces sun.misc.Unsafe for field-level atomics + fences.
  • Modes: getVolatile, getAcquire/setRelease, getOpaque, compareAndSet; fullFence()/loadLoadFence().
static final VarHandle V =
  MethodHandles.lookup()
    .findVarHandle(C.class,"f",int.class);
V.compareAndSet(obj, 0, 1);

ConcurrentHashMap

  • CAS + bin-level locks; reads lock-free. ! No null key/value.
  • computeIfAbsent atomic per-key; ! don't recursively update same map inside mapping fn (deadlock/livelock).
  • size() approximate under concurrency; iterators weakly consistent.

False sharing

  • Two hot fields on one 64B line → cache-line ping-pong, no logical contention.
  • Fix: pad to line size or @jdk.internal.vm.annotation.Contended (needs -XX:-RestrictContended). LongAdder cells already padded.

Virtual Threads & Structured Concurrency (21)

What & how

  • VT = cheap (millions), JVM-scheduled onto a pool of carrier platform threads; mounts on carrier while running, unmounts on blocking I/O.
  • Create: Thread.ofVirtual().start(r) or Executors.newVirtualThreadPerTaskExecutor().
try (var ex =
  Executors.newVirtualThreadPerTaskExecutor()) {
  ex.submit(() -> handle(req));   // 1 VT / request
}

Use vs avoid

WINAVOID
blocking I/O, thread-per-requestCPU-bound work
high fan-out, many waitspooling/reusing VTs
  • ! Don't pool VTs — they're disposable, one per task. Pooling defeats the model.
  • Limit a scarce resource (DB conns) with a Semaphore, not a thread pool.

Pinning !

causefix
synchronized over I/Ouse ReentrantLock
native frame on stackunavoidable; isolate
  • Pinned VT holds its carrier → starves scheduler. Detect: -Djdk.tracePinnedThreads=full.

StructuredTaskScope (preview)

try (var s = new StructuredTaskScope
       .ShutdownOnFailure()) {
  var a = s.fork(() -> fetchA());
  var b = s.fork(() -> fetchB());
  s.join();             // wait all
  s.throwIfFailed();
  return combine(a.get(), b.get());
}
  • ShutdownOnFailure: any subtask fails → cancel siblings. ShutdownOnSuccess: first ok → cancel rest.
  • Scoped lifetime: subtasks can't outlive the scope; cancellation propagates down.

ThreadLocal → ScopedValue (preview)

  • ! Millions of VTs × ThreadLocal = memory blowup + mutable, unbounded lifetime.
  • ScopedValue: immutable, bound for a dynamic scope, inherited by forked subtasks.
private static final ScopedValue<User> U =
  ScopedValue.newInstance();
ScopedValue.where(U, user).run(() -> handle());

Garbage Collection (deep)

Generational model

  • Hypothesis: most objects die young.
  • Young = Eden + 2 Survivor (S0/S1) -> minor GC; survivors copied S0<->S1, age++.
  • Age > threshold -> tenured to Old gen.
  • Old fills -> major / G1 mixed GC; Old exhausted -> full GC (stop-the-world, slow).

Collectors

GCModelUse for
G1 (default)region-based, pause target, concurrent mark + evacbalanced, most apps
ParallelSTW, multi-thread copy/compactthroughput / batch, pause OK
ZGCconcurrent, colored ptrs, regionsub-ms pause, huge heaps (TB)
Shenandoahconcurrent compactlow pause, mid heaps

Key flags

-Xms/-Xmxmin/max heap; set EQUAL in prod (no resize churn)
-XX:+UseG1GCG1 (default 21)
-XX:MaxGCPauseMillis=NG1 soft pause target
-XX:+UseZGCZGC (add -XX:+ZGenerational)
-Xlog:gc*:file=gc.logunified GC logging (9+)

Footguns & tuning

  • ! Humongous objs (> ½ G1 region) allocate straight into Old -> fragmentation, premature GC. Size region via -XX:G1HeapRegionSize.
  • Allocation rate drives GC frequency: cut garbage (pooling, reuse, primitives) -> fewer pauses.
  • ! Promotion failure / evac failure (Old can't fit survivors) -> full GC. Symptom of undersized Old or high promotion.
  • Tune pause vs throughput: lower MaxGCPauseMillis = more frequent, shorter GCs.

Reading GC logs

  • Watch: pause time, heap before->after, GC frequency, % time in GC.
  • Rising after-GC heap each cycle => leak; frequent full GCs => undersized heap / leak.
  • Tools: JFR (low overhead, -XX:+FlightRecorder), GCViewer, GCeasy, jstat -gc.

Garbage Collection

flowchart TD A["Allocate in Eden"] --> B{"Eden full?"} B -->|"yes"| C["Minor GC: copy live to Survivor"] C --> D{"age > threshold?"} D -->|"yes"| E["Promote to Old"] D -->|"no"| A E --> F{"Old full / alloc fail?"} F -->|"yes"| G["Major / Mixed GC (G1) or concurrent (ZGC)"]

Pick by goal: G1 = balanced default · ZGC/Shenandoah = sub-ms pauses, big heaps · Parallel = max throughput.

Low-Latency Java

Allocation in the hot path

  • ☐ Reuse objects/buffers; avoid per-iteration new
  • ☐ int[]/long[] over List<Integer> — no boxing, contiguous
  • ☐ Avoid autoboxing: Integer cache only -128..127; map keys box
  • ☐ No streams/lambdas in hottest loops — capture allocs, megamorphic calls; plain for
  • ☐ Defer String concat/format; no varargs in hot path
! Allocation pressure = GC frequency. Less garbage beats faster GC.

GC for low pause

GCPauseUse
ZGCsub-ms, heap-indeplarge heap, latency-critical
Shenandoahsub-ms concurrentsame; non-Oracle JDK
G1~10ms+ targetdefault, balanced
  • ☐ -XX:+UseZGC (gen ZGC default 21)
  • ☐ Size heap big enough to absorb churn between collections
  • ☐ Concurrent GC trades CPU/throughput for pause

Mechanical sympathy

  • ☐ Cache-friendly: arrays of primitives, struct-of-arrays vs array-of-objects
  • ☐ Avoid pointer chasing (linked lists, deep refs) — cache misses dominate
  • ☐ 64B cache line; pad to avoid false sharing
  • ☐ @Contended (jdk.internal.vm.annotation; -XX:-RestrictContended) on hot concurrent fields

Warmup & JIT

  • ☐ Hot methods C2-compiled after ~10k calls — warm up before measuring/serving
  • ☐ Drive representative load pre-traffic so steady-state is JIT'd
  • ☐ -XX:+AlwaysPreTouch pages in heap upfront (no fault stalls)
  • ☐ Avoid deopt: stable types, no rare exceptions in hot path

  • ☐ Only when measurement proves allocation dominates

Records, Sealed & Pattern Matching

record — immutable data carrier

record Point(int x, int y) {
  Point {                 // compact ctor: validate/normalize
    if (x < 0) throw new IllegalArgumentException();

equals / hashCode & Immutability

equals contract (5 laws)

  • Reflexive: x.equals(x)
  • Symmetric: x.equals(y) == y.equals(x)
  • Transitive: x=y, y=z → x=z
  • Consistent: repeated calls, same inputs, same result
  • x.equals(null) == false (never NPE)
! Override hashCode whenever you override equals: equal objects MUST share a hash. Break it → lost keys in HashMap/HashSet. ! Symmetry breaks when a subclass adds fields to equals; prefer getClass() check or composition over inheritance.

Canonical skeleton

@Override public boolean equals(Object o){
  if (this == o) return true;
  if (!(o instanceof Point p)) return false; // pattern (21)
  return x == p.x && y == p.y;
}
@Override public int hashCode(){
  return Objects.hash(x, y); // or cache for immutables
}
  • Bad hashCode (e.g. constant) → all entries one bucket → O(n) lookups.
  • Immutable + heavy hash → cache in a final field (lazy or eager).

Comparable / Comparator

  • compareTo SHOULD be consistent with equals (==0 iff equals); else TreeMap/TreeSet drop "duplicate" keys silently.!
  • Comparator.comparing(A::x).thenComparing(A::y).reversed()
  • Use Integer.compare(a,b) not a-b (overflow).!

Immutability recipe

RuleWhy
final classno override breaking invariants
final fields, no settersstate fixed post-construct
defensive copy INcaller can't mutate held ref
defensive copy OUTcaller can't mutate internals (List.copyOf)
no this-escape in ctorno partially-built object leak

Payoff

  • Thread-safe with zero locks; freely shareable/cacheable.
  • Safe as Map/Set keys (hash never drifts).
  • record Point(int x,int y){} gives equals/hashCode/toString/final fields free — still copy mutable components in the compact ctor.!

Reviewing Java Code — Checklist

Correctness

  • ☐ Null/empty/edge inputs handled; no implicit NPE on chained calls
  • ☐ equals/hashCode overridden together & consistent; use records where data-only
  • ☐ Off-by-one in loops/slices; integer overflow (Math.*Exact, use long)
  • ☐ Immutability preferred; final fields, no leaking mutable internals
  • ☐ switch/pattern matching (21) exhaustive; no silent default swallow

Concurrency

  • ☐ Shared mutable state guarded: volatile/lock/Atomic*; publish safely
  • ☐ No check-then-act races (use computeIfAbsent, CAS, single lock scope)
  • ☐ Pools sized & bounded; bounded queue + reject policy, not unbounded
  • ☐ No blocking under lock; no synchronized on virtual threads (21) → pinning !

Resources

  • ☐ try-with-resources for every AutoCloseable; no manual close in finally
  • ☐ No leak on exception path (streams, connections, locks released)
  • ☐ Bounded buffers/collections; stream/IO not loaded fully into memory

API / Design

  • ☐ Minimal public surface; back-compat preserved (no signature/semantic breaks)
  • ☐ Optional as return only — never field/param/collection element
  • ☐ Defensive copies in/out for mutable params & getters
  • ☐ Exceptions specific, carry cause; no swallowed catch

Tests

  • ☐ Assertions meaningful (state/behaviour), not just "no throw"
  • ☐ Edge + failure paths covered; boundaries & nulls tested
  • ☐ Deterministic — no sleep/wall-clock timing; inject clock, await conditions !

Security

  • ☐ No ObjectInputStream on untrusted input (deserialization RCE) !
  • ☐ Validate/sanitise all external input at boundary
  • ☐ No secrets in code/logs; no PII or tokens in log lines
  • ☐ SQL via PreparedStatement; Runtime.exec with arg array, no shell string
