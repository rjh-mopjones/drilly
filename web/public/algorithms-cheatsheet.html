Complexity & Big-O

  • Big-O upper bound (grows no faster), Ω lower, Θ tight (both). "O(n²)" only claims a ceiling — could be faster. Use Θ when you can prove tightness.
  • Formal: T(n)=O(g) if ∃ c,n₀ with T(n)≤c·g(n) ∀ n≥n₀ — that "∀ large n" is why constants & lower terms drop.
  • Best/avg/worst fixes n, varies which input; independent axis from O/Θ/Ω. Interviewers want worst-case unless you flag an avg-case distribution !

Growth ladder (slow→fast growth)

O(1) < log n < n < n log n < n² < n³ < 2ⁿ < n!

Amortized ≠ average

  • Amortized = avg cost over a sequence, holds even vs adversary (dyn-array push = O(1) amort: resizes at 1,2,4,…,n cost <2n total). Doubling is essential — grow-by-constant is O(n²) !
  • Average = expected over an input distribution; fails if the distribution is violated (hash table O(1) avg).
  • Amortized O(1) is a sequence guarantee — does not bound one op's latency (matters for real-time) !

Recursion & Divide and Conquer

Every recursive function needs exactly two things: a base case that returns without recursing, and a recursive step that makes the input strictly smaller. Missing either → infinite recursion.

divide_and_conquer(problem):
    if small enough: return solve_directly(problem)   # base case
    parts = divide(problem)                           # split
    sub   = [divide_and_conquer(p) for p in parts]    # conquer
    return combine(sub)                               # the hard part
  • The combine step is where the cost and the cleverness live. Merge sort's combine is an O(n) merge → n log n. Binary search's combine is free (discard one half) → log n.
  • Stack depth counts as space: recursing n deep is O(n) memory even with O(1) locals. Depth log n (balanced split) is safe; depth n (linked list, skewed tree, n≤10⁵) overflows !
  • Python has no tail-call optimisation — default limit ~1000 frames. Convert to an explicit stack/loop rather than raising the limit !
  • Karatsuba: 4 recursive multiplies → 3 by reusing (a+b)(c+d). nlog₂3 ≈ n1.585 beats n². The lesson: fewer subproblems beats a cheaper combine.
  • D&C vs DP: D&C subproblems are disjoint; DP's overlap (so you memoise). Same recursion, different reuse.
  • Prove correctness by induction: base case holds, and if the recursive calls are correct then combine is correct.

Recurrences & Master Theorem

Form T(n) from structure: a subproblems of size n/b plus f(n) non-recursive work. Compare f(n) to the watershed n^(log_b a).

CaseConditionT(n)
1 leavesf = O(n^(log_b a−ε))Θ(n^(log_b a))
2 evenf = Θ(n^(log_b a))Θ(n^(log_b a)·log n)
3 rootf = Ω(n^(log_b a+ε)) & regularΘ(f(n))
  • Merge sort: 2T(n/2)+n, watershed n¹ → Case 2 → Θ(n log n). Binary search: T(n/2)+O(1) → Θ(log n). Karatsuba 3T(n/2)+n → Θ(n^1.585).
  • Fails when !: unequal splits (T(n/3)+T(2n/3) — use recursion tree / Akra-Bazzi), non-constant a/b, f in the gap between cases, Case-3 regularity fails, or subtract not divide (T(n−1)+n = Θ(n²)).
  • Recursion-tree fallback: sum work per level × #levels. Geometric series → dominated by root or leaves.

Quicksort & Partition

quicksort(a, lo, hi):
  if lo >= hi: return
  p = partition(a, lo, hi)    # Lomuto
  quicksort(a, lo, p-1)
  quicksort(a, p+1, hi)

partition(a, lo, hi):
  pivot = a[hi]; i = lo
  for j in lo..hi-1:
    if a[j] < pivot: swap(a[i], a[j]); i++
  swap(a[i], a[hi]); return i
  • Worst case O(n²) hits on already-sorted / all-equal input with a fixed end pivot ! Fix: randomized or median-of-three pivot; 3-way partition (Dutch flag) for many duplicates.
  • Bound stack: recurse on the smaller partition, loop on the larger → O(log n) stack even worst-case.
  • Quickselect: same partition, recurse only into the side holding rank k → O(n) avg, O(n²) worst; median-of-medians pivot → O(n) worst.

Binary Search

# invariant: answer in [lo, hi]
lo, hi = 0, n-1
while lo <= hi:
  mid = lo + (hi-lo)//2      # avoids overflow !
  if a[mid] == t: return mid
  elif a[mid] < t: lo = mid+1
  else: hi = mid-1
return -1                    # lo = insertion point

Binary search on the answer

# monotone predicate: feasible(x) F..FT..T
lo, hi = min_ans, max_ans
while lo < hi:
  mid = (lo+hi)//2
  if feasible(mid): hi = mid   # first true
  else: lo = mid+1
return lo
  • Requires a monotone predicate, not a sorted array literally. Classic for "min capacity / max min / smallest k such that…" !
  • Off-by-one is the #1 bug: pick one template (<= with mid±1, or < boundary) and keep the loop invariant explicit. Mind lower_bound vs upper_bound for duplicates.

Greedy Algorithms

Build incrementally, take the locally best option, never reconsider. Trivial to code — the work is proving it optimal.

  • Needs both: greedy-choice property (some optimum makes the greedy first choice) + optimal substructure (remainder is a smaller same-problem).
  • Prove via exchange argument: edit any optimum toward the greedy choice, swap by swap, without worsening it.
  • Cost usually dominated by the sort → O(n log n).
ProblemGreedy key
Interval schedulingearliest finish time (not shortest/earliest start) !
Fractional knapsackvalue/weight ratio
Huffman codingmerge two lowest-freq nodes
Min platforms / meetingssort starts & ends, sweep

Greedy FAILS !: 0/1 knapsack (density looks right, is wrong), coin change with arbitrary denominations ({1,3,4} for 6: greedy 4+1+1=3 coins, optimal 3+3=2). "Passes examples" ≠ proof — if you can't write the exchange argument, fall back to DP.

DP Fundamentals

Applies with optimal substructure + overlapping subproblems (both required — merge sort has substructure, no overlap, so not DP).

The recipe

  • State: minimal params identifying a subproblem (dp[i] = best over first i).
  • Transition: recurrence to smaller states.
  • Order: fill so every dependency is ready first.
  • Base cases: smallest states answered directly.

time = #states × cost/transition; space = table size.

MemoizationTabulation
Dirtop-down + cachebottom-up loop
Proliteral recurrence; only reachable statesno stack; tight constants; rolling array
Conrecursion overhead / stack overflowmust nail order; may compute unused
  • Same asymptotics — they trade constants/stack, not Big-O !
  • Bugs: under-specified state (two subproblems collide), backwards iteration order (reads unfilled cell), over-optimizing space before 2D is correct !

  • Knapsack is pseudo-polynomial — O(nW), exponential in the bit-length of W, not truly poly !
  • Rolling array: knapsack drops to O(W) if you iterate w descending for 0/1 (ascending = unbounded knapsack) !
  • Reconstruct the choice by storing parent pointers or back-tracing the table.
  • State-design tell: the smallest set of variables that fully describes a subproblem (index, remaining capacity, last choice, grid position). Too many dims → look for one to drop (rolling array) or a greedy/math shortcut.
  • "Count the number of ways" / "min/max cost to reach" with choices affecting the future is the classic DP fingerprint. If a greedy choice is provably safe, prefer it — it's cheaper !

Graph Traversal: BFS & DFS

Both O(V+E) on adjacency lists (each vertex + edge touched once); O(V²) on a matrix. Traversal is cheap — value is what you extract.

BFS(s):                    # shortest hops, unweighted
  q=[s]; seen={s}
  while q: u=q.popleft()
    for v in adj[u] if v not in seen:
      seen.add(v); dist[v]=dist[u]+1; q.append(v)

DFS(u):                    # deep: order, cycles, comps
  seen.add(u)
  for v in adj[u] if v not in seen: DFS(v)
  • BFS: shortest path in unweighted graphs, level order; frontier can be O(V) wide. Don't use BFS for weighted shortest paths !
  • DFS: topo sort, cycle detection, components, edge classification; recursion can overflow on deep graphs → use explicit stack.
  • Undirected cycle = edge to a visited non-parent. Bipartite = 2-colour BFS, conflict on same-colour edge.

Topological Sort (DAG)

Kahn (BFS, in-degrees)

compute indeg[]; q = all v with indeg 0
while q: u = q.pop(); out.append(u)
  for v in adj[u]:
    if --indeg[v] == 0: q.push(v)
if len(out) < V: CYCLE   # emitted < V !
  • DFS variant: push each vertex on finish, then reverse the list.
  • Directed cycle detection needs the on-stack (gray) distinction — a cross edge to a finished vertex is not a cycle ! "visited" alone is insufficient.
  • Topo order requires a DAG; a cyclic graph has none. Order is generally not unique ! Uses: build order, task scheduling, dependency resolution.

Union-Find (DSU)

find(x):                      # path compression
  while p[x]!=x: p[x]=p[p[x]]; x=p[x]
  return x
union(a,b):                   # union by rank/size
  ra,rb=find(a),find(b)
  if ra==rb: return False     # already joined
  if rank[ra]<rank[rb]: ra,rb=rb,ra
  p[rb]=ra
  if rank[ra]==rank[rb]: rank[ra]+=1
  return True
  • Both optimizations together → O(α(n)) inverse-Ackermann, effectively constant per op.
  • Uses: Kruskal cycle check, connected components, dynamic connectivity, "count islands / groups", detect cycle in an undirected graph.
  • No efficient un-union ! — DSU is for incremental merges; deletions need other structures. Path compression alone (no rank) is still O(log n) amortized.

Shortest Paths — Selector

Every algo here just relaxes edges in a different order: if d[u]+w < d[v]: d[v]=d[u]+w.

SituationAlgorithmTime
UnweightedBFSV+E
Weights all 0 or 10-1 BFS (deque)V+E
DAG, any weightsTopo order + relaxV+E
Non-neg weights, 1 srcDijkstra(V+E)log V
Negative edgesBellman-FordV·E
All pairs, denseFloyd-WarshallV³
Goal-directed, gridA* (g+h)≤ Dijkstra
  • 0-1 BFS: push weight-0 edges to the front of a deque, weight-1 to the back — the deque stays sorted by distance, so you get Dijkstra's answer without the heap's log factor.
  • DAG: no cycles means one pass in topological order suffices — relax each vertex's out-edges when you reach it. Handles negative weights in linear time, which Dijkstra cannot.
  • Cannot add a constant to remove negatives — it penalizes longer paths unequally, changing the answer !
  • Dijkstra does not detect negative cycles — silently wrong on negatives !
  • Floyd-Warshall: intermediate vertex k must be the outermost loop ! A* optimal only with an admissible (and consistent) heuristic.

Dijkstra & Bellman-Ford

Dijkstra(s):
  d[s]=0; pq=[(0,s)]
  while pq: (du,u)=pop_min(pq)
    if du>d[u]: continue     # stale entry, skip !
    for (v,w) in adj[u]:
      if d[u]+w < d[v]:
        d[v]=d[u]+w; push(pq,(d[v],v))
  • Invariant: a vertex's distance is final when popped — holds only with non-negative weights. "Settled" (popped) ≠ "visited/pushed" ! Lazy deletion: skip if popped dist > stored.
  • Binary heap O((V+E)log V); Fib-heap O(E+V log V) theory, binary wins in practice.

Bellman-Ford

for i in 1..V-1:               # V-1 rounds
  for (u,v,w) in edges:
    if d[u]+w < d[v]: d[v]=d[u]+w
# V-th round still relaxes ⇒ negative cycle

Handles negatives + detects negative cycles; shortest simple paths have ≤ V−1 edges, so V−1 rounds suffice.

Minimum Spanning Trees

Cheapest V−1 edges connecting all vertices, no cycle. Both algos are greedy, justified by the cut property: the lightest edge crossing any cut is in some MST.

AlgoHowTime
Kruskalsort edges, add if endpoints differ (DSU)E log E
Primgrow one tree, heap of crossing edgesE log V
  • Kruskal edge-centric, great on sparse / pre-sorted edges, gives a spanning forest if disconnected. Prim vertex-centric, dense-graph O(V²) matrix form beats sorting; only spans its start component.
  • MST is not a shortest-path tree ! MST unique only if all weights distinct. Works with negative weights (no path accumulation), unlike Dijkstra.
  • Cycle property: the heaviest edge on any cycle is never in the MST. Directed analogue = min arborescence (Edmonds), not Prim/Kruskal.

Backtracking & Constraint Search

backtrack(state):
  if complete(state): record(state); return
  for choice in candidates(state):
    if prune(state, choice): continue   # feasibility
    apply(choice)          # choose
    backtrack(state)       # explore
    undo(choice)           # UNCHOOSE !
  • DFS over the tree of partial solutions; abandon a partial the instant it can't complete. Space O(depth) — emit & discard solutions.
  • Forgetting to unchoose corrupts sibling branches (mutated used[]/board) !
  • Pruning changes the practical node count, not the exponential worst case !

Dedupe by skipping duplicate choices at the same tree level (sort first), not post-filtering. Branch-and-bound = backtracking + a bound to prune by objective (optimization).

Number Theory, Math & Randomized

  • gcd Euclid: gcd(a,b)=gcd(b, a%b), O(log min). lcm = a/gcd·b (divide first — overflow) !
  • Sieve of Eratosthenes: primes ≤ n in O(n log log n); mark multiples from i·i.
  • Fast (binary) expo: aⁿ in O(log n) by squaring; core of matrix expo for linear recurrences (Fibonacci in O(log n)).
  • Modular: keep products under the modulus; inverse via Fermat a^(p-2) mod p (p prime) or extended Euclid. Overflow kills silently ! — 64-bit, reduce mod early.
  • Las Vegas (always correct, time random: rand-quicksort) vs Monte Carlo (fixed time, high-prob correct: Miller-Rabin, Karger).
  • Quickselect: k-th smallest O(n) avg (one-sided partition), O(n²) worst; median-of-medians pivot → O(n) worst.
  • Reservoir sampling: uniform k from a stream of unknown length, O(1) space. Fisher-Yates: swap i with random j∈[i,n) — the only unbiased in-place shuffle !

Prefix Sums & Range Techniques

  • Prefix sum P[i]=P[i-1]+a[i] → range sum P[r]-P[l-1] in O(1) after O(n) build. 2D: inclusion-exclusion with 4 corners.
  • Difference array: to add v over [l,r], do d[l]+=v; d[r+1]-=v; one prefix-sum pass applies all updates → O(1) per range update, O(n) finalize.
  • Sliding window: two pointers for subarray/substring on monotone conditions — O(n) instead of O(n²) !
  • Prefix sums are immutable — for point updates + range queries use a Fenwick (BIT, O(log n)) or segment tree.
  • Prefix-XOR / prefix-count for parity and "subarrays summing to k" (hash the prefix).

Intractability: P, NP & Coping

  • P: solvable in poly time. NP: a "yes" has a certificate verifiable in poly time (NP = nondeterministic poly, not "non-polynomial") ! P ⊆ NP; P vs NP is open.
  • NP-hard: ≥ as hard as all of NP (need not be in NP — halting problem, optimization TSP). NP-complete = in NP and NP-hard (SAT via Cook-Levin, 3-SAT, TSP-decision, subset-sum, vertex cover, clique).
  • Reduction: poly-transform A→B preserving the answer ⇒ B's difficulty ≥ A's. This is how you argue "my problem is NP-hard."

When it's NP-hard — cope

RouteBuys / costs
Approximationprovable ratio (2-approx vertex cover); not optimal
Heuristicfast, good in practice; no guarantee
Exact exp.optimal; only small n (Held-Karp 2ⁿ·n²)

A 2-approx = never worse than 2× optimal (not "within 2%") ! Signal: "brute force → can you do better?" → "NP-hard, here's the reduction, so approximate/heuristic/exact-for-small-n."

Heaps & Priority Queues

Binary heap = complete tree in an array; parent of i at (i-1)/2, children at 2i+1, 2i+2. Root is the min (or max). Not sorted — only the heap property (parent ≤ children) holds.

OpCostHow
peekO(1)read root
pushO(log n)append, sift-up
popO(log n)swap root/last, sift-down
buildO(n)Floyd sift-down bottom-up
decrease-keyO(log n)sift-up (needs index map)
  • Bottom-up build is O(n), not O(n log n): most nodes are near the leaves where sift-down is cheap — the level sum telescopes !
  • Uses: k-largest (size-k min-heap, evict the smallest), streaming median (two heaps), merge k sorted lists, Dijkstra/Prim frontier, event/sweep schedulers.
  • No O(log n) arbitrary search or delete-by-value without a side index; no cheap "kth" beyond the root. Ties aren't stable unless you push a sequence tiebreaker !
  • Top-k in O(n log k) with a bounded heap beats a full O(n log n) sort when k ≪ n. Quickselect gives the boundary in O(n) avg if you don't need them ordered.

Segment Tree & Fenwick (BIT)

Prefix sums are immutable. For point update + range query you need a log-structure.

StructureUpdateQuerySpace
Prefix sumO(n) rebuildO(1)n
Fenwick (BIT)O(log n)O(log n)n
Segment treeO(log n)O(log n)~2n
Seg + lazyrange O(log n)O(log n)~4n
  • Fenwick: tiny, fast, invertible ops only (sum, xor) — walk by i += i&-i (update) / i -= i&-i (query). Can't do min without tricks.
  • Segment tree: any associative merge (min/max/gcd/sum), the general answer; store the op at each node, combine children.
  • Lazy propagation defers range updates onto subtree roots, pushing down only when a query descends — required for range-update+range-query, easy to get wrong !
  • Sparse table: O(1) idempotent range query (min/gcd) after O(n log n) build, but static only (no updates).

Two Pointers & Sliding Window

Turn an O(n²) pair/subarray scan into O(n) by moving indices monotonically instead of restarting.

ShapeWhen
Opposite endssorted array, pair-sum, palindrome, container
Fast/slowcycle detect (Floyd), middle node, dedup in place
Sliding windowlongest/shortest subarray under a monotone constraint
Merge twomerge sorted lists, intersection, small-range union
  • Window template: expand right; while the window is invalid, shrink left; record the answer each step. Works only when growing the window can't fix a violation (monotone) !
  • Variable window needs a running aggregate (count map, sum) so validity is O(1) to test. Fixed-k window slides by add-one / drop-one.
  • Floyd cycle: slow +1, fast +2 — they meet iff a cycle exists; restart one at head, advance both by 1 to find the entry.
  • Subarray (contiguous) ⇒ window / prefix; subsequence ⇒ usually DP, not a window !

Strongly Connected Components

SCC = maximal set in a directed graph where every vertex reaches every other. Contract each SCC → the condensation is a DAG (then run DAG algos). Both methods O(V+E).

KosarajuTarjan
Passes2 DFS + transpose1 DFS
Ideafinish-order, then DFS on reversed graphdisc/low + stack
Pickeasier to explainfaster, no transpose
  • Kosaraju: DFS pushing each vertex on finish; then pop in that order and DFS the transposed graph — each tree is one SCC (finish-order starts you in a sink SCC of the condensation).
  • Tarjan: track disc[v] and low[v] (lowest disc reachable via subtree + one back edge); when low[v]==disc[v], pop the stack down to v = one SCC.
  • SCCs are a directed concept; undirected → just connected components !

Bridges, Cut Vertices & Low-link

low[v] = earliest-discovered vertex reachable from v's DFS subtree via ≤1 back edge. One low-link DFS finds bridges and articulation points in O(V+E).

  • Mnemonic: bridges use strict > (subtree can't reach even u), cut vertices use >= (may reach u itself, not above) !
  • Bridge ⇏ articulation and vice-versa: two triangles sharing one vertex → that vertex is a cut point but there's no bridge (every edge on a cycle) !
  • Uses: network reliability / single points of failure, 2-edge- and 2-vertex-connected component decomposition.

Max-Flow / Min-Cut & Matching

Flow network: directed, edge capacities, source s, sink t. Max-flow = min-cut — the maximum throughput equals the cheapest set of edges separating s from t.

AlgoPath ruleTime
Ford-Fulkersonany augmenting pathcan be exp. !
Edmonds-KarpBFS (shortest)V·E²
Diniclevel graph + blocking flowV²·E; E·√V unit-cap
  • Residual / back edges are mandatory: pushing f on (u,v) adds a reverse edge cap f so later paths can re-route earlier flow. Omit them and max-flow is simply wrong !
  • Min-cut certificate: when no augmenting path remains, vertices reachable from s in the residual graph are one side of the min cut.
  • Bipartite matching reduces to flow: s→L (cap 1), L→R edges (cap 1), R→t (cap 1); max-flow = max matching. Dinic here is O(E·√V) (= Hopcroft-Karp).
  • König: max matching = min vertex cover (bipartite). "Separate X from Y at min cost" or "assign under capacity" is often flow in disguise — spotting the reduction is the senior signal.

Computational Geometry

Almost everything is the sign of a cross product (a 2×2 determinant): cross(B−A, C−A) >0 left turn, <0 right, =0 collinear. Stay in integers — exact, no trig.

Backtracking Dedup & The Three Shapes

Enumeration counts: subsets 2ⁿ (in/out each), permutations n! (track used), combinations n choose k (enforce increasing start index).

# subsets/combos with duplicate INPUT values:
sort(a)
for i in start..n-1:
  if i>start and a[i]==a[i-1]: continue  # skip
  choose a[i]; recurse(i+1); unchoose
  • Dedup by skipping equal choices at the same tree level (sort first) — never post-filter a set of results !
  • Permutations with dups: sort, and skip a[i] if a[i]==a[i-1] and a[i-1] is not currently used (its branch already covered this value).
  • Mutate-and-undo is faster than copy-down (no allocation) but every path must restore state exactly — the classic footgun !
  • Branch-and-bound = backtracking + an optimistic bound to prune by objective (optimization, not just feasibility).

Paradigm Ladder — Interview Playbook

The meta-skill: narrow the space out loud. Restate → brute force + its cost → read n for the budget → name candidate paradigms → verify the precondition → code → test.

Pick by structure

SignalReach for
locally-optimal choice provablegreedy (+ exchange arg)
independent equal halvesdivide & conquer
overlapping subproblemsDP
entities + relations / reachabilitygraph model
min-max / max-min, big rangebinary search on answer
try-all-with-pruningbacktracking
  • "Recursion" ≠ "DP": DP = recursion + memo over overlapping subproblems. No overlap → it's plain divide & conquer !
  • Match effort to the budget — if n≤100, an O(n³) brute force (~10⁶ ops) is fine; correct beats clever, no prize for beating the required bound.
  • "Can you make it faster?" = move down the ladder: find the dominant term, ask what structure is unexploited (a sort/hash killing an inner loop, a monotone predicate enabling binary search, prefix sums for O(1) queries), restate the new complexity, re-argue correctness.
  • Most wrong answers = skipping the precondition check (greedy without a proof, DP state with a forward dependency).

★ Interview Checklist

Before coding

  • ☐ Restated problem, clarified constraints & edge cases (empty, single, duplicates, negatives, overflow).
  • ☐ Inferred target complexity from max n before picking an approach !
  • ☐ Named the algorithm family and why (weighted? negatives? all-pairs? monotone?).

Correctness

  • ☐ Greedy has an exchange-argument justification — or fell back to DP.
  • ☐ DP state fully specifies the subproblem; transitions read only already-filled states; base cases covered.
  • ☐ Backtracking undoes every choice; dedup by skipping same-level duplicates.
  • ☐ Dijkstra only on non-negative weights; negatives → Bellman-Ford.

Complexity & safety

  • ☐ Stated time and auxiliary space (incl. recursion depth).
  • ☐ Binary-search bounds & loop invariant explicit — off-by-one checked.
  • ☐ 64-bit for sums/products near 10⁹; mod reduced early.
  • ☐ Directed-cycle detection uses on-stack, not just visited.
