How to read & print

  • ! footgun / classic trap   ☐ checklist step
  • Design problems test data-structure choice: given the ops + a complexity target, pick the structure that hits it.
  • Each theme card: problem → core structure → the trick. Full solutions (Py/Java/Rust/Go/C++) live in the primer.
  • Print: Ctrl/⌘-P → A4, margins None, scale 100%, background graphics on. 4 columns built-in.

The Design Method

  • 1. Clarify the ops + the required complexity of each (O(1)? O(log n)?). That target dictates the structure.
  • 2. Pick structure from the ops (see quick-pick card).
  • 3. State the invariant the structure maintains between calls.
  • 4. Edge cases: empty, single element, full/capacity, duplicate keys, wraparound.
  • ! Almost every "O(1)" design = hashmap + a second structure (list / heap / array) kept in sync.

☐ Interview Playbook

  • ☐ Restate the ops + each op's target complexity before coding.
  • ☐ Say the structure out loud + why it hits the target.
  • ☐ O(1) get/put/evict → hashmap + DLL (LRU); order-by-freq → freq buckets (LFU).
  • ☐ O(1) random → array + index map, swap-with-last delete.
  • ☐ Running min/median/top-k → heap(s); "top of stream" → size-k min-heap.
  • ☐ Prefix / ordered / bounds → trie or TreeMap/BST.
  • ☐ Range sum + updates → BIT; static → prefix sums.
  • ☐ Overlap/booking → sorted map or difference-array sweep.
  • ☐ State the invariant maintained between calls; then edge cases (empty, full, dup, wraparound).
  • ☐ Mention the stdlib shortcut (OrderedDict, LinkedHashMap, TreeMap, heapq, container/list).
