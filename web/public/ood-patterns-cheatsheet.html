Four Pillars of OOP

  • Encapsulation: hide state, expose behavior (invariants stay valid).
  • Abstraction: model the essential, ignore the rest.
  • Inheritance: is-a reuse (use sparingly).
  • Polymorphism: one interface, many impls (dynamic dispatch).

Core Principles

  • DRY · KISS · YAGNI — don't repeat, keep simple, don't build ahead.
  • Composition over inheritance — has-a beats is-a for reuse.
  • Program to an interface, not an implementation.
  • Law of Demeter — a.getB().getC().do() is a smell. !
  • Encapsulate what varies; Tell-Don't-Ask; high cohesion / low coupling.

Strategy — canonical code

interface PayStrategy { void pay(int cents); }
class Card implements PayStrategy {…}
class Cash implements PayStrategy {…}

class Checkout {
  private PayStrategy s;            // compose, don't extend
  Checkout(PayStrategy s){this.s=s;}
  void charge(int c){ s.pay(c); }   // program to interface
}

Add a payment type → new class, zero edits to Checkout (OCP).

Code Smells & Refactoring

  • Smells: god class, long method, feature envy, primitive obsession, data clumps, shotgun surgery, message chains.
  • Moves: extract method/class, replace conditional with polymorphism, introduce parameter object, replace temp w/ query.
  • ! A big switch(type) repeated everywhere → subclass + polymorphism.
  • Refactor in small safe steps, behind tests (Tidy First).

Anti-Patterns

  • God object: one class does everything → split by responsibility.
  • Anemic model: data-only classes + logic elsewhere → put behavior with data.
  • Golden hammer: one pattern for every problem.
  • Patternitis: patterns where a plain function would do. !
  • Premature abstraction > duplication early on (YAGNI).

☐ LLD Interview Playbook

  • ☐ Clarify requirements & scope first — don't code yet.
  • ☐ Extract nouns → entities, verbs → methods.
  • ☐ Assign each responsibility to ONE class (SRP, info expert).
  • ☐ Pick relationships (composition vs aggregation vs inheritance).
  • ☐ Define interfaces before implementations.
  • ☐ Apply a pattern only where it earns its keep (Strategy/State/Factory/Observer are the usual four).
  • ☐ Walk an example flow; then edge cases, extensibility, thread-safety.
  • ☐ Narrate tradeoffs out loud — that's the signal.
