! The list's O(1) insert assumes you already hold the node; finding it is O(n). In practice arrays win by cache locality unless you splice a lot.

Dynamic Array (amortized)

  • Full → allocate 2x, copy n, keep going. A single append is O(n), but n appends cost O(n) total → O(1) amortized.
  • ! Growth factor 2 (or 1.5) matters; growing by +1 makes append O(n).
  • Capacity ≥ size; shrink lazily to avoid thrashing.

Hash Table Internals

  • Bucket = hash(key) mod m. Collisions are inevitable (pigeonhole).
  • Chaining: bucket → list/tree of entries. Simple; degrades gracefully.
  • Open addressing: probe (linear/quadratic/double) to next free slot; needs tombstones on delete. !
  • Load factor alpha = n/m; resize (rehash all) when alpha > ~0.7 → keeps O(1).
  • ! O(1) is expected; adversarial/bad hash → O(n). Iteration order is unspecified.

Trees · BST · Balanced

  • BST invariant: left < node < right. In-order traversal = sorted.
  • ! Plain BST on sorted input degenerates to a list → O(n). Balancing forces h = O(log n).
  • AVL: strict height-balance, faster lookups, more rotations.
  • Red-Black: looser balance, fewer rotations on write → the engine behind Java TreeMap / C++ std::map.
  • Rotation = local O(1) re-link restoring balance.

Traversals

DFS (stack/recursion):
  pre  : node, L, R
  in   : L, node, R   # BST -> sorted
  post : L, R, node
BFS (queue): level by level

DFS space O(h); BFS space O(width). Use BFS for shortest path in an unweighted graph.

Heaps & Priority Queues

array heap: child(i)=2i+1,2i+2
            parent(i)=(i-1)/2
push: append + sift-up   O(log n)
pop : swap root/last + sift-down
heapify whole array:     O(n)
  • Min-heap = O(1) peek-min; not searchable (O(n)).
  • Uses: Dijkstra/Prim, top-k (size-k heap), merge k lists, scheduling, heapsort.

Tries (Prefix Trees)

  • One node per char; path spells the key. Ops O(L) in key length, independent of n.
  • Wins for prefix queries / autocomplete — a hash set can't do "all keys starting with…".
  • Radix/Patricia: compress single-child chains → less space.
  • ! Memory-heavy (pointers per node); a hash set is smaller for pure membership.

Union-Find (DSU)

find(x): follow parent to root
         (path compression)
union(a,b): link smaller root
            under larger (by rank)
  • Both optimizations → near O(1) amortized (inverse Ackermann).
  • Uses: Kruskal MST, connectivity/components, dynamic equivalence, cycle detection in undirected graphs.

Skip Lists & Probabilistic

  • Skip list: layered linked list, coin-flip levels → O(log n) expected; simpler to write than a balanced BST. Redis sorted sets use it.
  • Bloom filter: k hashes into a bit array; "possibly present" or "definitely absent" — false positives, never false negatives. ! No delete (use Counting Bloom).
  • Count-Min Sketch: approx frequencies; HyperLogLog: approx cardinality. Tiny memory, bounded error.

B-Trees & B+ Trees

  • High fanout (hundreds of keys/node = one disk page) → very shallow → few disk seeks. The DB/filesystem index structure.
  • B+ tree: values only in leaves, leaves linked → great for range scans + sequential I/O.
  • ! A binary BST is wrong for disk: h ~ log2(n) seeks vs log_fanout(n).

☐ Interview Playbook

  • ☐ List the required operations + each op's target complexity before picking anything.
  • ☐ Map ops → structure (see the table) and say why it hits the target.
  • ☐ Name the trade-off you're accepting (memory, ordering, worst-case).
  • ☐ Hash = expected O(1) but no order + O(n) worst; tree = O(log n) but sorted + range.
  • ☐ "Repeatedly need the extreme" → heap. "Need order too" → balanced BST, not a heap.
  • ☐ O(1) get/put/evict → hashmap + DLL. O(1) random → array + index map.
  • ☐ On-disk / huge → B+ tree, not a binary BST.
  • ☐ Recall amortized vs worst-case honestly; mention cache locality when arrays win.
