  • "Dealing with many things" vs "doing many things." You can have concurrency without parallelism (event loop).
  • Amdahl: speedup ≤ 1/(s + (1−s)/N); a 5% serial part caps you at 20×. ! Coordination overhead can make more threads slower.

Race Condition vs Data Race

  • Data race: 2 threads touch same memory, ≥1 write, no ordering → UB. Fix with sync/atomics.
  • Race condition: wrong result from timing; can exist even with atomics (check-then-act).
// count++ is 3 ops, not atomic:
T1: load 0        T2: load 0
T1: add  1        T2: add  1
T1: store 1       T2: store 1   // lost update → 1 not 2 !

! volatile/atomic-read does NOT make x++ safe — it's read-modify-write. Use an atomic add or a lock.

Memory Model & Happens-Before

  • Compiler & CPU reorder for speed; without a happens-before edge, one thread may never see another's write.
  • Java: volatile = visibility + ordering (not atomicity); synchronized unlock→lock; final safe publication.
  • C++ memory_order: relaxed < acquire/release < seq_cst. Pair release-store with acquire-load.
// Double-checked locking (Java, correct):
private volatile Singleton inst;   // volatile is essential !
Singleton get(){
  if(inst==null) synchronized(this){
    if(inst==null) inst=new Singleton();
  }
  return inst;
}

Atomics & Lock-Free

  • CAS(addr, expected, new): atomically swap iff unchanged → retry loop.
  • Progress: lock-free (some thread advances) > wait-free (all bounded) > blocking.
// CAS push (Treiber stack)
do { old = top; n.next = old; }
while(!CAS(&top, old, n));

! ABA: value goes A→B→A, CAS wrongly succeeds. Fix: tagged pointer / hazard pointers / epoch GC. Lock-free ≠ always faster — under low contention a mutex often wins.

Deadlock & Friends

Needs all 4 Coffman: mutual excl · hold-and-wait · no preempt · circular wait.

T1: lock A; lock B     // classic
T2: lock B; lock A     // → deadlock
// fix: GLOBAL lock ordering (always A before B)
  • Livelock: threads react, no progress. Starvation: unlucky thread never runs.
  • Priority inversion: low holds lock high needs → priority inheritance (Mars Pathfinder). !
  • Also: try-lock + backoff, lock timeout, single big lock.

  • Pool avoids per-task thread creation cost. Fork-join = work-stealing deques for recursive splits.
  • ! Unbounded queue → hides overload → OOM. Bound the queue + a rejection policy.
  • Blocking inside a small pool → starvation/deadlock (esp. dependent tasks). Virtual threads (Loom) relax this.

Async / Event Loop

flowchart LR Q["task queue"] --> L{"event loop
(1 thread)"} L -->|run to await| L L -->|await IO| IO["OS async IO"] IO -->|ready| Q
  • One thread, many tasks; await yields at IO points (cooperative). Great for IO-bound, huge fan-out.
  • ! Never block the loop — a CPU-heavy or sync-IO call freezes ALL tasks. Offload to a worker/pool.
  • Coroutines: stackless (async/await state machine) vs stackful (goroutines). Microtasks (promises) drain before macrotasks.

Concurrent Data Structures

  • ConcurrentHashMap: CAS on bins / lock striping — reads mostly lock-free.
  • CopyOnWrite: read-heavy, rare writes (listener lists).
  • BlockingQueue: the backbone of producer-consumer (bounded → backpressure).
  • ! Thread-safe methods ≠ thread-safe sequences: if(!m.contains(k)) m.put(k,v) still races → use putIfAbsent/compute.
  • Immutable / persistent structures sidestep the whole problem.

Scaling & Contention

  • False sharing: two vars on one 64B cache line → cores ping-pong ownership. Pad / @Contended. !
  • MESI coherence + NUMA: remote memory is slow; pin & shard per core.
  • Contention collapse: past a point, more threads = more lock waiting = slower.
  • Fixes: shard/thread-local aggregate, read-mostly (RCU/seqlock), lock-free, batch. Little's law: L = λ·W to size pools.

Distributed Concurrency

  • Optimistic (version/CAS, retry on conflict) vs pessimistic (lock upfront). OCC wins under low contention.
  • Idempotency + at-least-once → dedup keys. Backpressure & load shedding over unbounded buffering.
  • Rate limit: token bucket. ! Distributed locks need fencing tokens (a lease can expire mid-op).
  • Sagas + compensation instead of distributed 2PC.

☐ Spot-the-Bug & Interview Checklist

  • ☐ Find the shared mutable state — that's where races live.
  • ☐ Compound op (check-then-act / read-modify-write)? Make it atomic or lock it.
  • ☐ Publication safe? (visibility — volatile/final/sync, not just "I set it").
  • ☐ Multiple locks? Impose a global order; hold briefly; no IO under lock.
  • ☐ wait() inside a while, not if.
  • ☐ Slower with more threads? Contention / false sharing / GIL / IO-bound / too-small pool.
  • ☐ Pick the primitive: counter→atomic; pool→semaphore; pipeline→queue/channel; read-heavy→RWLock/COW.
  • ☐ Reason out loud via an explicit T1/T2 interleaving.
