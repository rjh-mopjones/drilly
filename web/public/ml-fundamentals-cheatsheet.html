Loop: frame problem → collect/clean data → features → pick model → train → evaluate → deploy → monitor → retrain. Real systems mix paradigms (unsupervised embeddings → supervised head; RLHF = supervised + RL).

  • Parameter = learned from data (weights). Hyperparameter = set by you before training (lr, depth, λ, k) — tuned on validation, never test.
  • Generalization = performance on unseen data — the only thing that matters. Every model needs an inductive bias (assumptions) to generalize at all.
  • ! When NOT to use ML: a deterministic rule works, you can't get labels/signal, errors are unacceptable & unexplainable, or data is too scarce/drifting. Always build the dumb baseline first.

Bias–Variance Tradeoff

E[(y - f̂(x))²] = bias² + variance + σ²
bias  = E[f̂] - f      (systematic, wrong assumptions)
var   = E[(f̂ - E[f̂])²] (sensitivity to the sample)
σ²    = irreducible noise (floor, unbeatable)
  • High bias → underfit: train AND val both bad, small gap.
  • High variance → overfit: train good, val bad, large gap. !
  • Same knob (capacity) moves both opposite ways → minimize the sum, not either alone.

Diagnose from train/val gap

TrainValVerdict → fix
2%25%variance → more data, regularize, ↓capacity
20%22%bias → ↑capacity, better features, train longer
20%40%both → fix bias first, then variance
  • ! Wrong-signed fix is the classic blunder: adding complexity to an overfit model. More data cuts variance, never bias.
  • Double descent: past the interpolation threshold, huge over-parameterized models see test error fall again — refines, doesn't refute, the U-curve.

Overfitting, Underfitting & Capacity

  • Capacity = richness of representable functions: poly degree, tree depth, #params, kernel width, k in kNN (small k = high capacity).
  • Learning curve (vs data size): curves converge high = underfit (more data won't help); a persistent gap = overfit (more data helps).
  • Training curve (vs epochs): val loss turns up while train keeps dropping = overfitting onset → early stop.

If underfitting (won't help vs will)

  • ↑ model capacity, add/engineer features, reduce regularization, train longer. ! More data won't fix bias.

If overfitting

  • More data, regularization/dropout, ↓capacity, early stopping, feature selection, augmentation. ! A bigger model won't fix variance.

! Both low but prod is terrible ⇒ not a capacity problem — leakage, train/serve skew, or drift.

Regularization

PenaltyEffect
L2 / Ridgeλ·Σwᵢ²shrinks weights toward 0, none exactly 0; handles collinearity
L1 / Lassoλ·Σ|wᵢ|sparse — drives weights to exactly 0 → feature selection
Elastic netαL1+(1−α)L2sparsity + stability with correlated features
  • Why L1 is sparse: its diamond constraint has corners on the axes; the loss contour hits a corner → coefficient = 0. L2's circle has no corners.
  • λ sweep: λ→0 = unregularized (overfit); λ→∞ = all weights→0 (underfit, predicts the mean). Pick λ by CV.
  • ! Standardize features first — the penalty is scale-sensitive; unscaled features get unequal shrinkage.
  • Weight decay ≈ L2 (identical for plain SGD; decoupled in AdamW). Dropout, early stopping, data augmentation are all regularizers too.
  • Mechanism: trades a little bias for less variance — helps only when variance-limited. Too much → underfit.

Cross-Validation & Model Selection

  • Why 3 splits: train fits params, val tunes hyperparameters/selects models, test gives one honest final estimate.
  • k-fold (k=5/10): rotate the held-out fold, average — lower-variance estimate than one split; every row is validated once.
  • Stratified k-fold: preserve class ratios (imbalanced/small data).
  • LOOCV: k=n — low bias, high variance, costly.
  • ! Time series: never shuffle — use forward-chaining / expanding window so you never train on the future.
  • ! Grouped data (same user/patient) → GroupKFold so a group can't span train & val (leakage).
  • Nested CV: inner loop tunes, outer loop estimates — avoids optimistic bias from tuning on the same folds you report.
  • ! CV ≫ test score ⇒ you tuned on the reported folds or leaked across them → nested CV.
  • Repeated k-fold (different seeds) shrinks split-luck variance; report mean ± std, not one number.

! Golden rule: touch the test set once, at the very end. Fit all preprocessing inside the CV fold, not on the full data.

Classification Metrics

            pred +   pred −
actual +     TP       FN
actual −     FP       TN
precision = TP/(TP+FP)   recall/TPR = TP/(TP+FN)
F1 = 2·P·R/(P+R)         FPR = FP/(FP+TN)
accuracy = (TP+TN)/N     specificity = TN/(TN+FP)
  • ! Accuracy lies under imbalance: 99% by always predicting the majority. Use precision/recall/F1/PR-AUC.
  • Precision = cost of a false positive; recall = cost of a false negative. Anchor to the denominator, not the name.
  • Threshold (default 0.5 is arbitrary): lower → ↑recall ↓precision. Set it from business cost.
  • ROC-AUC = ranking quality (TPR vs FPR), threshold-free but ! optimistic under heavy imbalance. PR-AUC for rare positives.
  • Log loss penalizes confident-wrong probabilities; high AUC ≠ calibrated.
  • F-beta: β>1 weights recall (Fβ=2 for screening), β<1 weights precision. Macro F1 averages per-class equally (fair to minority); micro aggregates counts (favors majority).
  • Balanced accuracy = mean of per-class recall — honest under imbalance. MCC / Cohen's κ summarize the whole matrix, robust to skew.

Fraud/cancer → recall (a miss is catastrophic). Spam-to-inbox → precision (deleting a real email hurts). Anchor the metric to FP-vs-FN cost, then set the threshold.

Regression & Ranking Metrics

MSE  = mean((y−ŷ)²)          # penalizes big errors²
RMSE = √MSE                   # same units as y
MAE  = mean(|y−ŷ|)            # robust to outliers
MAPE = mean(|y−ŷ|/|y|)        # % error, ! blows up near y=0
R²   = 1 − SS_res/SS_tot      # frac. variance explained
  • RMSE vs MAE: RMSE is outlier-sensitive (squares); MAE robust. Big outliers & you care → RMSE, else MAE.
  • ! R² can go negative (worse than predicting the mean); it inflates with more features → use adjusted R².
  • Optimize a Huber loss for outlier-robust yet smooth gradients.

Ranking / recsys

  • NDCG (graded, position-discounted), MAP, MRR (rank of first hit), Precision@k / Recall@k. Match the metric to what the user actually sees (top-k order).

Feature Engineering

  • Categoricals: one-hot (low cardinality) · ordinal (ordered) · target/mean encoding (high cardinality — ! leakage-prone, fit inside CV folds with smoothing) · hashing (huge cardinality).
  • Scaling: standardize (z-score) or min-max for distance/gradient models (kNN, SVM, linear, NN, PCA, k-means). Trees don't need scaling — they split on thresholds.
  • Numeric: log/Box-Cox for skew, binning, polynomial & interaction terms.
  • Dates: decompose to day/hour/is_weekend + cyclical sin/cos. Text: TF-IDF / embeddings. Geo: distances, clusters.
  • Selection: filter (correlation/MI) · wrapper (RFE) · embedded (L1, tree importance).

Scaling methods

MethodUse when
Standardize (z)roughly Gaussian; default for linear/NN/PCA

Features > model: a good feature beats a fancier algorithm on the same data. This is where domain knowledge pays. ! Fit every transform on train only, apply to val/test.

Data Leakage !

Model sees at train what it won't have at predict time → brilliant offline, dead in prod. The #1 cause of "too-good-to-be-true" metrics.

TypeExample
Target leakfeature is a proxy/consequence of y (e.g. "account_closed" predicting churn)
Temporalusing future info; not respecting event time
Preprocessingscaler/imputer/encoder fit on full data before split
Group / dupsame entity in train & test; leaked duplicates
Train/serve skewfeature computed differently offline vs online
  • Tell: suspiciously high metric, one feature dominating importance.
  • Fix: split first; wrap all preprocessing in a Pipeline fit inside CV; ask of every feature "is this known at prediction time?"

Data Prep & Imbalanced Data

Missing values

  • Delete (if MCAR & few) · impute (mean/median/mode, KNN, model) · + missingness indicator (the fact it's missing can be signal). ! Fit imputer on train only.

Outliers

  • Detect (z>3, IQR, isolation forest); clip/winsorize or use robust models/losses. Don't blindly delete — could be the signal.

Class imbalance

  • Resample: oversample minority (SMOTE — synthesize, ! only on train), undersample majority.
  • Class weights / cost-sensitive loss (no data churn — often first choice).
  • Tune the threshold; evaluate with PR-AUC / F1, never accuracy.

Linear Models

linreg:  ŷ = wᵀx + b,  loss = MSE  (convex, closed-form OLS)
logreg:  p = σ(wᵀx + b),  loss = log-loss / BCE
σ(z) = 1/(1+e⁻ᶻ)
  • ! Logistic regression is CLASSIFICATION — "regression" refers to modeling log-odds, not a continuous output.
  • Coefficients interpretable: logreg weight = change in log-odds per unit feature; e^w = odds ratio.
  • High bias / low variance family: strong linear inductive bias. Add polynomial/interaction features for nonlinearity.
  • Assumptions: roughly linear relationship, low multicollinearity (→ ridge), independent errors.
  • Great baseline: fast, calibratable, scales to millions of sparse features (text). Regularize (L1/L2) when p is large.
  • ! Perfect separation → logreg weights diverge to ±∞ (MLE undefined) → regularize. Multiclass via softmax (multinomial) or one-vs-rest.
  • OLS closed form: w = (XᵀX)⁻¹Xᵀy — but XᵀX is singular under collinearity → ridge adds λI and makes it invertible.

Tree Ensembles: Bagging vs Boosting

Bagging (RF)Boosting (GBM)
Treesdeep, parallel, independentshallow, sequential on residuals
Attacksvariancebias
Overfit risklow (more trees safe)higher (more trees can overfit) !
Key knobs#trees, max_featureslr, depth, #trees, subsample
  • Single tree: greedy splits on Gini/entropy (class) or variance (reg); zero-bias if grown deep → high variance → prune / limit depth.
  • GBM (XGBoost / LightGBM / CatBoost) = the tabular workhorse. Lower lr + more trees + early stopping.
  • No scaling needed; handles mixed types & nonlinearity/interactions natively.
  • ! Impurity (Gini) importance is biased toward high-cardinality/continuous features → use permutation importance or SHAP.
  • Key GBM knobs: learning_rate (lower + more trees generalizes better), max_depth/num_leaves (3–8 typical), subsample & colsample (stochastic → regularizes), min_child_weight, L1/L2 leaf penalties, early stopping on a val set.
  • CatBoost handles categoricals natively (ordered target encoding, less leakage); LightGBM leaf-wise growth is fast but ! overfits small data without depth limits.

Distance & Margin Models

kNN

  • Lazy: no training; predict = majority/mean of k nearest. Small k = high variance, large k = high bias.
  • ! Must scale features; dies in high dimensions (curse of dimensionality — distances concentrate); slow at predict.

SVM

  • Maximizes the margin to the nearest points (support vectors). Soft margin C trades margin width vs violations.
  • Kernel trick (RBF/poly) = nonlinear boundaries without explicit feature map. ! Scale first; O(n²–n³) → not for huge n.
  • Strong on small/medium, high-dim (text) data with clear margins.

Optimization & Gradient Descent

w ← w − η·∇L(w)          # η = learning rate
VariantTrait
Batch GDfull data/step — stable, slow, memory-heavy
SGD1 sample — noisy, fast, escapes shallow minima
Mini-batch32–512 — the default sweet spot
  • Momentum accumulates velocity; Adam = momentum + per-param adaptive lr (robust default). AdamW decouples weight decay.
  • ! LR is the #1 hyperparameter: too high → diverge/oscillate; too low → crawls/stuck. Use warmup + decay/schedules.
  • Convex (linear/logistic/SVM) → one global min. Non-convex (NN) → local minima & saddles; init & normalization matter.
  • Always standardize inputs — skewed scales make ill-conditioned, slow-converging loss surfaces.

Neural Network Fundamentals

  • Neuron: a = φ(wᵀx + b). Stacked layers + nonlinearity = universal approximator. ! Without a nonlinear activation, any depth collapses to one linear layer.
  • Activations: ReLU default (cheap, no vanishing for x>0, ! dying-ReLU → LeakyReLU/GELU); sigmoid/tanh saturate; softmax for multiclass output.
  • Backprop = chain rule caching gradients layer by layer. ! Vanishing/exploding gradients in deep nets → ReLU, residual connections, normalization, gradient clipping.
  • Regularize: dropout, weight decay, early stopping, batch/layer norm, augmentation.
  • Normalization: BatchNorm stabilizes/speeds training (batch stats — awkward for tiny batches/RNNs); LayerNorm per-sample (transformers). Both ease the vanishing-gradient problem.
  • ! Init matters: all-zero weights → every neuron identical (symmetry never breaks). Use He (ReLU) / Xavier (tanh) init.
  • Needs lots of data & compute; wins on unstructured data (image/text/audio). For tabular, GBMs usually still beat NNs.

  • PCA: orthogonal axes of max variance (eigenvectors of covariance); keep components to ~90–95% cumulative variance. ! Standardize first; linear only.
  • t-SNE / UMAP: nonlinear visualization — ! distances/cluster sizes between blobs aren't meaningful; don't feed downstream blindly.

Reinforcement Learning Basics

  • Agent takes actions in an environment (state), gets reward, learns a policy π(a|s) maximizing expected discounted return.
  • MDP = (S, A, P, R, γ); Markov = next state depends only on current state+action.
  • γ (discount, 0–1): low = myopic, high = far-sighted (but harder credit assignment).
  • Explore vs exploit: ε-greedy takes a random action w.p. ε, else the greedy one.
  • Value-based (Q-learning: Q(s,a)=expected return, off-policy) vs policy-based (optimize π directly, better for continuous actions).
  • ! Reward hacking: agent games a misspecified reward. Credit assignment over long horizons is the core difficulty.
  • Looks-like-RL-but-isn't → if you have labeled optimal actions, use supervised. Contextual bandits = 1-step RL. RLHF aligns LLMs.
  • On- vs off-policy: SARSA learns the policy it follows; Q-learning learns the greedy policy while exploring (off-policy). Model-free (learn from experience) vs model-based (learn/known transition dynamics, plan).
  • ! RL is sample-hungry and unstable — needs a simulator or cheap interaction; rarely the right first tool for a supervised-shaped problem.

Interpretability & Explainability

ScopeTools
Globallinear coefficients, tree structure, permutation importance, PDP
LocalSHAP (Shapley, additive, consistent), LIME (local surrogate), ICE
  • Intrinsic (linear, shallow tree, GAM) vs post-hoc (SHAP/LIME on a black box). Prefer intrinsic when stakes/regulation demand it.
  • ! Correlation, not causation — importance ≠ a lever you can pull. Explanations can mislead if features are correlated.
  • Interpretability is a real objective in regulated domains (credit, health): sometimes worth trading a few points of accuracy.
  • SHAP = game-theoretic Shapley values: each feature's additive contribution to this prediction; sums to pred − base. Consistent & local+global, but slow.
  • PDP shows the average marginal effect; ! misleading under correlated features (extrapolates to unrealistic combos) → ALE plots are safer.

Ensembling — Why & How

Combine several models so errors cancel. Works best when members are accurate but decorrelated — diverse errors average out; identical models add nothing.

MethodMechanism
Baggingsame algo on bootstrap samples, average → cuts variance (RF)
Boostingsequential, each fits prior residuals → cuts bias (GBM)
Votinghard (majority) or soft (avg probs) across different algos
Stackinga meta-model learns to combine base out-of-fold preds
Blendingstacking on a held-out set (simpler, less data-efficient)
  • ! Stacking must use out-of-fold predictions for the meta-features — training the meta-model on in-sample base preds leaks.
  • RF decorrelates trees via feature subsampling at each split, not just row bootstrap.
  • Diminishing returns + serving cost/latency — a single well-tuned GBM often beats a fragile 5-model stack in production.

Threshold from Cost — Worked Example

The 0.5 cutoff is arbitrary. Pick the threshold that minimizes expected cost, given C_FP and C_FN.

# fraud: miss (FN) costs $500, false alarm (FP) costs $5
# → 100:1 asymmetry, favor recall, lower the threshold
cost(t) = C_FP·FP(t) + C_FN·FN(t)
t* = argmin_t cost(t)          # sweep t on the val set
# Bayes-optimal for calibrated p:  flag if p > C_FP/(C_FP+C_FN)
#   = 5/(5+500) ≈ 0.0099  → flag at ~1%, not 50%
  • Sweep t over the validation set, plot precision/recall vs t, pick the operating point that hits the budget (e.g. analyst review capacity).
  • ! The Bayes formula only holds if probabilities are calibrated — otherwise tune t empirically.
  • Re-tune when the base rate or costs shift; a fixed threshold silently drifts out of optimum.

Anomaly & Outlier Detection

  • Flag points that don't fit "normal" — fraud, intrusion, defect, monitoring. Usually extreme class imbalance or no labels at all.
  • Statistical: z-score >3, IQR fences, Mahalanobis distance (accounts for covariance).
  • Isolation Forest: anomalies isolate in fewer random splits → short path length. Scales well, few assumptions.
  • One-Class SVM: learns a boundary around normal data.
  • LOF: local density vs neighbors — catches anomalies in variable-density regions.
  • Autoencoder: high reconstruction error = anomaly (unstructured data).

! Novelty (train on clean normals) vs outlier detection (contaminated training set) are different setups. Evaluate with PR-AUC / recall@budget, never accuracy.

Curse of Dimensionality

  • As dimensions grow, points spread out: volume explodes, data becomes sparse, and pairwise distances concentrate — nearest and farthest neighbor become nearly equidistant, so "similarity" loses meaning.
  • Hits distance-based methods hardest: kNN, k-means, RBF-SVM, clustering all degrade.
  • Data needed to cover the space grows exponentially with dimension.

Fixes: feature selection, PCA / embeddings, regularization, distance metrics learned for the task, or models less distance-reliant (trees). ! More features is not free — past a point they add noise and variance, not signal.

Supervised Setup & Loss Functions

y ~ f(x) + noise            # reality: unknown f + noise
ŷ = f(x; θ)                 # your model family + params
θ* = argmin_θ mean loss(y, f(x;θ))   # training

Every supervised model = function family + loss + optimizer. The family encodes the inductive bias; the loss encodes what you care about; the optimizer searches θ.

TaskTrain onEvaluate on
RegressionMSE (outlier-sensitive) / MAE (robust) / HuberRMSE, MAE, R²
Classificationcross-entropy / log-lossaccuracy, F1, AUC
  • ! Never train on accuracy: not differentiable, flat almost everywhere (zero gradient), and ignores confidence (0.51 vs 0.99 score alike). Optimize a smooth surrogate, evaluate on the business metric.
  • ! MSE + sigmoid = non-convex with saturated flat regions → training stalls. Cross-entropy keeps the gradient ∝ (p−y), strong signal exactly when confidently wrong; it's also the max-likelihood loss.
  • Align loss to the metric you're judged on as closely as you can — that's the recurring senior point.

Choosing an Algorithm (No Free Lunch)

NFL: averaged over all problems no algorithm beats another — superiority on one class is paid for on another. Practically: no universal best model, match inductive bias to the problem, and compare empirically via CV. Real problems aren't random, so strong priors exist.

Data / needReach for
Any baselinemajority/mean, then linear/logreg
TabularGBM (XGBoost/LightGBM); RF as low-tuning alt
Image / audio / big textneural nets (CNN/transformer)
Small high-dim (bag-of-words)SVM / naive Bayes
Need interpretable/regulatedlinear, shallow tree, GAM
  • Process: characterize (shape, size, linearity, latency, #labels) → baseline + simple → strong default for the data type → CV on the business metric → simplest model that clears the bar.
  • ! "Always use a neural net / XGBoost" is a junior tell — NN's bias is usually wrong for tabular data.

Naive Bayes & Generative vs Discriminative

P(y|x) ∝ P(y)·∏ P(xᵢ|y)   # "naive" = features cond. indep. | y
predict argmax_y  P(y)·∏ P(xᵢ|y)
  • Generative (naive Bayes, GMM, LDA): model P(x,y) / P(x|y) — can generate data, works with less data, handles missing features.
  • Discriminative (logreg, SVM, trees, NN): model P(y|x) / the boundary directly — usually higher accuracy with enough data.
  • Naive Bayes: fast, tiny data, strong on text/spam despite the crude independence assumption; well-calibrated ranking but probabilities often over-confident.
  • ! Zero-frequency: an unseen feature/class term zeroes the whole product → Laplace/add-one smoothing.
  • Variants: Multinomial (counts, text), Bernoulli (binary), Gaussian (continuous).

Probability Calibration

Calibrated = predicted probabilities match observed frequencies: of all "70%" cases, ~70% are truly positive. Distinct from ranking (AUC) and accuracy.

  • ! A model can rank perfectly (high AUC) yet be badly calibrated — right order, meaningless numbers. Calibration ≠ discrimination.
  • Care when the probability feeds a decision: expected-value (P(churn)·value > cost), risk/pricing (credit, insurance, medical), thresholding across shifting base rates, combining model outputs.
  • Care less for a pure ranking or one fixed threshold (top-k).
  • logreg is reasonably calibrated by construction (log-loss); trees / SVM / boosting often aren't.
  • Fix on a held-out set: Platt scaling (sigmoid) or isotonic regression. Check with a reliability diagram or Brier score.

Label Efficiency — Labels Are the Bottleneck

Labels are usually the scarcest, slowest, most expensive, noisiest ingredient. Label quality caps model quality — you can't learn a clean map from dirty targets. "Get more data" often means "get more labels," a cost/logistics problem more than an ML one.

ApproachIdea
Transfer learningfine-tune a pretrained model → far fewer labels
Semi-supervisedfew labels + lots of unlabeled data
Self-supervisedpretext task on unlabeled data, then fine-tune
Active learninglabel the model's most uncertain points first
Weak supervisionheuristics/rules generate approximate labels
  • ! A small clean label set often beats a large noisy one — measure label quality (multi-annotator agreement, adjudication).
  • Data strategy frequently matters more than model choice.

ML in Practice — Pitfalls

  • ! Baseline first, then the simplest model that clears it. Complexity is a cost you must justify.
  • ~80% of ML is data — cleaning, labeling, features. Modeling is the small, glamorous part.
  • ! Train/serve skew: the feature pipeline differs offline vs online → same code path both sides (feature store).
  • Drift: data/concept distribution shifts post-deploy → monitor inputs & metrics, alert, retrain. A model that tested great decays.
  • Reproducibility: fix seeds, version data + code + model, log experiments.
  • Optimize the business metric, not just the offline loss — validate with an A/B test, not just backtest.

★ Interview Playbook / Checklist

Frame any problem

  • ☐ State the task, label source, baseline, metric (from FP-vs-FN cost), validation scheme, deploy + monitor plan.
  • ☐ Confirm ML is even warranted — could a rule do it?

Diagnose scenarios

  • ☐ "Train 99% / val 70%" → overfit/variance → data, regularize, ↓capacity, early stop.
  • ☐ "Train & val both 75%" → underfit/bias → capacity, features, train longer.
  • ☐ "99% accuracy, useless" → imbalance → precision/recall/PR-AUC + threshold.
  • ☐ "Great offline, dead in prod" → leakage / train-serve skew / drift.
  • ☐ "Val loss turns up mid-training" → early stop / regularize.

Don't get caught

  • ☐ Every feature known at prediction time? (leakage guard)
  • ☐ Preprocessing fit inside CV folds; test touched once.
  • ☐ Scaled for kNN/SVM/linear/NN; not needed for trees.
  • ☐ Tabular → try GBM; huge unstructured → NN; interpretable/fast → linear.
  • ☐ Time series / grouped data → the right CV split.
