RAII & Smart Pointers

RAII: a resource's lifetime = an object's lifetime. Acquire in the ctor, release in the dtor. Cleanup is automatic and exception-safe — no manual delete, no finally.

TypeUse
unique_ptr<T>sole owner, move-only, zero overhead. Default choice.
shared_ptr<T>shared ownership; atomic refcount + control block ! (not free)
weak_ptr<T>non-owning observer; breaks shared_ptr cycles; .lock() to use
auto p = std::make_unique<Widget>(args);   // never `new`
auto s = std::make_shared<Widget>(args);   // 1 alloc (obj+ctrl)
std::unique_ptr<FILE, decltype(&fclose)>
    f(fopen(path,"r"), &fclose);           // custom deleter
  • Prefer make_unique/make_shared — exception-safe, one allocation.
  • Cycle = leak ! two shared_ptrs pointing at each other never hit refcount 0 → make one a weak_ptr.
  • Pass params by const T&/T*; take unique_ptr by value only to transfer ownership.

Rule of Five / Zero

The five special members: destructor, copy ctor, copy assign, move ctor, move assign.

struct Buf {
  Buf(const Buf&);            // copy ctor
  Buf& operator=(const Buf&); // copy assign
  Buf(Buf&&) noexcept;        // move ctor
  Buf& operator=(Buf&&) noexcept;
  ~Buf();                     // dtor
};
  • Rule of Zero prefer: own nothing raw — hold vector/string/unique_ptr members, write none of the five, let the compiler default them.
  • Rule of Five: if you write one (because you manage a raw resource), you almost always need all five.
  • Declaring a dtor/copy suppresses the implicit move ! → silent expensive copies.
  • Make move ops noexcept — else vector reallocation copies instead of moving !
  • =default / =delete to be explicit.

Move Semantics & Value Categories

  • lvalue = has a name/address; rvalue (prvalue/xvalue) = temporary, safe to pilfer.
  • std::move(x) is just a cast to T&& — it moves nothing; it lets the next overload move.
  • std::forward<T>(x) — perfect-forward inside a T&& template (forwarding ref).
template<class T>
void wrap(T&& x) {            // forwarding ref
  sink(std::forward<T>(x));   // keeps lvalue/rvalue-ness
}
auto v2 = std::move(v1);      // v1 now valid-but-unspecified
  • A moved-from object is valid but unspecified — only safe to destroy or reassign. Reading its value is a bug !
  • Don't return std::move(local) — it disables NRVO/copy-elision ! Just return local;.
  • Guaranteed copy elision (C++17) for prvalues: return Widget{...}; constructs in place.

const · constexpr · Casts

  • const-correctness: mark member fns const when they don't mutate; pass read-only params by const&.
  • const = runtime immutable; constexpr = usable at compile time; consteval = must run at compile time (C++20); constinit = static init, no dynamic-init order issues.
  • mutable = a member that stays writable through a const method (caches, mutexes).
CastUse
static_castrelated types, up/down (no check), numeric
dynamic_castchecked down-cast on polymorphic types (RTTI)
const_caststrip const — writing through it if the object is truly const is UB !
reinterpret_castbit reinterpret — aliasing/UB minefield !

Avoid C-style casts — they silently pick any of the above. Prefer enum class over plain enum.

STL Containers — pick & cost

ContainerLookupNote
vectorO(1) idxdefault; contiguous, cache-friendly; reserve()

  • Iterator/reference invalidation ! vector: any reallocation (push_back past cap) invalidates all; erase invalidates from the point on. map/list: only the erased node.
  • emplace_back(args...) constructs in place; push_back may copy/move.
  • vector<bool> is a bit-packed proxy — not a real container of bool !
  • Views (non-owning): string_view, span<T> — cheap params, but must not outlive the data !

Iterators & Algorithms

Categories: input · output · forward · bidirectional · random-access · contiguous (C++20).

std::sort(v.begin(), v.end());
std::sort(v.begin(), v.end(),
          [](auto& a, auto& b){ return a.k < b.k; });
auto it = std::find(v.begin(), v.end(), x);
auto n  = std::count_if(v.begin(), v.end(), pred);
std::transform(a.begin(), a.end(),
               std::back_inserter(out), f);

erase–remove idiom !

v.erase(std::remove_if(v.begin(), v.end(), pred),
        v.end());          // remove_* only reorders!
// C++20: std::erase_if(v, pred);
  • remove/remove_if don't erase — they shuffle kept elements front and return the new logical end.
  • std::sort is unstable — use stable_sort to preserve ties.
  • Beware the accumulate init-type trap: accumulate(v.begin(),v.end(), 0) sums as int even for doubles !

Templates & Concepts (C++20)

template<std::integral T>        // concept-constrained
T gcd(T a, T b){ return b? gcd(b, a%b) : a; }

template<class T>
concept Addable = requires(T a, T b){ a + b; };

if constexpr (std::is_pointer_v<T>) { ... }  // compile-time branch
  • Definitions live in headers — templates instantiate at the call site !
  • Concepts replace most SFINAE/enable_if — clearer errors, constrained overloads.
  • if constexpr discards the untaken branch at compile time (no instantiation).
  • Variadics + fold expressions (C++17): (... + args).
  • Watch template code bloat: each type combo = a fresh instantiation.
  • Need typename/template disambiguators for dependent names.

Lambdas & std::function

int base = 10;
auto f = [base](int x){ return x + base; };  // capture by value
auto g = [&](int x){ total += x; };          // capture by ref !
auto h = [p = std::move(ptr)]{ use(*p); };   // init-capture (C++14)
auto gen = [](auto x){ return x*x; };        // generic (C++14)
  • Capture by ref only if the lambda won't outlive the referent — else dangling !
  • Capturing this captures the pointer; the object must outlive the lambda. Use [*this] (C++17) to copy.
  • [=] on a member fn captures this, not the members — surprise dangling !
  • std::function = type erasure → heap alloc + indirect call. Prefer a template/auto param on hot paths.
  • Prefer lambdas over std::bind.

Polymorphism & the vtable

flowchart LR obj["Derived object
[vptr | fields]"] --> vt["vtable (per class)"] vt --> f1["&Derived::foo"] vt --> f2["&Base::bar"]

Each polymorphic object stores a hidden vptr → its class vtable of function pointers. A virtual call = load vptr, index, indirect call (one extra indirection, defeats inlining).

  • Virtual destructor on any class deleted through a base pointer ! else UB / partial destruction.
  • Object slicing ! copying a Derived into a Base value drops the derived part. Store base */references, never by value.
  • Mark overrides override; use final to seal.
  • Don't call virtuals from ctors/dtors — dispatch resolves to the current type, not the derived one !

Exceptions & Error Handling

Safety guarantees

LevelMeaning
nothrownever throws (noexcept)
strongcommit-or-rollback; state unchanged on throw
basicvalid but unspecified state; no leaks
nonecan leak/corrupt — avoid
  • RAII gives exception safety for free — unwinding runs dtors.
  • Never let a destructor throw ! → std::terminate during unwinding.
  • catch (const std::exception& e) — by const ref, never by value (slicing).
  • Zero-cost model: no penalty on the happy path; throwing is expensive — not for control flow.
  • Alternatives: std::optional (maybe), std::expected<T,E> (C++23), std::error_code. -fno-exceptions builds exist (embedded).

Memory Model & Atomics

std::atomic<int> cnt{0};
cnt.fetch_add(1, std::memory_order_relaxed); // counter: no ordering needed

// publish pattern:
data = compute();
flag.store(true, std::memory_order_release);
// reader:
if (flag.load(std::memory_order_acquire)) use(data);
OrderMeaning
seq_cstdefault; single total order; safest, priciest
acquire/releasepairwise publish/consume of data
relaxedatomicity only, no ordering (counters)
  • release store synchronizes-with an acquire load of the same var → establishes happens-before.
  • compare_exchange_weak in a loop (may spuriously fail); watch the ABA problem !
  • volatile is not atomic and gives no cross-thread ordering !

Undefined Behaviour — catalog

UB = the optimizer assumes it never happens and rewrites your code around it. Not "works differently" — anything may happen !

UBTrigger
use-after-free / danglingref/ptr/iterator/string_view outlives data
out-of-boundsv[i] past end, bad pointer math
uninitialised readreading a member never set
signed overflowINT_MAX + 1
data raceunsynchronised concurrent write
invalid downcaststatic_cast to wrong derived
strict aliasingread via unrelated pointer type
shift ≥ width / by negativex << 32 on 32-bit int

Catch it: ASan (memory), UBSan (-fsanitize=undefined), TSan (races), MSan (uninit), valgrind. Turn on -Wall -Wextra.

Compilation · Headers · ODR · Build

Pipeline: preprocess → compile (per TU) → link. Each .cpp is a translation unit.

  • ODR: every entity defined once across the program (inline/templates exempt but definitions must be identical) !
  • Headers: declarations + inline/constexpr/templates. #pragma once (or include guards).
  • Never using namespace in a header !
  • inline = "multiple identical definitions OK" (linkage), not just an inlining hint.
  • static/anonymous namespace = internal linkage (TU-local).
  • PIMPL hides implementation, cuts rebuild coupling & compile time.
  • extern "C" disables name-mangling for C interop.
# fast, strict dev build
g++ -std=c++20 -Wall -Wextra -O2 \
    -fsanitize=address,undefined app.cpp

Speed: forward-declare, PCH, unity builds, C++20 modules.

★ Code Review Checklist

Memory & ownership

  • ☐ No raw new/delete; ownership expressed via smart pointers/containers.
  • ☐ Right pointer: unique_ptr (sole) vs shared_ptr (shared) vs weak_ptr (break cycle).
  • ☐ RAII for every resource (file, socket, lock, handle); no leak/double-free path.
  • ☐ No returning a ref/pointer to a local or expired temporary.

Special members & const

  • ☐ Rule of Zero where possible; if any of the five, all correct; move ops noexcept.
  • ☐ No accidental deep copies of heavy objects (pass const& / std::move).
  • ☐ const-correct APIs; no const_cast/C-casts; enum class; no narrowing.

Lifetime & UB traps

  • ☐ No dangling string_view/span; no use-after-move; members initialised.
  • ☐ No iterator/reference invalidation across a container mutation.

Concurrency & errors

  • ☐ Shared state guarded; consistent lock order; correct memory-order on atomics.
  • ☐ Exception safety (strong/basic) held; no throwing dtor; noexcept accurate.

STL, headers & gates

  • ☐ Right container for the access pattern; algorithm over hand-rolled loop; reserve where sizes known.
  • ☐ string_view/span params over owning copies where non-owning.
  • ☐ Include-what-you-use; no ODR violation; no using namespace in headers.
  • ☐ clang-format clean; clang-tidy / -Wall -Wextra -Werror; ASan/UBSan/TSan on tests.
