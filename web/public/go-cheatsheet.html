Goroutines & the Scheduler (G·M·P)

flowchart TD G["Goroutines (G)
2KB stack, grows"] --> P["Logical procs (P)
= GOMAXPROCS"] P --> M["OS threads (M)"] M --> CPU["CPU cores"] P -.->|"local runqueue
empty → steal"| P2["other P"]

M:N scheduler — many G multiplexed onto few M via P. Blocking syscall → M parks, P hands off to a fresh M (work continues). Preemptive since 1.14 (async, signal-based). 1.25 runtime is cgroup-aware: GOMAXPROCS respects container CPU limits natively.

  • go f() ≈ cheap (µs, 2KB). But every goroutine needs an answer to "how does this end" — closed chan, cancelled ctx, or finite loop. No answer = leak !
  • runtime.Gosched() yields; GOMAXPROCS(n) caps parallelism (default NumCPU).

close — who & rules

  • The sender closes, never the receiver. One closer only.
  • send on closed = panic !; close of closed = panic !; recv on closed = zero value + ok==false (drains buffer first).
  • v, ok := <-ch tests closed; for v := range ch exits when closed.
select {
case v := <-ch:      use(v)
case out <- x:        // send
case <-ctx.Done():    return ctx.Err()
default:              // non-blocking
}
  • select picks a ready case at random; default makes it non-blocking.

Memory Model & Races

  • A data race (concurrent access, ≥1 write, no synchronisation) is undefined behaviour ! — not "eventually consistent". Can corrupt, not just stale-read.
  • No happens-before edge → writes from one goroutine may be invisible/reordered in another.

happens-before sources

EdgeEstablishes
chan send → corresponding recvsend (and prior writes) visible to receiver
chan close → recv that observes itsame
mu.Unlock() → next mu.Lock()critical-section writes published
sync/atomic store → loadrelease/acquire ordering
once.Do returninit writes visible to all callers

Always run go test -race. The detector is sound (no false positives) but only flags races it observes at runtime — exercise the concurrent paths.

Slices, Arrays & Maps

Slice = (ptr, len, cap) header

s := []int{1,2,3}
t := s[:2]          // shares backing array !
t = append(t, 9)    // OVERWRITES s[2] if cap allows !
u := append([]int{}, s...) // safe copy
b := make([]byte, n) // pre-size to avoid regrowth
  • append reallocates only when len > cap; until then writes alias the original !
  • Re-slicing keeps the whole backing array alive (memory leak holding a small slice of a huge buffer) ! — copy out.
  • Use the 3-index slice s[a:b:c] to cap and force a fresh array on next append.

Maps

  • Write to a nil map panics !; read of nil map is fine (zero value). m := map[K]V{} or make.
  • Iteration order is randomised — never rely on it; sort keys for determinism.
  • Concurrent map read+write panics ("fatal error: concurrent map ...", not recoverable) ! — guard with a Mutex or sync.Map.
  • v, ok := m[k] distinguishes "absent" from "zero value".

Interfaces & nil

  • An interface value is a (type, value) tuple. It's nil only when both are nil.

The typed-nil trap !

func do() error {
  var e *MyErr = nil
  return e            // (*MyErr, nil) — NOT nil iface !
}
if do() != nil { /* ALWAYS true */ }
// Fix: return nil explicitly, or
//   if e == nil { return nil }
  • Assertion: v, ok := x.(T) (safe); x.(T) without ok panics on mismatch !
  • switch v := x.(type) { case T: ... } for multi-type dispatch.
  • any = alias for interface{} (1.18). Accept interfaces, return concrete types. Keep interfaces small (1–2 methods) and define them on the consumer side.

Errors

  • Errors are values, returned as the last result. No exceptions. if err != nil { return ... } — handle or propagate, don't ignore.
  • Wrap with %w to preserve the chain: fmt.Errorf("load %s: %w", id, err).
  • errors.Is(err, ErrNotFound) — sentinel match through the chain.
  • errors.As(err, &target) — extract a typed error from the chain.
  • Sentinels: var ErrX = errors.New("..."). Custom: implement Error() string (+ Unwrap()).

panic / recover — boundaries only

defer func() {
  if r := recover(); r != nil {
    log.Printf("recovered: %v", r)
  }
}()
  • recover works only inside a deferred func !. Use for true invariants / server top-of-handler — not control flow.
  • A panic in a goroutine with no recover crashes the whole process !

defer / panic / recover Timing

  • Deferred calls run LIFO at function return (not block/scope end) — including on panic-unwind.
  • Args are evaluated at the defer statement, body runs later !:
x := 1
defer fmt.Println(x)   // prints 1
x = 2                  // (captured at defer time)

// Closure sees the LATER value:
defer func(){ fmt.Println(x) }() // prints 2

Named returns + defer

func f() (err error) {
  defer func(){ if err != nil { err = wrap(err) } }()
  return doThing()      // defer can mutate err !
}

for _, p := range paths {
  f, _ := os.Open(p)

Receivers — value vs pointer

ReceiverEffect
func (t T) M()operates on a copy — mutations don't persist
func (t *T) M()mutates the original; required to change state
  • Use a pointer receiver to mutate, for large structs (avoid copy), or for any type holding a sync.Mutex ! (a value receiver copies the lock).
  • Be consistent: if any method needs a pointer receiver, give them all pointer receivers.

Method sets & interfaces !

  • *T's method set includes both value- and pointer-receiver methods; T's includes only value-receiver ones.
  • So if M has a pointer receiver, only *T satisfies the interface — a T value won't. (And you can't take the address of a map element / non-addressable value to call it.)

Generics (1.18+) & Iterators

func Map[T, U any](s []T, f func(T) U) []U {
  r := make([]U, len(s))
  for i, v := range s { r[i] = f(v) }
  return r
}
type Number interface{ ~int | ~float64 }
func Sum[T Number](xs []T) T { ... }
  • Constraints are interfaces; ~int = "any type whose underlying type is int". comparable for map keys / ==.
  • Type inference usually lets you omit explicit type args.
  • Don't over-reach — if one concrete type or a plain interface works, skip generics. They don't monomorphise like Rust/C++ (dictionary/shape-based) so they're not always faster.
  • (1.23) range-over-func iterators: iter.Seq[T] / iter.Seq2[K,V] drive for x := range myIter.

Runtime, GC & Performance

  • Concurrent tri-colour mark-sweep GC, non-generational, sub-ms STW pauses. You tune frequency, not pauses.
  • GOGC (default 100) — grow heap to 2× live set before next GC; raise to trade RAM for fewer GCs.
  • GOMEMLIMIT (1.19) — soft heap ceiling; turns OOM-kills into back-pressure (GC works harder near the limit).

Allocation = the latency tax

  • Escape analysis: values that outlive their frame escape to the heap. go build -gcflags=-m shows decisions.
  • Levers: pass small structs by value (stay on stack); pre-size slices/maps; sync.Pool for transient buffers; strings.Builder over +=.
  • Measure first — refactors that "look" alloc-free can defeat inlining and regress. pprof heap + -benchmem.

★ Code Review Checklist

Receiver type — value vs pointer

  • ☐ Pointer receiver where the method must mutate (value receiver silently no-ops).
  • ☐ No value receiver on a type holding a sync.Mutex/WaitGroup — copies the lock !
  • ☐ Receiver kind consistent across all methods of the type.

Goroutine / closure capture

  • ☐ Loop var captured by a goroutine/closure — shared-var bug pre-1.22; per-iteration & safe in 1.22+, but confirm the module's go directive !
  • ☐ Loop value passed as an arg / re-shadowed (v := v) where older semantics apply.

Concurrency / shared state

  • ☐ Every var touched by >1 goroutine (maps, slices, counters, flags) is read/written under the same lock or via atomic.
  • ☐ Map access guarded; no struct-with-mutex copies; -race clean in CI.

Error handling

  • ☐ No dropped errors (_ = or unchecked); wrap with %w where a caller inspects.
  • ☐ defer x.Close() error checked where it matters (writers/flush).

Nil

  • ☐ Nil-pointer deref guarded; no write to a nil map.
  • ☐ No typed-nil returned as an error/interface (!= nil always true) !; nil channel/func paths considered.

Channels

  • ☐ Direction-typed params; buffering size justified.
  • ☐ Exactly one closer (the sender); no send-on-closed / double-close; select has default/ctx where non-blocking intended.

Defer timing

  • ☐ Fires at function return — present on every early-return path; not stacking inside a loop body unless intended !
  • ☐ Deferred-arg value captured at the defer point is the one you mean; per-iteration cleanup extracted to a helper.

Goroutine leak — blocked forever

No receiver / no close ⇒ producer parks forever, its stack & captured memory never freed. Fix: ctx cancellation, a done channel, buffered/closed channels, or select with <-ctx.Done(). Every go needs a defined exit.
