REST Resource Modeling

GET    /v1/orders?status=paid&limit=20
POST   /v1/orders
GET    /v1/orders/{id}
PATCH  /v1/orders/{id}
DELETE /v1/orders/{id}
GET    /v1/orders/{id}/items   // nested
  • Nouns, plural, not verbs. ! Not /getOrder or /createOrder.
  • Stateless; the URI names a resource; the method is the verb.
  • Actions that don't fit CRUD → sub-resource or POST /orders/{id}/refunds.

Idempotency Keys

POST /v1/payments
Idempotency-Key: 8f3a-…-b21   // client-generated
{ "amount": 4200, "currency": "usd" }
  • Server stores key → result. Retry with same key → returns the SAME response, no double charge.
  • Pair with backoff + jitter on retries; dedup on the consumer side.
  • ! "Exactly once" = at-least-once delivery + idempotent handling.

Caching

GET /v1/orders/123
→ ETag: "a1b2"
   Cache-Control: private, max-age=60

GET /v1/orders/123
   If-None-Match: "a1b2"
→ 304 Not Modified   // no body, cheap
  • ETag + conditional GET saves bandwidth. Compress (gzip/br). Prefer field selection over huge payloads.
  • Avoid chatty APIs — batch or expand related resources.

Webhooks

sequenceDiagram participant S as Your API participant C as Consumer S->>C: POST /hook (event + HMAC sig) C-->>S: 2xx (ack fast) Note over S,C: no 2xx → retry w/ backoff → DLQ
  • Sign payloads (HMAC) so consumers verify authenticity.
  • Retry w/ exponential backoff; at-least-once → consumer dedups on event ID.
  • ! Ordering NOT guaranteed. Ack fast, process async. Guard against SSRF.

API Security — OWASP Top Hits

  • ! BOLA/IDOR (#1): GET /orders/{id} without checking the caller OWNS it → check object-level authz every time.
  • Mass assignment: binding {"role":"admin"} → allowlist writable fields.
  • Excessive data exposure: don't return internal/PII fields "just because."
  • Validate all input; TLS everywhere; no secrets in URLs; CORS locked to known origins; rate-limit everything.

☐ API Design-Review Checklist

  • ☐ Resources are nouns; methods carry the verb; consistent naming.
  • ☐ Right status codes; consistent error model (problem+json).
  • ☐ Pagination on every collection (cursor for scale).
  • ☐ Idempotency for POST/payments; safe retries.
  • ☐ AuthN + object-level authZ on every endpoint (BOLA).
  • ☐ Rate limited; input validated; no data over-exposure.
  • ☐ Versioning + backward-compat plan; only additive changes.
  • ☐ OpenAPI contract, examples, changelog; caching where it helps.
  • ☐ Right style: REST public · gRPC internal · GraphQL flexible clients · webhooks for events.
