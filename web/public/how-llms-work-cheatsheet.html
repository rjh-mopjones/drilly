The Big Picture

  • Single objective: predict the next token. That's the whole thing — reasoning, code, translation all emerge from it.
  • Transformer (2017) replaced RNN/LSTM: parallel over the sequence + attention for long-range dependency (no recurrent bottleneck, no vanishing state).
  • Decoder-only (GPT) = generation (causal); encoder-only (BERT) = understanding (bidirectional); encoder-decoder (T5) = seq2seq.
  • Knowledge lives in the weights (mostly FFN); there's no database. Hence hallucination ! — it interpolates plausible text, not retrieves facts.
  • Pipeline: text → tokens → embed+pos → N blocks → logits → sample.

Tokenization (BPE)

  • Text → integer IDs via a subword vocab (byte-level BPE / SentencePiece), V ≈ 30k–130k.
  • BPE build: start from bytes/chars, repeatedly merge the most frequent adjacent pair into a new token until vocab full. Greedy, frequency-driven.
  • Byte-level → no OOV ever: worst case falls back to raw bytes.
  • Not part of the neural net — a deterministic pre/post-processing step.

  • ! Tokens ≠ words: " apple", "apple", "App" are distinct IDs (leading space matters).
  • ! "strawberry": model sees token IDs, not letters → can't count the r's. Same reason arithmetic is fragile (numbers split oddly).
  • ! A trailing space/newline changes the token stream → can change output. Code & non-English burn more tokens (less merged).
  • Tokens are the unit of cost and context, not chars/words.

Embeddings & Unembedding

E: (V, D) lookup by token id → (T, D)
meaning = geometry: nearby vectors ≈ similar use
  • Embeddings are learned (random init, trained by backprop), not hand-designed. Turning discrete IDs into continuous vectors is what makes the whole thing differentiable.
  • Input embedding is static/context-free; the transformer produces contextual representations. ! The row for "apple" does not yet know fruit-vs-company — attention disambiguates.
  • LM head / unembedding: (D, V), maps final vector → one logit per vocab token.
  • Weight tying: reuse E (transposed) as the LM head → saves V·D params, often helps.
  • Compare embeddings with cosine similarity (direction, scale-invariant), not Euclidean.
  • Embedding params = V·D: dominant in small models, a rounding error in large ones.

Positional Encodings

  • Attention is a set op (permutation-invariant) — without position, "dog bites man" = "man bites dog". ! Must inject order.

  • RoPE is applied to Q and K inside attention, not added to embeddings — that's what makes it relative and KV-cache-friendly.
  • Extend context: RoPE interpolation/scaling — compress position frequencies so a short-trained model handles longer sequences.
  • ! Causal mask does not encode position — it only blocks the future; a permutation of past tokens is still indistinguishable without pos enc.

Attention (QKV)

Q = x·Wq   K = x·Wk   V = x·Wv
Attn = softmax(Q·Kᵀ / √d_k) · V
flowchart LR X["token x"] --> Q & K & V Q --> S["scores Q·Kᵀ"] K --> S S --> W["softmax weights"] W --> O["Σ weight·V"] V --> O
  • Q asks, K advertises, dot = relevance, softmax = weights, out = weighted average of V (soft dictionary lookup).
  • ! /√d_k: dot products grow with d_k; without scaling, softmax saturates → near-zero gradients (one-hot).
  • ! In self-attention Q,K,V are three projections of the same input, not separate inputs.
  • Project to Q/K/V (not raw dots) so the model learns what to match on. Remove softmax → just a linear map, no selectivity.

Masking: causal · cross · padding

  • Self-attn: Q,K,V from one sequence. Cross-attn: Q from decoder, K/V from encoder (seq2seq only).
  • Causal mask: set future scores to −∞ before softmax so token t can't see >t. ! Enables training on all positions at once (each predicts its next).
scores = Q·Kᵀ/√d_k
scores = scores.masked_fill(future, -inf)
w = softmax(scores)   # future → exp(-inf)=0
  • Mask before softmax, not after: zeroing after softmax breaks normalization (rows wouldn't sum to 1). !
  • Use large negative (-1e9) ≈ −∞ in practice (fp-safe).
  • Padding mask hides batch pad tokens (data-dependent); orthogonal to the causal mask — both get OR'd into scores.
  • ! Bug: loss → ~0 almost instantly = label leakage, mask off-by-one letting a token see its own target.

Multi-Head Attention

d_k = D / h
per head: Q,K,V are (T, d_k)
concat h heads → (T, D), then · W_o
  • h heads of dim d_k = D/h run in parallel; each learns a different relation (syntax, coreference, position…), then concat + output projection W_o mixes them.
  • Same FLOPs as one big head but multiple representation subspaces → strictly more expressive.
  • Computed as one batched matmul (reshape to (B, h, T, d_k)), not a Python loop.
  • ! W_o is not optional — without it the concatenated heads are never combined.
  • Attention params ≈ 4·D² (Wq,Wk,Wv,Wo each D×D).
  • e.g. D=512, h=8 → d_k=64.

The Transformer Block (pre-LN)

x = x + MHA(LN(x))    # sublayer 1: mix tokens
x = x + FFN(LN(x))    # sublayer 2: think per-token
  • Two sublayers, each wrapped in norm + residual. Shape (B,T,D) in = out → N identical blocks stack.
  • Attention moves info between tokens; FFN computes on each token. Order matters — gather context, then process it.
  • Blocks share shape, not weights — each has its own params (early=syntax, late=semantics).
  • ! Residual is x + Sub(x) — it adds, never overwrites. The residual stream is a running accumulator.

FFN & Activations

FFN(x) = W2 · act(W1·x + b1) + b2
d_ff = 4·D   (W1: D→4D,  W2: 4D→D)
  • Position-wise: same weights per token, no cross-token mixing — that's attention's job.
  • ! Most params live here: FFN ≈ 8·D²/layer vs attention 4·D² — roughly 2/3 of non-embedding weights.
  • Interpreted as key-value memory: W1 rows detect patterns (keys), W2 rows emit stored features (values) — where "facts" sit.
  • Activation: ReLU → GELU (GPT/BERT) → SwiGLU (LLaMA/PaLM, gated, extra matrix, ~8/3·D hidden to match params).
  • Target of MoE: swap the one dense FFN for many experts.

Normalization & Residuals

LayerNorm: γ·(x−μ)/√(σ²+ε) + β   # over D features
RMSNorm:   γ· x /√(mean(x²)+ε)   # no mean/bias
  • LayerNorm normalizes each token across its D features — independent of batch/seq. ! Not BatchNorm (which couples examples).
  • RMSNorm drops mean-centering + bias → cheaper, ~same quality; modern default (LLaMA).
  • pre-LN x+Sub(LN(x)) keeps a clean identity highway → trains deep & stable, tolerates higher LR. post-LN (orig.) needs warmup, fragile at depth. !
  • Residual grad = 1 + dSub/dx: the 1 is the gradient highway that stops vanishing/exploding across N layers.
  • Pre-LN never normalizes the main path → stream magnitude grows → a final LayerNorm before the LM head. Count = 2N+1 norms.

Full Architecture & Param Count

flowchart TB E["embed + pos (B,T,D)"] --> B["block × N"] B --> F["final norm"] F --> H["LM head (D,V)"] H --> L["logits (B,T,V)"] 
params ≈ V·D            # embedding (+ tied head)
      + N·(4·D² + 8·D²) # attn + FFN per block
      = V·D + 12·N·D²
  • FFN (8D²) dominates each layer; embeddings dominate only small models / huge vocab.
  • Output is logits (B,T,V) — raw scores, not probabilities. !
  • Depth (N) vs width (D): both help with diminishing returns; taller = more sequential compute, wider = more parallel.

The Forward Pass (shapes)

ids            (B, T)
 → embed+pos   (B, T, D)
 → N blocks    (B, T, D)   # shape preserved
 → final norm  (B, T, D)
 → LM head     (B, T, V)   # logits
generation: take LAST position → (V,)
  • At training, all T positions are scored in one pass (causal mask) — one forward = T next-token predictions.
  • At generation, only the last position's logits matter; earlier ones already committed.
  • Inference cost ≈ 2·N_params FLOPs per token (fwd only; training ≈ 6·N_params, adds backward).

Sampling & Decoding

p = softmax(logits / T)     # T = temperature
top-k: keep k highest, renorm
top-p: smallest set with Σp ≥ p (nucleus)
min-p: keep p_i ≥ p·max(p)
  • Two stages: shape the distribution (temp, truncate) then pick (argmax = greedy, or random draw = sampling).
  • T→0 ≈ greedy (deterministic); T=1 honest distribution; T>1 flatter/wilder. Temperature only reshapes; randomness is in the draw.
  • top-k = fixed count; top-p = adaptive count (1 token on a peaked dist, many on a flat one). Truncation clips the garbage tail before rolling.
  • Repetition/frequency penalty: subtract from logits of seen tokens to break loops.
  • ! Same prompt → different answers = sampling, not the weights. Even T=0 isn't fully deterministic: GPU reduction order, batch composition, MoE routing flip near-tie argmaxes.
  • Beam search maximizes sequence likelihood — good for translation, bland/degenerate for open chat.

Autoregressive Gen & KV Cache

loop: forward → last logits → sample
      → append token → repeat until EOS/max
  • Naive: re-encode the whole prefix each step → recomputes unchanged K,V → O(n²) waste.
  • KV cache: a token's K,V depend only on itself (+pos) and never change → store per layer, reuse. New step computes Q/K/V for one token, attends over the cache. ! Pure speedup, identical output.
  • ! Cache stores K,V tensors (not text/logits). Q is never cached — a past Q is never reused.
  • Cache size = 2 · N · T · n_kv_heads · d_head · bytes → grows linearly; long chats are memory-bound. ! It spends memory to save compute.

Pretraining

objective: predict next token
loss = −log p_model(true next)   # cross-entropy
      averaged over all positions
  • Self-supervised: the text is its own label (next token = target). No human annotation needed → scales to trillions of tokens.
  • Produces a base model: a fluent text-completer, ! not an assistant. Ask it a question and it may continue with more questions.
  • Loss floor = irreducible entropy of language; you approach it, never hit 0.
  • Data: web + code + books, heavily filtered/deduped. Roughly <1 epoch (each token seen ~once).

Training Mechanics

  • One step = forward (compute loss) → backward (backprop: chain rule, reuse cached activations, one dL/dW per weight) → optimizer update.
  • ! Gradient descent updates the weight matrices (E, Wq/k/v/o, FFN, norms) — not activations, not the data. Classic gotcha.
  • Backprop doesn't "send data backward"; it propagates gradients. Adam consumes backprop's output, doesn't replace it.
W = W − lr · dL/dW           # SGD
AdamW: per-param adaptive step + decoupled decay
  • AdamW not SGD: adaptive per-param steps handle the ill-conditioned transformer loss surface.
  • LR: warmup (ramp from ~0) then cosine/linear decay. Grad accumulation fakes a huge batch on limited VRAM. bf16 mixed precision.

Scaling Laws & Compute

loss ~ N^-a  (smooth power law in N, D, C)
FLOPs_train ≈ 6 · N · D      # params × tokens
FLOPs_infer ≈ 2 · N / token
  • Loss falls as a straight line on log-log vs params N, data D, compute C → fit small, extrapolate big before spending.
  • Chinchilla: for a fixed C, scale N and D together — ~20 tokens/param is compute-optimal. ! GPT-3-era models were under-trained (too big, too little data).
  • ! Returns diminish but don't vanish — irreducible floor, never 0.
  • Emergent abilities: appear sharply above scale — but many vanish under smoother metrics (possible measurement artifact, treat with skepticism).
  • Training compute = one-time, enormous; inference = recurring, per-request.

Post-Training: SFT

  • ! Base ≠ chat. Post-training reshapes the base distribution toward preferred behavior.
  • SFT (supervised fine-tuning): next-token training on curated (instruction, response) demos + a chat template (role tokens like <|user|>/<|assistant|>).
  • Teaches "when I see a user turn, produce an assistant turn." Coarse alignment move.
  • Limitation: demos only show good behavior, never what's bad — and humans find it easier to compare two answers than write the ideal one → motivates preference tuning next.
  • Refusals/safety are largely learned behavior installed here + in preference tuning, not just data filtering.

Post-Training: RLHF / DPO

  • Preference data: (prompt, chosen, rejected) — humans rank two model outputs.
  • RLHF: train a reward model (LLM + scalar head) on prefs → optimize policy with PPO to maximize reward − KL penalty.
  • ! KL penalty job = stop reward hacking/collapse: keep policy near the frozen SFT reference so it stays fluent.
  • DPO: closed-form classification loss straight on pairs — no reward model, no RL loop. Simpler, popular. Not RL.

Efficiency & Modern Architecture

Everything fights two costs: attention O(n²) compute + KV cache memory.

TrickFixes
FlashAttentionexact; tiles + online softmax so n×n never hits slow HBM !
MQAall Q heads share 1 K/V head → smallest cache
GQAK/V shared in groups; MHA↔MQA middle ground
MoEroute token to top-k of many expert FFNs
RoPE scalinglonger context (extrapolate position)
Sliding windowattend a local window → linear
Quantizationint8/int4 weights → less memory+bandwidth
  • ! FlashAttn is exact, not an approximation — win is IO, not dropped terms.
  • ! GQA/MQA main win = smaller KV cache (decode is memory-bound), not FLOPs.
  • ! MoE = sparse activation: huge total params, few active/token → more params at ~same FLOPs/token.
  • ! Quantization casts existing weights; it doesn't shrink the param count or retrain.

★ Interview Playbook

Must be able to say cold

  • ☐ Attention from scratch: Q asks, K advertises, softmax-weighted V; why /√d_k.
  • ☐ Causal mask: −∞ before softmax, no peeking at the token you must predict.
  • ☐ Walk a token: tokenize → embed+pos → N pre-LN blocks → final norm → logits → sample.
  • ☐ Attention mixes tokens; FFN computes per-token & holds most params (8D² vs 4D²).
  • ☐ Residual = gradient highway (adds, never overwrites); pre-LN > post-LN at depth.

The classic probes

  • ☐ "strawberry" → it sees token IDs, not letters.
  • ☐ Same prompt varies → sampling; even T=0 drifts (float/batch/MoE).
  • ☐ What training updates → the weight matrices, via loss gradient (not data/activations).
  • ☐ Base vs chat → pretraining vs SFT + RLHF/DPO.
  • ☐ KV cache → cache K,V (not Q, not text); linear memory; prefill vs decode.
  • ☐ params ≈ V·D + 12·N·D²; train FLOPs ≈ 6ND; Chinchilla ≈ 20 tok/param.
