How to read & print

  • Baseline: Kotlin 2.x (K2 compiler), JVM target. Coroutines = kotlinx-coroutines. Most idioms are stable since 1.5.
  • Senior focus: null safety · coroutines & structured concurrency · variance · delegation · Java interop. Last 2 cards = review checklist + spot-the-bug.
  • Print: Ctrl/⌘-P → A4, margins None, scale 100%, background graphics on (keeps colour bars). 4 columns built-in.

val / var, Properties, Defaults

  • val = immutable binding (not deep immutability); var = reassignable. val xs = mutableListOf(); xs.add(1) is legal !
  • Kotlin inverts Java defaults: val>var, final>open, non-null>nullable, public but internal available. Defaults encode a design opinion, not just terseness.
  • Everything is an expression: if/when/try return values — no ternary operator.
val x = if (cond) a else b       // if is expr
var age: Int = 0
  get() = field                  // backing field
  set(v) { field = maxOf(0, v) } // custom setter
class C { private set }          // property w/ private setter
  • Property = getter (+ setter for var) + optional backing field. Not a bare Java field. JVM val name → getName().
  • const val = compile-time constant (top-level or in companion), primitives/String only.

Null Safety

Nullability is part of the type. String and String? are distinct types; most NPEs become compile errors.

OpMeaning
?.safe call — short-circuits to null: a?.b?.c
?:Elvis — fallback: x ?: default; RHS can return/throw
!!assert non-null; throws NPE if null !
?.let{}run block only if non-null
val len = name?.length ?: 0
val u = user ?: throw NotFound()   // guard via Elvis
obj?.let { use(it) }               // null-guarded

lateinit & platform types !

  • lateinit var x: String — non-null, non-primitive, var only. Access before init → UninitializedPropertyAccessException. Check ::x.isInitialized.
  • Java call → platform type String!: compiler accepts as String OR String? with no warning. NPE at runtime if wrong. Wrap Java APIs at the boundary with explicit T?.
  • Every !! is you overriding the type checker — treat as a future bug report. Prefer requireNotNull(x)/checkNotNull.

Data & Sealed Classes

data class User(val id: Int, val name: String)
// generates equals/hashCode/toString/copy/componentN
val (id, name) = user             // destructuring
val u2 = user.copy(name = "bob")  // non-destructive update
  • Data class: value objects/DTOs. ≥1 primary-ctor param; can't be abstract/open. Use val props — var in a data class + Set/Map key mutates the hash → lost element !
  • equals/hashCode use only primary-ctor props — body props are ignored !

Sealed = closed hierarchy

sealed interface Result<out T>
data class Ok<T>(val v: T) : Result<T>
data class Err(val e: Throwable) : Result<Nothing>

val msg = when (r) {              // exhaustive: no else
  is Ok  -> r.v.toString()
  is Err -> r.e.message
}
  • Sealed enumerates subtypes (each carries own state); enum enumerates instances. when over a sealed type is compiler-checked exhaustive → drop else so a new subtype is a compile error.

Extension Functions

fun String.isEmail() = contains("@")
"a@b.com".isEmail()               // reads like a member
fun <T> List<T>.second() = this[1]
  • Add methods without subclassing. JVM compiles to a static method with receiver as first arg — no runtime cost, no reflection.
  • Resolved statically on the declared type, not the runtime type — no virtual dispatch !
  • Members win: if a member with the same signature exists, the extension is shadowed and never called !
  • Extension on nullable receiver is valid: fun String?.orEmpty().
  • Also: extension properties (no backing field — getter only), and member extensions (scoped to a class).

when, Smart Casts, Destructuring

when (x) {
  is String -> x.length          // smart-cast to String
  in 1..10  -> "small"
  0, 1      -> "bit"
  else      -> "other"
}
when {                            // no subject = if/else chain
  a > b -> hi()
  else  -> lo()
}
  • Smart cast: after is/!= null, the compiler narrows the type inside the branch — no explicit cast. Blocked on var that could change between check and use (esp. mutable props / other threads) ! — copy to a val first.
  • Destructuring uses componentN(): data classes, Pair/Triple, Map.Entry. for ((k, v) in map). Positional, not by name ! — reorder props → silent bug.
  • as? = safe cast → null on mismatch; as = throws ClassCastException.

Coroutines — Builders & Dispatchers

suspend is a compile-time transform: each suspend fn is rewritten into a state machine taking a hidden Continuation. No green threads — just callbacks that read sequentially. Thousands per thread.

BuilderReturnsUse
launchJobfire-and-forget
asyncDeferred<T>parallel result, .await()
withContext(d)Tswitch dispatcher, get value
runBlockingTblock thread — main/tests only !
val a = async { fetchA() }        // both run
val b = async { fetchB() }        // concurrently
val sum = a.await() + b.await()
val data = withContext(Dispatchers.IO) { db.load() }
  • Dispatchers: Main (UI), IO (large pool, blocking-friendly), Default (CPU, sized to cores), Unconfined (avoid).
  • Coroutine may resume on a different thread — thread-locals are a footgun ! Use context, not ThreadLocal.

Structured Concurrency & Cancellation

  • Every coroutine is a child of a scope's Job → jobs form a tree. Cancel scope ⇒ cancel all descendants. Child failure cancels siblings (unless SupervisorJob). Leaks nearly impossible if you avoid GlobalScope !
  • Scopes tied to lifetime: viewModelScope, lifecycleScope, or CoroutineScope(Job()+Dispatchers.IO).

Cancellation is cooperative !

while (isActive) { work(); yield() }   // checks cancel
try { doWork() }
finally { cleanup() }                  // runs on cancel too
  • Suspend fns (delay, withTimeout) throw CancellationException at suspension points. A tight CPU loop with no suspension point can't be cancelled — call yield()/ensureActive().
  • Don't swallow CancellationException in a broad catch (e: Exception) — rethrow it, or cancellation silently breaks !
  • withTimeout(ms){} throws; withTimeoutOrNull returns null.
  • async exceptions surface on await(), not when thrown; CoroutineExceptionHandler only catches launch.

Flow, StateFlow, SharedFlow, Channel

  • Cold Flow: runs its block once per collector, pull-based, lazy — like a suspend Sequence. Nothing runs until a terminal collect.
  • Hot StateFlow/SharedFlow: run once, broadcast to N collectors, push-based.
flow { emit(1); emit(2) }
  .map { it * 2 }.filter { it > 2 }
  .flowOn(Dispatchers.IO)          // upstream dispatcher
  .collect { println(it) }         // terminal, suspends

val state = MutableStateFlow(0)    // always has a value
state.value = 1                    // conflated, replay(1)
val events = MutableSharedFlow<E>(replay = 0)
scope.launch { flow.collect {} }   // or flow.launchIn(scope)
  • flatMapLatest cancels the previous inner flow on each new upstream value — search-as-you-type.
  • StateFlow is conflated + always replay(1); equal consecutive values are not re-emitted !
  • Channel = coroutine-safe queue (send/receive) for actor/pipeline; capacities RENDEZVOUS/buffered/CONFLATED/UNLIMITED (unbounded = OOM risk !). Backpressure: cold Flow is naturally back-pressured.

Collections — Read-only vs Mutable

  • List<T> is read-only (type-level), not immutable. JVM usually the same ArrayList — exposed to Java as fully mutable ! Defensive-copy at the boundary or use kotlinx.collections.immutable.
  • MutableList adds add/remove/clear. Keep mutable types local / behind private fields.
listOf(1,2,3); mutableListOf(); buildList { add(1) }
mapOf("a" to 1); mutableMapOf(); linkedMapOf(); sortedMapOf()
users.groupBy { it.team }
  .mapValues { (_, us) -> us.sumOf { it.score } }
val (ok, bad) = items.partition { it.valid }   // one pass

Sequences vs List

  • List = eager: xs.map{}.filter{} allocates an intermediate list after map, iterates twice.
  • Sequence = lazy: fuses into one pass, one element at a time; asSequence(), sequenceOf, generateSequence, sequence { yield(x) }.
xs.asSequence()
  .map { f(it) }.filter { p(it) }
  .first()                         // short-circuits — stops early
  • Reach for sequences on: long chains (3+ ops), large/unbounded inputs, and short-circuiting terminals (first/take).
  • Lists win on short chains / small inputs — per-element wrapper overhead of a Sequence loses ! Benchmark; don't cargo-cult.
  • Terminal ops (toList, count, sum) materialise; a Sequence is single-shot — collect once.

Generics & Variance

KindRule
invariant (default)MutableList<Int> ≠ MutableList<Number>

  • PECS: Producer Extends (out), Consumer Super (in). MutableList<T> is invariant because it both produces and consumes.
  • Variance (how the param behaves in subtyping) ≠ bounds (<T : Number>, what T can be) — orthogonal.
  • Erasure JVM: List<Int> ≡ List<String> at runtime → can't x is List<String>, only is List<*>. Star projection <*> ≈ read-Any?, write-blocked.
  • reified (inline only) restores the type at the call site: inline fun <reified T> parse(s) = gson.fromJson(s, T::class.java).
  • Nothing = bottom type, no instances; return type of throw/TODO(); subtype of all. Not Unit ("returns nothing meaningful") — it never returns.

Delegation — class & property

class LoggedList<T>(private val b: MutableList<T>)
  : MutableList<T> by b {          // forwards every method to b
  override fun add(e: T): Boolean { log(e); return b.add(e) }
}
  • Class delegation by = decorator with no boilerplate. It does not extend the interface — no super.method(), and overrides in the delegate are not seen by forwarded calls !

Property delegation

val cfg by lazy { load() }                     // once, cached, sync
var name by Delegates.observable("") { _, o, n -> log("$o→$n") }
var age  by Delegates.vetoable(0) { _, _, n -> n >= 0 }
val port by map                                // Delegates from Map
  • Delegate implements getValue/setValue (or ReadOnlyProperty/ReadWriteProperty).
  • by lazy: default SYNCHRONIZED; PUBLICATION/NONE drop the lock. Each delegated prop emits a KProperty + delegate object — negligible once, adds up over thousands of instances !

inline / crossinline / noinline / tailrec

inline fun <T> measure(block: () -> T): T {
  val t = System.nanoTime(); val r = block()
  log(System.nanoTime()-t); return r
}
tailrec fun fib(n: Int, a: Long=0, b: Long=1): Long =
  if (n == 0) a else fib(n-1, b, a+b)   // rewritten to a loop
  • inline: copies fn + lambda bodies into each call site → no Function1 allocation, enables non-local return from the lambda and reified. Why the stdlib marks nearly every collection op inline.
  • Not free: duplicates bytecode per call site; overuse on big fns bloats class files and can defeat JIT inlining ! Inline is for lambda-taking fns, not everything.
  • crossinline: lambda called from another context (thread, nested lambda) — forbids non-local return.
  • noinline: this lambda param must not be inlined — you store/pass it by reference.
  • tailrec: needs the recursive call as the literal last expression. n * f(n-1) is not tail-rec; accumulator form is. inline + recursion = bytecode explosion !

Java Interoperability

  • Java return String → platform type String! (accepts as String/String?, no warning). Kotlin reads @Nullable/@NotNull to recover real types. Wrap at the boundary !
  • Kotlin has no checked exceptions — Java throws IOException callable with no try; still propagates. Add @Throws so Java callers can catch.
  • SAM conversion: Kotlin lambda → Java single-abstract-method interface (Runnable, Comparator). Kotlin's own needs fun interface.
  • Unit↔void automatic. List<T> is mutable from Java even if read-only in Kotlin !
AnnotationEmits for Java

@JvmFieldpublic field, no getter/setter
@JvmOverloadsoverloads for default args (else Java passes all) !
@JvmName("x")rename fn/prop/file (top-level → FooKt)

Value Classes, typealias & Cost

@JvmInline value class UserId(val id: Int)  // type-safe, 0-alloc
typealias Handler = (String) -> Unit        // pure rename, no safety
  • Value class: single-prop wrapper, JVM erases to the underlying value at runtime — full compile-time type distinction, zero allocation. Boxes only when used as a generic/nullable/interface. For IDs, units, money.
  • typealias: compile-time alias only — UserId and Int are interchangeable, no type-safety boundary. Value class is a real type; typealias is not.
  • Boxing !: List<Int> boxes every Int→Integer. Hot numeric paths → IntArray/LongArray/DoubleArray (flat int[]), not Array<Int> (Integer[]).
  • Every non-inlined lambda = a Function1 allocation per call. GC pressure = high allocation rate → frequent GC; usual cause is intermediate collections + lambdas in hot loops. Measure (JFR/async-profiler) before optimising.
  • == calls equals; === is identity — rarely what you want (string interning makes === unreliable).

object & companion object

object Registry { val items = mutableListOf<String>() } // singleton
class Logger {
  companion object Factory {          // one per class
    const val LEVEL = 2               // compile-time const
    fun create() = Logger()
  }
}
Logger.create()                       // no instance needed
  • object = thread-safe lazy singleton; JVM handles init. Replaces the Java singleton pattern (no double-checked locking). Can extend classes / implement interfaces; anonymous form object : Listener { ... }.
  • Companion = singleton nested in a class, Kotlin's stand-in for Java static — but has a type, can implement interfaces, and can be named. Only one per class.
  • JVM from Java: object Foo → Foo.INSTANCE; companion member → MyClass.Companion.bar() unless @JvmStatic !
  • companion object { operator fun invoke(...) = ... } = factory that reads like a constructor call.

Higher-Order Functions & Lambdas

fun apply(x: Int, op: (Int) -> Int) = op(x)   // takes a fn
fun adder(n: Int): (Int) -> Int = { it + n }  // returns a fn
list.map { it * 2 }                            // trailing lambda
list.map(::transform)                          // fn reference
val f: (Int, Int) -> Int = { a, b -> a + b }
val g: String.() -> Int = { length }           // lambda w/ receiver
  • Functions are first-class at source level only. JVM (Int)->Int compiles to a Function1 instance — every non-inlined lambda is one allocation per call ! That's why stdlib collection ops are inline.
  • Trailing lambda: last-arg lambda moves outside (); if it's the only arg, drop the parens. Single param = implicit it; two params must be named.
  • References: ::topFun, String::length (unbound), obj::method (bound). Function type nullable ((A)->B)?, suspending suspend (A)->B.
  • Lambda with receiver T.()->R: inside, this is the T — the DSL/scope-function primitive. Differs from an extension fn (receiver in its type, not signature).

  • Kotlin is multi-paradigm, not Haskell: no enforced purity, no auto-currying. Currying/partial application are hand-rolled. Nullable types (?./?:) are a simplified Maybe/Option monad; ?.let ≈ flatMap, short-circuiting on null.

CoroutineContext, Supervisor & Exceptions

  • CoroutineContext = composable bag: Job + Dispatcher + CoroutineExceptionHandler + name. Combine with +: launch(Dispatchers.IO + handler) {}. Children inherit the parent's context, overriding only what you pass.
val handler = CoroutineExceptionHandler { _, e -> log(e) }
supervisorScope {
  launch(handler) { risky() }   // failure here…
  launch { other() }            // …doesn't cancel this sibling
}
  • Default Job: a child failure cancels parent + all siblings. SupervisorJob/supervisorScope: failures stay isolated — for independent parallel work (N network calls).
  • SupervisorJob does not catch — the exception still surfaces via handler/try !
  • CoroutineExceptionHandler catches uncaught launch exceptions only. async stores the exception in its Deferred; it surfaces on await(), silent until then !

Mutex, Actors & Backpressure

val mutex = Mutex()
mutex.withLock { shared++ }        // suspends, doesn't block thread
// actor: state owned by one coroutine, updated via messages
val counter = scope.actor<Msg> {
  var n = 0
  for (m in channel) when (m) {
    is Inc -> n++
    is Get -> m.reply.complete(n)
  }
}
  • Mutex.withLock = coroutine mutual exclusion — suspends waiters instead of blocking the OS thread (unlike synchronized/ReentrantLock). Not reentrant !
  • Prefer confining shared mutable state to an actor (serial message processing) or atomics over locks.
  • Backpressure: producer faster than consumer. Cold Flow is naturally back-pressured (nothing emits until collect). Channel capacity picks the strategy: RENDEZVOUS (producer waits), buffered, CONFLATED (keep latest), UNLIMITED (OOM risk !). Flow operators: buffer, conflate, collectLatest.

Spring on Kotlin

@Service
class UserService(private val repo: UserRepository) { // ctor inject
  @Transactional
  fun rename(id: Long, name: String) { ... }
}
interface UserRepository : CrudRepository<User, Long>
fun <T,ID> CrudRepository<T,ID>.findByIdOrNull(id: ID): T? =

  • Constructor injection is idiomatic — no @Autowired since Spring 4.3 on single-ctor classes. Immutable deps, trivially mockable.
  • @Component/@Service/@Repository all register beans; @Repository adds exception translation. @Configuration is CGLIB-proxied so inter-@Bean calls return the singleton.
  • Compiler plugins are mandatory !: kotlin-spring makes annotated classes open (proxies need to subclass — Kotlin classes are final by default); kotlin-jpa synthesises the no-arg ctor Hibernate needs.
  • @Transactional is proxy-based: only public, externally-called methods. Self-invocation this.foo() bypasses the proxy !
  • Alternatives: Exposed (Kotlin-first typed SQL DSL, no reflection), Ktor (coroutine-native, fast startup, GraalVM-friendly).

Reflection & Metaprogramming

inline fun <reified T> parse(s: String): T =
  gson.fromJson(s, T::class.java)      // reified needs inline !
@Serializable data class User(val name: String)  // codegen, no reflect
MyClass::class.memberProperties       // needs kotlin-reflect (~3MB)
  • Two routes: runtime reflection (KClass/KProperty/KFunction, opt-in kotlin-reflect jar, slow) vs compile-time codegen — modern Kotlin strongly prefers codegen (AOT/GraalVM-friendly).
  • reified only in inline fns: the type is substituted at each call site, so T::class/is T survive JVM erasure.
  • kotlinx.serialization generates KSerializers at compile time (vs reflection-based Jackson/Gson). Bridge to Java: ::class.java.
  • KSP (Kotlin Symbol Processing) supersedes KAPT — no Java stub generation, faster, Kotlin-aware. Plugins: Compose, Parcelize, AllOpen. expect/actual = KMP per-platform impls.

DSL Design

@DslMarker annotation class HtmlDsl
@HtmlDsl class Body { fun h1(b: H1.()->Unit) { … } }
html { body { h1 { +"hi" } } }   // nested lambdas-with-receiver
val s = buildString { append("a"); append("b") }  // scoped builder
infix fun String.eq(v: String) = Pair(this, v)     // "k" eq "v"
  • A DSL is just a tree of lambdas-with-receiver — each block sets its receiver as this. Desugars to ordinary method calls + (unless inline) one lambda alloc per block.
  • @DslMarker stops nested blocks from implicitly seeing outer receivers — prevents putting a <div> in a <head> ! For a real DSL it's not optional.
  • infix ≠ operator: infix just drops the dot for a binary fn; operators are a fixed conventional-name set. Restrain both — shallow nesting, obvious names.
  • Builders: buildString/buildList/buildMap hand you a mutable receiver, return an immutable result. Type-safe builders = kotlinx.html, Exposed, Gradle KTS, Compose, Ktor routing.

Android & Platform

class VM : ViewModel() {
  private val _state = MutableStateFlow(UiState())
  val state: StateFlow<UiState> = _state.asStateFlow()
  fun load() = viewModelScope.launch { _state.value = fetch() }
}
@Composable fun Counter() {
  var n by remember { mutableStateOf(0) }   // survives recompose
  Button(onClick = { n++ }) { Text("$n") }
}
  • viewModelScope/lifecycleScope cancel with their owner — the structured-concurrency fix for the classic leak. GlobalScope.launch in an Activity/VM leaks !
  • New code: StateFlow (view state) + SharedFlow (events), collected via repeatOnLifecycle(STARTED). LiveData is Android-only, lifecycle-aware, being phased out.
  • Compose = React-style declarative: @Composable re-runs (recomposes) on state change — many times per frame; keep state in remember, wrap side effects in LaunchedEffect/DisposableEffect !
  • Delegates everywhere: by viewModels(), by navArgs(), by viewBinding(). DataStore replaces SharedPreferences.

Performance, Boxing & References

RefGC behaviour
strong (default)never collected while reachable
WeakReferencecollected at next GC if else-unreachable
SoftReferencekept until memory pressure — caches
WeakHashMapweak keys — per-instance metadata
  • Boxing !: List<Int> boxes each Int→Integer; a nullable/generic slot boxes too. Hot numeric paths → IntArray/LongArray/DoubleArray (flat int[]), not Array<Int> (Integer[]).
  • GC pressure = sustained high allocation → frequent GC. Usual cause: intermediate collections + non-inlined lambdas in tight loops. asSequence() fuses long chains; inline removes lambda allocs. Measure first (JFR/async-profiler) — most "optimisations" are folklore.
  • data class equals/hashCode are linear in property count — negligible for small classes, visible only in extreme hot loops.
  • Weak refs prevent retention but introduce null — always handle ref.get() == null.

★ Code Review Checklist

Null safety

  • ☐ No unjustified !! — use ?./?:/requireNotNull. Java results wrapped as explicit T? at the boundary !
  • ☐ lateinit only where init truly precedes use; guarded with ::x.isInitialized if uncertain.

Immutability & data

  • ☐ val by default; MutableList/var confined to local/private scope.
  • ☐ No var in a data class used as a Set/Map key; API returns List<T> not MutableList<T>.

Coroutines

  • ☐ No GlobalScope; scope tied to a lifetime. No runBlocking in async/server paths.
  • ☐ Cooperative cancellation (isActive/yield) in CPU loops; CancellationException rethrown, not swallowed !
  • ☐ Blocking IO inside withContext(Dispatchers.IO); shared mutable state guarded (Mutex/atomics/actor).

Types & interop

  • ☐ when over sealed type has no else (exhaustive → new subtype breaks build).
  • ☐ Variance correct (out producer / in consumer); no member shadowing an extension.
  • ☐ @JvmStatic/@JvmOverloads/@Throws present on Kotlin APIs consumed from Java.

Cost

  • ☐ Long/large chains use asSequence(); primitive-heavy hot paths use primitive arrays; inline reserved for lambda-taking fns.
