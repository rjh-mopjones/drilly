Encapsulation (send path): app data → prepend L4 header = segment → prepend L3 header = packet → prepend L2 header/trailer = frame → bits. Each layer adds its own header; the receiver strips them in reverse. TCP/IP collapses OSI to 4 layers (Link · Internet · Transport · Application).

  • *TLS straddles 5–6; interviewers accept "L7-ish, on top of TCP."
  • Why it matters: isolate the failing layer. Can't resolve = DNS(L7); resolves but no connect = L3/L4; connects but cert error = TLS. Don't debug up a layer until the one below is proven good !

IP Addressing & Subnetting

  • IPv4 = 32 bits (4 octets). CIDR /n = number of network bits; host bits = 32−n.
  • Usable hosts = 2^(32−n) − 2 (subtract network + broadcast). ! exceptions: /31 = 2 usable (RFC3021 p2p links), /32 = single host.

  • Private (RFC1918): 10/8, 172.16/12, 192.168/16. Loopback 127/8 (::1). Link-local 169.254/16 (APIPA — "DHCP failed" !).
  • Same subnet? host ANDs dst IP with its mask, compares to its own network → match = deliver direct (ARP); else → default gateway.
  • IPv6 = 128 bits, hex, :: compresses zeros; SLAAC + no NAT. Dual-stack is the norm.

Link Layer & LAN (L2)

  • Moves a frame between two nodes on the same segment, addressed by 48-bit MAC (flat, burned-in, non-routable).
  • ARP resolves IP→MAC on the local subnet: broadcast "who has 10.0.0.5?", owner replies with its MAC; cached in the ARP table.
  • Switch learns MAC→port from source addresses, forwards frames to the right port; floods unknown/broadcast within the broadcast domain.
  • VLAN = segments one physical switch into isolated L2 domains (802.1Q tag); inter-VLAN needs an L3 router.
  • MTU = max frame payload, 1500B on Ethernet; jumbo = 9000 in datacentres.

Routing & the Network Layer (L3)

$ ip route
default via 192.168.1.1 dev eth0     # 0.0.0.0/0 catch-all
10.0.0.0/8 via 10.0.0.1 dev eth1
10.0.5.0/24 via 10.0.5.1 dev eth1    # more specific
  • Hop-by-hop & local: each router reads dst IP, does a longest-prefix match, decrements TTL, rewrites L2 framing, forwards. dst IP never changes; no router knows the full path.
  • Longest-prefix wins first; admin distance picks which protocol to trust (connected 0 < static 1 < eBGP 20 < OSPF 110); metric only breaks ties within a protocol.
  • Routing = build the table (control plane, slow); forwarding = per-packet lookup (data plane, ASIC line-rate). RIB → FIB.
  • IGP (inside an AS): OSPF/IS-IS (link-state, Dijkstra), RIP (legacy). BGP (between ASes): path-vector, policy-driven, trust-based — "runs the internet." Fat-finger a prefix → global blackhole/hijack (RPKI + prefix filters mitigate) !
  • ICMP: echo=ping; time-exceeded (TTL=0)=traceroute; frag-needed=PMTUD. Block all ICMP → large packets vanish, conns hang ! (allow types 3 & 11).
  • ECMP: hash the 5-tuple → same flow, same path (no reorder); spreads flows across links.

TCP — Reliability & Handshake

SYN  →                (seq=x)
     ← SYN-ACK        (seq=y, ack=x+1)   1 RTT
ACK  →   ...data...   (seq=x+1, ack=y+1)
FIN/ACK ×2            (4-way close)
  • Reliable, ordered, byte-stream, full-duplex. Every byte has a seq; receiver ACKs cumulatively. Loss → retransmit.
  • Fast retransmit: 3 duplicate ACKs ⇒ resend the missing segment without waiting for RTO. SACK tells the sender exactly which ranges arrived.
  • MSS = MTU − IP − TCP headers (≈1460 on 1500 MTU); negotiated in SYN. PMTU black hole = large segments silently dropped !
  • Nagle (coalesce small writes) + delayed ACK can interact → ~40ms stalls; TCP_NODELAY for latency-sensitive/request-response !
  • RST = abortive reset (port closed / app crashed) — not a graceful FIN.

TCP — Flow & Congestion Control

Flow controlCongestion control
protectsthe receiverthe network
signaladvertised rwndinferred loss/delay
windowrwndcwnd
  • In-flight bytes ≤ min(rwnd, cwnd). Throughput ≈ window / RTT (bandwidth-delay product — a fat, long pipe needs a big window; scale-window option).
  • Slow start: cwnd doubles per RTT until ssthresh or loss. Then congestion avoidance — AIMD (additive-increase, multiplicative-decrease): +1 MSS/RTT, halve on loss. Sawtooth.
  • CUBIC (Linux default) — loss-based, scales to fat pipes. BBR — models bottleneck bw+RTT, ignores loss; better on lossy/wireless links.
  • Loss → backoff → throughput collapse; a tiny loss rate murders long-fat-pipe throughput ! Watch p99 tail, not the mean.

UDP vs TCP & QUIC

TCPUDP
connectionhandshakenone (fire & forget)
reliable/orderedyesno
flow/congestionyesno (app's job)
header20B+8B
useweb, APIs, DB, filesDNS, VoIP, games, video, QUIC
  • UDP = a thin wrapper over IP: ports + checksum, nothing else. You add reliability only where you want it (custom ACK/FEC).
  • QUIC (basis of HTTP/3) rebuilds streams + reliability + congestion + TLS 1.3 over UDP in user space. Wins: no TCP head-of-line blocking (per-stream loss), 0/1-RTT setup, connection migration (survives IP change, e.g. Wi-Fi→cellular) via connection IDs.
  • ! UDP is the amplification vector for reflection DDoS (DNS/NTP/memcached) — small spoofed request, huge reply.

HTTP

CodeClass / common
2xx200 OK · 201 Created · 204 No Content
3xx301 perm · 302 temp · 304 Not Modified
4xx400 · 401 auth · 403 forbid · 404 · 409 · 429 rate
5xx500 · 502 bad-gw · 503 unavail · 504 timeout
  • Idempotent (safe to retry): GET, PUT, DELETE, HEAD. POST is not — use an idempotency key ! Safe = read-only: GET/HEAD.
  • From a proxy/LB: 502 = upstream gave a garbage/closed reply; 504 = upstream didn't answer in time. Different bugs.
  • Versions: H1.1 keep-alive but text + head-of-line blocking → H2 binary, multiplexed streams over 1 TCP + HPACK (still TCP-HOL on loss) → H3/QUIC over UDP, no HOL.
  • Stateless: state via cookies (Secure/HttpOnly/SameSite) or tokens. REST verbs map to CRUD.

HTTP Caching & Headers

  • Cache-Control drives everything: max-age, no-cache (revalidate), no-store (never), private vs public, s-maxage (shared/CDN), stale-while-revalidate.
  • Validators (conditional GET → 304, no body): ETag + If-None-Match; Last-Modified + If-Modified-Since.
  • Content negotiation: Accept, Accept-Encoding (gzip/br), Vary (cache key dimensions — forget it and users get each other's variants !).
  • Range requests (206) for resumable/video. Chunked transfer-encoding streams unknown-length bodies.
  • Immutable assets: fingerprint the URL (app.9fa3.js) + long max-age, immutable — invalidate by changing the name, never purge !
  • CORS: Access-Control-Allow-Origin; preflight OPTIONS for non-simple requests.

HTTPS / TLS

openssl s_client -connect host:443 -servername host
curl -Iv https://host/          # -I head, -v handshake
echo | openssl s_client -connect host:443 2>/dev/null \
  | openssl x509 -noout -dates -subject   # expiry
  • Provides confidentiality + integrity + authentication. Hybrid: asymmetric (RSA/ECDHE) to authenticate + agree a key, symmetric (AES-GCM/ChaCha20) for bulk.
  • Handshake: ClientHello (ciphers, SNI) → ServerHello + cert → key exchange → Finished. TLS 1.3 = 1-RTT (0-RTT on resume), forward secrecy by default, dropped RSA key-exchange & weak ciphers !
  • Cert validation: chain leaf→intermediate→root anchored in the trust store, not expired, hostname/SAN match, not revoked (OCSP stapling). Any failure = MITM risk.
  • SNI = which host (plaintext; ECH hides it) → many sites, one IP. mTLS = client also presents a cert (zero-trust/service mesh).
  • Errors: expired · name mismatch · untrusted issuer · wrong chain order (missing intermediate) · clock skew (fix NTP) !

Proxies, Reverse Proxies & Gateways

  • Forward proxy = sits in front of clients (egress filter, corporate cache, anonymity). Server sees the proxy's IP.
  • Reverse proxy = sits in front of servers (TLS termination, LB, cache, compression, routing) — nginx / HAProxy / Envoy. Client sees the proxy; the proxy fans out to backends.
  • API gateway = L7 reverse proxy specialised for APIs: authn/z, rate-limit, quota, request transform, aggregation, routing, versioning — one edge for many services.
  • Service mesh = per-pod sidecar proxies (Envoy) giving mTLS, retries, timeouts, circuit-breaking, and traffic-shift/observability without app code. Control plane = Istio/Linkerd; ambient/sidecarless is the trend.
  • Canonical request path: CDN → LB → reverse proxy / API gw → app → DB. Each hop can cache, retry, terminate TLS, or add headers !

CDN & Edge

  • CDN = geographically-distributed edge caches near users. Anycast advertises one IP from many PoPs; BGP routes each user to the nearest one.
  • Cache hit served at the edge (single-digit ms); miss → fetch from origin, optionally via a shield/mid-tier that collapses many misses into one origin request (request coalescing) !
  • Cache key = URL + Vary dimensions. Control freshness with s-maxage + stale-while-revalidate/stale-if-error (serve stale during origin outages).
  • Invalidate by versioned/fingerprinted URLs ≫ purge (purge is slow & global). Cache static aggressively; be careful caching authenticated/personalised responses !
  • The edge also absorbs DDoS, runs the WAF, terminates TLS, and runs edge compute (workers) for A/B, auth, redirects near the user.

NAT & Firewalls

  • NAT maps private↔public addresses. SNAT/masquerade = outbound (many hosts → 1 public IP, multiplexed by port = PAT). DNAT/port-forward = inbound. Exists for IPv4 exhaustion; breaks end-to-end & inbound P2P (→ STUN/TURN/hole-punching) !
  • Stateful firewall tracks connections (conntrack) → auto-allows return traffic; policy is default-deny, allow-list. Stateless filters each packet in isolation.
  • Cloud: security groups = stateful, per-instance, allow-only. NACLs = stateless, per-subnet, ordered allow+deny, need explicit return rules !
  • Refused vs timeout (memorise): RST / nothing-listening → connection refused fast; silent DROP → client times out (firewall/blackhole) !
  • Lock down egress too (data exfil); never bind DB/Redis to 0.0.0.0. WAF = L7 (SQLi/XSS/bot). Asymmetric routing breaks stateful boxes !

Performance: Latency vs Bandwidth

  • Bandwidth = pipe width (bits/s); latency/RTT = pipe length (time). More bandwidth does NOT fix latency — the #1 misconception !
  • Latency = propagation (speed of light, ~5µs/km fibre) + transmission + queuing + processing. Cross-continent RTT is physics you can't beat — you can only reduce round trips.
  • Each RTT-bound step stacks: DNS + TCP + TLS + request. Kill round trips: keep-alive/pooling, TLS 1.3 (1-RTT), H2/3, CDN (shorten distance), caching, 0-RTT resume.
  • Bufferbloat: oversized router buffers hoard packets → latency spikes under load; fix with AQM (fq_codel/CAKE).
  • Throughput ≈ window/RTT and collapses under loss on long-fat pipes. Optimise the p99 tail, not the mean; one slow dependency dominates fan-out latency !

Sockets & Network Programming

server: socket→bind→listen→accept→read/write→close
client: socket→connect→write/read→close
ss -tlnp                 # listening sockets + owning pid
ss -tan state established | wc -l
lsof -i :443             # who holds the port
  • A connection = 4-tuple (src IP:port, dst IP:port). One listener serves many clients — each accepted socket is a distinct 4-tuple.
  • Sockets are file descriptors → ulimit -n caps them; hit it under load = EMFILE "too many open files" !
  • C10K: one thread + epoll/kqueue (event loop / reactor) handles thousands of conns — nginx, Node, Netty. Blocking thread-per-conn doesn't scale.
  • TCP is a byte stream, not messages — you must frame (length-prefix or delimiter); one read() may return partial/multiple messages !
  • SO_REUSEADDR (rebind TIME_WAIT), SO_REUSEPORT (kernel load-balances accepts across workers). Reuse conns (pool) to skip handshakes.

Cloud & Virtual Networking

  • VPC = your private virtual network; carved into subnets per AZ. Public subnet has a route to an Internet Gateway; private subnet reaches out via a NAT gateway (no inbound) !
  • Route tables per subnet decide IGW vs NAT vs peering. VPC peering (non-transitive) / Transit Gateway (hub) connect VPCs; PrivateLink exposes a service privately without internet.
  • Reach on-prem via VPN (IPsec over internet) or Direct Connect/dedicated (private, low-jitter).
  • Overlays: VXLAN tunnels tenant L2 over the physical L3 fabric. K8s: each pod gets a routable IP (CNI); Service = stable virtual IP; kube-proxy iptables/IPVS or eBPF (Cilium) load-balances; NetworkPolicy = L3/4 firewall.
  • ! Overlapping CIDRs break peering; SG referencing another SG ≫ hardcoded IPs.

Security & Attacks

  • TLS everywhere; cert validation stops MITM; HSTS stops SSL-strip downgrade.
  • DDoS: volumetric/reflection-amplification (spoofed UDP DNS/NTP/memcached), SYN flood (half-open — SYN cookies), L7 request-flood → absorb with CDN/anycast + rate-limit + WAF.
  • Spoofing: ARP (LAN MITM), DNS cache poisoning (→ DNSSEC), IP spoofing (→ ingress filtering/BCP38). On-path can read/alter unencrypted traffic.
  • Defence-in-depth: default-deny SG/NACL, private subnets, least-privilege egress, mTLS between services.
  • VPN ≠ zero trust. VPN trusts the network perimeter; zero-trust authenticates every request by identity (mTLS/SSO), never trusts the network — assume breach.

Modern Networking

  • HTTP/3 + QUIC over UDP: no HOL blocking, faster setup, connection migration — now default at big edges.
  • eBPF: run sandboxed programs in the kernel for networking/observability — Cilium replaces kube-proxy, XDP does line-rate DDoS drop & LB.
  • Ambient / sidecar-less mesh cuts the per-pod proxy tax; ECH encrypts SNI; DoH/DoT encrypt DNS; IPv6 + dual-stack mainstream.
  • RDMA / RoCE and lossless fabrics for AI/HPC clusters (GPU-to-GPU, kernel-bypass, µs latency).
  • SD-WAN & programmable dataplanes (P4); QUIC-based multipath (MPTCP-like) for mobile.

DHCP & Address Assignment

DORA — how a host with no IP gets one (all broadcast until it has an address):

1 DISCOVER  client → 255.255.255.255  "any servers?"
2 OFFER     server → "take 192.168.1.50/24, gw .1, DNS ..."
3 REQUEST   client → "I'll take that one"  (locks 1 server)
4 ACK       server → confirms lease + duration
  • Client source is 0.0.0.0 (no IP yet), dst is the L2 broadcast — a prime reason broadcast exists. Server also hands out mask, gateway, DNS, sometimes NTP/search-domain.
  • Lease = finite; client renews at ~50% of lifetime (unicast to the same server). No answer at all → falls back to APIPA 169.254.x.x — the tell that DHCP is broken !
  • Cross-subnet: a DHCP relay (ip-helper) forwards the broadcast to a central server as unicast. Cloud equivalent: the platform auto-assigns ENI/interface IPs from the subnet range.
  • ! Two DHCP servers on one L2 (a rogue home router plugged in) hand out conflicting leases & gateways — a classic "half the office lost internet."

VLANs, Trunks & L2 Loops

PortCarriesFaces
Access1 VLAN, untaggedend host (edge)
Trunkmany VLANs, 802.1Q-taggedswitch↔switch (backbone)
  • Trunk mis-set as access ⇒ only one VLAN passes, the rest silently vanish. Native VLAN = the one that rides a trunk untagged; a mismatch leaks traffic between VLANs (VLAN-hopping) !
  • Collision domain = 1 per switch port (full-duplex killed collisions). Broadcast domain = whole switch/VLAN; only a router or VLAN boundary stops a broadcast. Flat huge L2 ⇒ ARP/DHCP hit everyone.
  • STP (802.1D) stops L2 loops: Ethernet frames have no TTL, so a looped broadcast circulates forever = broadcast storm (network dead in seconds). Switches elect a root bridge via BPDUs and block redundant ports into a loop-free tree; a link fails → unblock a standby. RSTP (802.1w) converges in seconds vs 30–50s !
  • Gratuitous ARP = unsolicited "IP X is at my MAC" — after a failover / VIP move / VM migration the new owner blasts it so switches & clients relearn instantly (keepalived/VRRP fast cutover). Same mechanism ARP spoofing abuses.

Playbook — p99 spiky, mean fine

Healthy mean + bad tail ⇒ most requests fine, a minority hit something expensive. You're debugging variance, not throughput. Usual suspects:

  • Queueing / bufferbloat — under load packets pile in oversized buffers/accept queues; latency climbs sharply near capacity. Fix: AQM (fq_codel/CAKE), BBR !
  • HOL blocking — one lost packet stalls all H2-over-TCP streams on that conn (exactly what H3/QUIC fixes); the unlucky conns spike.
  • Cold-start — fresh conns pay DNS+TCP+TLS + TCP slow-start (small initial cwnd ramping). Poor pooling ⇒ tail requests open cold. Fix: keep-alive/pooling.
  • GC / stop-the-world — JVM/Go pauses freeze handlers periodically; correlate p99 spikes with GC logs.
  • Contention — saturated DB pool, lock waits, a downstream at capacity; retries amplify load exactly when struggling.

! "Add capacity" helps queueing but won't fix cold-start or GC pauses.

Playbook — where is the packet loss?

ping proves loss exists; mtr proves where. Reading the per-hop table is the skill:

mtr -rw -c 100 host    # report, 100 pkts, wide, per-hop loss%
  • Loss that starts at hop N and persists to the destination → the real fault is at/after hop N.
  • Loss at a middle hop that vanishes by the destination → red herring: that router just rate-limits ICMP to its own control plane while forwarding your traffic fine. Only end-to-end loss is actionable !
  • Loss only under load → congestion, not a broken link. Run mtr both directions — routing is often asymmetric, loss may be on the return path.
  • Inside your network → fix it; at an ISP/transit hop → open a ticket with the mtr evidence.

Email & Messaging Protocols

  • Send: client → SMTP submission (587, STARTTLS) → sender's MTA → recipient MX (found via MX record) over 25 → recipient store. Fetch: IMAP (993, server-side folders, multi-device) or legacy POP3 (995, download-and-delete).
  • Anti-spoof trio (all TXT records): SPF = which IPs may send for the domain; DKIM = cryptographic signature on the message; DMARC = policy + reporting tying SPF/DKIM to the visible From, tells receivers what to do on fail !
  • WebSocket = full-duplex over one upgraded TCP (chat/live); SSE = one-way server→client stream over plain HTTP, auto-reconnect. gRPC = RPC over H2 + protobuf (internal); REST/JSON for public/browser.

★ Network Design Review Checklist

Naming & discovery

  • ☐ Sensible DNS TTLs; lowered ahead of any planned cutover.
  • ☐ No CNAME at a zone apex; failover has a defined DNS/health story.

Connections & sockets

  • ☐ Clients pool/reuse connections — no per-request TCP+TLS setup; sockets always close()d (no CLOSE_WAIT leak) !
  • ☐ ulimit -n / fd budget sized for peak concurrency; TIME_WAIT/ephemeral range considered on proxies.
  • ☐ Messages are framed (length-prefix/delimiter) — code never assumes one read = one message !

TLS & security

  • ☐ TLS 1.2+ (prefer 1.3), full cert chain incl. intermediate, auto-renewal + expiry alerts; NTP in sync.
  • ☐ Default-deny SG/NACL; egress locked; DB/Redis not on 0.0.0.0; XFF trusted only from own LB !

Resilience & performance

  • ☐ LB is HA (no SPOF); health checks tuned (no flapping); apps stateless or shared session store — no sticky reliance.
  • ☐ Timeouts + bounded retries with backoff + idempotency on POST; circuit breakers on downstreams.
  • ☐ CDN/caching in front of static; round trips minimised (keep-alive, H2/3); p99 tail measured, not just mean.
  • ☐ ICMP types 3 & 11 allowed (PMTUD, error signalling) even if echo is dropped !
