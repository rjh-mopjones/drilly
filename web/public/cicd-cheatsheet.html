CI = integrate + build + test every change. CD = deliver (human gate) or deploy (auto) that artifact to prod, safely, with rollback.

CI vs CD & Pipeline Model

TermMeans
CImerge often + auto build/test; keep main green
Continuous Deliveryevery green build is releasable; human clicks deploy
Continuous Deploymentevery green build auto-ships to prod
  • Pipeline = stages → jobs → steps, triggered by events (push/PR/tag/cron/manual).
  • Jobs run in parallel; use a DAG (needs/depends_on) for order → faster.
  • Pipeline-as-code in the repo (reviewed, versioned) > click-configured jobs.

CI Practices

  • Trunk-based: short-lived branches, merge within a day — no long feature branches / merge hell !
  • Keep main green: branch protection, required checks, required reviews, no direct pushes.
  • Merge queue / trains: serialize merges so two individually-green PRs can't break main together.
  • Fast feedback (minutes) — parallelize/cache/split; a slow CI kills the practice !
  • Feature flags let you merge incomplete work safely (deploy ≠ release).

GitHub Actions

name: ci
on: { push: { branches: [main] }, pull_request: {} }
permissions: { contents: read, id-token: write }  # OIDC
jobs:
  build:
    runs-on: ubuntu-latest
    strategy: { matrix: { node: [20, 22] } }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: ${{ matrix.node }} }
      - run: npm ci && npm test
      - uses: actions/upload-artifact@v4
        with: { name: dist, path: dist/ }
  deploy:
    needs: build
    environment: production        # required reviewers gate
    steps:
      - uses: aws-actions/configure-aws-credentials@v4
        with: { role-to-assume: arn:aws:iam::123:role/deploy }
  • Pin third-party actions by commit SHA; scope permissions: least-privilege.
  • Reusable workflows (workflow_call) & composite actions for DRY; concurrency to cancel dupes.

GitLab CI

stages: [build, test, deploy]
build:
  stage: build
  image: node:22
  script: [npm ci, npm run build]
  artifacts: { paths: [dist/] }
test:
  stage: test
  needs: [build]          # DAG — start early
  script: [npm test]
deploy_prod:
  stage: deploy
  environment: { name: production, url: https://acme.com }
  rules: [{ if: '$CI_COMMIT_BRANCH == "main"', when: manual }]
  script: [./deploy.sh]
  • rules (not only/except) decide when a job runs; needs = DAG.
  • Review apps = ephemeral env per MR; built-in Container Registry & CI_* vars.
  • Protected branches/variables gate prod; include for templates.

Build · Test · Artifacts

  • Build the artifact once; run the test pyramid (fast unit → integration → few e2e), gate merges on the fast layers.
  • Speed: cache deps, parallelize/shard tests, affected-only builds in monorepos.
  • Flaky tests erode trust — quarantine & fix, don't ignore !

Artifacts

  • Immutable, versioned (git-sha/semver/@digest); store in a repo (Artifactory/Nexus/registry/Packages).
  • Build once → promote the same artifact up the ladder; config injected per env (12-factor) !
  • Attach provenance/SBOM; sign it.

Progressive Delivery

  • Canary on autopilot: shift traffic in steps + automated analysis (error rate/latency/saturation) → promote or auto-rollback.
  • Argo Rollouts (K8s Rollout CRD: setWeight → pause → analysis) / Flagger (Flux + mesh).
  • Traffic shifting via ingress/service mesh weights; gate on SLOs (needs good observability).
  • Ring deployments: internal → early adopters → everyone.

Environments & Promotion

  • dev → staging → prod; parity matters (staging mirrors prod) — avoid snowflakes !
  • Promote the same artifact/digest up the ladder; gate prod with required reviewers / manual approval.
  • Config & secrets per env injected at deploy — keep them OUT of the artifact.
  • Ephemeral preview envs per PR (review apps / per-PR namespace) — tear down on merge.
  • Separation of duties: who can deploy to prod.

GitOps (pull-based CD)

  • Git = single source of truth; an in-cluster agent pulls & reconciles desired state.
  • Push (CI runs kubectl, needs cluster creds) vs pull (ArgoCD/Flux; no cluster creds in CI) — pull is safer !
  • ArgoCD Application CRD, sync/health/self-heal, app-of-apps; Flux controllers + image automation.
  • Self-heal reverts manual kubectl drift back to Git.
  • CI builds+pushes image & bumps the tag in a config repo → GitOps deploys. Rollback = git revert.
  • Secrets: sealed-secrets / SOPS / external-secrets (never commit plaintext) !

Versioning & Releases

  • SemVer MAJOR.MINOR.PATCH = breaking / feature / fix.
  • Automate: semantic-release / release-please / changesets derive version + changelog from Conventional Commits, tag & publish in CI.
  • Monorepo: release only changed packages (changesets/Nx) vs lockstep one-version.
  • Hotfix via cherry-pick / release branch; feature flags to deploy without releasing.
  • Tag immutably; :latest is mutable — don't deploy it !

Secrets & Supply Chain

  • OIDC → short-lived cloud creds (assume an IAM role) instead of long-lived keys in secrets — the #1 modern practice !
  • Least-privilege pipeline identity & GITHUB_TOKEN permissions; secret managers (Vault/cloud), masking.
  • pull_request_target / PPE: fork PRs must NOT get secrets — poisoned-pipeline exfiltration footgun !
  • Pin actions by SHA; scan deps (Dependabot/Snyk); SAST/DAST/secret-scan gates.
  • SLSA provenance + sign (cosign) + verify at admission; SBOM (syft); ephemeral hardened runners.
  • A compromised pipeline = compromised prod — protect the CI system (RBAC, audit) !

Deploy Observability & DORA

  • Post-deploy: health/readiness gates + smoke tests; watch error rate/latency vs baseline.
  • Automated rollback on failure criteria (blue-green flip / canary abort / rolling undo / git revert). Fast rollback > slow perfect fix.
  • Feature flags cut deploy risk & MTTR (kill-switch without redeploy).

★ How Code Reaches Prod

  • 1. Branch → PR → PR pipeline (build, test, lint, SAST, image scan, preview env).
  • 2. Review + required checks pass → merge to main (merge queue keeps it green).
  • 3. Main pipeline builds the immutable artifact once (image @git-sha) → push to registry.
  • 4. Auto-deploy to staging → e2e + smoke tests (+ optional QA).
  • 5. Promote the same artifact to prod — approval gate (delivery) or automatic (deployment).
  • 6. Deploy via rolling/blue-green/canary; post-deploy smoke + health.
  • 7. Observe error rate/latency → auto/manual rollback if unhealthy.
  • GitOps variant: CI commits the new tag to a config repo → ArgoCD/Flux deploys.

☐ Pipeline Review Checklist

  • ☐ Artifact built once, promoted by digest — not rebuilt per env.
  • ☐ Fast tests gate merges; main protected + required checks + merge queue.
  • ☐ OIDC / short-lived creds — no long-lived cloud keys in secrets.
  • ☐ Fork PRs can't reach secrets (no unsafe pull_request_target); actions pinned by SHA.
  • ☐ Image scanned + signed; SBOM/provenance; deps scanned.
  • ☐ Prod behind an approval / protected environment; least-privilege deploy role.
  • ☐ Safe deploy strategy (rolling/blue-green/canary) with a tested rollback.
  • ☐ Post-deploy smoke + health checks; deploy observability + auto-rollback.
  • ☐ Config/secrets per env injected at deploy; no secrets in artifact/logs.
  • ☐ Pipeline-as-code, reviewed & versioned; DORA tracked.
