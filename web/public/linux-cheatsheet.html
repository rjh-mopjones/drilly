Kernel, User Space & Boot

  • Three layers: kernel (Linus' ~30M-line core, scheduling/memory/drivers/FS/net) + GNU userland (bash, coreutils, glibc) + distro (kernel+userland+pkg mgr+defaults). "Linux" strictly = the kernel !
  • Ring 0 (kernel space) touches hardware; ring 3 (user space) is sandboxed. Only bridge = syscall (open read write fork execve mmap) — traps into the kernel. Kernel panic is fatal (nothing above it).
  • Blast radius of a CVE: kernel → patch+reboot; glibc → patch+restart everything linking it.

Boot chain (power → login)

Firmware(BIOS/UEFI) → GRUB2 (loads vmlinuz
 +initramfs from /boot) → kernel decompress
 → initramfs (drivers to mount real root)
 → pivot root, exec /sbin/init = PID 1
 → systemd → default.target → getty
  • Most "won't boot" bugs = bad GRUB, kernel upgrade that didn't rebuild initramfs, or broken /etc/fstab stalling systemd !
  • Monolithic but modular: lsmod, modprobe nvme, modinfo. uname -r kernel ver, -m arch.

Filesystem & FHS

PathHolds
/etcconfig
/varlogs, spool, variable data
/usrread-only programs/libs
/proc /syskernel interfaces (virtual, 0 disk)
/devdevice files
/bootkernel, initramfs, GRUB
/tmp /runtemp (often tmpfs, volatile)
  • Inode = metadata (perms, owner, size, block ptrs, link count) — not the name (name lives in the dir entry). ls -i, stat f.
  • Hard link = another name for the same inode (same FS, not dirs); file dies when link count and open fds hit 0. Symlink = a path pointer (crosses FS, can dangle) !
  • Everything is a file: devices, FIFOs, sockets. First ls -l char: -file ddir llink b/cdevice pfifo ssocket.
  • Single unified tree; other FS grafted on via mount. /proc/<pid>/ is live process state as files.

Permissions & Ownership

-rwxr-x---  user group
 └┬┘└┬┘└┬┘
  u   g   o     r=4 w=2 x=1
chmod 750 f     chmod u+x,g-w f
chown alice:web f   chgrp web f
  • Kernel checks the file mode against your effective UID then group set: owner → group → other, first match wins (no additive fallthrough) !
  • On a dir: x=traverse/enter, r=list names, w=create/delete entries (delete needs dir-w, not file-w) !
  • umask masks default perms (022 → files 644, dirs 755).
BitMeaning
SUID (4xxx)run as file owner (e.g. passwd) — root SUID is risky !
SGID (2xxx)run as group / on dir: children inherit group
sticky (1xxx)on /tmp: only owner deletes own files
  • Fine-grained: ACLs getfacl/setfacl -m u:bob:rw f.
  • Modern alt to root SUID: capabilities setcap cap_net_bind_service+ep ./svc (bind :80 without root).

  • New process = fork() (clone parent) then execve() (replace image). init/systemd (PID 1) reaps orphans.
StateMeans

  • SIGKILL(9)/SIGSTOP(19) can't be caught/ignored. Prefer TERM → cleanup → then KILL.

Job Scheduling — cron & timers

# m h dom mon dow  command
0 3 * * *  /usr/local/bin/backup.sh
*/5 * * * * cmd     # every 5 min
@reboot    cmd      # at boot
crontab -e   crontab -l   crontab -r !
  • cron runs in a minimal env: bare PATH, SHELL=/bin/sh, no profile sourced. ~80% of cron bugs. Use absolute paths + redirect output !
  • /etc/crontab & /etc/cron.d have an extra user field; user crontabs don't.
  • Plain cron does not catch up missed jobs (box off at 3am → skipped). Use anacron or a timer with Persistent=true.
  • Prevent overlap: flock -n /tmp/job.lock cmd.

systemd timers (preferred for prod)

[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true
# monotonic: OnBootSec= / OnUnitActiveSec=
systemctl list-timers --all

Two files (.timer+.service) but you get journald logging, deps, resource limits, missed-run handling.

systemd & Services

systemctl status|start|stop|restart nginx
systemctl reload nginx        # re-read config
systemctl enable --now nginx  # boot + start
systemctl daemon-reload       # after unit edit !
systemctl list-units --failed
systemctl edit nginx          # drop-in override
journalctl -u nginx -f        # follow logs
journalctl -b -p err --since "1h ago"
systemd-analyze blame         # slow boot units
  • enable ≠ start: enable = at boot; start = now. --now does both.
  • Deps: Requires= (hard, stops together) vs Wants= (soft) vs After= (order only, not a dependency) !
  • Crash recovery: Restart=on-failure + RestartSec=. Targets replace runlevels (multi-user.target≈3, graphical≈5).
  • Sandboxing/limits in-unit: MemoryMax=, CPUQuota=, LimitNOFILE=, ProtectSystem= (all cgroup-backed).
  • Edit a unit → always daemon-reload or changes are ignored !

Bash Scripting Quick-ref

#!/usr/bin/env bash
set -euo pipefail          # strict: fail fast + safe
trap 'rm -f "$tmp"' EXIT   # cleanup on any exit

name="${1:?usage: deploy NAME}"   # required arg
host="${2:-localhost}"            # default
files=(*.txt); echo "${#files[@]}" # array + count
for f in "${files[@]}"; do echo "$f"; done
while read -r line; do :; done < file
if [[ -f "$path" && -n "$var" ]]; then :; fi
count=$(( a + b ))   out=$(cmd)   # $? rides apart
  • Bash = macro-expansion: brace→tilde→$var→$(...)→arith→word-split→glob, then exec.
  • Always quote "$var" / "$@" — unquoted = word-split + glob = the #1 bug !
  • Single quotes = literal (no expansion); double = expand but no split. "$@" keeps args separate; "$*" joins.
  • [[ ]] (safe, =~ regex) > [ ]; (( )) arithmetic. Returns via exit code, not value.
  • set -e has holes (if/||/pipeline w/o pipefail). Run ShellCheck; past ~100 lines reach for Python.

Memory & Swap

free -h        # used / free / buff/cache / available
vmstat 1       # si/so=swap in/out; r/b=run/block
cat /proc/meminfo   ps -eo pid,rss,cmd --sort=-rss
dmesg -T | grep -i oom
sysctl vm.swappiness   # 0-100 swap eagerness
  • "free" is low = normal — the kernel uses spare RAM as page cache; read the available column (counts reclaimable cache). Cache ≠ leak !
  • OOM killer fires on true exhaustion; picks the highest oom_score (big RSS). Evidence: dmesg "Out of memory: Killed process".
  • VSZ (virtual, reserved, cheap) vs RSS (resident, real RAM). Compare RSS.
  • In containers, the cgroup memory limit triggers OOM inside the cgroup while the host has RAM free !
  • Swap = spillover, not "more RAM"; heavy si/so = thrashing → add RAM / cut footprint.

CPU, Load & Scheduling

uptime            # load avg 1/5/15 min
top   # %us %sy %id %wa(iowait) %st(steal!)
mpstat -P ALL 1   # per-core: one hot or all?
pidstat 1         # per-process cpu/io/ctxsw
vmstat 1   nproc  # r column vs core count
  • Load = R + D tasks (runnable + uninterruptible I/O), not CPU%. High load + idle CPU = I/O wait or blocked, not CPU ! Compare load to nproc.
  • %wa iowait = idle CPU waiting on disk — a disk problem in a CPU costume.
  • %st steal = hypervisor starving your VM (noisy neighbour).
  • One core pinned = single-threaded hot loop; all cores = genuinely CPU-bound.
  • Idle CPU + idle disk + low throughput = lock contention (futex); confirm with strace -c/perf.

Disk, Filesystems & LVM

lsblk   df -h   df -i   # bytes vs INODES
du -sh ./* | sort -h    # space by dir
lsof +L1                # deleted-but-open files !
mount | column -t   cat /etc/fstab
mkfs.ext4 /dev/vg/lv    xfs_growfs /mnt
  • Stack: block dev → partition (GPT) → (LVM) → filesystem (ext4/xfs) → mount. ext4 shrinkable offline; xfs cannot shrink !
  • "No space left" but df shows free? → inodes exhausted (millions of tiny files), df -i !
  • Disk full after rm? A process holds the deleted file open — space frees only when the fd closes. lsof +L1 → restart the holder !
  • LVM: PV → VG → LV. Grow online: lvextend -r -L +10G /dev/vg/lv (-r resizes FS too). Snapshots for backups.
  • RAID survives disk failure, not rm -rf/corruption — RAID ≠ backup !

Network Troubleshooting

ping -c3 host          # reachability (ICMP)
mtr host               # path + loss per hop
dig +short host        # DNS only
curl -sv https://host/ # verbose: DNS/TCP/TLS/hdrs
curl -I --resolve h:443:1.2.3.4 https://h/
nc -zv host 443        # is the port open?
tcpdump -ni eth0 port 443 and host 1.2.3.4

  • Triage in layers: link → IP/route → DNS → firewall → app. Isolate before fixing.
  • "Unknown host" = DNS; "100% loss" = reachability/firewall; TLS error = cert/SNI.
  • curl -v shows DNS, TCP, TLS handshake, and headers in one shot — start here.
  • --resolve bypasses DNS to test a specific backend behind a LB.

Containers & the Kernel

  • Containers are isolated processes, not VMs — built from kernel namespaces + cgroups + an overlay FS. Shared host kernel.
  • Namespaces isolate the view: pid, net, mnt, uts, ipc, user, cgroup. PID 1 inside ≠ PID 1 on host.
  • cgroups (v2) limit resources: --memory/--cpus map to cgroup limits. OOM can fire inside a cgroup while the host has RAM !
  • overlayfs: read-only image layers + a copy-on-write writable layer on top.
  • free/top/nproc inside a container report host totals unless cgroup-aware — your JVM/Go heap sizing may be wrong !
  • --privileged drops isolation — avoid; drop capabilities, apply seccomp, run non-root.

★ Troubleshooting Playbook

Server slow — first 60s

  • ☐ uptime (load vs nproc) → dmesg|tail → vmstat 1 / mpstat / pidstat / iostat -xz 1 / free -m: CPU-bound (%us), I/O-bound (%wa), or mem (swap si/so)?

Disk full (df 100%)

  • ☐ du -sh /* | sort -h to find it; df -i for inodes; lsof +L1 for deleted-open files → restart the holder.

High load, idle CPU

  • ☐ D-state / iowait — ps -eo state,pid,cmd | grep '^D', iostat -xz 1; suspect disk / NFS stall.

OOM killed a process

  • ☐ dmesg -T | grep -i oom; leak vs cgroup limit; free -h, per-proc RSS.

Service won't start

  • ☐ systemctl status svc + journalctl -u svc -e; config test; port conflict; daemon-reload after edits.

Can't SSH

  • ☐ ping → nc -zv host 22 (refused vs timeout) → firewall / sshd / key perms / host-key.

Port already in use

  • ☐ ss -tlnp | grep :PORT → kill or relocate the holder.

Cron job didn't run

  • ☐ absolute paths? output redirected? grep CRON /var/log/syslog / journalctl -u; env stripped, not your shell.

☐ Command Safety Checklist

  • ☐ rm -rf with a variable path — guard "${dir:?}" so an empty var can't wipe / !
  • ☐ Quote every "$var" / "$@"; never parse ls; use -- before user paths.
  • ☐ Test chmod -R/chown -R targets first — recursive on / or $HOME is fatal !
  • ☐ dd/mkfs/> on the wrong device destroys data — confirm with lsblk twice !
  • ☐ kill -9 only after TERM; it skips cleanup (corrupt state / stale locks).
  • ☐ Editing firewall/sshd remotely — keep a second session open or a timed rollback so you don't lock yourself out !
  • ☐ set -euo pipefail + ShellCheck on every script; redirect cron output somewhere.
  • ☐ Don't setenforce 0 / disable the firewall to "fix" a denial — read the audit log first.
