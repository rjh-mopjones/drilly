  • Inode = metadata (perms, owner, size, block ptrs) — not the name. ls -i.
  • Hard link = another name for the same inode (same FS, not dirs). Symlink = a path pointer (can cross FS, can dangle) !
  • Everything is a file (devices, sockets, pipes). First ls -l char: -file ddir llink b/cdevice pfifo ssocket.

  • SIGKILL/SIGSTOP can't be caught. Prefer TERM → let it clean up, then KILL.
  • Zombies = parent didn't wait(); fix the parent, not the zombie.
  • nice -n 10 cmd / renice: lower priority (−20 high … 19 low).

systemd

systemctl status|start|stop|restart nginx
systemctl reload nginx        # re-read config
systemctl enable --now nginx  # boot + start
systemctl daemon-reload       # after unit edit
systemctl list-units --failed
journalctl -u nginx -f        # follow logs
journalctl -b -p err --since "1h ago"
systemctl edit nginx          # drop-in override
systemd-analyze blame         # slow boot units
  • enable ≠ start: enable = at boot; start = now.
  • Deps: Requires= (hard) vs Wants= (soft) vs After= (order only).
  • Restart=on-failure + RestartSec= for crash recovery.
  • Limits via unit: MemoryMax=, CPUQuota= (cgroups).

Bash Scripting Quick-ref

#!/usr/bin/env bash
set -euo pipefail          # fail fast + safe
trap 'rm -f "$tmp"' EXIT   # cleanup

name="${1:?usage: deploy NAME}"   # required arg
for f in *.txt; do echo "$f"; done
while read -r line; do :; done < file
if [[ -f "$path" && -n "$var" ]]; then :; fi
count=$(( a + b ))
  • Always quote "$var" — unquoted = word-split + glob = the #1 bug !
  • [[ ]] (bash test) > [ ]; (( )) for arithmetic.
  • set -e exit on error · -u unset var = error · -o pipefail catch pipe failures.
  • Run ShellCheck. Reach for Python when it outgrows bash.

  • >file 2>&1 ≠ 2>&1 >file — redirections apply left-to-right !
  • cmd | while read runs in a subshell → variable changes don't escape !

Memory & Swap

free -h        # used / free / buff/cache / available
vmstat 1       # si/so = swap in/out; r/b = run/block
cat /proc/meminfo
dmesg -T | grep -i oom
  • "free" is low, that's normal — the kernel uses RAM as page cache; look at available, which counts reclaimable cache. Cache ≠ leak !
  • OOM killer fires on true exhaustion; picks high oom_score. Evidence in dmesg: "Out of memory: Killed process".
  • VSZ (virtual, cheap) vs RSS (resident, real RAM).
  • In containers, cgroup memory limit → OOM inside the cgroup while host has RAM !
  • swappiness (0–100) tunes swap eagerness.

CPU, Load & Disk

uptime            # load avg 1/5/15 min
top   # %us %sy %id %wa(iowait) %st(steal!)
vmstat 1   mpstat -P ALL 1   iostat -xz 1
df -h     df -i   # bytes vs INODES
du -sh ./*        # space by dir
lsblk    lsof +L1 # deleted-but-open files !
  • Load counts R + D (uninterruptible I/O) tasks — high load with idle CPU = I/O wait or blocked, not CPU ! Compare load to core count.
  • %st steal = hypervisor starving your VM.
  • "No space left" but df shows free? → inodes exhausted (df -i) !
  • Disk full after rm? A process holds the deleted file open — lsof +L1, restart it !
  • Grow LVM online: lvextend -r -L +10G /dev/vg/lv.

Networking

ip addr    ip route    ip -s link
ss -tlnp             # listening TCP + owning proc
ss -tan state established
dig +short example.com   dig @1.1.1.1 A host
getent hosts example.com # respects nsswitch
resolvectl status        # systemd-resolved
  • ss > netstat; ip > ifconfig.
  • DNS order: /etc/nsswitch.conf → /etc/hosts then DNS (/etc/resolv.conf).
  • Lots of TIME_WAIT = normal on the side that closed; tune only if exhausting ports.
  • Connection refused = reached host, nothing listening / RST. Timeout = firewall drop or unreachable !

Network Troubleshooting

ping -c3 host          # reachability (ICMP)
mtr host               # path + loss per hop
dig +short host        # DNS only
curl -sv https://host/ # verbose HTTP(S)
curl -I --resolve h:443:1.2.3.4 https://h/
nc -zv host 443        # port open?
tcpdump -ni eth0 port 443 and host 1.2.3.4
openssl s_client -connect host:443
  • Triage in layers: link → IP/route → DNS → firewall → app.
  • "Unknown host" = DNS; "100% loss" = reachability/firewall.
  • curl -v shows DNS, TCP, TLS, and headers in one shot.

SSH & Hardening

ssh-keygen -t ed25519
ssh-copy-id alice@web01
# /etc/ssh/sshd_config
PermitRootLogin no
PasswordAuthentication no
# ufw
ufw default deny incoming; ufw allow 22/tcp; ufw enable

  • Key auth only; disable root login & passwords; keep the box patched.
  • Firewalls: nftables (successor) / iptables; frontends ufw (Debian), firewalld (RHEL); default-deny.
  • fail2ban bans brute-force. Key files chmod 600; never commit secrets !
  • SELinux denials look like app bugs — check ausearch/audit2allow before disabling.

Debugging Tools

strace -f -e trace=open,connect -p <pid>
strace -c cmd            # syscall time summary
lsof -p <pid>            # open files
lsof -i :443            # who owns the port
lsof +L1                # deleted-but-open
cat /proc/<pid>/limits   # ulimits
perf top                # live CPU hot funcs
  • Process hangs? strace -p shows the syscall it's stuck in (often a read/connect).
  • "Too many open files" (EMFILE) → raise ulimit -n / LimitNOFILE= !
  • 60-sec triage: uptime dmesg vmstat mpstat pidstat iostat free sar top.

Containers & the Kernel

  • Containers are isolated processes, not VMs — built from kernel namespaces + cgroups + an overlay FS.
  • Namespaces isolate the view: pid, net, mnt, uts, ipc, user.
  • cgroups limit resources: --memory/--cpus map to cgroup limits (v2). OOM can fire inside a cgroup while the host has RAM !
  • overlayfs: read-only image layers + a copy-on-write writable layer.
  • free/top inside a container may report host memory/CPU unless cgroup-aware !
  • --privileged drops isolation — avoid; drop capabilities, use seccomp.

★ Troubleshooting Playbook

Server slow

  • ☐ uptime (load vs cores) → top/vmstat 1: CPU-bound (%us), I/O-bound (%wa), or mem (swap si/so)?

Disk full (df 100%)

  • ☐ du -sh /* | sort -h to find it; check df -i for inodes; lsof +L1 for deleted-open files → restart the holder.

High load, idle CPU

  • ☐ D-state tasks / iowait — ps -eo state,pid,cmd | grep '^D', iostat -xz 1; suspect disk/NFS.

OOM killed a process

  • ☐ dmesg -T | grep -i oom; check leak vs cgroup limit; free -h, per-proc RSS.

Service won't start

  • ☐ systemctl status svc + journalctl -u svc -e; config test; port conflict.

Can't SSH

  • ☐ ping → nc -zv host 22 (refused vs timeout) → firewall/sshd/key/host-key.

Port already in use

  • ☐ ss -tlnp | grep :PORT → kill/relocate the holder.

☐ Command Safety Checklist

  • ☐ rm -rf with a variable path — guard "${dir:?}" so an empty var can't wipe / !
  • ☐ Quote every "$var" / "$@"; never parse ls.
  • ☐ Test chmod -R/chown -R targets first — recursive on / is fatal !
  • ☐ dd/mkfs/> on the wrong device destroys data — confirm with lsblk !
  • ☐ kill -9 only after TERM; it skips cleanup (corrupt state/locks).
  • ☐ Editing firewall/sshd remotely — keep a session open / use a timeout rollback so you don't lock yourself out !
  • ☐ set -euo pipefail + ShellCheck on every script.
