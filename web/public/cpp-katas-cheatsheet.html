Attack Plan — Ownership First

Turn the prompt into a lifetime plan before writing logic. Every C++ decision starts with ownership made explicit: owns a resource → RAII + rule of five; owns nothing → rule of zero, no special members.

The first questions

  • Owns a resource? yes → release in the dtor (runs on every path: return, early return, throw), reason about all five members. no → write none.
  • Copy, move, or neither? unique resource = move-only (=delete copies, define moves); value type = copyable; a view owns nothing.
  • const-correct? read-only methods const; read-only params const&. It's the API contract.
  • Raw storage? separate allocation (operator new, aligned) from construction (placement new, destroy_at).
  • Shared across threads? pick the primitive deliberately (mutex / atomics / seqlock / lock-free) + name the memory ordering — the compiler guarantees nothing.

! A moved-from object must stay valid & destructible (empty-but-safe, like a nullptr unique_ptr) — never broken. Move transfers ownership; it is not a fast copy.

Clarify & Design First — the questions that set up every kata

Open with clarifying questions out loud — they show you design before typing, and each answer pins a decision the implementation depends on. The ownership answer is the design.

  • Design the class + its special members first — deleting copies and defining moves already encodes "unique, transferable resource" before a single method body exists.

Value Semantics & const-correctness

Every type's public surface is a set of promises. Encode them in the signature so the compiler and the reader both see the contract.

  • Read-only methods const: is_open() const, size() const — a non-const observer is a lie the caller can't const-qualify around.
  • Read-only params const&: send(const Order&) — no copy, no mutation, callable with a temporary.
  • Observers are const noexcept: they neither change state nor throw; mark both.
  • Rule of zero for non-owners: a view / value aggregate owns nothing → write none of the five, let the compiler default them.
  • Moved-from = valid & unspecified, never broken: destructible, and every method still defined (here send throws, is_open() is false).
// copy-and-swap: one exception-safe assignment for BOTH copy & move
void swap(T& o) noexcept { using std::swap; swap(a_,o.a_); swap(b_,o.b_); }
T& operator=(T o) noexcept { swap(o); return *this; }  // o is the copy/moved temp

! A swap member + free swap makes std::swap allocation-free and noexcept, and collapses copy/move-assign into one line — the copy-and-swap idiom.

Testing Toolkit — Harness + StartGate + TSan

No GoogleTest/Catch2 — a ~100-line hand-rolled header (solution/common/harness.hpp) driven by CTest, keeping the module std-only. Practice ships no tests; writing them is half the exercise.

#include "harness.hpp"
KATA_TEST(overwrites_oldest_when_full) {   // auto-registers
    TickBuffer<int> buf(2);
    buf.record(1); buf.record(2); buf.record(3);
    EXPECT_EQ(buf.size(), 2u);
    EXPECT_EQ(buf.snapshot(), (std::vector<int>{2,3}));
}
KATA_TEST(latest_on_empty_throws) {
    EXPECT_THROWS(TickBuffer<int>(4).latest(), std::out_of_range);
}
KATA_MAIN()   // expands to main(); runs all, argv[1] filter
  • EXPECT_TRUE/EQ/THROWS(expr,Exc) — failures print file:line + values. Test the throw path, not just happy path.
  • Lifetime katas: a live-instance counter is the instrument — a leak never returns to 0, a double-free goes negative.
  • Concurrency = two checks: an invariant assertion (self-consistency / FIFO / conserved count) and TSan (a race is UB that often looks fine).
kata::StartGate gate;               // std::latch: all wait(), open() releases together
std::vector<std::jthread> ws;        // auto-join at scope end
// ... gate.wait() in each worker → max overlap → exposes torn/lost value
gate.open();

! Never sleep to synchronise (flaky coin-flip); gate with a std::latch, join deterministically, assert an invariant not an interleaving. TSan (-fsanitize=thread) is Go's -race analogue.

exchange_session — Move-Only RAII / Rule of Five

Topic: RAII + rule of five. A venue connection: ctor connects, dtor disconnects exactly once. Sessions are moved (factory return, emplace_back, reassign). unique_ptr by hand.

class ExchangeSession {
  ~ExchangeSession() noexcept;                  // release once
  ExchangeSession(const ExchangeSession&) = delete;   // one owner
  ExchangeSession& operator=(const ExchangeSession&) = delete;
  ExchangeSession(ExchangeSession&&) noexcept;         // steal + null src
  ExchangeSession& operator=(ExchangeSession&&) noexcept;
  void send(const Order&);   bool is_open() const noexcept;
  static int live_count() noexcept;  // leak / double-close detector
};
  • Move ctor: steal members, then other.open_ = false — that one line makes the source's dtor a no-op. Forget it → double decrement, live_count() hits -1.
  • Move-assign: close() what you own first (else leak the old conn), then steal, then null source; guard this != &other.
  • Route both release sites through one private close() — noexcept + idempotent (if(open_)), so "release exactly once" lives in one place.
  • Test: assert live_count() around every scope — no-double-close-after-move (not -1) and move-assign-releases-previous (not 2).
  • Every observer const noexcept: is_open, venue, sent, live_count — no ownership stake, no throw.
  • Extension: back it with a real int fd you dup/close so a leak or double-close is a loud ASan report, not a silent counter drift.

! Gotcha: shared_ptr "to avoid move complexity" models the domain wrong — a venue slot has one owner; move-only is the honest encoding.

! Gotcha: deleting copy stops double-ownership by copy — the move path must still null the source or you double-close through it.

tick_buffer — Raw Aligned Storage + Placement New

Topic: manual object lifetime over raw storage. Fixed-capacity rolling window of last N ticks; overwrite oldest when full; zero heap alloc per tick. Not vector<T> — it default-constructs every slot & may realloc.

::operator new(sizeof(T)*cap, std::align_val_t(alignof(T)))  // alloc once, raw
::new (slot) T(tick)                    // placement new: construct, no alloc
std::destroy_at(slot)                   // destroy, no free
// ring: head_ = oldest live idx, count_ = live; write = (head_+count_)%cap_
  • Destroy-before-overwrite: when full, destroy_at(write) before the placement-new, else the overwritten object's dtor never runs (leak).
  • Dtor destroys exactly the live range: walk count_ slots from head_ with wrap — never a never-constructed slot; then ::operator delete with the matching sized + aligned overload.
  • Ring math: head_+count_ can be 2*cap-1 → one modulo; latest() is head_+count_-1, not +count_.
  • Test: a Counted live-instance type — counted_live()<=cap in the loop (leak) and ==0 after scope (double-destroy).
  • Non-copyable, non-movable here (all four =delete): manual lifetime makes correct copy/move fiddly, and the kata is about the storage discipline, not the rule of five.
  • Extension: make it copyable — placement-new each live element from the source, leave the source's spare slots raw; that turns it into a full manual-lifetime container.

! Gotcha: placement new does not allocate — pairing it with plain delete, or under-aligning with plain operator new, is UB.

! Gotcha: vector<T>/new T[] default-construct every slot up front and may realloc — exactly the two costs this hot path forbids.

order_handle — Intrusive Reference Counting

Topic: rule of five on a shared resource. A pooled Order held at once by price-level queue + id-index + risk engine; alive while any owner references it, back to the pool on the last drop. A hand-rolled intrusive_ptr.

struct Order { ...; int ref_count{0}; };  // count INSIDE the resource
// copy bumps · move steals+nulls (count unchanged) · dtor/reset releases
OrderHandle& operator=(const OrderHandle& o) noexcept {
    Order* in = o.order_;
    if (in) ++in->ref_count;   // claim incoming FIRST
    release();                // then drop old — safe even if same slot
    order_ = in; return *this;
}
  • The sharpest line: copy-assign bumps before releasing. h = h; (or two handles to one order) would else reclaim the slot then re-point at freed memory — a use-after-free. Bump-first needs no this==&other guard.
  • Move transfers an owner: steal pointer, null source, count unchanged — only copy adds an owner.
  • Reclaim exactly once: the 0-transition lives in one release() called by dtor + reset; miss a decrement = leaked slot, double = live order recycled.
  • Null-safe accessors: use_count() on null is a defined 0, not a nullptr deref — the null handle is a first-class state.
  • Intrusive vs external: shared_ptr puts the count in a separate heap control block (an alloc + indirection); intrusive puts it inside the Order — one cache line, and a raw Order* promotes to a handle with no lookup.
  • Reclaim = recycle, not delete: the pool is a fixed vector<Order>; ref_count==0 just marks a slot free for a later acquire().

! Gotcha: plain int = single-thread only. A shared pool needs atomic<int>, fetch_sub(1,acq_rel) on the decrement-to-zero + a lock-free free-list.

! Gotcha: a slot recycled while it still rests in the book fills a recycled order — phantom fills, wrong price, exposure booked to the wrong account.

top_of_book — Seqlock (Atomic Payload, TSan)

Topic: seqlock + the C++ memory model. One writer installs a multi-word Quote; dozens of readers take the latest per tick — wait-free, no lock, no torn read (new bid stitched to stale ask).

// writer: even → odd(+1) → write payload → even(+2), +2 per publish
seq_.store(s+1, relaxed); atomic_thread_fence(release);
/* store each field relaxed */
atomic_thread_fence(release); seq_.store(s+2, relaxed);
// reader: snapshot → copy → recheck, return only if unchanged & even
b = seq_.load(acquire); if (b&1) continue;
/* relaxed-load fields */ atomic_thread_fence(acquire);
if (b == seq_.load(relaxed)) return out;
  • The whole tell: plain-payload copies are a data race → UB under the memory model even though the retry rejects every torn value. TSan flags it (Boehm & Adve).
  • Fix: each field a std::atomic accessed relaxed — same instruction on x86/ARM, race-free by definition.
  • Relaxed gives per-field atomicity, not group consistency — the sequence counter supplies that (else bid from N, ask from N+1).
  • Single writer only — two drive the odd/even counter and corrupt it; serialise writers with a mutex (readers stay lock-free).
  • Fences bracket the payload: two release fences pin the field stores strictly between odd and even; the reader's acquire fence pairs so seeing even ⇒ seeing the payload.
  • Relaxed is free: a relaxed load/store is the same instruction as a plain one on x86/ARM — you pay nothing for definedness.
  • Wait-free reads: a reader spins only while a publish is genuinely in flight, never on another reader — the odd-check + recheck is the whole protocol.

! Gotcha: a green stress run passes value asserts but is still UB — run under TSan. Extension: double-buffer (2 slots + atomic active-index) → no reader retries.

! Gotcha: drop the sequence re-check and relaxed atomics stitch bid from publish N to ask from N+1 — per-field atomicity is not group consistency.

feed_pipe — Lock-Free SPSC Ring

Topic: the std::atomic memory model. Feed-handler → strategy hand-off: exactly 1 producer, 1 consumer; no lock, no per-event alloc, never lose/dup/reorder. Wait-free SPSC ring.

// producer owns tail_, consumer owns head_ → single writer/index → NO CAS
std::optional<T> try_pop() {
  auto h = head_.load(relaxed);                 // I own head
  if (h == tail_.load(acquire)) return nullopt; // empty
  T v = std::move(slots_[h]);                   // plain read
  head_.store(next(h), release); return v;      // publish
}
alignas(64) atomic<size_t> head_, tail_;  // separate cache lines
  • No CAS: one writer per index → a release store suffices (CAS is only for MPMC).
  • Plain T slots are race-free: the producer writes slot then release-stores tail; consumer acquire-loads tail before reading slot — the edge synchronizes-with, one accessor per slot at a time. (Opposite of the seqlock, where both touch the payload → atomic.)
  • One-empty-slot: cap+1 slots — head==tail empty, tail+1==head full, no shared size counter.
  • Load your own index relaxed; the cross-thread index acquire. alignas(64) kills false sharing.
  • Wait-free both ends: single writer per index → each op is a bounded number of steps, no spin, no retry loop (stronger than lock-free).
  • Support move-only payloads: try_push(const T&) + try_push(T&&); pop does std::move(slots_[head]).
  • Money stakes: a dropped event is a missed fill; a duplicated event is a phantom position — the strictly-increasing-seq assert is what catches both.

! Gotcha: reflexive seq_cst works but costs throughput; atomic slots are needless. Test: StartGate-gated producer/consumer asserting strictly-increasing seq, under TSan.

! Gotcha: sizing to capacity with a shared size counter re-introduces contention + a CAS — the cap+1 one-empty-slot trick avoids the counter entirely.

Sanitizers — ASan / TSan / UBSan (the compiler proves nothing)

The whole module's premise: for lifetime and races the compiler is silent, so a green run is the start, not the proof. Sanitizers are how you actually check. They instrument the binary — build a separate tree per sanitizer, they don't compose freely (ASan+TSan can't share one build).

ToolCatchesKata
ASan -fsanitize=addressuse-after-free, leak, double-free, OOB, bad new/delete pairingsession (real fd), tick_buffer, order_handle
TSan -fsanitize=threaddata races, bad lock order — the -race analoguetop_of_book, feed_pipe
UBSan -fsanitize=undefinedsigned overflow, misaligned access, bad casts, nullptr derefalignment / ring math
cmake -B build-tsan -DKATAS_SANITIZE=thread && cmake --build build-tsan
ctest --test-dir build-tsan -R top_of_book   # and feed_pipe
  • TSan reports both stacks of a racing write/read — it proves the seqlock's fences and the ring's head/tail hand-off are actually sound, not "green on my machine".
  • A green stress run under no sanitizer is worthless for races — a data race is UB that usually looks fine; only TSan (or prod, eventually) reveals it.
  • Portable fallback: a self-consistency invariant (every field derived from one counter) catches torn/lost/dup values even where Apple's arm64 TSan runtime won't launch.

! ASan/TSan add overhead and change timing — they are for correctness runs, not the latency numbers you quote.

feed_parser — Zero-Copy Parse (string_view + from_chars)

Topic: fast delimited text. One record per line SYM|BID|ASK|QTY, millions/sec. A single malformed line must not throw, not allocate wildly, not abort the stream — report it with its line number and skip. The reflexive stringstream/stod parse is wrong 3 ways.

// valid only if WHOLE view parsed: no error AND ptr reached the end
bool parse_u64(std::string_view s, uint64_t& out) noexcept {
  if (s.empty()) return false;
  auto [p,ec] = std::from_chars(s.data(), s.data()+s.size(), out);
  return ec == std::errc{} && p == s.data()+s.size();
}
std::string_view fields[5];   // 4 valid + 1 overflow sentinel → n!=4 catches BOTH too-few/too-many
// on_quote(line, Quote{ std::string(symbol), bid, ask, qty });  // symbol COPIED — view dangles next getline
  • Why not stod/stringstream: it throws on bad input (aborts the feed), allocates per field, and is locale-sensitive (comma-decimal misreads 1.95). from_chars does none.
  • Whole-field check: ec==errc{} is not enough — from_chars("1.0x") parses 1.0 with no error, leaving ptr short. Also require ptr==last, else garbage-suffixed prices slip in.
  • Unsigned rejects the sign for free: parse qty into uint64_t → -5 fails as InvalidQty, no hand-rolled sign check.
  • Physical line numbers: ++line_no before the blank/comment skip, so error lines match the raw file.
  • Fixed order, short-circuit: count → empty-symbol → bid → ask → qty; one error per bad line.
  • Streaming, not collecting: parse_feed fires a callback per line (constant memory over a multi-GB replay); parse_all is a thin collector on top.

! Gotcha: a field string_view points into the reused getline buffer — storing it in the Quote is a use-after-free the moment the next line loads. Anything outliving the line (the symbol) must be copied into an owning std::string.

Memory Ordering — relaxed / acquire / release & synchronizes-with

The three orderings you actually use, and the one edge that makes lock-free hand-offs sound. Load your own index relaxed; the cross-thread index acquire; publish with release.

OrderUse
relaxedatomicity only, no ordering — self-owned index, seqlock payload fields
acquirea load; everything the matching release wrote becomes visible after it
releasea store; everything written before it is visible to the paired acquire
acq_rela read-modify-write (refcount fetch_sub-to-zero)
seq_cstcorrect default, single global order — but a full barrier; overkill on hot paths

synchronizes-with: a release store that a later acquire load reads creates a happens-before edge — the producer's plain slot write is ordered before the consumer's plain slot read, so it's not a race.

The load-bearing contrast

SPSC ringseqlock
who touches payloadone accessor/slot at a timeboth concurrently
payload typeplain T (edge orders it)per-field atomic, relaxed
reader blocks?no (wait-free)retries only mid-write
needs CAS?no (1 writer/index)no (1 writer)
  • Relaxed ≠ consistent group: relaxed gives per-field atomicity, never group ordering — the sequence counter (seqlock) or the index edge (ring) supplies that.
  • False sharing: alignas(64) puts head/tail on separate cache lines — else each op dirties one shared line, bouncing it between cores (or hardware_destructive_interference_size).

! A plain-payload seqlock is a data race → UB by the memory model even though the retry rejects every torn value (Boehm & Adve). TSan flags it; relaxed atomics fix it at zero cost on x86/ARM.

★ Pre-Code Checklist

Design (before typing)

  • ☐ Decided ownership first: owns a resource → RAII + rule of five; owns nothing → rule of zero.
  • ☐ Copy / move / neither chosen deliberately; unique resource = move-only (=delete copy).
  • ☐ Read-only methods + params marked const.
  • ☐ Raw storage: allocation (operator new+aligned) separated from construction (placement new).

Lifetime

  • ☐ Moved-from source left valid & inert (nulled) so its dtor is a no-op.
  • ☐ Dtor + release path noexcept; release routed through one idempotent site, fires exactly once.
  • ☐ Every placement new has a matching destroy_at; free with the sized, aligned operator delete.

Concurrency

  • ☐ Memory ordering is minimal + justified: relaxed self-load, acquire cross-load, release publish.
  • ☐ Seqlock payload is per-field atomic (relaxed); sequence supplies group consistency; single writer.
  • ☐ SPSC: no CAS, one-empty-slot full/empty, alignas(64) on head/tail.
  • ☐ Ordering picked by role: relaxed self-index, acquire cross-index, release publish — not reflexive seq_cst.

Parsing / text

  • ☐ from_chars not stod (no throw / alloc / locale); field valid only if ec==errc{} and ptr==last.
  • ☐ qty parsed unsigned (rejects -); anything outliving the line copied out of the reused buffer; line numbers physical.

Tests first

  • ☐ Hand-rolled harness (no GoogleTest); throw path tested; live-instance counter on lifetime katas.
  • ☐ Concurrency = StartGate-gated jthreads asserting an invariant, verified under TSan.
