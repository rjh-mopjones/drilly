Attack Plan — the loop

Open-ended prompt → working tested code in the time box. Three collapsing funnels: ambiguity → spec → API → impl. Never write 50 lines then hope.

1 · Clarify (~3 min)

  • Bounds: bounded? capacity? at the limit — evict, block, or reject?
  • Nulls/args: null keys/values? bad args throw or ignore? (decides assertThrows tests)
  • Concurrency: single- or multi-threaded? Biggest fork — changes data structures (HashMap vs ConcurrentHashMap) and adds a stress group !
  • Ordering/ties: eviction order? tie-break? (LRU=recency, LFU=freq then recency)
  • Return shape: miss = Optional.empty() / null / throw? Signature falls out of this.

2 · Smallest API (~3 min)

Write the interface before logic. Minimal methods; signatures that make invariants expressible.

interface Cache<K,V> {
  Optional<V> get(K k);   // miss = empty
  void put(K k, V v);      // evicts on overflow
  int size();              // in [0, cap]
}

3 · Tests first, in order

Contract (happy round-trip) → Core (the thing the kata is about) → Edges (cap 1, empty, dup keys, null/neg → throws) → Concurrency (stress). Make one group green at a time.

4 · State complexity out loud

Commit time and space Big-O before/after. Interviewers grade the reasoning, not the green bar.

Concurrency Stress Harness

The reusable template that makes a real race fail. N threads released together by a start-gate, hammer the SUT, join, assert an invariant a lost update would break.

int threads=16, iters=10_000;
var pool  = Executors.newFixedThreadPool(threads);
var start = new CountDownLatch(1);   // start-gate
var done  = new CountDownLatch(threads);
var sut   = new ConcurrentLruCache<Integer,Integer>(64);

for (int t=0; t<threads; t++) pool.submit(() -> {
  start.await();                     // all block here
  for (int i=0;i<iters;i++){ sut.put(i%128,i); sut.get(i%128); }
  done.countDown(); return null;
});
start.countDown();                   // release together
assertTrue(done.await(10, SECONDS)); // no deadlock
pool.shutdownNow();
assertTrue(sut.size() <= 64);        // invariant holds
  • Start-gate (CountDownLatch(1)) maximises overlap so contention actually happens.
  • Assert an invariant, not exact values !: size<=cap, transfers sum to 0, dequeued==enqueued, "ran exactly once".
  • Turn up threads × iters; collect Future.get() so a blown-up worker fails the test, not dies silently.

Inject the clock — test time without sleeping !

Time-based katas are only deterministic if time is an input, not System.nanoTime() buried inside.

class TokenBucket {
  private final LongSupplier nanos;   // inject
  TokenBucket(int cap,double perSec,LongSupplier nanos){…}
}
@Test void refills_after_1s(){
  long[] now={0};
  var b=new TokenBucket(10,10,()->now[0]);
  drain(b); assertFalse(b.tryAcquire());
  now[0]=1_000_000_000L;              // advance 1s instantly
  assertTrue(b.tryAcquire());         // no real waiting
}
  • Same trick tests retry backoff, breaker OPEN→HALF_OPEN, scheduler due-times. A Thread.sleep(1000) in a test = slow, flaky !
  • No Mockito needed — a 10-line hand fake (fails twice, then succeeds) is clearer.

Cache — LRU

DS: HashMap for O(1) lookup + doubly-linked list for O(1) recency reorder. Head = MRU, tail = LRU (evict tail).

Optional<V> get(K k);   // hit → moveToHead
void put(K k, V v);      // update+moveToHead, or add;
                          // if size>cap evict tail
  • Use a sentinel head/tail node so unlink/insert never null-checks. Store node refs in the map so removal is O(1).
  • ! LinkedHashMap(cap,0.75f,true) + override removeEldestEntry is the 5-line version — mention it, then build the DLL by hand to show you can.
  • ! Node stores the key too, not just the value — eviction reads tail.prev.key to remove it from the map. Value-only nodes can't evict.
  • ! get must promote. A get that's a pure read is not an LRU — the get_promotes test exists to catch exactly this.
  • Pre-size the map to (int)(cap/0.75f)+1 so it never resizes mid-run.

Tests

  • contract: put/get round-trip · core: access reorders → LRU evicted first; cap-1 evicts on 2nd put · edge: update existing key doesn't grow size · Big-O: get/put O(1).

Ship answer: LinkedHashMap for a single-thread LRU; Caffeine (W-TinyLFU) in production — pure LRU suffers scan pollution, pure LFU suffers frequency bias, so real caches blend both.

Cache — LFU & Concurrent

LFU — frequency buckets

  • Map<K,V> + Map<K,int freq> + Map<int, LinkedHashSet<K>> freq→keys, and a minFreq pointer.
  • On access: bump freq, move key between buckets. Evict from freq[minFreq], oldest first (tie-break by recency). Reset minFreq=1 on insert.
  • ! Keep minFreq correct — after evicting the last key at minFreq, next insert resets it to 1. Getting this wrong evicts the wrong entry.

ConcurrentLruCache

  • Wrap the whole LRU in a single ReentrantLock; lock/try…finally unlock around get and put.
  • ! A ReadWriteLock is wrong here: get mutates recency (a write), so "readers" contend anyway. One plain lock is simpler and correct.
  • Test with the stress harness → assert size<=cap after 16×10k ops.

Bounded Blocking Queue

DS: ring buffer / ArrayDeque + one ReentrantLock + two Conditions: notFull, notEmpty.

void put(T x){ lock.lock(); try {
  while (count==cap) notFull.await();   // WHILE, not if !
  enqueue(x); count++;
  notEmpty.signal();
} finally { lock.unlock(); } }

T take(){ lock.lock(); try {
  while (count==0) notEmpty.await();
  T x=dequeue(); count--;
  notFull.signal(); return x;
} finally { lock.unlock(); } }
  • ! Guard the wait with while, never if — spurious wakeups + multiple waiters mean the condition can be false again on wake. An if proceeds on invalid state → lost/duplicated item.
  • Signal the opposite condition; a producer signals notEmpty, a consumer signals notFull. Signalling your own side wakes threads that can't progress.
  • ! Never one condition + signal(): it can wake a producer when only consumers can run → re-blocks → the queue stalls under load. Use two conditions + signal(), or one + signalAll().
  • With a circular array, head==tail is ambiguous (empty vs full) — keep a separate size counter to disambiguate.
  • Use lockInterruptibly() so a blocked put/take stays cancellable.
  • Tests: contract FIFO · producer blocks when full, unblocks on take (assertTimeoutPreemptively) · concurrency: N producers + N consumers, assert dequeued==enqueued, none lost.

Ship answer: ArrayBlockingQueue — this is a teaching re-implementation.

Concurrency: hold state (tokens+lastRefill) in one immutable object behind AtomicReference; tryAcquire = compute-new-state + compareAndSet loop (lock-free CAS).

boolean tryAcquire(){
  while(true){
    State s=ref.get();
    State n=refill(s, nanos.getAsLong());
    if(n.tokens<1) return false;
    State a=n.spend(1);
    if(ref.compareAndSet(s,a)) return true; // retry on race
  }
}
  • ! Inject the clock (LongSupplier nanos) so refill tests advance time instantly. Compute refill from elapsed nanos, don't run a timer thread.

Circuit Breaker

States CLOSED → OPEN → HALF_OPEN. Injected clock drives the timeout.

StateBehaviour
CLOSEDcalls pass; count failures. ≥ threshold → OPEN.
OPENfail-fast (reject) until openTimeout elapsed → HALF_OPEN.
HALF_OPENallow a trial call: success → CLOSED (reset); failure → OPEN (restart timer).
  • Signature <T> T call(Supplier<T> action) — throws / rejects when OPEN.
  • ! Never hold the lock across action.get() — that serialises every caller into a global mutex. Read state under lock, release, run the action, re-acquire to record the outcome.
  • ! Record the outcome against the state captured at dispatch, not a re-read — if another thread trips the breaker mid-flight, re-reading corrupts HALF_OPEN trial counting.
  • Do OPEN→HALF_OPEN lazily on the next call — no background timer thread. Re-stamp openedAtNanos on every trip so a HALF_OPEN failure restarts the timer.
  • Make CircuitOpenException unchecked — it's operational state, not a domain error.
  • ! Test the transition table with the injected clock: force N failures → assert OPEN rejects; advance past timeout → assert one trial allowed (HALF_OPEN); trial fails → OPEN again. No sleeping.
  • Pairs with retry: breaker stops hammering a dead dep; retry handles transient blips. Ship: Resilience4j.

Retry — Backoff + Jitter

Retry transient failures with exponential backoff (base·2^n) capped at maxDelay, plus jitter to avoid thundering-herd sync.

<T> T withRetry(Supplier<T> op){
  for(int n=0;;n++){
    try { return op.get(); }
    catch(Exception e){
      if(n==maxRetries) throw e;      // give up
      long d=min(base*(1L<<n), maxDelay);
      sleeper.sleep(d/2 + rnd(d/2));  // full/equal jitter
    }
  }
}
  • ! Inject the sleeper (LongConsumer/fake) — tests assert the backoff sequence without real waiting, and count attempts (fail-twice-then-succeed fake → 3 calls).
  • Only retry idempotent / transient failures; never retry a 4xx or a validation error.
  • Tests: succeeds first try = 1 call · succeeds on 3rd = 3 calls · exhausts → rethrows last · delays match schedule.

Connection Pool & Idempotency

Connection Pool

  • Semaphore(cap) bounds borrowers. borrow() = sem.acquire() then poll a concurrent idle queue (or create). release() = return to queue + sem.release().
  • Validate on borrow: if the pooled conn is dead, discard and make a fresh one before handing out.
  • ! Release the permit only after requeuing the resource — reverse it and another thread over-creates past maxSize. The #1 way to fail this kata.
  • ! After a successful acquire, an empty idle queue means create, not "exhausted" — the permit is your proof you're under cap.
  • ! release() exactly once in a finally; a leaked permit shrinks the pool forever. Timeout on borrow returns null (cheap, caller-driven), exception only on interruption.
  • Non-fair semaphore is the right default (throughput > strict FIFO); create lazily on first borrow, not eagerly.
  • Tests: cap-N pool → (N+1)th borrow blocks until a release; stress → never exceed N live.
  • Ship: HikariCP — size ≈ cores×2 + spindles; bigger pools are usually slower. Adds max-lifetime, idle eviction, keep-alive pings.

Idempotent Processor

  • Exactly-once dedup keyed by request id. ConcurrentHashMap.computeIfAbsent(id, k -> process()) — the map's per-bin lock guarantees the mapping fn runs once even under concurrent dupes.
  • ! Don't containsKey-then-put (TOCTOU race — two threads both process). computeIfAbsent is the atomic move.
  • Test: 16 threads submit the same id → assert the side effect ran once (AtomicInteger==1).

Scatter-Gather Aggregator

Fan out to N sources in parallel, gather within a deadline, tolerate partial failure.

List<CompletableFuture<R>> fs = sources.stream()
  .map(s -> CompletableFuture
     .supplyAsync(() -> s.fetch(), pool)
     .orTimeout(200, MILLISECONDS)
     .handle((v,e) -> e==null ? v : FALLBACK))  // survive one dead source
  .toList();
CompletableFuture.allOf(fs.toArray(new CompletableFuture[0]))
  .join();
List<R> out = fs.stream().map(CompletableFuture::join).toList();
  • allOf waits for all; per-future orTimeout + handle converts a slow/failed source into a fallback instead of sinking the whole batch.
  • ! Without per-future timeout, one hung source hangs the aggregate. Use assertTimeoutPreemptively to prove the deadline holds.
  • Tests: all succeed → merged · one throws → fallback in result · one slow → returns by deadline.

Event Bus & Scheduler

Event Bus (sync pub/sub, Observer)

  • Map<Class<?>, CopyOnWriteArrayList<Handler>>. publish(e) dispatches to handlers keyed by e.getClass().
  • CopyOnWriteArrayList lets a handler subscribe/unsubscribe during dispatch without ConcurrentModificationException !
  • Test: subscribe → publish → handler ran; unsubscribe → not called; two subs both fire.

Task Scheduler (delayed exec)

  • DelayQueue<Task> (Task implements Delayed, compares by due-time) + one worker thread looping queue.take() (blocks until the head is due).
  • ! DelayQueue.take() returns only when delay expired — no busy-poll. It also unparks early when a sooner task arrives; a sleep-loop can't be woken to re-examine a new head.
  • ! compareTo uses Long.compare(dueA,dueB), never (int)(a-b) — the cast overflows and mis-orders the heap. Use monotonic nanoTime, not wall-clock, end to end.
  • ! Wrap each task run in a try/catch — a throwing Runnable otherwise kills the worker silently and stops the scheduler forever.
  • Shutdown idiom: interrupt → catch InterruptedException → restore flag → break → join(timeout). Check cancellation after take(), not before (a task can be cancelled while parked). Ship: ScheduledThreadPoolExecutor.

Bank — Deadlock-Free Transfer

DS: per-account ReentrantLock, balances in BigDecimal (never double for money !).

void transfer(Account a, Account b, BigDecimal amt){
  Account first  = a.id < b.id ? a : b;   // lock ordering !
  Account second = a.id < b.id ? b : a;
  first.lock.lock();
  try { second.lock.lock();
    try { a.debit(amt); b.credit(amt); }
    finally { second.lock.unlock(); }
  } finally { first.lock.unlock(); }
}
  • ! Always acquire in a global order (by account id min→max). Locking in argument order lets A→B and B→A deadlock.
  • Reject overdraft / negative amount before mutating.
  • Killer test: M threads do random transfers among K accounts; after join assert total balance unchanged (money is conserved) — an unsafe impl loses/creates money.

Cinema & Restaurant Booking

Cinema — hold / confirm / TTL

  • Per-screening lock. hold(seats) marks seats HELD with an expiry Instant; confirm(holdId) → BOOKED; expired holds auto-release.
  • ! Take the caller-supplied Instant (inject the clock) so TTL-expiry tests advance time — don't call Instant.now() inside.
  • Test: hold blocks re-hold of same seat; confirm within TTL succeeds; after TTL the seat frees and re-holds.

Restaurant — time-slot overlap

  • Per-table lock. Book [start,end) — half-open intervals so back-to-back slots (end==next start) don't collide.
  • Overlap test: aStart < bEnd && bStart < aEnd. ! Off-by-one here double-books or blocks adjacent slots.
  • Tests: overlapping request rejected; adjacent slot allowed; per-table isolation.

Parking Lot — Sealed Spots · Best-Fit

DS: sealed interface Spot permits Motorcycle, Compact, Large — model with a sizeRank so any vehicle fits a spot of equal-or-larger rank (LSP: subtypes substitute cleanly).

  • Best-fit park: choose the smallest free spot whose sizeRank >= vehicle rank (don't waste a Large on a bike).
  • Per-spot lock (or a concurrent free-set per size) so parking is fine-grained, not one global lock.
  • ! On leave(), null out the vacated slot / return it to the free-set — forgetting this leaks capacity and double-assigns.
  • Pattern-switch on the sealed type for exhaustive fee/size logic — compiler enforces all cases.
  • Tests: bike takes smallest fit; lot full → reject; leave frees the exact spot; concurrent park never double-assigns one spot.

Vending Machine — State + Change

Two sub-problems: a state machine + a change-making algorithm.

State machine

  • States IDLE → COLLECTING (coins in) → DISPENSING. sealed interface DispenseResult permits Ok, InsufficientFunds, SoldOut, NoChange — return it, don't throw for expected outcomes.

Change-making (greedy)

  • Plan then commit: compute the coin plan greedily (largest-first) against current inventory; only deduct coins if a full plan exists, else refund.
  • ! Greedy is correct only for canonical coin systems (1/5/10/25). Non-canonical denominations need DP — call this out.
  • Tests (@ParameterizedTest amount/paid/coins): exact change, needs change, can't make change → refund + no stock change.

Elevator Controller — LOOK

Algorithm: LOOK (SCAN without going to the ends). Keep two directional sets of pending stops.

  • TreeSet<Integer> up and TreeSet<Integer> down. Moving up → serve up.ceiling(cur)… in order; when none above, flip direction and drain down.
  • Dispatch: assign a request to the car with lowest cost (distance + direction agreement) — a car already heading your way beats a closer idle car going the other way.
  • ! A naive nearest-floor (SSTF) starves far requests; LOOK sweeps so every request is eventually served.
  • Tests: requests served in sweep order (not arrival order); direction flips only when no stop ahead; idle car parks; dispatch picks the cheaper car.

Limit Order Book — Price-Time

DS: two TreeMap<Price, ArrayDeque<Order>> — bids (desc) & asks (asc). TreeMap orders price levels; the deque holds FIFO time priority within a level.

  • Match: incoming buy crosses while bestAsk <= limit — fill against the front of the best ask level, walk deque then levels. Partial fills leave a resting remainder.
  • Price-time priority: best price first, then earliest order (FIFO) at that price. ArrayDeque = O(1) FIFO; TreeMap.firstKey() = O(log n) best price.
  • ! Trade prints at the resting price, not the aggressor's limit (price improvement) — the single most-tested assertion.
  • ! Partial fill keeps the resting order at the head with its original timestamp, only qty reduced — never move it to the back.
  • ! Bids need a reverseOrder() comparator so firstEntry() is the highest bid; natural order returns the lowest.
  • ! Money is BigDecimal compared with compareTo, never ==/equals — new BigDecimal("100").equals("100.0") is false (scale differs).
  • ! Remove an emptied price level from the map (else bestBid/bestAsk return phantom liquidity). Cancel uses a flat UUID→Order index — O(1), not an O(n) book scan.
  • Single lock around match (the next decision depends on the last fill — it's sequential, so one lock is both correct and faster than per-level locks). Tests: FIFO at a price, price priority across levels, partial fill rests, cancel removes.
  • Scale: shard per symbol, single-writer per book (LMAX Disruptor model) — don't parallelise one book.

Lock-Free Structures

CAS-based, no locks. Retry loop on compareAndSet.

Treiber stack

void push(T v){
  Node<T> n=new Node<>(v);
  Node<T> h;
  do { h=head.get(); n.next=h; }
  while(!head.compareAndSet(h,n)); // retry on race
}

Michael-Scott queue

  • Lock-free FIFO: separate head/tail AtomicReferences; CAS tail forward, then swing head. Handles the "tail lagging" case by helping advance it.

ABA problem !

  • A→B→A between read and CAS: value looks unchanged but the world moved. CAS succeeds wrongly.
  • Fix: AtomicStampedReference — pair the pointer with a version stamp; CAS checks (ref, stamp) so a reused node is detected. AtomicMarkableReference (one bit) is not enough — the mark cycles back.
  • ! Claiming "ABA can't happen on the JVM" is only true under plain GC — a free-list, object pool, or off-heap allocator reintroduces it.
  • Stress-test: N pushers + N poppers → assert count conserved, no lost/duplicated nodes. Single-threaded tests miss a missing retry loop entirely.

Rules of the CAS loop !

  • Step 2 (propose next state) must be pure — build a detached node; touch head/tail only at the CAS. A lost CAS is a cheap no-op that retries.
  • Always wrap in while(true); if(cas(...))return; alone silently drops ops under contention.
  • Michael-Scott: keep the helping branch ("advance tail if tail.next!=null") or one preempted enqueuer stalls everyone. The two enqueue CASes touch different locations (tail.next, tail) — they can't be one atomic step, which is why helping exists.
  • Exact lock-free size() isn't achievable with one CAS — offer isEmpty() and say why (a strong senior tell).

Feed Parser — Errors as Values

Turn a stream of SYMBOL|BID|ASK|QTY lines into a lazy Stream<ParsedLine>, each an Ok(quote) or Err(line,kind). Blank/#-comment lines are skipped but still counted. A bad tick is a value, never an exception — one fat-fingered line must not tear down the feed.

sealed interface ParsedLine permits Ok, Err {
  record Ok (int line, Quote q)    implements ParsedLine {}
  record Err(ParseError e)         implements ParsedLine {}
}
static Stream<ParsedLine> parse(Stream<String> in){
  var lineNo = new AtomicInteger(0);      // Stream has no index
  return in.<ParsedLine>mapMulti((raw,out)->{
    int n=lineNo.incrementAndGet();       // BEFORE the skip test
    String t=raw.trim();
    if(t.isEmpty()||t.startsWith("#")) return; // drop, counter ticked
    out.accept(parseLine(t,n));
  });
}
  • ! split("\\|", -1) — the negative limit keeps trailing empties, so "TOO|1|2|" is length 4≠3 and mis-classifies. Escape the pipe (bare | is regex alternation).
  • ! Physical line number: increment on every line incl. skipped ones, or later errors' positions drift. A record-index counter fails the canonical feed.
  • ! Long.parseLong("-5") succeeds — the non-negative rule is a separate if(qty<0) guard, not a caught exception.
  • ! Validate in a fixed order (count→symbol→bid→ask→qty), short-circuit on the first failure; coerce only after validating.
  • ! Stay lazy — mapMulti stream→stream, never collect internally, or findFirst/limit stop short-circuiting and an unbounded socket source hangs. Never parallel() (the counter assumes encounter order).
  • parseAll drains via an exhaustive switch over the sealed type — no default, so a future third arm breaks compile (the point).

Ship: bid/ask are double for the kata; a real pricing feed uses BigDecimal + a quoted-field escape rule + BufferedReader.lines() socket adapter.

Sealed Types & Result Modeling

Model a closed set of outcomes as a sealed interface and handle it with an exhaustive switch — the compiler proves no case is dropped, which beats nulls + a side-channel error list.

sealed interface DispenseResult
  permits Ok, InsufficientFunds, SoldOut, NoChange {}

String render(DispenseResult r){
  return switch(r){                 // no default —
    case Ok o              -> "vend "+o.item();
    case InsufficientFunds i-> "add "+i.shortfall();
    case SoldOut s         -> "sold out";
    case NoChange n        -> "refunded";
  };                                // adding an arm later
}                                   // breaks THIS switch at compile
  • Return, don't throw, for expected outcomes — exceptions are for the exceptional. Optional.empty() / a Result arm for a cache miss or a bad tick.
  • Pattern-switch on a sealed vehicle/spot type for exhaustive fee/size logic — the compiler enforces every case.
  • Records give you value semantics (equals/hashCode) free — ideal for immutable state snapshots (rate-limiter State, a parsed Quote) held behind an AtomicReference.
  • ! A default arm silently swallows a newly-added case — omit it so the compiler flags the gap.

★ Pre-Code Checklist

Before you type

  • ☐ Clarified bounds (capacity, at-limit behaviour), nulls/args, concurrency, ordering/ties, return shape.
  • ☐ Wrote the smallest API (interface + signatures) before any logic.
  • ☐ Stated the complexity budget (time and space) out loud.

Tests-first

  • ☐ Test list in order: contract → core → edges → concurrency; one group green at a time.
  • ☐ Edges: capacity 1, empty, duplicate key, null/negative → assertThrows.
  • ☐ Time-based? Injected clock — no Thread.sleep in tests.
  • ☐ Concurrent? Stress harness that asserts an invariant, not exact values; Future.get() surfaces worker crashes.

Concurrency correctness

  • ☐ Every lock unlock()ed in a finally.
  • ☐ while (not if) around every Condition.await().
  • ☐ Multi-lock paths acquire in a global order (deadlock-free).
  • ☐ Check-then-act replaced by an atomic (computeIfAbsent, CAS loop).
