Dimensional Model

  • Star: one fact + denormalized dimensions (fast, simple). Snowflake: normalized dims (less dup, more joins).
  • Fact = measures at a grain; dimension = descriptive context.
  • SCD2: keep history via valid_from/valid_to + is_current (new row per change). SCD1 = overwrite. !

Spark Model

  • Driver plans the DAG; executors run tasks on partitions.
  • Lazy: transformations build the DAG; an action triggers it.
  • Narrow (map/filter) = no shuffle; wide (join/groupBy) = shuffle !
  • DataFrame > RDD (Catalyst optimizes it).

Spark Optimization

  • Shuffle = network + disk + serialize → minimize wide ops.
  • Broadcast join a small table to skip the shuffle.
  • Skew: one hot key → straggler → salt the key / enable AQE skew join.
  • AQE re-optimizes at runtime; cache() reused DFs; watch spill in the UI. !

Stream Processing

  • Event time (when it happened) vs processing time (when seen) — use event time. !
  • Watermark: "no events older than T expected" → closes windows, drops late data.
  • Windows: tumbling (fixed, no overlap), sliding (overlap), session (gap-based).
  • Exactly-once = source offsets + checkpointed state + idempotent sink.

Warehouse

  • Columnar + MPP: scan only needed columns across many nodes.
  • Separate storage & compute (Snowflake/BigQuery/Redshift RA3) → scale independently.
  • Cost = bytes scanned → partition/cluster + select fewer columns. !
  • dbt = the T in ELT (SQL models, tests, incremental).

Ingestion & CDC

  • CDC log-based (Debezium reads WAL/binlog): captures inserts/updates/deletes, low DB load. !
  • Query-based (timestamp polling) misses deletes & hard-deletes.
  • Kafka Connect for no-code source/sink; Schema Registry for evolution.

Orchestration & Quality

  • Airflow DAGs: deps, retries, backfills — make tasks idempotent. !
  • dbt: transforms + tests (not_null/unique) + lineage.
  • Data quality: contracts, freshness/volume/schema monitoring — catch the silent data bug (green pipeline, wrong numbers).

☐ Design Playbook

  • ☐ Batch or streaming? latency SLA + freshness need + cost + complexity.
  • ☐ Streaming: Kafka → Flink/Spark → warehouse/OLAP; event time + watermarks.
  • ☐ Warehouse design: pick the fact grain, conformed dims, SCD2 for history.
  • ☐ CDC: Debezium → Kafka → lakehouse MERGE (idempotent upsert).
  • ☐ Real-time analytics: Druid/Pinot/ClickHouse; Lambda vs Kappa (replay).
  • ☐ Reliability: idempotency, exactly-once = at-least-once + dedup, DLQ, replay.
  • ☐ Slow Spark? shuffle/skew/spill — broadcast, salt, repartition, AQE.
  • ☐ Consumer lag? add partitions/consumers, speed the sink, check rebalancing.
