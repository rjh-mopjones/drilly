Floating-Point & Numeric Types

TypeBits / digitsUse
float32 / ~7bulk storage, SIMD/GPU only
double64 / ~15-16the default — prices, rates, vols, grids

Layout: 1 sign + 11 exp + 52 mantissa; value = (-1)^s · 1.m · 2^(e-1023). Only dyadic rationals exact — 0.1 repeats in binary, so 0.1+0.2 != 0.3 (prints 0.30000000000000004). Well-defined, not UB.

Never == two doubles !

bool near(double a, double b,
          double rel=1e-9, double abs_t=1e-12){
  double d = std::fabs(a-b);
  if (d <= abs_t) return true;          // near-zero
  return d <= rel*std::max(std::fabs(a),
                          std::fabs(b));
}
  • Combined abs+rel tol; a lone 1e-9 is too loose for tiny, too tight for large. ULP compare (bit-cast to int64) for last-bit validation.
  • numeric_limits<double>::epsilon() ≈ 2.22e-16 (spacing near 1.0). Assume every op injects ~1e-16 relative noise.

Cancellation & Stable Summation

Catastrophic cancellation: subtracting near-equal values annihilates leading digits; the ~1e-16 absolute noise survives and dominates. This is the precision floor of bump-and-revalue Greeks !

// noisy: numerator cancels, /2h amplifies !
delta = (price(S+h) - price(S-h)) / (2*h);

U-shaped error: big h → truncation bias, tiny h → cancellation. Optimum h ≈ eps^(1/3)·S ≈ 1e-5·S (central, 1st deriv). Real fix: AAD (analytic, no subtraction) or closed form (BS delta = N(d1)).

Reformulate, don't add precision

  • log(1+x) small x → std::log1p(x); exp(x)-1 → std::expm1(x).
  • 1-N(d) tail → complementary N(-d).
  • Quadratic root: use q=-0.5(b+copysign(disc,b)), then r1=q/a, r2=c/q.

Summing a P&L vector

double kahan(const std::vector<double>& x){
  double s=0, c=0;               // c = lost bits
  for(double v:x){ double y=v-c, t=s+y;
    c=(t-s)-y; s=t; }            // O(1) error
  return s; }

std::reduce (17) may pairwise-sum (not ordered like accumulate). For MC mean+variance use Welford, not E[x²]-E[x]².

NaN, inf & Money

  • inf: overflow / 1.0/0.0, exp(1000). NaN: 0.0/0.0, sqrt(-1), log(-1), inf-inf.
  • Both propagate — one stray NaN early poisons the whole MC average.
  • ! NaN == NaN is false; NaN < K and NaN > K both false, so if(price<barrier) silently mis-branches.
std::isnan(x);   // NOT x==NaN
std::isinf(y);
std::isfinite(z);  // not NaN and not inf

Validate at the boundary: reject T<=0, sigma<0, S<=0; debug assert(std::isfinite(result)) to fail fast.

Money is never a double !

double t=0; for(int i=0;i<10;++i) t+=0.1;
t == 1.0;    // false (0.9999999999999999)
int64_t cents = 1050;  // $10.50 exact
  • Model qty (price, vol, NPV) = double, approximate by nature. Ledger qty (settleable cash) = int64 minor units or a decimal type. Confusing them is a hard-fail.

RAII & Value Semantics

RAII: resource lifetime = object lifetime. Acquire in ctor, release in dtor; dtor runs at scope exit including on exception (stack unwinding). Cleanup is unmissable and deterministic — no GC pause at the wrong microsecond.

{
  std::lock_guard<std::mutex> g(book_mtx); // acquire
  update_book();                          // may throw
}   // g's dtor releases the lock — always
  • RAII covers any resource: locks, files, sockets, DB handles — not just memory.
  • Value semantics: a variable is its value; copies are independent, no null, no hidden sharing. Default; use refs/pointers only for deliberate sharing/indirection.
  • Deterministic destruction is why a desk can trust "lock released / buffer freed" at a precise instant. Manual mgmt leaks under exceptions; RAII makes leaks structurally impossible.

Ownership: Rule of 0/3/5 & Smart Ptrs

TypeCost / use
unique_ptr<T>zero overhead; sole owner, move-only — the default
shared_ptr<T>! atomic refcount + 2nd heap block; only for genuine shared ownership; avoid on hot path
weak_ptr<T>non-owning observer; breaks cycles; .lock() to use
  • Rule of 0 (the goal): write no special members; let vector/unique_ptr members manage resources.
  • Rule of 3/5: if you write one of dtor / copy-ctor / copy-assign (/ move-ctor / move-assign), you likely need all — only when hand-owning a raw resource.
  • No raw new/delete in modern code. make_unique/make_shared.
  • shared_ptr cycle = leak ! (refcounts never hit 0) — break with weak_ptr.

Move Semantics & Forwarding

vector<double> = small handle (begin,end,cap) over a big heap buffer. Copy = new alloc + O(n) element copy; move = swap 3 pointers, null the source, O(1). The point: return a 100MB matrix by value for the price of pointer swaps.

auto v = make_path();          // rvalue -> moved in
auto w = v;                    // lvalue -> COPIED
auto x = std::move(v);         // v's buffer stolen
  • std::move moves nothing — it's a static_cast to T&& (xvalue) enabling a move ctor.
  • ! return std::move(local) disables NRVO — usually slower. Just return local;.
  • ! std::move on a const object silently copies (move ctor needs non-const T&&).
  • Moved-from = valid but unspecified: reassign/destroy, don't read.
  • Mark move ctor noexcept or vector growth copies instead of moves !

Perfect forwarding

template<class T> void wrap(T&& x){       // T deduced =>
  sink(std::forward<T>(x)); }             // fwd ref

T&& with deduced T = forwarding ref (binds lvalue+rvalue); with a concrete type it's a plain rvalue ref.

Templates, CRTP & Policies

A template is a compile-time recipe: mean<double> stamps a double-specific, inlinable, vectorizable version — monomorphisation (unlike Java's erasure-to-Object). Move dispatch from run time to compile time.

CRTP — static polymorphism, no vtable

template<class D> struct Payoff{
  double value(double S) const{
    return static_cast<const D&>(*this).impl(S);
  }
};
struct Call : Payoff<Call>{ double K;
  double impl(double S) const{return std::max(S-K,0.0);} };
  • Call resolves + inlines at compile time; loop vectorizes. Cost: no runtime type choice, no heterogeneous vector<Base*>, code bloat, worse errors.
  • Policy-based design: inject RNG/payoff/discount as template params, composed at compile time.
  • if constexpr (17): untaken branch is discarded, need not compile for that type.

Expression Templates & Concepts

Expression template: operator+ returns a tiny node describing the op, not the result; the whole tree evaluates in one fused loop on assignment, zero temporaries. Why Vec d = a+b+c allocates 2 temporaries in a naive lib but none in Eigen.

  • Win for elementwise chains only; a single op or matmul still wants BLAS. Adds compile time.

Concepts (20) — constrain, readable errors

template<std::floating_point T>
T norm_cdf(T x){ /* clean error if caller passes int */ }

template<class T>
concept Payoff = requires(T p, double S){
  { p.value(S) } -> std::convertible_to<double>;
};
  • Purely compile-time: change which overload wins + error quality, never generated code. Replace most SFINAE.

Algorithms > hand loops

// MC payoff aggregation — one pass, parallelizable
double px = std::transform_reduce(
  std::execution::par, S.begin(), S.end(), 0.0,

  • accumulate (ordered) vs reduce (par, reassociates). ranges views (20) fuse transform|filter lazily, no temporaries.
  • Add std::execution::par for near-free parallel reductions on contiguous data.

Memory & Cache Performance

Memory, not FLOPs, is the bottleneck. L1 ~4cyc, L3 ~40, DRAM ~200. CPU fetches a whole 64-byte cache line (8 doubles): use all of it before eviction. Two O(n) loops can differ 10x on layout alone.

for(double x : payoffs) sum += x;    // vector: 1 miss/8, prefetch
for(Node* n : ptrs)     sum += n->pv;// scattered: 1 miss/elem !

SoA vs AoS

  • SoA (parallel vector<double> per field) streams only touched fields + vectorizes — wins for bulk column ops. AoS wins when you touch all fields of one object. Match layout to access.
  • Stack by default (bump ptr, RAII); heap only when big/unknown-size/outlives scope — and let vector own it.
  • ! False sharing: two threads writing different vars on one line → coherence ping-pong. Pad to 64B / per-thread accumulators.
  • Arena/pool for O(1) alloc + bulk free on the hot path; no new in the loop.

Low-Latency Hot Path

Keep it straight-line, inlinable, branch-predictable, cache-resident, allocation-free. A cache miss ~200cyc, a mispredict ~15-20cyc, a virtual call blocks inlining. Measure, don't guess.

  • [[likely]]/[[unlikely]] (20) aid code layout for lopsided branches; a ~50/50 branch → make it branchless (arithmetic/cmov).
  • SIMD: mostly free from auto-vectorization on clean contiguous loops under -O3 -march=native; intrinsics last resort. LTO + PGO for cross-TU inlining + layout.

Random Number Generation

Engine = deterministic uniform-bit state machine; distribution = stateless transform. Wire: dist(engine).

std::mt19937_64 eng(seed);            // default, never rand() !
std::normal_distribution<double> N(0,1);
double z = N(eng);
  • mt19937_64 default; PCG/xoshiro faster small-state. Box-Muller simple, Ziggurat fast.
  • Reproducible: same engine+seed+call-sequence — within one stdlib build only ! (distribution impls differ across libstdc++/libc++/MSVC).
  • Parallel MC cardinal rule !: one engine per thread, distinct seed / jump-ahead / stream. Sharing one engine = data race and correlated streams (SE becomes a lie). A lock fixes the race but not the correlation.
  • Correlated normals: X = L·Z, L = Cholesky of covariance.
  • Smooth low-dim payoffs: Sobol (quasi-random) → ~1/N vs pseudo 1/sqrt(N).

Linear Algebra (Eigen / BLAS)

Eigen (header-only, expression templates, SIMD) = quant default; drops to BLAS/LAPACK/MKL kernels for large ops. Layout + temporaries dominate, not FLOP count.

Eigen::VectorXd x = A.llt().solve(b);   // SPD -> Cholesky
Eigen::MatrixXd L = Sigma.llt().matrixL();
Eigen::VectorXd corr = L * z;           // correlated normals
DecompFor

QR A=QRleast-squares, calibration
Cholesky Σ=LLᵀSPD — correlated normals, ~2x cheaper than LU
SVD A=USVᵀrank, pseudo-inverse, PCA, ill-conditioned
  • ! Eigen/BLAS are column-major, C/C++ arrays row-major — mind the transpose.
  • High condition number → prefer SVD/QR over LU.

Monte Carlo Engine

Pipeline: RNG → PathGenerator → Payoff → Accumulator. Price = sample mean of discounted payoffs; always report price ± SE, SE = stdev/sqrt(N). Error ~1/sqrt(N): halving error = 4x paths.

template<class Gen, class Payoff>
Result run(Gen& gen, Payoff pay, size_t N, Rng& rng){
  Welford acc;                         // mean + variance, 1 pass
  for(size_t i=0;i<N;++i)
    acc.add( pay(gen(rng)) );           // all inlined, no vtable
  return { disc*acc.mean(),
           disc*acc.stderr() };
}
  • Template on Gen+Payoff so the whole loop inlines; a virtual/std::function per path kills it !
  • GBM step: S·exp((r-0.5σ²)dt + σ√dt·Z).
  • Variance reduction: antithetic (+Z/-Z, ~free, wins for monotone payoffs), control variate (subtract correlated known-mean term).
  • Parallel: per-thread RNG + local accumulator, reduce once. Parallel sum ≠ bit-identical (float non-assoc) — fix order if risk sign-off needs reproducibility.

Numerical Methods

Root-find / implied vol

// Newton: fast but needs derivative (vega) & good guess
for(int i=0;i<maxit;++i){
  double f = price(sig)-mkt, v = vega(sig);
  if(std::fabs(f) < tol) break;
  sig -= f/v;                          // diverges if vega~0 !
}
// Brent: bracket [lo,hi], guaranteed, no derivative — robust default
  • Newton quadratic near root but diverges if vega≈0 (deep OTM) or bad seed ! — fall back to bisection/Brent bracketing.

Greeks & PDE

  • Central diff (f(x+h)-f(x-h))/2h beats forward; gamma needs 3 points /h². Prefer analytic / AAD (all Greeks in O(1)x one price, no cancellation).
  • ! Time-step with an int count, derive t=i·dt — never for(double t=0; t!=T; t+=dt) (dt not exact → infinite / off-by-one loop).

Concurrency & Parallelism

PrimitiveUse
jthread (20)auto-joins (RAII) + stop_token; the default
async/futurevalue/exception back via .get()
threadraw — must join/detach or terminate !
  • Pricing is embarrassingly parallel: fan out independent work, reduce partials.
  • ! Data race (concurrent access, ≥1 write, no sync) = UB, silent corruption. Not "stale read".
  • One shared atomic accumulator serializes on one cache line — use per-thread partials, combine once.
  • atomic order: relaxed (atomicity only) / acquire-release (pairwise) / seq_cst (default). Don't sprinkle seq_cst; don't use relaxed where you needed release.
  • ! async default policy may defer (lazy on get()) — pass std::launch::async to force a thread.
  • ! volatile ≠ thread-safe (it's for MMIO). Use atomic. Prefer reduce(par,…)/OpenMP over hand-rolled threads.

Error Handling & Robustness

Two-region model. Outside the border (ctors, config, price() entry): validate hard, throw loudly (setup runs once, exception cost is nil). Inside (MC loop, PDE sweep): assume valid, no throw, branch-free arithmetic.

std::expected<double, CalibError>         // C++23
implied_vol(double mkt){
  if(mkt <= 0) return std::unexpected(CalibError::Bad);
  return solve(mkt);                       // value or error, no unwind
}
  • ! noexcept is a lever, not a comment: a noexcept move ctor lets vector move (not copy) on growth.
  • Exceptions ~zero-cost when not thrown; the hot-path reason to avoid is they defeat inlining/vectorization.
  • std::fma(a,b,c) = a*b+c single rounding — more accurate + often faster.
  • Denormals ~10-100x slower; FTZ trades negligible accuracy for speed on hot kernels.
  • NaN detect at the end (isnan(result)), never mid-loop.

C++ ↔ Python Interfacing

pybind11 (or nanobind) is the standard bridge: expose a fast C++ pricer/engine, drive it from research Python. Numeric arrays cross as NumPy buffers with zero copy where layout matches.

PYBIND11_MODULE(pricer, m){
  m.def("bs_call", &bs_call, "S"_a,"K"_a,"r"_a,"sig"_a,"T"_a);
  py::class_<MonteCarlo>(m,"MonteCarlo")
    .def(py::init<size_t>())
    .def("price", &MonteCarlo::price);
}
  • Accept py::array_t<double> for bulk data; request a contiguous buffer to avoid a copy.
  • ! A thrown C++ exception must be translated to a Python exception (pybind maps std::exception) — never let it leak across the ABI.
  • ! Release the GIL (py::gil_scoped_release) around long C++ compute or you block all Python threads.
  • Ownership across the boundary: return by value (copied into Python) or use holder types; watch dangling views into Python-owned buffers.

Greeks: Bump-Revalue vs AAD

  • Finite difference (bump-revalue): price(x+h) − price(x−h) over 2h. Simple, engine-agnostic, but O(N) revaluations for N greeks and noisy for MC ! (use common random numbers to cut variance).
  • AAD / adjoint algorithmic differentiation: compute all sensitivities in ~4× the price cost, independent of N — the modern standard for XVA/portfolio risk.
// forward: record ops on a tape
// reverse: seed dP/dP=1, walk tape
//   backward accumulating adjoints
// result: dP/dx_i for every input x_i
  • Reverse-mode = cheap for many-inputs→one-output (exactly the greeks shape). Libs: dco/c++, Adept, CoDiPack; or operator-overloading vs source-transform.
  • Bump for a handful of greeks / smoke tests; AAD when N is large (curves have hundreds of buckets) !

Curve Building & Calibration

  • Bootstrapping: solve a discount curve so market instruments (deposits, FRAs, swaps) reprice to par — sequential root-find per pillar.
  • Multi-curve post-2008: separate discount (OIS/SOFR) and forecast curves; basis spreads matter !
  • Calibration: fit model params (Heston, SABR, Hull-White) to market prices by minimising Σ(model − market)² — Levenberg-Marquardt / global optimiser; watch for local minima and overfitting.
  • Interpolation choice (linear on rates vs log-linear on DFs vs monotone cubic) changes forwards & greeks — pick deliberately.

Scenario Playbook

  • "Design a Monte Carlo pricer": Payoff functor + PathGenerator (RNG → correlated GBM via Cholesky) + Engine (Template Method) + variance reduction (antithetic, control variate) + CRN for greeks + parallel over paths (thread pool / par_unseq). State O(1/√N) convergence.
  • "Make this pricing loop faster": profile first; SoA layout, remove virtual from inner loop (CRTP), pre-size vectors, cache-friendly path storage, SIMD the payoff, reuse RNG state; state before/after in ns.
  • "Price a book overnight": batch by model, share curves, AAD for risk, checkpoint, distribute across cores/boxes.

Real-World Quant Systems

  • Risk engine: revalue a whole portfolio under thousands of market scenarios (historical VaR, stress, sensitivities). The dominant cost is repeated pricing, so the wins are: cache curves/vol surfaces once, group trades by model, vectorise across scenarios, and prefer AAD over bump-and-revalue when the sensitivity count is large. Determinism matters — the same inputs must give bit-identical numbers for P&L attribution and audit.
  • XVA (CVA/DVA/FVA) is the heaviest workload in a bank: a Monte-Carlo simulation of the whole netting set forward in time, with a full pricing at every exposure date — nested valuation. This is why AAD and GPU offload became mainstream in quant C++; a naive bump-revalue XVA is infeasible.
  • Determinism & reproducibility: seed every RNG explicitly, avoid std::unordered_map iteration order in anything that feeds a number, pin the math library version, and beware fast-math/FMA reordering changing the last ULPs across builds !

Numerical Robustness — Deep

  • Prefer algorithms that are stable by construction: log-space for products of probabilities, Kahan/Neumaier summation for long accumulations, and reformulating 1 − e^{-x} as -expm1(-x) to avoid cancellation near zero.
  • Root-finders (implied vol from price) need bracketing + a fallback: Newton is fast but can diverge on flat vega, so guard with bisection (Brent) and cap iterations. Always validate the input is arbitrage-free before inverting !
  • Watch matrix conditioning: a near-singular covariance breaks Cholesky (correlations of exactly ±1, or more assets than observations) — regularise (shrinkage, nearest-correlation-matrix) rather than ship NaNs downstream.
  • Money is never a double for accounting; use scaled integers or a decimal type. double is fine for market prices/greeks where relative error ~1e-15 is acceptable, but never compare two doubles with ==.

C++ vs Python / Rust — When

  • C++ earns its keep on the hot path: pricing kernels, the market-data/order path, and anything measured in microseconds or revalued millions of times. The cost is developer time and footguns, so keep the C++ surface small and well-tested.
  • Python owns research, glue, and orchestration — pandas/NumPy for exploration, then push the proven kernel into C++ behind pybind11. Most quant desks are "Python outside, C++ inside".
  • Rust is increasingly used where memory-safety matters as much as speed (new low-latency components); it removes whole classes of UB the C++ hot path is prone to, at the cost of a smaller ecosystem for numerics. In interviews, name the boundary: research vs production, and why you'd cross it.

Testing & Validating Numerical Code

  • Analytic anchors: test the Monte-Carlo/tree/PDE price against a closed form where one exists (a vanilla European under Black-Scholes) and assert convergence within the standard error, not exact equality !
  • Put-call parity, monotonicity (call price rises with spot), and bounds (0 ≤ call ≤ spot) are cheap invariants that catch whole classes of bugs — property-test them across random but valid inputs.
  • Convergence order: halving the step (or 4× the paths) should shrink the error predictably (O(1/√N) for MC, O(Δt) or O(Δt²) for schemes); a plot that doesn't converge means a bug, not just noise.
  • Greeks by two methods: bump-revalue vs AAD (or vs analytic) must agree — a mismatch localises the error to one or the other.
  • Golden-file regression on a representative portfolio guards against silent drift when you refactor the hot path; combine with sanitiser + valgrind builds in CI so UB and leaks fail the pipeline, not production.
  • Benchmark micro-kernels with a proper harness (Google Benchmark) that controls for warm-up, frequency scaling, and the optimiser deleting your unused result; report ns/op and allocations, and pin the CPU to reduce jitter for reproducible numbers.
  • For random-driven code, fix the seed in tests so a failure is reproducible; separately run a fuzz/stress pass with many seeds to shake out rare edge cases that a single seed would hide.
