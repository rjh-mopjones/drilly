Synchronization

  • Race condition: concurrent access, ≥1 write, no ordering (count++ = load/inc/store — lost update) !
  • Critical section needs: mutual exclusion + progress + bounded waiting.
  • Primitives: mutex (ownership) · semaphore (counter, no owner; binary≈mutex, counting=N) · monitor/condvar (wait in a loop on the predicate).
  • Built on atomics (test-and-set, CAS); spinlock = busy-wait (only short sections, multicore).
  • Classics: producer-consumer, readers-writers, dining philosophers.

Deadlock

Virtual Memory & Paging

flowchart LR VA["virtual addr = page# | offset"] --> TLB{"TLB hit?"} TLB -->|hit| PA["frame | offset"] TLB -->|miss| PT["page table walk"] PT -->|present| PA PT -->|not present| PF["page fault → load from disk"]
  • Fixed pages↔frames; per-process page table (multi-level); TLB caches translations (flushed on context switch !).
  • Demand paging; page fault = trap → find on disk → evict a frame → load → restart the instruction. Major fault = disk I/O = slow.
  • COW makes fork cheap. Internal frag on the last page; no external frag (unlike segmentation).

Memory Management

  • Logical (virtual) → physical via the MMU. Base/limit for relocation + protection.
  • External frag (free memory scattered — segmentation/contiguous) vs internal frag (slack inside a block — fixed partitions/pages).
  • Fit: first / best / worst. Segmentation = variable logical segments (ext frag) vs paging = fixed (no ext frag).
  • Allocators: free lists, buddy, slab. Bugs: leak, double-free, dangling.

File Systems

  • Inode = file metadata + block pointers (the NAME lives in the directory entry, not the inode).
  • Hard link = another name for the same inode; soft link = a file holding a path (can dangle) !
  • Allocation: contiguous (frag) · linked/FAT (bad random access) · indexed (inode direct + single/double/triple indirect → huge files).
  • Journaling = write-ahead log for crash consistency (ext4/NTFS); vs COW FS (ZFS/btrfs). VFS unifies filesystems.

Storage & I/O

  • HDD: seek + rotational latency → slow random. SSD: uniform low latency, erase-before-write, wear/TRIM.
  • Disk scheduling: FCFS / SSTF / SCAN(elevator) / C-SCAN (matters on HDD, not SSD).
  • RAID: 0 stripe · 1 mirror · 5 parity(1 fail) · 6 (2 fail) · 10 mirror+stripe.
  • I/O: polling vs interrupts vs DMA (bulk, no CPU). Page/buffer cache; blocking vs async vs epoll (C10K).

Interrupts, Traps & Syscalls

  • Interrupt = async (external device). Trap/exception = sync (caused by the instruction): syscall, fault (page fault — restart), abort.
  • Handling: save state → kernel mode → vector table → ISR → restore → iret.
  • System call: put number+args in registers → trap (syscall) → kernel validates & dispatches → result in a register → return. Never trust user pointers !
  • The timer interrupt enables preemptive scheduling. Syscalls are costly (mode switch + cache/TLB).

Kernel · Protection · Security

  • Dual mode: Ring 0 kernel vs Ring 3 user; privileged instructions kernel-only. Per-process page tables → isolation.
  • Monolithic (Linux — fast, big TCB) vs microkernel (services in user space — robust, IPC cost) vs hybrid (NT, XNU).
  • Least privilege; DAC vs MAC (SELinux) vs RBAC. A user crash is isolated; a kernel bug is total.
  • Exploit defenses: ASLR (randomize addresses) + DEP/NX (no-exec data) + stack canaries vs buffer overflows; seccomp/sandboxing; Spectre/Meltdown = speculative side channels !

Virtualization · Boot · Perf

  • VM (hypervisor, own kernel — strong isolation, heavy) vs container (shares host kernel — light, weaker isolation). Containers = namespaces (isolate view) + cgroups (limit resources) !
  • Boot: firmware (BIOS/UEFI) → POST → bootloader (GRUB) → kernel + initramfs → mount root → init/PID 1 (systemd).
  • Perf latency: cache ns · RAM ~100ns · SSD µs · HDD seek ~ms. Context switch (regs + TLB flush + cold cache) & major page faults are the costs.
  • Load avg counts R + D (uninterruptible) tasks → high load + idle CPU = I/O wait ! USE method to find bottlenecks; /proc, perf, eBPF.

★ "What happens when you run a program"

  • 1. Shell fork()s a child, then exec()s the binary.
  • 2. Loader maps the ELF/PE into a fresh address space (text/data/heap/stack); the dynamic linker resolves shared libs.
  • 3. Jump to _start→main; pages fault in on demand (demand paging).
  • 4. The scheduler time-slices it onto a CPU (context switches); syscalls (traps) do I/O.
  • 5. On exit, the parent wait()s & reaps it (else it's a zombie).

☐ Interview Reasoning Checklist

  • ☐ Process vs thread: what's shared (address space) vs private (stack/regs)?
  • ☐ Concurrency bug? Find the shared state + missing ordering → mutex/CAS/monitor.
  • ☐ Deadlock? Check the 4 conditions; break circular wait via lock ordering.
  • ☐ Memory question? Distinguish virtual vs physical, paging vs segmentation, int vs ext frag.
  • ☐ "Slow"? CPU vs memory vs I/O vs lock-bound (USE); high load+idle CPU = iowait.
  • ☐ "Adding threads slower"? Context switches / contention / false sharing / GIL / I/O-bound.
  • ☐ VM vs container: separate kernel (strong) vs shared kernel (light).
  • ☐ Use real latency numbers; trace the interleaving for spot-the-bug.
