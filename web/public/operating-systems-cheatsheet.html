Process Lifecycle & fork/exec

States

new → ready ⇄ running → terminated
            running → waiting (block on I/O)
            waiting → ready  (I/O done)
            ready ← running  (preempted / quantum)
  • Ready = runnable, waiting for a CPU. Waiting/blocked = waiting for an event (I/O, lock) — the scheduler skips it.
  • fork() = clone parent via copy-on-write; returns twice (0 in child, child PID in parent) !
  • exec() = replace the current image with a new program (same PID, fresh address space). Shell = fork then exec.
  • wait() = parent reaps child's exit status.
  • Zombie = exited but not yet wait()ed (holds a PCB slot) !; orphan = parent died first → reparented to init/PID 1, which reaps it.

Threads — user vs kernel

ModelNote
1:1 (kernel)each user thread = a kernel thread; true parallelism, kernel schedules. Linux/Windows.
N:1 (user)many user threads on 1 kernel thread; fast switch but one blocking syscall blocks all & no multicore !
M:Nhybrid; complex (Go runtime, old Solaris).
  • User threads (green/goroutines): scheduled in userspace, µs-cheap, invisible to kernel.
  • Kernel threads: kernel-scheduled, can run on separate cores, but switch costs a mode switch.
  • Cost order: context switch process > thread > user-thread yield. Too many threads → context-switch & cache thrash, not speedup !

Synchronization — the core

  • Race condition: concurrent access, ≥1 write, no ordering. count++ = load/inc/store → interleave → lost update !
  • Critical-section requirements: mutual exclusion + progress + bounded waiting.

Primitives

TypeSemantics

  • Built on hardware atomics: test-and-set, compare-and-swap (CAS), fetch-and-add. Lock-free = CAS-retry loops.
  • Disabling interrupts gives mutual exclusion on a uniprocessor only — useless on multicore !

Classic Sync Problems

// Producer-consumer (bounded buffer)
sem empty = N, full = 0; mutex mtx
producer: wait(empty); lock(mtx); put(); unlock(mtx); signal(full)
consumer: wait(full);  lock(mtx); take();unlock(mtx); signal(empty)
  • Order matters: take the counting sem before the mutex, else deadlock !
  • Readers-writers: many readers OR one writer. Reader-priority starves writers; writer-priority starves readers → fair variant.
  • Dining philosophers: 5 forks, each grabs left then right → all hold one → circular-wait deadlock. Fixes: global fork ordering (one grabs right-first), limit to 4 seated, or waiter/arbitrator.

Deadlock

Needs ALL 4 Coffman conditions at once:

  • ☐ mutual exclusion · hold-and-wait · no preemption · circular wait.
StrategyHow
preventionbreak one condition (e.g. global lock ordering kills circular wait; request-all-at-once kills hold-and-wait)
avoidanceonly enter safe states — Banker's algorithm (needs max-claim up front)
detection+recoverywait-for graph, find a cycle → kill / rollback / preempt a victim
ostrichignore — what Linux/Windows do; rare, reboot
  • Two threads lock A,B vs B,A → deadlock; fix = one global lock order !
  • Livelock (busy but no progress) & starvation (never scheduled) & priority inversion (low holds lock a high needs → priority inheritance) ≠ deadlock.

Memory Management

  • Logical (virtual) → physical via the MMU. Base/limit registers give relocation + protection.
  • External frag = free memory scattered in unusable holes (contiguous / segmentation) — needs compaction. Internal frag = slack inside a fixed block (paging, last page) !
  • Contiguous fit: first / best / worst. First-fit fast, best-fit leaves tiny holes.
  • Segmentation = variable-size logical segments (code/data/stack), external frag. Paging = fixed size, no external frag → won.
  • Allocators: free lists, buddy (power-of-2, kernel pages), slab (fixed objects, caches). Bugs: leak, double-free, use-after-free / dangling.

Virtual Memory & Address Translation

flowchart LR VA["virtual addr
page# | offset"] --> TLB{"TLB hit?"} TLB -->|hit ~99%| PA["frame | offset"] TLB -->|miss| PT["page-table walk
(4 levels x86-64)"] PT -->|present| PA PT -->|valid=0| PF["page fault → kernel"]
  • VA = page number (indexes table) + offset (passes through unchanged). 4KB page → 12-bit offset.
  • Per-process page table; PTE = frame# + valid · R/W/X · dirty · referenced. Context switch reloads CR3.
  • Multi-level table: paging the page table → allocate only used regions (a flat 48-bit table = 512 GB/proc) !
  • TLB caches translations (not data). Flushed on context switch → cold TLB stall, unless ASID/PCID tags entries !

Demand Paging & Page Fault Path

access page, valid bit = 0 → TRAP
1. legal addr (in a VMA, perms ok)?
     no  → SIGSEGV (segfault). done.
     yes → not resident, continue
2. locate backing store (swap / file / zero-fill)
3. free frame? none → replace a victim
     (dirty victim → write back first)
4. schedule disk read; process BLOCKS
5. I/O done → set PTE valid=1, install TLB
6. RESTART the faulting instruction
  • Minor (soft) fault = page already in RAM (page cache, COW, zero-fill) → just fix the PTE. µs.
  • Major (hard) fault = read from disk/swap → ms; blocks. Soaring majflt = thrashing !
  • Segfault is not a separate event — it's the fault handler deciding the access was illegal.

EAT & Copy-on-Write

Effective Access Time

EAT = (1−p)·ma + p·pf     p = fault probability
ma=100ns, pf=8ms(8,000,000ns):
 p=0        → 100 ns
 p=0.001    → 8,100 ns   (81× slower!)
 p=1e-7     → 100.8 ns   (<1% hit)
  • Disk fault ≈ 100,000–1,000,000× slower than RAM → a 1-in-1000 fault rate is already 80× slowdown. Whole design = keep p microscopic via locality !

Copy-on-write (why fork is cheap)

  • fork → parent & child share frames read-only. First write → protection fault → kernel copies just that page, marks it writable. If child exec()s immediately, almost nothing is copied.
  • Same trick = shared libraries (one physical libc mapped into every process).

Page Replacement

AlgoNote
OPT / MINevict farthest-future use; minimal faults, unimplementable — the benchmark
FIFOevict oldest-loaded; ignores usage; Belady's anomaly !
LRUevict least-recently-used; strong OPT approx; true LRU needs per-access bookkeeping (costly)
Clock / 2nd-chancecircular scan of reference bits; set bit → clear & skip (second chance). Cheap LRU approx — what real kernels ship
LFU/MFUfrequency-based; rarely used alone
  • Belady's anomaly: for FIFO, adding frames can increase faults. Impossible for stack algorithms (LRU/OPT — more frames ⊇ fewer's resident set) !
  • Dirty victim = write-back cost; clean victim = drop free. Global (steal any) vs local (only own frames) replacement.

Working Set & Thrashing

  • Working set W(t,Δ) = pages referenced in the last Δ accesses. Sum of all WS ≤ frames → low faults; exceed it → thrashing.
  • Thrashing: too little RAM for the active working sets → every fault steals a frame another process needed → all disk, no compute; CPU utilisation collapses !

"Added workers, box got slower, CPU dropped to 5%"

  • = thrashing. Wrong fix: add workers (worse). Right fix: reduce multiprogramming / add RAM / kill a hog.
  • Page-fault-frequency (PFF) control: fault rate too high → give the process more frames; too low → take some away. Admission control suspends processes when overcommitted.
  • Locality of reference is why paging (and this whole topic) works at all.

File Systems

  • Inode = file metadata (size, perms, timestamps, owner) + block pointers. The name lives in the directory entry, not the inode !
  • Hard link = another dir entry → same inode (ref-counted; file gone when count=0). Soft/symlink = a file holding a path — can dangle !

contiguousfast seq/random read; external frag, hard to grow

  • Journaling = write-ahead log → crash consistency (ext4, NTFS). vs copy-on-write FS (ZFS, btrfs). VFS = common layer over many filesystems.
  • fsync forces durability; the page cache buffers writes → data loss window on crash !

Interrupts, Traps & Syscalls

EventKind
interruptasync — external device (timer, NIC, disk)
trap / syscallsync — deliberate (syscall instr)
faultsync — recoverable (page fault → restart instr)
abortsync — unrecoverable (double fault)
  • Handling: save state → switch to kernel mode → interrupt vector table → ISR → restore → iret.
  • Syscall: put number + args in registers → syscall traps → kernel validates & dispatches → result in a register → return. Never trust user pointers (TOCTOU, copy_from_user) !
  • The timer interrupt is what makes preemptive scheduling possible. Syscalls are costly: mode switch + cache/TLB pollution.

Kernel · Protection · Virtualization

  • Dual mode: Ring 0 kernel vs Ring 3 user; privileged instructions (I/O, page-table load, halt) are kernel-only. Per-process page tables → isolation.
  • Monolithic (Linux — fast, big TCB, driver bug = crash) vs microkernel (drivers/FS in user space — robust, but IPC cost) vs hybrid (Windows NT, macOS XNU).
  • VM (hypervisor, own guest kernel — strong isolation, heavy) vs container (shares host kernel — light, weaker isolation). Containers = namespaces (isolate view: PID/net/mount) + cgroups (limit CPU/mem) !
  • Boot: firmware (BIOS/UEFI) → POST → bootloader (GRUB) → kernel + initramfs → mount root → init / PID 1 (systemd).

OS Security & Perf

  • Least privilege; DAC (owner sets perms) vs MAC (policy, SELinux) vs RBAC. A user crash is contained; a kernel bug is total.
  • Exploit defences vs buffer overflow: ASLR (randomise addresses) + DEP/NX (no-exec data pages) + stack canaries. Sandboxing: seccomp, capabilities.
  • Spectre/Meltdown = speculative-execution side channels leaking across the privilege boundary; mitigations (KPTI) force TLB flushes → cost !

Latency numbers you must know

L1        ~1 ns
RAM       ~100 ns
SSD read  ~100 µs   (100,000 ns)
HDD seek  ~10 ms    (10,000,000 ns)
  • Load avg counts R + D (uninterruptible) tasks → high load + idle CPU = I/O wait ! USE method (Utilisation/Saturation/Errors); tools: /proc, perf, eBPF.

★ "What happens when you run a program"

  • 1. Shell fork()s a child, then exec()s the binary (same PID).
  • 2. Loader maps the ELF/PE into a fresh address space (text/data/heap/stack, all demand-paged); the dynamic linker maps shared libs (COW-shared frames).
  • 3. Jump to _start → main; each first page touch faults in (demand paging).
  • 4. The scheduler time-slices it onto a CPU; the timer interrupt preempts; syscalls (traps) do I/O and block it.
  • 5. Page not resident → page fault → TLB/page-table → disk. Contended lock → sleep on a futex.
  • 6. On exit(), parent wait()s & reaps it (else zombie); kernel frees frames & FDs.

☐ Interview Reasoning Checklist

  • ☐ Process vs thread: name what's shared (address space, heap, FDs) vs private (stack, regs, PC).
  • ☐ Concurrency bug? Find the shared state + missing ordering → mutex / atomic / monitor (while-loop the predicate).
  • ☐ Deadlock? Check the 4 Coffman conditions; break circular wait via global lock ordering.
  • ☐ Scheduling: state preemptive vs not, the metric optimised, and quantum tradeoff; can you do the Gantt arithmetic?
  • ☐ Memory: distinguish virtual vs physical, paging vs segmentation, internal vs external frag.
  • ☐ Translation: split addr → TLB → page-table walk → present bit → fault → disk → restart instruction.
  • ☐ Page fault: legality check first (segv vs demand-page), evict victim (write back if dirty), restart.
  • ☐ Replacement: OPT/LRU/Clock; explain Belady; compute EAT with a fault rate.
  • ☐ "Slow"? CPU vs memory vs I/O vs lock-bound (USE); high load + idle CPU = iowait; low CPU + heavy paging = thrashing.
  • ☐ VM vs container: separate kernel (strong) vs shared kernel + namespaces/cgroups (light).
  • ☐ Use real latency numbers (RAM 100ns, SSD 100µs, HDD 10ms); trace the interleaving for spot-the-bug.
