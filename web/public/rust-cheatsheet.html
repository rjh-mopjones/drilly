Ownership & Moves

  • Three rules: every value has one owner; one owner at a time; when the owner leaves scope the value is dropped (freed deterministically).
  • Assignment / passing / returning move by default (non-Copy). The source binding is statically dead — reuse = E0382. This is what makes double-free impossible: always exactly one drop.
let s = String::from("hi");
let t = s;          // ownership MOVES to t
// println!("{s}"); // E0382: borrow of moved value
println!("{t}");    // ok
  • No GC: the compiler inserts drop at scope exit. "Memory management" is a type-system concern resolved at compile time, zero runtime tracing.
  • A move is a static ownership transfer, not necessarily a byte copy — optimiser elides it !
  • Cost vs GC: no pauses, tight footprint; you pay in borrow-checker friction, slow builds, awkward cyclic/graph data.

Copy vs Clone vs Move

KindWhen
Movedefault for non-Copy; source invalidated
Copyimplicit bit-dup; both bindings stay live
Cloneexplicit .clone(); whatever the type defines
  • Copy = duplicating bits yields a valid independent value: i32,bool,char,f64,&T, tuples/arrays of Copy. Not String/Vec/Box (own a heap ptr).
  • Hard rule: Copy requires Clone, and Copy is mutually exclusive with Drop ! — a destructor + implicit copy = double free.
  • .clone() ≠ "expensive" universally: Rc::clone/Arc::clone only bump a refcount; Vec::clone deep-copies.
  • Reflexive .clone() to silence the borrow checker is a smell ! — usually you wanted a borrow (&T).

Drop & RAII

  • Drop::drop(&mut self) runs automatically at scope exit — heap, files, sockets, MutexGuard released here. No manual cleanup on early-return paths; runs on panic-unwind too.
  • Order: locals drop in reverse declaration (LIFO); struct fields in declaration order.
struct Noisy(&'static str);
impl Drop for Noisy {
    fn drop(&mut self){ println!("drop {}", self.0); }
}
let _a = Noisy("a");
let _b = Noisy("b");   // drops b, then a
  • Early release: std::mem::drop(guard) (takes by value). Shrinks a critical section.
  • value.drop() is a compile error ! (would double-drop). Go through mem::drop.
  • mem::forget / ManuallyDrop suppress drop (FFI hand-off) — leaks by design.

Borrowing & Aliasing-XOR-Mutability

  • &T shared/read pass — Copy, many live at once. &mut T exclusive/write pass — while it lives, no other ref (not even &T) to that data.
  • The rule: at any point, data has either many readers xor one writer — never both.
let mut v = vec![1,2,3];
let r = &v[0];   // shared borrow live...
v.push(4);       // E0502: needs &mut while r alive !
println!("{r}"); // r's last use extends the borrow
  • Why it's real: push can reallocate → r dangles. Same bug as C++ iterator invalidation.
  • NLL (2018): a borrow ends at last use, not the closing brace. Reordering often fixes the error.
  • Disjoint &mut the checker can't prove: split_at_mut, iter_mut, destructuring.
  • Fix a borrow error by redesigning (narrow scope, copy out, store an index) — not by reaching for RefCell/.clone().

Lifetimes & Elision

  • A lifetime 'a is the compile-time region a reference is valid. Compile-time only, erased before codegen, zero runtime cost. It asserts a relationship, never lengthens how long data lives !
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() >= y.len() { x } else { y }
}   // 'a = intersection (shorter) of the two inputs

Elision rules (why you rarely annotate)

  • 1. each input ref gets its own lifetime; 2. one input lifetime → assigned to all outputs; 3. method with &self → self's lifetime to outputs.
  • Two-&str-in, one-out fails elision (2 inputs, no self) → you must annotate.

'static — two meanings, don't conflate !

  • &'static T: data lives the whole program (literals, const, Box::leak).
  • T: 'static bound: type holds no shorter borrows — every owned String/i32 qualifies. This is what thread::spawn/tokio::spawn demand.

Enums, Structs & Pattern Matching

  • Enum = true sum type (tagged union), each variant carries its own data — not a C named integer. Struct = product type. Model state machines as enums: the type is the invariant.
  • match is exhaustive — miss a case and it won't compile; adding a variant flags every site to update.
enum Shape { Circle(f64), Rect{ w:f64, h:f64 } }
let area = match s {
    Shape::Circle(r)       => PI*r*r,
    Shape::Rect{ w, h }    => w*h,
};
if let Some(x) = opt { use(x); }        // one-arm
let Some(x) = opt else { return; };     // let-else (1.65)
  • Guards (if cond), binding (n @ 1..=9), _ wildcard. Arm order matters — _ swallows everything after !
  • Newtype struct UserId(u64): zero-cost type safety so UserId/OrderId can't be swapped.

Option & Result

  • Option<T> = Some(T)|None — Rust's null. Option<&T>/Option<Box<T>> are pointer-sized via niche optimisation (null = None) — zero overhead.
  • Result<T,E> = Ok(T)|Err(E) — recoverable errors as values.
CombinatorDoes
map/map_errtransform the Ok/Err
and_thenchain a fallible step (flatMap)
ok_or(e)Option → Result
unwrap_or(_else/_default)supply a fallback, no panic

  • Don't if x.is_some() { x.unwrap() } — match/if let/combinators. unwrap() in libraries on fallible I/O is a latent panic ! — prefer expect("invariant: …") documenting why it can't fail.
  • #[must_use] on Result warns if you drop it unhandled.

Traits & the Orphan Rule

  • Trait = a contract (method sigs + default bodies + associated types/consts). No fields, no state inheritance — composition only.
  • Associated type (type Item;) is a per-impl output → one Iterator::Item per type, so inference works. A generic Iterator<T> would be ambiguous.
trait Greet {
    fn name(&self) -> String;
    fn greet(&self) -> String {          // default method
        format!("Hi, {}", self.name())
    }
}
  • Orphan / coherence rule !: to impl Trait for Type, you must own the trait or the type. Can't impl Display for Vec<T> (both foreign). Guarantees ≤1 impl per (trait,type) globally.
  • Workaround = newtype: struct MyVec(Vec<T>) is local, so you may impl foreign traits.
  • Blanket impl: impl<T: A> B for T. Marker traits (Send,Sync,Copy) = no methods, used as bounds.

Error Handling — ? / thiserror / anyhow

  • x? desugars to: Err(e) => return Err(From::from(e)); else unwrap Ok. The From conversion is load-bearing — ? changes the error type !
#[derive(thiserror::Error, Debug)]
enum MyErr {
    #[error("io")]      Io(#[from] std::io::Error),
    #[error("bad {0}")] Parse(String),
}
fn load() -> Result<Cfg, MyErr> {
    let s = std::fs::read_to_string(p)?;  // io::Error -> MyErr via From
    Ok(parse(&s)?)
}
LayerUse

anyhow (Error + .context())apps — log & bail, type-erased

  • Libraries returning anyhow = anti-pattern ! (erases the type). panic! is for bugs/broken invariants, not expected failure — it unwinds, runs Drop, crosses the recoverable line. .context() wraps, original stays in source().

Iterators & Collections

  • Iterators are lazy & zero-cost — adapters build a struct; nothing runs until a consumer (collect, sum, for, find). Compiles to a hand-loop.
let evens: Vec<i32> = v.iter()
    .filter(|&&x| x % 2 == 0)
    .map(|&x| x * 10)
    .collect();
let total: i32 = v.iter().sum();
  • Three flavours: iter()→&T, iter_mut()→&mut T, into_iter()→T (consumes) !
  • collect::<Result<Vec<_>,E>>() short-circuits on first Err. ? works inside a for.

Smart Pointers — Box / Rc / Arc

TypeGives
Box<T>unique heap ownership; bare ptr, only cost = the alloc. Enables recursive types & dyn Trait.
Rc<T>shared ownership, single-thread, non-atomic count
Arc<T>shared ownership, thread-safe, atomic count

  • Rc/Arc give shared immutable (&T) access only ! — to mutate you compose with interior mutability.
  • Rc/Arc leak on reference cycles (parent↔child) — Rust has no GC to collect them. Break the back-edge with Weak.
  • Arc::clone is an atomic RMW — cheap but not free under contention; Rc wins single-threaded. Deref coercion makes them act like &T.

Interior Mutability

  • Mutating through a shared &, soundly, by moving the borrow check inward. The aliasing rule isn't broken — enforcement moves to runtime/hardware.
TypeCheck
Cell<T>get/set by value, no refs out; single-thread
RefCell<T>runtime borrow flag; borrow()/borrow_mut()
Mutex<T>lock across threads; blocks
RwLock<T>many readers xor one writer

  • RefCell: two live borrow_mut() = runtime panic! (already borrowed: BorrowMutError), not a compile error !
  • Compose: Rc<RefCell<T>> single-thread; Arc<Mutex<T>> cross-thread. Send/Sync police which is sound.

Concurrency — Send / Sync

  • Send = safe to move to another thread. Sync = safe to share &T across threads (T: Sync iff &T: Send). Auto traits — derived structurally from fields.
  • Rc is !Send !: non-atomic refcount would tear under concurrent clone/drop → use-after-free. Arc uses atomics → Send+Sync when T: Send+Sync.
  • RefCell is Send but !Sync (non-atomic borrow flag). Mutex<T>: Sync needs only T: Send — the lock provides the sync.
let data = Arc::new(Mutex::new(0));
let d = Arc::clone(&data);
thread::spawn(move || { *d.lock().unwrap() += 1; });
  • Rust kills data races (UB); deadlocks & lost updates are still yours. std Mutex poisons on a holder panic — .lock().unwrap() propagating is often correct.
  • thread::scope lets threads borrow non-'static stack data. rayon par_iter() for data parallelism — wins only past a size threshold !

Async / Await & Futures

  • An async fn compiles to a state machine implementing Future. Calling it runs zero body — futures are lazy until an executor (tokio) polls them ! (unlike JS/Python eager promises).
  • Each .await = a cooperative suspension point; Poll::Pending yields, a Waker re-schedules. No preemption — a future that never awaits monopolises its thread.
async fn fetch() -> u32 { /* inert until polled */ 0 }
#[tokio::main] async fn main() { let n = fetch().await; }
  • Blocking a runtime thread (std::fs::read, big CPU loop, thread::sleep) stalls all tasks on it ! → use spawn_blocking / async I/O.
  • Holding a std::sync::MutexGuard across .await = latent deadlock ! — drop it first, or use tokio::Mutex (slower, only for this).
  • A future is Send iff every value held across an .await is Send — the #1 "won't tokio::spawn" error (an Rc/guard is live). Pin restricts moving, not mutation.

  • Hierarchy: Fn ⊂ FnMut ⊂ FnOnce. Compiler picks the least restrictive automatically from what the body does.
  • move forces captures by value — required to send a closure to a thread / tokio::spawn (needs 'static) !
let mut n = 0;
let mut inc = || { n += 1; };   // FnMut
let add = move |x| x + base;    // moves `base` in
fn apply(f: impl Fn(i32)->i32) -> i32 { f(1) }
  • Store closures as impl Fn(..) (static) or Box<dyn Fn(..)> (heterogeneous). Each closure is its own anonymous type.

Strings & Text

  • String = owned, growable, heap, UTF-8. &str = borrowed view (ptr+len). Take &str at APIs, return String when you create.
  • Bytes ≠ chars ≠ graphemes ! — UTF-8 is variable width. You cannot index s[0] — that byte may split a codepoint.
for c in s.chars() { .. }     // Unicode scalars
for b in s.bytes() { .. }     // raw u8
let n = s.chars().count();    // O(n), not s.len()
let slice = &s[0..4];         // byte range — panics mid-char !
  • s.len() is bytes, not chars. Slicing on a non-boundary panics at runtime.
  • Build with String::push_str/write!/format!; + takes String + &str and moves the LHS.
  • Cow<'a, str> = borrow when possible, allocate only on modify.

Memory, Layout & Performance

  • Default repr(Rust) layout is unspecified — the compiler reorders fields to minimise padding. Use #[repr(C)] only for FFI/stable layout !
  • Enum size = largest variant + discriminant tag; niche optimisation makes Option<&T> pointer-sized.
  • Zero-cost abstractions: generics monomorphize (one specialised copy per type) — fast at runtime, but a binary-size & compile-time cost.

Integer overflow — debug vs release !

  • dev: overflow-checks=true → panics. release: off → wraps silently (2's-complement). "Works in tests, corrupts in prod." Never UB (unlike C).
  • Explicit families: checked_*→Option, saturating_*→clamp, wrapping_*→modular, overflowing_*→(T,bool).

Levers: pre-size Vec/HashMap, borrow instead of clone, Box::leak/arenas, measure with cargo flamegraph + criterion before optimising.

Unsafe & FFI

  • unsafe is not "turn off the borrow checker" ! — borrowck/typeck/lifetimes still fully apply. It's a promise you uphold invariants the compiler can't verify.
  • 5 superpowers: deref a raw ptr; call an unsafe fn; access/mutate a static mut (hard-deprecated 2024 — use OnceLock/Atomic); impl an unsafe trait (Send/Sync); read a union field.
  • UB = licence to miscompile, not "a crash" — may "work" until the optimiser changes !
let (a, b) = slice.split_at_mut(mid);   // unsafe inside, SAFE api
extern "C" { fn c_fn(p: *const u8, n: usize) -> i32; }
#[no_mangle] pub extern "C" fn rs_fn() {}
  • Soundness lives at the module boundary, not the block: a sound API is one no safe caller can misuse into UB. Every unsafe fn needs a // Safety: contract.
  • FFI needs extern "C" + #[repr(C)] types + don't unwind across the boundary. Verify with Miri.

Testing

  • Unit tests live in-module behind #[cfg(test)] mod tests — can reach private items. Integration tests in tests/ see only the public API. Doctests in /// run on cargo test.
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn adds() { assert_eq!(add(2,2), 4); }
    #[test]
    #[should_panic(expected = "overflow")]
    fn overflows() { add(u8::MAX, 1); }
}
  • assert_eq!/assert!; a #[test] fn returning Result lets you use ?. #[ignore] for slow tests (--ignored to run).
  • Tests run in parallel threads by default — no shared mutable global without sync !; --test-threads=1 to serialise.
  • #[bench]/criterion for benchmarks; proptest for property tests; cargo test -- --nocapture to see println!.

Channels & Message Passing

  • std::sync::mpsc = multi-producer, single-consumer: clone the Sender, only one Receiver. Recent std uses the crossbeam algorithm (landed ~1.67) so it's fast — but still single-consumer. Reach for crossbeam-channel for multi-consumer (work-stealing pool), select!, or a rendezvous channel (bounded(0)).
let (tx, rx) = mpsc::channel();        // UNBOUNDED
for id in 0..4 {
    let tx = tx.clone();
    thread::spawn(move || tx.send(id).unwrap());
}
drop(tx);                 // so rx knows all senders gone !
for msg in rx { /* ends when channel closes */ }
  • Bounded vs unbounded !: channel() never blocks send → a fast producer + slow consumer is an OOM waiting to happen. sync_channel(n) blocks send when full → backpressure. Prefer bounded in any real pipeline.
  • Closing = the shutdown signal: all Senders dropped → recv() returns Err and the for loop ends. Receiver dropped → send() returns Err(SendError(value)), handing the value back. No "poison pill" needed — closure is the signal.
  • Async analogue: tokio::sync::mpsc (bounded by default). Never feed a blocking std channel from an async task ! — it parks a runtime worker.

Scoped Threads & Rayon

  • thread::spawn demands a 'static closure — it can't borrow local stack data, forcing Arc/clone. thread::scope (1.63) guarantees all spawned threads join before it returns, so the borrow checker safely lets them borrow non-'static locals by reference.
let mut data = [1,2,3,4,5,6];
thread::scope(|s| {
    let (a, b) = data.split_at_mut(3);   // disjoint &mut
    s.spawn(|| a.iter_mut().for_each(|x| *x *= 2));
    s.spawn(|| b.iter_mut().for_each(|x| *x *= 2));
}); // joined here — zero Arc/Mutex
  • Scope joins even on panic-unwind, so the borrows stay sound. Use it for structured fork-join bounded by a function's lifetime; use plain spawn+Arc only for detached/long-lived threads.
  • Rayon for data parallelism: par_iter() is a near drop-in for iter(), backed by a global work-stealing pool that auto-balances uneven work.
use rayon::prelude::*;
let total: u64 = (0..1_000_000u64)
    .into_par_iter().map(expensive).sum();
  • Not free !: splitting/scheduling overhead loses on small inputs — benchmark. If every iteration locks a shared Mutex you've serialised yourself; prefer map+reduce/thread-local fold. Never put blocking I/O or .await in par_iter — that's tokio's job.
  • Task parallelism (heterogeneous, communicating units) → threads/channels or tokio. Data parallelism (same op over a big collection) → rayon.

Serde & JSON Boundary

  • serde separates your data model from the wire format: derive once, drive serde_json/bincode/toml/rmp — no reflection, no runtime cost beyond the format. That decoupling is why it's everywhere.
#[derive(Serialize, Deserialize, Debug)]
#[serde(rename_all = "camelCase")]
struct User {
    id: u64,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    email: Option<String>,
}
  • Attributes carry the weight: rename_all, default, flatten, tag="type" (tagged enums), skip_serializing_if. Reach for the right attribute before a hand-written impl Deserialize.
  • Zero-copy: #[serde(borrow)] kind: &'a str borrows slices out of the input buffer instead of allocating — a real win on hot parse paths, but ties the struct's lifetime to the buffer. Falls back to owning when a string needs unescaping !
  • The boundary: from_slice::<T>(&bytes) turns untrusted bytes into a validated T or an error with line/col. Parse into a concrete struct, not serde_json::Value — Value defers validation to runtime and allocates heavily. In axum, Json<T> is this boundary (400 on failure).

Axum / Tower Web Service

  • A handler is an async fn whose args are extractors and whose return impl IntoResponse. Any fn whose params implement FromRequestParts (plus one final body-consuming FromRequest) is a Handler.
async fn get_user(
    State(s): State<Arc<AppState>>,
    Path(id): Path<u64>,
) -> impl IntoResponse { Json(json!({"id": id})) }

let app = Router::new()
    .route("/users/:id", get(get_user))
    .with_state(state);
axum::serve(listener, app).await?;   // 0.7+: no Server builder
  • State is with_state + the State extractor; must be Clone (hence Arc). Body-consuming extractors (Json, String) must come last — there's one body !
  • Tower Service = poll_ready + call(req) -> Future; a Layer wraps one service in another. TraceLayer/TimeoutLayer/ConcurrencyLimitLayer/auth stack via .layer() like an onion — outermost-first on request, innermost-first on response. Declare top-down with ServiceBuilder.

Pools, Shutdown & Backpressure

  • Connection pool: build a PgPool once at startup (it's Arc inside — cheap Clone); acquire().await parks the task when exhausted instead of blocking a thread.
  • Sizing: more connections ≠ more throughput. Rule of thumb ~(2·cores)+spindles → often 10–20, not 200. Cap against the DB's max_connections summed across all app instances; front with PgBouncer when the fleet outgrows the DB !
  • Use an async-native driver (sqlx/tokio-postgres); wrap sync diesel in spawn_blocking. Set acquire_timeout so saturation fails fast (503) rather than hanging; never hold a connection across an unrelated .await.

Graceful shutdown

  • On SIGTERM: stop accepting, drain in-flight, force-exit past a timeout shorter than k8s terminationGracePeriodSeconds. axum::serve(..).with_graceful_shutdown(fut); select! ctrl_c and SIGTERM — forgetting SIGTERM = shutdown silently never fires in k8s ! Fan out to workers with a CancellationToken; flush tracing/metrics before exit.

Backpressure

  • A slow consumer must throttle a fast producer — a stability property, not an optimisation. tokio::sync::mpsc::channel(cap): send().await parks when full. unbounded_channel has none → OOMs on a spike ! When you can't slow external traffic, shed load (503 via LoadShedLayer) rather than queue work you'll never catch up on.

Self-Referential Structs & Graphs

  • A struct can't hold a reference into itself: Rust values are movable, so a self-& would dangle on move — and the borrow checker can't express a lifetime referring back to its own struct. That's why you're told never to hand-roll a next: &Node linked list !
ApproachUse / cost
Index/arena (Vec<Node>, links = usize)graphs/trees/ASTs/ECS; no unsafe, cache-friendly; no per-node free
Rc<RefCell<T>>shared-ownership graph, single-thread; cycles leak → Weak
unsafe + raw ptrsintrusive lists, perf internals; uphold aliasing by hand, verify with Miri
struct Graph { nodes: Vec<Node> }
struct Node { value: i32, edges: Vec<usize> } // indices, not refs
  • The arena pattern is what production uses (petgraph, AST crates, ECS) — a usize isn't a borrow, so it sidesteps the checker entirely. True self-referential values (async generators, some FFI) need Pin+unsafe or a crate like ouroboros — reach for that last.

★ Code Review Checklist

Ownership / borrows

  • ☐ .clone() used to decide ownership, not to silence E0502/E0382 — could it be a &T borrow or an index? !
  • ☐ API takes &str/&T to read, String/T only to store/consume.
  • ☐ Returned reference's lifetime doesn't over-constrain the caller.

Errors / panics

  • ☐ No unwrap()/expect() on fallible I/O in library code; panic! only for broken invariants.
  • ☐ Libraries expose a thiserror enum (not anyhow); ?'s From impls present.
  • ☐ No dropped Result (heed #[must_use]).

Concurrency / async

  • ☐ No std::sync::MutexGuard / Rc / RefCell held across an .await !
  • ☐ No blocking call (std::fs, sleep, CPU loop) on a runtime thread — use spawn_blocking.
  • ☐ Shared state is Arc<Mutex/RwLock> or atomics; lock scope minimal; no lock-order inversions.

Correctness

  • ☐ Integer arithmetic uses checked/saturating/wrapping where release-wrap would corrupt !
  • ☐ No String byte-indexing / mid-codepoint slicing.
  • ☐ Rc/Arc cycles broken with Weak; no reflexive RefCell that could double-borrow_mut.

Unsafe

  • ☐ Every unsafe block has a // Safety: note; the safe wrapper guarantees the contract; Miri-clean.
  • ☐ FFI is extern "C" + #[repr(C)] and never unwinds across the boundary.
