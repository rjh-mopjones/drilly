Maturity: 0 manual → 1 automated pipeline → 2 CI/CD/CT. ! Models fail SILENTLY.

Version Everything

  • Data (DVC/lakeFS/Delta) + code (git) + model (registry) + config + env.
  • Reproducible = answer "which data+code+params made this model?"
  • Experiment tracking (MLflow/W&B): params, metrics, artifacts per run → registry.

Feature Store

  • Solves train/serve skew + feature reuse.
  • Offline (batch, point-in-time-correct → no leakage) + online (low-latency KV for serving).
  • Same definition computes both → consistency. ! Point-in-time (as-of) joins.
  • Feast / Tecton. Skip if you don't need real-time features.

Pipelines & CT

  • DAG: ingest→validate→featurize→train→eval→register (Kubeflow/Airflow/Flyte).
  • Reproducible, parameterized, cached steps.
  • Continuous Training: trigger on schedule / drift / decay → retrain → validate → canary → promote. ! Guardrails so a bad retrain can't ship.

Registry & Packaging

  • Registry = source of truth: versions + stages (Staging/Prod/Archived), lineage, model cards.
  • Rollback = re-point prod to a prior version.
  • Package: ONNX/TorchScript/SavedModel (avoid raw pickle), containerize, pin deps. ! Reproducibility crisis.

CI/CD/CT for ML

  • Test code (unit) + data (schema/distribution — GE/TFDV) + model (metric gates, no-regression vs prod, slice + fairness).
  • Integration-test the serving artifact; GitOps.
  • The pipeline is code that's tested.

Serve mode: batch vs online vs streaming. Feature-flag models.

Serving Infra

  • REST/gRPC service; TF Serving / TorchServe / Triton / KServe / BentoML.
  • Autoscale (HPA, scale-to-zero), GPU serving, multi-model.
  • In-app lib vs sidecar vs central microservice — latency vs coupling.

Serving at Scale

  • Dynamic batching (latency↑ a bit, throughput↑↑ on GPU).
  • Cache; optimize model: quantize / distill / prune (ONNX/TensorRT).
  • Budget p50/p99; CPU vs GPU; cost per 1k preds. ! Throughput vs latency tradeoff.

Monitoring (2 layers)

  • Operational: latency, throughput, errors, saturation (SRE).
  • ML: prediction & feature distributions, quality when labels arrive, business KPIs.
  • ! "Model is down" (ops) vs "model is wrong" (silent). Log inputs+preds. Ground-truth is delayed.

Drift

PSI = sum (actual% - expected%) * ln(actual%/expected%)
 <0.1 ok | 0.1-0.25 watch | >0.25 shift
  • Data P(x) shift · concept P(y|x) shift · label P(y) shift.
  • Detect: KS / chi-square / PSI / embedding drift. ! Drift != a proven perf drop.

A/B & Feedback

  • Online experiment beats offline metrics (the offline-online gap).
  • A/B: primary + guardrail metrics, significance, power; bandits; shadow.
  • ! Peeking, novelty, Simpson's paradox; feedback loops reinforce the model.

Infra, Governance, LLMOps

  • Infra: GPU/TPU on K8s, spot + checkpoint, autoscale, cost-optimize.
  • Governance: audit, lineage, model cards, bias/PII/security, regulation.
  • LLMOps: often no retrain → version prompts / RAG / eval sets; eval-in-CI; cost/latency. (See AI Engineering.)

☐ "Model dropped in prod" / Design

  • ☐ Diagnose decay: data-pipeline break? drift? train/serve skew? upstream schema change? label delay? feedback loop?
  • ☐ Rollback fast (registry → prior version); canary the fix.
  • ☐ Design a platform: data→feature store→pipelines→registry→serving→monitoring→CT.
  • ☐ Real-time serving: online features + low-latency model + fallback + monitoring.
  • ☐ Retraining: drift/decay-triggered CT with validation gates + canary.
  • ☐ Prove a new model wins with an A/B + guardrails, not offline metrics.
