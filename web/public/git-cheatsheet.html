The Three Trees

flowchart LR W["working dir"] -->|"git add"| I["index / staging"] I -->|"git commit"| H["HEAD (repo)"] H -->|"restore / checkout"| W I -->|"restore --staged"| W

add: working→index. commit: index→a new commit. HEAD = last commit. diff = working↔index; diff --staged = index↔HEAD.

Object Model

  • blob = file contents · tree = a directory (→ blobs/trees) · commit = one tree + parent(s) + author/msg · tag object.
  • Everything content-addressed by SHA → identical content stored once; changing anything changes the hash & all descendants (immutable history).
  • Snapshots, not diffs (each commit = full state; deltas only in packfiles at storage time).
  • A branch/HEAD/ref = a file holding a commit SHA — a movable pointer.
git cat-file -p HEAD    git ls-tree HEAD
git rev-parse HEAD~2

Basics

git status -sb          git add -p          # stage hunks
git commit -m "msg"     git commit --amend  # fix last (unpushed!)
git diff                # working vs index
git diff --staged       # index vs HEAD
git log --oneline --graph --all
git show HEAD:path      git blame -L 10,20 file
  • Refs: HEAD, HEAD~3 (ancestor), HEAD^2 (2nd merge parent), A..B range.
  • Commit msg: imperative subject ≤50, body explains why.

Branches & Remotes

git switch -c feature/x         # create+switch
git branch -vv                  # upstream + ahead/behind
git fetch                       # download, no merge (safe)
git pull --rebase               # fetch + rebase (linear)
git push -u origin feature/x
git push origin --delete old
  • origin/main = read-only cache of the remote at last fetch.
  • "rejected non-fast-forward" = remote has commits you lack → fetch/rebase first, don't blind-force !
  • Detached HEAD: on a SHA/tag, not a branch — commit there & switch away = "lost" (reflog recovers) !

Merge vs Rebase

mergerebase
historytrue, with bubbleslinear, clean
commitspreserved + merge commitrewritten (new SHAs)
safe on shared?yesNO !
  • Fast-forward: no divergence → just move the pointer (--no-ff forces a bubble).
  • 3-way merge: combine both tips + merge-base → a 2-parent commit (conflicts if same lines).
  • Golden rule: never rebase/rewrite commits others have pulled ! Your own PR branch → --force-with-lease.

Undo — reset / revert / restore

resetHEAD·index·wd
--softmove HEAD only (keep staged)
--mixed (default)+ reset index (keep edits)
--hard+ reset wd → DISCARD !
git reset --soft HEAD~1     # uncommit, keep staged
git restore --staged file   # unstage
git restore file            # discard edits (loss!)
git revert <sha>             # NEW commit that undoes (shared-safe)
git reset --hard origin/main

Local/unpushed → reset. Shared/pushed → revert !

Stash & Reflog

git stash push -u -m "wip"   git stash list
git stash pop                # apply + drop
git stash apply stash@{1}
git reflog                   # every HEAD move (safety net!)
git reset --hard HEAD@{1}    # undo a bad reset/rebase
git checkout -b recover <sha-from-reflog>
  • Reflog records where HEAD/branches have been (~90 days) → recover "lost" commits after reset/rebase/amend/branch-delete !
  • git fsck --lost-found for dangling commits when reflog won't help.

Conflicts

<<<<<<< HEAD        (ours)
your change
||||||| base        (zdiff3 shows ancestor)
=======
their change
>>>>>>> branch     (theirs)
  • Edit to the intended result, remove all markers, git add, then commit/--continue. Bail: merge/rebase --abort.
  • Enable merge.conflictStyle=zdiff3 (shows the base) & rerere.enabled (auto-reapply resolutions) !
  • In a rebase, "ours" = the branch you rebase ONTO (flips vs merge) !
  • A clean text merge can still be semantically broken → run tests.

Cherry-pick & Bisect

git cherry-pick <sha>        # apply one commit here (new SHA)
git cherry-pick A..B         # a range
git bisect start
git bisect bad; git bisect good v1.0
git bisect run ./test.sh     # AUTOMATE the search
git bisect reset
  • Cherry-pick to backport a fix to a release branch.
  • Bisect = binary search for the commit that broke it (log2 n) — atomic commits make it powerful.

Branching & PRs

  • Trunk-based (short branches + feature flags + CI) = modern default; GitHub Flow (main + PRs); GitFlow = heavy, scheduled releases; long branches → merge hell !
  • PR merge modes: merge commit (full history) · squash (one clean commit, popular) · rebase (linear, keep commits).
  • Branch protection: required review + CI checks, up-to-date branch, CODEOWNERS, no direct push to main.
  • Keep a PR current: rebase onto main (then --force-with-lease) or merge main in.

Tags & Config

git tag -a v1.2.0 -m "release"   # annotated (preferred)
git push origin v1.2.0           # tags NOT pushed by default!
git describe --tags              # v1.2.0-14-gabc123
  • Annotated (object + tagger/msg/sign) vs lightweight (bare pointer). Sign releases (-s).
git config --global pull.rebase true
git config --global merge.conflictStyle zdiff3
git config --global alias.lg "log --oneline --graph --all"

Levels: system → global → local. .gitignore can't untrack already-tracked files → git rm --cached !

Internals · Big Repos · Hooks

  • Loose objects → packfiles (delta-compressed) via git gc; unreachable objects pruned after the reflog grace window.
  • Big repos: shallow clone --depth 1 (CI), partial clone --filter=blob:none, sparse-checkout, Git LFS for big binaries (never commit large binaries raw — every clone keeps every version) !
  • Submodule = pinned pointer to another repo (extra --init --recursive); subtree = copied-in.
  • Hooks (pre-commit/commit-msg/pre-push) are local & advisory → CI/branch-protection enforces. Share via pre-commit/Husky/lefthook.

★ Recovery Playbook

  • ☐ Committed to wrong branch: git branch new; git reset --hard HEAD~1 (on the wrong one) — or cherry-pick.
  • ☐ Committed a secret: git filter-repo to purge from ALL history + ROTATE the secret (it's already leaked) !
  • ☐ Undo last commit, keep work: git reset --soft HEAD~1.
  • ☐ Undo a pushed commit: git revert <sha> (never reset+force on shared).
  • ☐ Lost commits (bad reset/rebase): git reflog → git reset --hard HEAD@{n}.
  • ☐ Force-push clobbered main: recover the old SHA from reflog / a good clone → reset + push.
  • ☐ Bad merge: git revert -m 1 <merge-sha> (mind the re-merge gotcha).
  • ☐ Which commit broke it: git bisect run.

☐ Safe-Habits Checklist

  • ☐ Only rewrite local/unpushed history; on shared branches use revert.
  • ☐ --force-with-lease, never bare --force.
  • ☐ fetch & review before you act; pull --rebase/--ff-only for clean history.
  • ☐ Small, atomic commits (better review / bisect / revert); clean the branch before a PR.
  • ☐ Enable zdiff3 + rerere; a .gitignore for junk; global identity + signing set up.
  • ☐ Never commit secrets/large binaries; protect main (no force-push, required checks).
  • ☐ When in doubt, it's in the reflog — don't panic.
