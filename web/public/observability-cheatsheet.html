Observability Cheat Sheet

SRE focus · metrics/logs/traces · SLOs · PromQL · drilly

How to read & print

  • ! footgun / gotcha   ☐ alert/dashboard review item
  • Concept-first, vendor-neutral; tools named where they matter (Prometheus, Grafana, Loki, Tempo, OTel).
  • Golden rule: observability = infer internal state from external outputs — debug unknown-unknowns, not just watch known dashboards.
  • Print: Ctrl/⌘-P → A4, margins None, scale 100%, background graphics on. 4 columns built-in.

The Three Pillars

PillarGood for / cost
Metricstrends, alerting, dashboards; cheap, aggregatable; keep cardinality low !
Logsthe "why", forensic detail; expensive at volume; high-cardinality OK
Tracesrequest flow across services; find the slow span; sampled

Correlate them: metric spike → exemplar → trace → logs (via trace_id). One pillar alone rarely closes an incident.

Which signals?

  • RED (services): Rate · Errors · Duration.
  • USE (resources): Utilization · Saturation · Errors.
  • 4 Golden Signals: Latency · Traffic · Errors · Saturation.

PromQL Quick-ref

# per-second request rate (counter needs a range vector)
sum(rate(http_requests_total[5m])) by (job)

# error ratio
sum(rate(http_requests_total{code=~"5.."}[5m]))
/ sum(rate(http_requests_total[5m]))

# p99 latency from a histogram
histogram_quantile(0.99,
  sum(rate(http_req_duration_seconds_bucket[5m])) by (le))

# recording rule (precompute)
# job:http_errors:ratio5m
  • rate() = per-sec avg (smooth); irate() = last 2 points (spiky); increase() = total over window.
  • Never rate() a gauge; never average percentiles !
  • absent() to alert on missing data.

Instrumentation

  • Instrument every endpoint with RED; every resource with USE.
  • Labels must be bounded — never user_id, request_id, raw URL/path as a label ! Normalize routes (/users/:id).
  • Histograms for latency (pick buckets or use native histograms).
  • Exporters for things you can't edit: node_exporter (host), blackbox_exporter (probe HTTP/TLS/DNS), *_exporter per system.
  • Pushgateway ONLY for short-lived batch jobs — anti-pattern for services !
  • Exemplars link a histogram bucket → a trace.

SLI / SLO / Error Budget

  • SLI = good events / valid events (a ratio). SLO = target over a window. SLA = SLO + contract/penalty. Error budget = 1 − SLO.
  • 100% is the wrong target — the budget funds releases; freeze when spent.
SLODowntime/30d
99%~7.2 h
99.9%~43 min
99.95%~22 min
99.99%~4.3 min

Latency SLO = threshold + percentile ("95% < 300ms").

Alerting & Burn Rate

  • Alert on symptoms (user-facing SLO breach), not every cause !
  • Every page must be actionable + urgent + human-needed — else delete it.
  • Burn rate = budget-spend speed. Rate 1 = on pace; rate 14.4 ≈ a month's budget in ~2 days.
  • Multi-window multi-burn-rate: fast-burn short window → page; slow-burn long window → ticket. Combining windows kills false positives & resets fast.
BurnWindow → action
14.4×1h/5m → page
6×6h/30m → page
1×3d/6h → ticket

Alertmanager

  • Prometheus fires; Alertmanager routes/dedups/notifies.
  • Routing tree matches on labels → receivers (PagerDuty/Slack/…).
  • Grouping (group_by + group_wait/interval) batches related alerts into one notice — stops storms !
  • Inhibition: a firing high-sev alert suppresses dependent low-sev ones (cluster-down mutes per-service).
  • Silences for maintenance; dedup across HA Prometheus replicas via gossip.
  • Dead-man's switch: an always-firing watchdog to detect a broken pipeline.

Logging

  • Structured (JSON) logs — queryable, not grep-and-pray.
  • Include trace_id + request/correlation IDs to pivot to traces.
  • Don't log what should be a metric; sample/drop DEBUG in prod — log volume is the silent bill !
  • Never log secrets/PII.

Storage models

  • Elasticsearch/OpenSearch — full-text index, powerful, pricey.
  • Loki — indexes labels only, stores compressed lines; cheap. Same low-cardinality label rule as metrics ! Filter content with LogQL.
  • Agents: Fluent Bit / Vector / Promtail-Alloy.

Tracing

  • Trace = tree of spans (op + duration + parent + attributes). Shows the causal path metrics/logs can't.
  • Context propagation: W3C traceparent header flows trace_id/span_id across services — a service that drops it breaks the trace !
  • Sampling: head (decide at start, cheap, may miss rare errors) vs tail (decide after whole trace — keep all errors/slow ones; needs a buffering collector).
  • Backends: Jaeger, Grafana Tempo (object storage, cheap), Zipkin.
  • Derive RED metrics from spans; find the critical-path slow span.

OpenTelemetry

  • Vendor-neutral standard for all three signals — instrument once, export anywhere (no re-instrument to switch vendors).
  • API vs SDK: code against the API; wire SDK/exporter at runtime.
  • OTLP = the wire protocol.
  • Collector = receivers → processors → exporters. Agent (DaemonSet) or gateway. Does batching, tail sampling, redaction, format translation.
  • Auto-instrumentation (Java/Python/Node agents) vs manual spans; semantic-convention attribute names.

Metrics at Scale

  • Single Prometheus is bound by active series (cardinality) + local disk + single region !
  • Scale out: functional sharding (split targets), federation (aggregate up), remote_write to a backend.
  • Thanos / Mimir / Cortex: object-storage long-term, global query view, dedup HA replicas, downsampling (raw → 5m → 1h), multi-tenancy.
  • Run 2 identical Prometheis for HA (no clustering); dedup at query/Alertmanager.
  • Recording rules pre-aggregate to cut query cost.

Kubernetes Monitoring

  • kube-prometheus-stack + Prometheus Operator: ServiceMonitor/PodMonitor (declarative scrape targets), PrometheusRule (alerts).
  • Layers: node-exporter (host), cAdvisor (container CPU/mem, in kubelet), kube-state-metrics (object state: desired vs ready), control-plane metrics.
  • metrics-server is only for HPA / kubectl top — NOT storage or alerting !
  • Pod churn creates new series → a cardinality driver !

Frontend & Synthetic

  • Black-box (probe like a user) + white-box (internal) — you need both.
  • Synthetic: scripted uptime/journey checks from many regions; deterministic, pre-launch, catches TLS/cert/DNS. Doesn't reflect real users.
  • RUM: instrument the real browser/app — geography, devices, network.
  • Core Web Vitals: LCP (load ≤2.5s), INP (responsiveness ≤200ms, replaced FID), CLS (layout shift ≤0.1).
  • JS error tracking (Sentry + source maps); OTel browser → connect to backend traces.

Cardinality & Cost

  • Cardinality = unique label-value combos = #series. One unbounded label (user_id / request_id / full URL) = millions of series → OOM + huge bill ! The #1 killer.
  • Find it: /api/v1/status/tsdb, count by (__name__)({__name__=~".+"}), topk offenders.
  • Control: drop/relabel via metric_relabel_configs, normalize routes, bounded labels.
  • Logs: sample, drop DEBUG, tiered retention. Traces: tune sampling.
  • Retention: raw short-term + downsampled long-term to object storage.
  • Managed APM billing traps: per-host, per-GB, custom-metric counts !

Profiling

  • Answers "WHICH function" burns CPU/allocates — beyond a trace's "which service".
  • Profiles: CPU, heap/alloc, goroutine/thread, mutex/block, off-CPU.
  • Flame graph: width = resource/time; x-axis is NOT time-ordered; find the widest frames.
  • pprof (Go: /debug/pprof); sampling profilers = low overhead.
  • Continuous profiling always-on in prod: Pyroscope / Parca / Polar Signals; eBPF = whole-system, no code change / redeploy.

★ Incident Playbook

  • Lifecycle: detect → triage → mitigate → resolve → learn. Mitigate before diagnose (rollback/failover/scale) !
  • Metrics: MTTD → MTTA → MTTR. Roles: IC · comms · ops · scribe.
  • Every page → a runbook. Blameless postmortem: timeline, contributing factors, action items w/ owners. "Human error" is never a root cause.

  • ☐ Dashboard (which endpoint?) → trace of a slow request (which span?) → logs for that trace_id → profile if CPU/mem.

Paged constantly

  • ☐ Audit alerts: non-actionable → delete; cause-based → replace with SLO/symptom; add grouping/inhibition.

☐ Alert / Dashboard Review

Alerts

  • ☐ Symptom / SLO-based, not cause-based; actionable + urgent + human-needed.
  • ☐ Multi-window multi-burn-rate; for: to debounce; links a runbook.
  • ☐ Routed/grouped/inhibited sanely; a dead-man's-switch exists.
  • ☐ Alert on missing data (absent()).

Metrics & dashboards

  • ☐ No unbounded labels; RED/USE covered; recording rules for heavy queries.
  • ☐ Dashboards: signal-first, right panel type, correct aggregation, deploy annotations, exemplars → traces.
  • ☐ SLIs measured at the user boundary; dashboards-as-code (no click-ops drift).
