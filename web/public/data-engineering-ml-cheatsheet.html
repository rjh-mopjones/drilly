Point-in-Time Correctness

-- join label to features AS OF the label time
SELECT l.*, f.val
FROM labels l ASOF JOIN features f
  ON f.entity = l.entity
 AND f.ts <= l.ts      -- NOT the latest value !

Using latest feature values leaks the FUTURE into training. Time-travel (Delta/Iceberg) makes it reproducible.

Train/Serve Skew (#1 bug)

  • Features computed differently in train (batch/notebook) vs serve (online) → model silently wrong. !
  • Causes: two code paths, two data sources, time misalignment, diff missing-value handling.
  • Fix: one shared transform / feature store; log served features & train on them.

Data Validation

  • Validate BEFORE training/serving: schema (types/ranges), distribution vs reference, missing-rate, cardinality.
  • Tools: Great Expectations / TFDV / Pandera / dbt tests.
  • Data contracts producer↔ML; validation as a gate (block/quarantine). !

Data Quality

  • Dimensions: completeness, accuracy, consistency, timeliness, uniqueness, validity.
  • Unit-test transforms (input rows → expected feature).
  • ! Silent bad data (pipeline succeeds, values wrong) is worse than a crash.

Missing / Late / Dup

  • Missing: impute OR flag — identically in train & serve. !
  • Late/out-of-order: watermarks, reprocessing windows.
  • Dedup: idempotency keys / exactly-once. Backfills must be idempotent.

Label Quality

  • Inter-annotator agreement (Cohen/Fleiss kappa); consensus/adjudication.
  • Gold sets to score annotators; clear guidelines (ambiguity = enemy).
  • Version labels (definitions change); audit; watch label leakage.

Versioning & Lineage

  • Version data (DVC / Delta / Iceberg / Hudi — ACID + time travel) + feature defs + training snapshot.
  • Reproducible = code + data + features + labels + config.
  • Lineage: feature→source, model→exact training data (audit/impact).

Big Data & DL Pipelines

  • Spark for feature eng at scale (watch the shuffle & join skew). Parquet; sample for dev.
  • DL: DataLoader/tf.data, augment (train-only), shard (TFRecord/WebDataset), prefetch. ! Keep the GPU fed — input pipeline is often the bottleneck.

Reliability & Cost

  • ! A stale feature = silent model decay. Monitor freshness + feature distributions at the pipeline.
  • Alert on broken/late/null-spiking features; safe backfills.
  • Cost triangle: freshness vs latency vs $. Materialize vs compute-on-read; batch beats streaming when hourly is fine.

Privacy / PII

  • ! A model can memorize PII — deleting the row doesn't untrain it (right-to-erasure problem).
  • Anonymize / hash / tokenize; consent & retention; access control on features. (See Security.)

☐ "Features wrong in prod" / Design

  • ☐ Diagnose stale/wrong features: upstream break? schema change? backfill bug? stream-vs-batch skew? late data? null spike?
  • ☐ Design a feature pipeline serving IDENTICAL batch + online features (prove no skew).
  • ☐ Training-data gen: point-in-time joins, no future leakage, reproducible.
  • ☐ Labelling: weak supervision + active learning + gold-set QA + versioning.
  • ☐ Validation gate blocks bad data before it trains/serves.
  • ☐ DL data: keep GPUs fed (shard/prefetch/parallel-load).
  • ☐ Version data+features+labels; lineage for audit.
