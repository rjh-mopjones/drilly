URL → Pixels & Browser Architecture

  • Type URL → DNS → TCP+TLS → HTTP request → HTML bytes → parse to DOM + CSSOM → render tree → layout → paint → composite → pixels.
  • Chromium is multi-process: browser (UI/privilege), one renderer per site (sandboxed), GPU, network, utility. A crash/exploit in one tab can't read another — site isolation.

Threads inside a renderer

ThreadRuns
MainJS, DOM, style, layout, paint. Single-threaded — everything competes here !
CompositorLayers → screen; can scroll/animate transforms without the main thread
Raster / GPUTurn paint records into textures on the GPU
WorkerWeb Worker JS, off the main thread (no DOM)

! A heavy JS task blocks the main thread → no input, no layout, no paint — the page freezes. Transform/opacity animations run on the compositor and stay smooth even then.

Critical Rendering Path

Sequence the browser runs before first pixels. Minimise the bytes that block it.

StageNote
DOMparse HTML; a sync <script> pauses parsing !
CSSOMCSS is render-blocking — nothing paints until it's built !
Render treeDOM ∩ CSSOM, minus display:none nodes
Layout (reflow)compute box geometry (position/size)
Paintfill pixels: text, colours, shadows, borders
Compositeassemble layers on the GPU
  • Reflow = geometry recompute (expensive). Repaint = visual only, no geometry. Composite = cheapest (transform/opacity).
  • CSS also blocks JS: a script waits for pending stylesheets because it may read computed styles !
  • Levers: inline critical CSS, defer the rest, defer/async scripts, minimise render-blocking bytes.

JS Engine (V8) & Memory

  • JS is JIT-compiled, not "interpreted": parse → AST → bytecode (Ignition) → hot code → optimised machine code (TurboFan) → deopt back to bytecode if assumptions break.
  • Hidden classes / shapes: objects with the same property order share a shape → fast property access. Add props in a consistent order; avoid delete (forces dictionary mode) !
  • Inline caches: a call site is monomorphic (1 shape, fastest) → polymorphic → megamorphic (slow). Passing many object shapes to one function deopts it.

GC & leaks

  • Generational mark-and-sweep: young (scavenge, frequent) + old (mark-sweep-compact). Reachable from a root (globals, stack, closures) = alive.
  • Leaks in a GC language: forgotten timers, detached DOM refs, growing closures/caches, listeners never removed ! — find with DevTools heap snapshots (compare, watch retained size climb).

Event Loop & Async JS

  • Call stack empties → drain ALL microtasks → render (if needed) → run one macrotask → repeat.
  • Microtasks: Promise.then, await continuation, queueMicrotask, MutationObserver. Macrotasks: setTimeout, events, I/O, MessageChannel.
console.log('A');
setTimeout(() => console.log('D'), 0);
Promise.resolve().then(() => console.log('C'));
console.log('B');
// A B C D  (sync, then microtasks, then macrotask)
  • setTimeout(fn,0) is not 0ms — clamped to ~4ms when nested, and waits for the current task + all microtasks.
  • An infinite microtask loop starves rendering forever (never yields) !; a chain of setTimeouts yields between each.
  • requestAnimationFrame runs before paint — use it for animation and DOM reads/writes, not setTimeout.

DOM & Manipulation

  • DOM = live in-memory object tree (a JS API); HTML = the source text. "View Source" = raw HTML; DevTools = the current DOM.
  • Attribute (HTML, initial string) ≠ property (DOM, live value) — input.value tracks typing; getAttribute('value') stays the initial !

Layout thrashing !

// BAD: read→write→read forces sync reflow each loop
for (const el of items)
  el.style.height = el.offsetHeight + 'px';
// GOOD: batch reads, then writes
const hs = items.map(el => el.offsetHeight);
items.forEach((el,i)=> el.style.height = hs[i]+'px');
  • Reading offsetTop/Width, getBoundingClientRect, getComputedStyle after a write forces sync layout.
  • Batch inserts with a DocumentFragment (one reflow). textContent is safe; innerHTML with user data = XSS !
  • Live collections (getElementsByTagName) update as you mutate — iterate a static querySelectorAll snapshot instead.

DOM Event Model

  • Three phases: capture (root→target) → target → bubble (target→root). Listeners bubble by default; {capture:true} for phase 1.
  • target = element that fired; currentTarget = element the listener is on !

Delegation & cleanup

list.addEventListener('click', e => {
  const li = e.target.closest('li');
  if (li) select(li.dataset.id);   // one listener, N rows
});
  • Delegation survives re-renders and scales to N children with one listener.
  • {passive:true} on scroll/touch → can't preventDefault but never blocks scroll. AbortController removes many listeners at once ({signal}) — forgotten removal leaks !

React — Rendering & Reconciliation

  • Render = call components to build a new element tree (pure, no side effects). Commit = React applies the diff to the DOM. Rendering ≠ DOM update.
  • A component re-renders when its state/props change or its parent re-renders — children re-render by default even with identical props !
ToolStops re-render / recompute when…
React.memoprops shallow-equal
useMemomemoise an expensive value / stable object prop
useCallbackstable fn identity for memoised children
  • Keys: stable & unique per list — never the array index for reorderable/removable lists (state binds to the wrong row) !
  • RSC render on the server and ship zero JS; Client Components ('use client') hydrate. <Suspense> streams a fallback while data loads.
  • Don't reach for memo first — fix structure (lift state down, pass children) before micro-optimising.

React — Hooks

  • Rules: call hooks at the top level, same order every render — never in conditions/loops ! Only in components/custom hooks.
useEffect(() => {
  const c = new AbortController();
  fetch(url, {signal:c.signal}).then(setData);
  return () => c.abort();   // cleanup on unmount/dep change
}, [url]);                  // re-run when url changes
HookPurpose
useStatelocal state; setter is async/batched — use updater s=>s+1 !
useEffectsynchronise with the outside (subs, fetch); not for derived data
useRefmutable box / DOM node; changing it doesn't re-render
useMemo/useCallbackmemoise value / fn identity
  • ! Stale closure: omit a dep and the effect captures old values. Include every referenced value; use the updater form or a ref to escape.
  • Derive during render instead of mirroring props into state (redundant state → sync bugs).

CSS — Box Model & Layout

  • Always set box-sizing:border-box — width includes padding+border (default content-box adds them on top) !
  • Margins collapse vertically between block siblings (max, not sum); flex/grid items and padding don't collapse.
SystemUse for
Flexbox1-D rows/columns; distribute along one axis
Grid2-D layout; explicit rows × columns
positionrelative / absolute (nearest positioned ancestor) / fixed (viewport) / sticky
.row { display:flex; gap:1rem;
  justify-content:space-between; /* main axis */
  align-items:center; }         /* cross axis */
.grid { display:grid;
  grid-template-columns:repeat(auto-fit,minmax(12rem,1fr)); }
  • Stacking context: created by position+z-index, opacity<1, transform, filter. z-index only compares within a context — a child can't escape its parent !
  • Prefer gap over margins; animate transform/opacity only (compositor, no reflow).

Cookie attributes

  • HttpOnly — JS can't read it (blunts XSS token theft). Secure — HTTPS only. SameSite: Strict / Lax (default, top-nav GET) / None (needs Secure) — CSRF lever.
  • Auth tokens: prefer an HttpOnly; Secure; SameSite cookie over localStorage — localStorage is readable by any XSS !
  • __Host- prefix forces Secure + path=/ + no Domain — hardening.

Browser Security Model

  • Origin = scheme + host + port. Same-origin policy blocks reading cross-origin DOM/responses (requests may still be sent).
  • CORS relaxes it: server opts in with Access-Control-Allow-Origin. Non-simple requests (custom headers, PUT) trigger a preflight OPTIONS. * + credentials is forbidden !
AttackDefence
XSS (inject script)escape output, framework auto-escaping, CSP, no innerHTML of user data
CSRF (ride cookie)SameSite cookies, CSRF token, check Origin
ClickjackingX-Frame-Options: DENY / CSP frame-ancestors
Tampered CDNSubresource Integrity integrity=sha384-
  • CSP: default-src 'self'; blocks inline/eval script — the strongest XSS backstop.
  • ! postMessage: always verify event.origin and set a target origin (never '*' for secrets).

  • Status essentials: 200/201/204, 301/302/304, 400/401/403/404/429, 500/502/503.

  • Compress text with brotli/gzip; TTFB = server + network (yes, a front-end concern).

Browser Caching

DirectiveMeaning
max-age=Nfresh for N s — served with no request
no-cachestore but revalidate every time (ETag)
no-storenever store (sensitive data)
immutablenever revalidate — for hashed assets
private/publicbrowser-only vs shared/CDN
  • Validation: ETag/Last-Modified → conditional request → 304 (no body). Cheaper than a full fetch, still a round trip.
  • Cache busting: content-hash filenames (app.9f3c.js) + immutable, and short-cached HTML pointing at them — solves invalidation !
  • SW strategies: cache-first (static), network-first (fresh data), stale-while-revalidate (fast + eventually fresh).
  • bfcache: instant back/forward from a frozen page. unload listeners and no-store disqualify it !
  • ! Vary splits the cache per header value — a wide Vary wrecks hit rate.

Web Performance — Loading & Runtime

Loading — fewer/smaller bytes, right order

  • Code splitting per route (import()); tree-shaking (ESM only) drops dead exports; minify; compress.
  • loading="lazy" for below-fold images; responsive srcset/sizes + modern formats (AVIF/WebP); dynamic import() for heavy components.
  • Preload the LCP image; inline critical CSS; defer non-critical JS/CSS.

Runtime — keep the main thread free

  • Long task = >50ms — break work into chunks, yield with scheduler.postTask / setTimeout / await !
  • Offload CPU work to a Web Worker; virtualise long lists (render only visible rows); debounce/throttle scroll & input handlers.
  • Animate transform/opacity (compositor); avoid animating width/top/left (reflow every frame) !

Rendering Strategies

One question: who builds the first HTML, and when? Trades first-paint vs interactivity vs SEO vs server cost. Choose per page.

StrategyHTML builtNotes
CSRclient at runtimeblank first paint, cheap server, SEO risk — dashboards
SSRserver per requestfast LCP/SEO, then hydrate — product pages

  • Hydration = client re-runs component code over server HTML to attach listeners. Big tree = long task = poor INP !
  • ! "Uncanny valley": page looks ready but doesn't respond until hydration finishes. SSR ships HTML and the JS bundle — often more total work than CSR, in a better order.

Accessibility & Semantics

  • Semantic HTML first: <button>, <nav>, <main>, <label> give role + keyboard + focus for free. A <div onClick> is invisible to assistive tech and not keyboard-focusable !
  • ARIA rule #1: don't use it if a native element exists. ARIA changes semantics, never behaviour — you still wire keys yourself.

★ Front-End Review Checklist

Rendering & main thread

  • ☐ No layout thrashing — reads batched before writes; no forced sync layout in a loop !
  • ☐ Animations use transform/opacity (compositor), not width/top.
  • ☐ Long tasks split/yielded; heavy CPU work in a Worker; long lists virtualised.

React

  • ☐ Stable, non-index keys on lists; hooks at top level; complete effect dep arrays.
  • ☐ Effect cleanup (abort/unsubscribe); no derived data mirrored into state; setState uses the updater form.

Loading & CWV

  • ☐ LCP image preloaded & sized (no CLS); route-level code splitting; below-fold images lazy.
  • ☐ Scripts defer/async; critical CSS inlined; hashed assets immutable.

Security

  • ☐ No innerHTML/dangerouslySetInnerHTML with unsanitised input; CSP set; external data validated.
  • ☐ Auth token in HttpOnly; Secure; SameSite cookie; CORS not * with credentials !

A11y

  • ☐ Real <button>/<a>, labelled inputs, visible focus, keyboard-operable, AA contrast.
