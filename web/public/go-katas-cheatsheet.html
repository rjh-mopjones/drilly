Attack plan — the loop

Turn an open prompt ("many handlers read the latest price", "drain the server without loss") into correct, tested code. Same five steps every time:

  • 1. Find the shared state + the lifecycle. What memory is touched by >1 goroutine, who writes/reads it? For every go you start, how does it end — closed chan, cancelled ctx, finite loop? State these out loud; each answer becomes a test.
  • 2. Design the API & pick synchronisation. Write the exported signatures first; committing to how you synchronise is the design (next card).
  • 3. Write the tests FIRST — in this order: contract (single-goroutine happy path) → core (the kata's real job) → edges (nil/closed chan, empty, ctx cancelled mid-flight, slow consumer) → -race stress (many goroutines, assert an invariant).
  • 4. Implement to green. Prefer the simplest primitive that removes the race.
  • 5. Repeat under load. go test -race -count=5 ./pkg/; go vet ./... (copylocks, loopclosure, printf). A single green run proves nothing !

The skill tested is not "do you know channels" but "can you reason about N goroutines hitting this at once, and write the test that proves it".

Synchronisation decision

Choosing among these is the design. Pick the simplest that removes the race.

PrimitiveUse when
sync.Mutexshared mutable struct; hold across the whole read-modify-write. Not reentrant !
sync.RWMutexreads ≫ writes and reads don't mutate. An LRU/LFU Get mutates recency → RLock corrupts it, use Mutex !
channeltransfer ownership (share by communicating) or serialise via a single-writer loop. No lock guards the owned state.
context.Contextthread cancellation/deadline to every downstream call; check ctx.Done() / ctx.Err().
atomic.Pointer[T]lock-free swap of a single immutable snapshot (whole-map replace, config).
WaitGroup+1 closerfan-in: count finishers, then one goroutine closes the output.
  • "Add a mutex to be safe" — a lock held across a downstream/blocking call serialises everything and can deadlock; scope it tight !
  • "Channels are always the answer" — a plain mutex-guarded struct is often simpler and faster than a channel dance.

The -race stress harness

The one test that catches the bug: many goroutines, a start-gate, mixed read/write, assert an invariant a race would break.

func TestX_RaceStress(t *testing.T) {
  if testing.Short() { t.Skip("stress") }
  l := New(); l.Open("a",1000); l.Open("b",1000)
  const G, N = 64, 5000
  var wg sync.WaitGroup
  start := make(chan struct{})   // gate: max contention
  for g := 0; g < G; g++ {
    wg.Add(1)
    go func(){ defer wg.Done(); <-start
      for i:=0;i<N;i++{ l.Transfer("a","b",1)
                        l.Transfer("b","a",1) }
    }()
  }
  close(start); wg.Wait()
  if l.Bal("a")+l.Bal("b") != 2000 {  // INVARIANT
    t.Fatalf("money not conserved")
  }
}
  • Run go test -race -count=5 ./pkg/. Fails an unsynchronised RMW; passes a correct lock every time.
  • Assert the invariant — conservation / exactly-once / no-leak — never an exact interleaving !
  • Detector is sound (no false positives) but only flags races it observes — the stress test's job is to force the path.

Leak & deadlock checks

A green functional test hides both. Add these two shapes.

Goroutine-leak — count returns to baseline

base := runtime.NumGoroutine()
f := NewFeed(); f.Start()
f.Close()                    // must unblock EVERY worker
time.Sleep(20*time.Millisecond) // let them unwind
if n := runtime.NumGoroutine(); n > base {
  t.Fatalf("leaked %d", n-base)
}

Deadlock / deadline — hang fails loudly

ctx,cancel := context.WithTimeout(ctx,10*time.Millisecond)
defer cancel()
err := Settle(ctx, bet)
if !errors.Is(err, context.DeadlineExceeded) {
  t.Fatalf("ctx not propagated: %v", err)
}
  • Wrap any op that could hang in a timeout so a deadlock fails the test, not the suite.
  • t.Cleanup(cancel) / t.Cleanup(server.Close) — teardown runs even on failure.
  • No time.Sleep to synchronise the test logic ! — gate with channels/WaitGroup; inject a clock for timeouts.

Channel discipline

OpBehaviour
send on closedpanic !

recv on closedzero value, ok==false (drains buffer first)

  • The sender closes, exactly once. Receivers never close. Many senders → close from a dedicated goroutine after wg.Wait(), or fence with sync.Once.
  • for v := range ch exits on close; v, ok := <-ch tests it.
select {
case v := <-in:        use(v)
case <-ctx.Done():      return ctx.Err()  // cancel
case out <- x:          // SEND must also race ctx !
default:                return ErrQueueFull // backpressure
}

! Guard both directions against ctx.Done(): a bare out <- x on a full buffer whose consumer left parks the sender forever → leak + a wg.Wait() that never returns → the output never closes.

Pattern — single-writer loop

One goroutine is the only thing that touches the state, so the state needs no lock. Callers hand off requests + a buffered reply chan (matchingengine).

func (e *Engine) Start() {
  go func() {
    defer close(e.stopped)
    for {
      select {
      case <-e.done: return
      case req := <-e.submit:
        req.reply <- e.book.Submit(req.order) // reply buffered(1)
      }
    }
  }()
}
func (e *Engine) Submit(ctx context.Context, o Order) ([]Trade, error) {
  req := submitReq{o, make(chan []Trade, 1)} // size 1: loop never blocks
  select {                       // hand off
  case e.submit <- req:
  case <-e.done:    return nil, ErrEngineClosed // no send-on-closed
  case <-ctx.Done(): return nil, ctx.Err()
  }
  select {                       // await reply
  case tr := <-req.reply: return tr, nil
  case <-ctx.Done():     return nil, ctx.Err() // buffered send still ok
  }
}
  • The submit send/recv is the happens-before edge that orders every book access — non-atomic mutations, no lock, race-clean.
  • Reply buffered(1) so the loop's send completes even if the caller gave up on ctx → no leak.
  • Close: sync.Once → close(done), then <-e.stopped handshake so it returns only once the loop is truly gone.

Pattern — fan-in (WaitGroup-then-close)

func FanIn(ctx context.Context, buf int, srcs ...<-chan Q) <-chan Q {
  out := make(chan Q, buf)
  var wg sync.WaitGroup; wg.Add(len(srcs))
  for _, src := range srcs {
    go func(src <-chan Q) {
      defer wg.Done()
      for {
        select {
        case <-ctx.Done(): return
        case q, ok := <-src:
          if !ok { return }        // source drained + closed
          select {                 // send must ALSO race ctx !
          case <-ctx.Done(): return
          case out <- q:
          }
        }
      }
    }(src)
  }
  go func(){ wg.Wait(); close(out) }() // single closer, exactly once
  return out
}
  • Why not a mutex: forwarders share no mutable state, they only communicate values; the only coordination is "count the finishers" = WaitGroup.
  • wg.Wait() happens-after every send → close(out) strictly follows the last value. Each source owned by one forwarder → each value forwarded once.
  • Don't close from a forwarder (drops siblings' in-flight / double-close panic), and don't spool overflow into a growing slice — blocking IS the backpressure design !

Pattern — graceful shutdown

Three primitives: done (closed once = shutting down), mu RWMutex (makes check-then-send atomic vs close), wg (counts workers).

func (s *Server) Submit(j Job) error {
  s.mu.RLock(); defer s.mu.RUnlock()
  select { case <-s.done: return ErrShuttingDown; default: }
  select {
  case <-s.done:      return ErrShuttingDown // wakes a parked Submit
  case s.jobs <- j:   return nil
  }
}
func (s *Server) Shutdown(ctx context.Context) error {
  s.closeOnce.Do(func(){
    close(s.done)        // fence: future/blocked Submits bail
    s.mu.Lock()          // granted only when no Submit mid-send
    close(s.jobs)        // the ONLY close — exactly once
    s.mu.Unlock()
  })
  fin := make(chan struct{})
  go func(){ s.wg.Wait(); close(fin) }()
  select {
  case <-fin:       return nil
  case <-ctx.Done(): return ctx.Err() // wedged worker → hand control back
  }
}

Workers: for j := range s.jobs drains the buffer after close, then defer wg.Done(). close(jobs)+wg.Wait() is the drain — never a manual drain or a bare wg.Wait() in a deploy path.

Pattern — single-flight & idempotency

Exactly-once HTTP / dedupe: install-or-find one in-flight entry under the lock, release the lock before the downstream call, publish via close(ready) (betgateway).

g.mu.Lock()
if e, ok := g.inflight[key]; ok {
  g.mu.Unlock(); <-e.ready              // waiter blocks on leader
  return e.bet, false, e.err
}
e := &entry{ready: make(chan struct{})}
g.inflight[key] = e
g.mu.Unlock()                           // BEFORE the slow call !
e.bet, e.err = g.placer.Place(ctx, acct, bet) // the single Place
if e.err != nil {                       // drop on failure → retryable
  g.mu.Lock(); delete(g.inflight, key); g.mu.Unlock()
}
close(e.ready)                          // publish edge for all waiters
  • Leader writes fields before close(ready); waiters read after <-ready — the close is the happens-before edge, no field lock needed.
  • Mutex serialises only the map op (closes the TOCTOU window); never wraps I/O !
  • Idempotency-key form (ledger/messagebus): dedupe-check + mutation + record-outcome are one critical section; a duplicate replays the stored outcome.

Deadlock-free locking & ledger

  • Transfer = two locks. "lock from, then to" deadlocks under A→B racing B→A. Acquire in sorted-id order (lower first) — a total order under which no waits-for cycle can form.
  • Reject same-account before locking — double-locking one mutex self-deadlocks !
first, second := src, dst
if first.id > second.id { first, second = second, first }
first.mu.Lock();  defer first.mu.Unlock()
second.mu.Lock(); defer second.mu.Unlock()
// dedupe-check + debit + credit + record all here
src.balance -= amt; dst.balance += amt   // nets to zero = conservation
  • Hold the account lock across the entire RMW — half-locked (read xor write) still loses updates.
  • Double-entry: a -amt/+amt posting that nets to zero makes conservation structural.
  • Money = integer minor units end-to-end; 0.1+0.2 != 0.3 fails audit !
  • DB framing: per-account mutex = SELECT … FOR UPDATE; sorted locks = ORDER BY id; optimistic = version-column CAS.

Context propagation & pipelines

  • Context is one-way: a parent cancel flows down to every derived context. context.Background() is a wall that stops the caller's cancel dead — never pass it downstream !
  • Two-sided fix: pass the received ctx unchanged (or narrow with WithTimeout, never replace) into each call; check ctx.Err() at the top of each iteration before dispatching the next.
  • You can't rescue a call that ignores its ctx, but refusing to start further calls bounds overrun to ≤1 in-flight.

Bounded staged pipeline (settlepipeline)

  • Reusable Stage: N workers over one in, one out, WaitGroup-then-close. Guard all three channel ops (recv + send-result + send-err) with ctx.Done().
  • Derive one cancellable ctx for feeder + every stage; first error → cancel() short-circuits the lot; then drain.
  • Bounded buffers → when a stage lags, backpressure walks upstream to the feeder; memory bounded regardless of an early stage's speed.

Caches — TTL · LRU · LFU

  • TTL: lazy expiry on read (treat expired as miss) + a background sweeper goroutine; the sweeper must exit on Close (leak otherwise) !
  • LRU O(1): map[K]*node + hand-rolled doubly-linked list with sentinel head/tail. Node stores its key so removeTail deletes from the map in O(1).
  • A read is a write ! — a hit calls moveToFront, reordering the list. So Get takes a full Mutex.Lock(), not RLock; two concurrent RLock gets would splice the same list and corrupt it.
  • LFU: map[K]*entry + map[freq]*list + minFreq. Touch moves entry f→f+1; if that drained the minFreq bucket, minFreq++ — O(1), no scan. Get mutates freq → Mutex too.
  • Singleflight (GetOrCompute): one leader computes, waiters block on a per-key ready chan — collapses a cache stampede.
  • Trade-off: LRU is the cheap default but a sequential scan flushes the hot set; LFU resists scans but a once-hot key squats without decay. Production = TinyLFU (decaying sketch as admission filter).

  • Under concurrency assert an invariant (count/sum/set), never an exact sequence — order is nondeterministic !

select, timers & loop-var traps

  • select is uniform-random over ready cases — never assume priority ordering. Need "prefer cancel"? Re-check ctx.Done() in a nested non-blocking select first.
  • Empty select{} blocks forever; a lone default makes any send/recv non-blocking → the backpressure/try-send idiom.
  • Disable a case with a nil channel — a nil arm blocks forever, so setting a chan var to nil removes it from the select (e.g. stop reading input once drained).
  • time.After in a loop leaks a timer until it fires ! — for a hot loop use a reused time.NewTimer/Ticker and Stop() it. One-shot deadlines are fine.
  • Loop-variable capture: pre-Go 1.22, for _,v:=range xs { go f(v) } shared one v — pass it as an arg or shadow v:=v. go vet's loopclosure flags it; 1.22+ gives each iteration a fresh var.
  • Buffered ≠ unbounded. A buffer of N absorbs bursts up to N then blocks — that block is backpressure. Sizing the buffer is a latency/memory trade, not a correctness fix.
  • context.WithTimeout always needs its cancel() called (defer / t.Cleanup) or the timer goroutine lingers to the deadline — go vet lostcancel catches the missing one.

Happens-before — the ordering edges

Every fix is really "install a happens-before edge so goroutine A's writes are visible to B". Know which primitive gives you one — a bare shared read next to a write has none.

EdgeGuarantee
chan send → recveverything before the send is visible after the matching recv. The workhorse edge.
close(ch) → recvwrites before close visible to a receiver that observes the close (drain / ok==false).
Unlock → Lockwrites under one holder visible to the next acquirer. Same for RUnlock→Lock.
wg.Done → Waitall workers' writes visible after Wait() returns — why "WaitGroup-then-close" is sound.
Once.Dothe one execution happens-before every other Do return.
atomic store→loada released store is visible to an acquiring load; the basis of atomic.Pointer snapshot swap.
  • Go's model is DRAG: a program with a data race has undefined behaviour — not "eventually consistent", not "reads a stale value". Torn reads, impossible interleavings, corruption !
  • The reason single-writer, buffered-reply, and singleflight all work: the channel/close is the edge that orders otherwise-unlocked state.
  • Ask at every shared value: "which of these six edges orders this access?" If the answer is "none", it's a race the detector will find.

Kata — feed parser (streaming ingest)

Ingest a gigabytes-per-day tick feed: pipe-delimited SYMBOL|BID|ASK|QTY, one record per line. The trap is slurp vs stream and abort vs report-and-continue.

func Parse(r io.Reader,
    fn func(line int, q Quote, e *ParseError)) error {
  sc := bufio.NewScanner(r); line := 0
  for sc.Scan() {
    line++                              // BEFORE skip check !
    t := strings.TrimSpace(sc.Text())
    if t=="" || strings.HasPrefix(t,"#") { continue }
    q, pe := parseLine(line, t)
    fn(line, q, pe)                     // XOR: quote xor error
  }
  return sc.Err()                       // NOT optional !
}
  • Stream, don't slurp ! — io.ReadAll+strings.Split pulls the whole feed into RAM and can't emit before EOF. bufio.Scanner reuses one buffer → flat memory, early emit.
  • Error-as-value: a bad line yields a line-numbered *ParseError through the same callback as a good Quote; one truncated record never discards the good ones after it. Parse's return is reserved for IO/scanner failures only.
  • line++ before the skip → numbers are physical (count blanks/comments) so an operator can find the line. Reversing it is the classic off-by-N.
  • scanner.Err() after the loop surfaces an over-long line (past bufio's 64KB token cap) or IO error — a bare for Scan() silently truncates !
  • Text() vs Bytes(): Text() returns a fresh owned string (1 alloc/line) so a retained Symbol stays valid; Bytes() aliases the reused buffer — zero-copy but invalidated next Scan. Name the trade.
  • ParseUint(f,10,64) rejects a leading - for free → negative qty falls out as InvalidQty, no special case. Fixed check order (fields→symbol→bid→ask→qty) makes the first error deterministic.

Kata deep — message bus (at-least-once)

An in-memory broker modelling RabbitMQ: topic routing (exact + trailing markets.*), bounded queues, manual ack/nack, prefetch, ack-timeout, dead-letter. Headline guarantee: at-least-once.

ConceptRule
ack ≠ receivedack means processed; the broker owns the delivery until Ack(). Crash/timeout/Nack(true) → redeliver.
exactly-oncea fantasy over an unreliable channel ! → make the consumer idempotent (dedupe on Message.ID).
prefetch/QoScap on unacked deliveries per consumer — backpressure, not a perf knob; without it a slow consumer OOMs.
dead-letterpoison msg past maxRetries or Nack(false) → DLQ, so it can't loop forever.
generation guardeach dispatch bumps gen; a timed-out delivery's late ack is a no-op, not a double-ack.
  • One dispatcher goroutine per subscription is the only thing that sends on and closes out → close-exactly-once, no send-on-closed. Consumer gets <-chan Delivery (can't close it).
  • Queue state (FIFO, inflight set, DLQ) lives behind one Mutex; mutate under lock, then pulse a cap-1 wake chan. No lock held across the channel send.
  • Publish sheds on a full queue (ErrQueueFull) — non-blocking; dispatch to the consumer is paced by prefetch. Deliberate asymmetry.
  • Drive ack-timeout off an injected clock, never time.Sleep — deterministic redelivery test. Prove no-loss under -race -count=N.

Kata deep — matching engine (price-time priority)

A limit order book matching incoming orders against resting liquidity, wrapped in a lock-free single-writer engine. Real money → deterministic + quantity-conserving.

  • The data structure IS the policy. Bids sorted high→low, asks low→high; each price level a FIFO queue. Walk best-level-first, drain front-to-back — that walk is price-time priority, no scoring, reproducible from arrival order alone.
  • maker-price rule ! — a cross fills at the resting (maker) price, not the taker's; the taker gets price improvement.
  • Integer ticks (int64), never float64 — floats drift, equality fails, fills don't reconcile !
  • Market never rests — only limit remainders rest; a market remainder is discarded. Amend-up / re-price → back of the level (or reject); reduce keeps priority.
  • Single-writer beats locking. Every op is a RMW of the same book and the order is the result — a mutex just serialises with extra overhead + a forgotten-critical-section risk on money. Funnel all orders through one channel into one goroutine: same serialisation, genuinely lock-free core, determinism free.
  • Each match decrements both sides by the same amount → total bought == total sold. The stress invariant is quantity conservation; demand≫liquidity → exactly N filled.
  • Scale by sharding per instrument (one engine per symbol, a router hashing orders) — not by adding locks. There's no independently-shardable work within one instrument.

★ Pre-code checklist

Shared state & lifecycle

  • ☐ Named every var touched by >1 goroutine; each is under one lock, an atomic, or owned by a single goroutine.
  • ☐ Every go has a defined exit — closed chan, cancelled ctx, or finite loop. No exit = leak !

Synchronisation

  • ☐ RWMutex only where the read is truly read-only (LRU/LFU Get mutates → Mutex) !
  • ☐ Whole read-modify-write inside one critical section (no split lock = lost update).
  • ☐ Lock scoped tight — never held across a downstream / blocking call !
  • ☐ Multiple locks acquired in a total order (sorted id); same-resource re-lock rejected up front.

Channels

  • ☐ Exactly one closer (a sender), fenced with sync.Once or WaitGroup-then-close.
  • ☐ Every blocking channel op in a cancellable path selects on ctx.Done() — both send and recv.
  • ☐ Bounded buffer / default arm where a fast producer could grow memory unbounded.

Context & idempotency

  • ☐ Received ctx threaded into every downstream call — no context.Background() detach.
  • ☐ Duplicate delivery handled — dedupe on an ID / idempotency key, effect applied once.

Proof

  • ☐ Tests written first: contract → core → edges → -race stress asserting an invariant.
  • ☐ Leak check + deadline-wrapped hang check present.
  • ☐ Run go test -race -count=N + go vet; one green run is not proof !
